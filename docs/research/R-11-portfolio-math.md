# R-11 포트폴리오 계산 방법

- 조사일: 2026-11-11 (모든 출처의 확인일은 따로 적지 않으면 이 날짜다)
- 기준 문서: 토스증권 Open API 1.2.28 (`docs/toss-openapi-1.2.28.json`), `docs/design.md`, `docs/architecture.md`, `docs/tasks.md`
- 예제 값은 `examples.py`(Python 3.14.3, 금액은 `Decimal`)로 직접 계산해 검증했다. 스크립트는 저장소 밖 임시 폴더에서 돌렸고, 실행 결과를 이 문서에 그대로 옮겼다.
- 실제 계좌나 API 키를 쓰는 호출은 하지 않았다. 토스 값과의 대조는 모두 "0단계 대조 항목"으로 남겼다.

## 1. 요약

1. 화면의 기본 숫자는 토스와 같아야 하므로(ACC-6) 종목별 평단·평가손익·손익률은 `GET /holdings` 값을 그대로 쓴다. 앱이 직접 계산하는 것은 통화 합산, 기간 수익률(TWR·MWR), 비중·쏠림, 위험 지표, 세금 추정이다.
2. 기간 수익률은 두 가지를 같이 보여 준다. 시간가중 수익률(TWR)은 벤치마크·AI 성적표 비교용이고, 금액가중 수익률(MWR, XIRR)은 "내 돈 기준" 수익률이다. TWR을 계산하려면 날마다 평가액 스냅샷과 외부 현금흐름 분류가 필요하다.
3. 평단은 법(소득세법 시행령 162조 5항)상 원칙이 선입선출이다. 다만 토스증권은 해외주식 양도소득을 이동평균법으로 계산한다고 스스로 밝힌다. 앱은 로트 원장 하나에서 두 방식을 모두 계산하고, 세금 추정의 기본값은 이동평균으로 둔다.
4. 2026년 세율은 다음과 같다. 증권거래세는 코스피 0.05%에 농특세 0.15%, 코스닥 0.20%다. 해외주식 양도세는 국내외 과세대상 주식을 합쳐 연 250만 원을 공제한 뒤 20%에 지방세 2%를 더한다. 배당은 국내 14%+1.4%, 미국은 조약세율 15%다. 실제 세액과 수수료는 거래내역의 `commission`·`tax`·`netAmount`를 정답으로 쓰고, 앱의 계산은 사전 추정에만 쓴다.
5. 토스 API에 없는 것이 있다. 예수금, 미국 지수, ETF 구성 종목, GICS 분류, 액면분할 이벤트는 주지 않는다. 그래서 현금 원장 재구성, 미국 벤치마크 대체 수단, 섹터 매핑 표, 기업 행위 감지 규칙을 설계에 넣어야 한다.

### Q1. 수익률: 단순·시간가중·금액가중

**정의와 수식**

| 이름 | 수식 | 의미 |
|---|---|---|
| 평가 손익률(단순) | `(평가액 − 매입금액) / 매입금액` | 지금 들고 있는 종목의 손익률이다. 토스의 `profitLoss.rate`가 이것이다 |
| 기간 단순 수익률 | `(V_end − V_start − ΣF) / (V_start + ΣF⁺)` | 손익을 총투입액으로 나눈다. 입출금 시점을 무시하므로 기간 비교에는 쓰지 않는다 |
| 시간가중 수익률(TWR) | `Π(1 + r_i) − 1`, `r_i = V_i^{흐름 직전} / V_{i−1}^{흐름 직후} − 1` | 현금흐름이 생길 때마다 구간을 나눠 수익률을 사슬처럼 곱한다. 입출금 크기와 시점의 영향을 없앤 "운용 실력"이다. GIPS는 이 방식을 기본으로 요구한다 |
| Modified Dietz(근사 TWR) | `(V_end − V_start − ΣF_j) / (V_start + Σ w_j F_j)`, `w_j = (T − t_j)/T` | 기간 중간 평가액이 없을 때 쓰는 근사다 |
| 금액가중 수익률(MWR, IRR/XIRR) | `Σ CF_j / (1+r)^{(t_j − t_0)/365} = 0`을 만족하는 `r` | 투자자 현금흐름의 내부수익률이다. 내가 넣고 뺀 시점까지 반영한 "내 돈의 수익률"이다 |

GIPS 2020은 시간가중 수익률을 원칙으로 한다. 금액가중 수익률은 운용자가 외부 현금흐름을 통제하고 폐쇄형·만기형 등의 조건을 갖춘 경우에만 대신 쓸 수 있다 ([CFA Institute GIPS 개요](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/overview-of-the-global-investment-performance-standards), [GIPS 2020 for Firms 핸드북](https://www.gipsstandards.org/wp-content/uploads/2021/04/gips-standards-handbook-firms.pdf)). 개인은 외부 현금흐름을 스스로 통제한다. 그래서 "내 성과"로는 MWR도 의미가 있다.

**외부 현금흐름 분류 (토스 `TransactionType` 기준)**

TWR은 외부 흐름만 구간을 나눈다. 배당·이자·수수료는 포트폴리오 안의 수익과 비용이다.

| 토스 유형 | 계좌 전체 TWR에서 | 근거·주의 |
|---|---|---|
| `DEPOSIT`, `WITHDRAWAL` (`assetClass = null`) | 외부 흐름 | 은행 입출금 |
| `DEPOSIT`, `WITHDRAWAL` (`assetClass` 있음) | 내부 | 채권 만기 원리금 입금이나 채권 이자 세금 출금이다. 스펙에 "채권 만기 원리금 등", "채권 이자 세금 등"으로 적혀 있다 |
| `EXCHANGE_IN`, `EXCHANGE_OUT` | 내부 | 한 계좌 안의 통화 이동이다. 환전 스프레드 손실은 수익률에 들어간다 |
| `BUY`, `SELL` | 내부 | 현금과 주식 사이의 이동이다 |
| `DIVIDEND`, `INTEREST` | 내부 수익 | |
| `FEE` | 내부 비용 | 외화보관수수료 등 |
| `SECURITIES_TRANSFER_IN`, `SECURITIES_TRANSFER_OUT` | **판단 필요** | 타사 이관이면 외부 흐름이고 주식배당이면 내부 수익이다. 스펙은 둘을 구분하지 않고 `amount`도 null이다(위험 1번) |
| `isCancellation = true` | 원거래와 함께 없앤다 | 원거래는 목록에서 빠지고 취소 내역만 남는다. 이미 저장해 둔 원거래가 있으면 지우고, 취소 금액은 적용하지 않는다 |

**토스 API로 할 수 있는 범위**

- 토스는 과거 평가액을 주지 않는다. 앱이 매일 정해진 시각(예: 16:00 KST)에 `holdings`·`buying-power`·환율 스냅샷을 저장해야 TWR을 정확히 계산할 수 있다.
- 과거 구간은 다음처럼 재구성한다. 거래내역으로 날짜별 보유 수량을 만들고, 수정 전 일봉(`/candles?interval=1d&adjusted=false`)과 그날 환율(`/exchange-rate?dateTime=`)을 곱한다. 일봉은 한 번에 최대 200개이고 `before`로 페이지를 넘긴다.
- 예수금 API가 없으므로 현금은 거래내역의 `netAmount`를 부호에 맞춰 누적해 원장을 만든다. 그 값을 `cashBuyingPower`와 비교해 차이를 표시한다. `netAmount`는 "예수금 변동과 같지 않을 수 있다"고 스펙에 적혀 있다.
- 현금 원장이 맞지 않는 기간에는 대안이 있다. 주식 부분만 따로 TWR을 구하는 방식이다. 매수는 유입, 매도는 유출로 보고 배당은 수익에 넣는다. 이 방식으로 바꾸면 화면에 "주식 부분 수익률"이라고 표시한다.

**예제 1 (테스트 기준값)**

- 2026-01-02 평가 10,000,000원
- 2026-07-01 입금 직전 평가 11,000,000원, 입금 5,000,000원
- 2026-12-31 평가 15,400,000원
- T = 363일, 입금 이후 183일

| 항목 | 값 |
|---|---|
| 손익 | 400,000 |
| 기간 단순 수익률 = 400,000 / 15,000,000 | 0.026667 |
| TWR = (11/10) × (15.4/16) − 1 | **0.058750** |
| Modified Dietz (w = 183/363 = 0.504132) | 0.031947 |
| MWR (XIRR, 연율, 365일 기준) | 0.032177 |
| MWR (기간 IRR, 비연율) | 0.031997 |

해석: 앞 반년에 10%를 벌었다. 큰돈이 들어온 뒤 3.75%를 잃었다. 운용 실력(TWR)은 +5.9%이고, 내 돈 기준(MWR)은 +3.2%다.

**화면에 보여 줄 것 (추천)**

| 위치 | 숫자 | 이유 |
|---|---|---|
| 보유 종목 표 | 평가손익, 평가 손익률(토스 값 그대로), 세후 손익(`amountAfterCost`) | 토스 앱과 같아야 한다(ACC-6) |
| 계좌 요약 | 총 평가손익(원화 환산, 환율·시각 표시), 오늘 손익 | |
| 기간 성과 탭 | TWR(1개월·3개월·연초 이후·1년·전체)과 같은 기간의 벤치마크 | 벤치마크와 비교할 수 있는 숫자는 TWR뿐이다 |
| 기간 성과 탭 | MWR(설정 이후 연율, 1년 미만이면 비연율) | 입출금 타이밍 효과를 본인이 알 수 있게 한다 |
| 규칙 | 1년 미만 기간은 연율화하지 않는다 | GIPS가 1년 미만 연율화를 금지하는 것으로 알려져 있으나 이번에 조항 원문은 확인하지 못했다(미확인). 오해를 막기 위한 제안 규칙으로 둔다 |

### Q2. 평균 매수 단가: 이동평균법과 선입선출법

**정의**

- 이동평균법: 매수할 때마다 `평단 = (기존 원가 + 매수 금액) / (기존 수량 + 매수 수량)`로 다시 계산한다. 매도해도 평단은 그대로이고, 실현손익은 `매도수량 × (매도가 − 평단)`이다. 소득세법 시행령 92조 2항 5호가 같은 정의를 쓴다.
- 선입선출법: 먼저 산 로트부터 판다. 실현손익은 로트별 `(매도가 − 로트 단가) × 수량`의 합이다.

**법과 실무**

| 항목 | 내용 | 출처 |
|---|---|---|
| 세법 원칙 | "양도한 자산의 취득시기가 분명하지 아니한 경우에는 먼저 취득한 자산을 먼저 양도한 것으로 본다" | [소득세법 시행령 제162조 제5항](https://www.law.go.kr/법령/소득세법시행령/제162조) (시행 2026-10-01 판에서 확인) |
| 비거주자 | 취득가액이 다른 같은 종목을 비거주자가 양도하면 이동평균법을 쓴다 | 소득세법 시행령 제183조 제2항(같은 판) |
| 양도·취득 시기 | 대금을 청산한 날, 즉 결제일 | [소득세법 제98조](https://www.law.go.kr/법령/소득세법/제98조) |
| 이동평균 허용 | 국세청이 2022년 유권해석으로 증권사가 계속 적용한 이동평균법 신고를 허용했다고 보도됐다. **국세청 원문은 찾지 못했다(미확인)** | [더파이낸스 기사(다음)](https://v.daum.net/v/20250409182039083) |
| 토스증권 | "토스증권의 경우 이동평균법으로 양도소득을 계산합니다." 타사에서 대체 입출고한 경우에는 단가가 다를 수 있다고 적혀 있다 | [토스증권 외화증권거래설명서 (심의필 2024-45, 2024-07-16)](https://home-files.tossinvest.com/files/notice/4775d90a-c677-40c7-8162-32392bac613b.pdf) Q5 |
| 토스 화면 평단 | `HoldingsItem.averagePurchasePrice`("매수 평균가, 거래 통화 기준")가 제공된다. 계산 방식, 수수료 포함 여부, 해외주식을 원화로 평균하는지 달러로 평균하는지는 **미확인** | OpenAPI 1.2.28 |
| 타사 이관 | 여러 번 산 주식을 내보내면 평균 단가로 보내고, 매수일은 출고일이 된다 | [토스증권 FAQ(검색 결과 요약 기준)](https://corp.tossinvest.com/en/faq?tab=115) |

**예제 2 (테스트 기준값)**: 매수 10@100 → 매수 10@120 → 매도 5@130 → 매수 5@110 → 매도 10@125

| 단계 | 이동평균: 수량 / 원가 / 평단 | 이동평균 실현 |
|---|---|---|
| 매수 10@100 | 10 / 1,000 / 100 | |
| 매수 10@120 | 20 / 2,200 / 110 | |
| 매도 5@130 | 15 / 1,650 / 110 | +100 |
| 매수 5@110 | 20 / 2,200 / 110 | |
| 매도 10@125 | 10 / 1,100 / 110 | +150 |
| **합계** | 잔여 원가 1,100, 평단 110 | **+250** |

선입선출: 실현 **+300**, 잔여 로트는 [5@120, 5@110], 잔여 원가 1,150, 평단 115.

**추천**: 로트 단위 원장(`Lot`)을 정본으로 저장하고, 이동평균과 선입선출은 거기서 계산하는 보기로 둔다. 화면의 평단은 토스 값을 쓴다. 앱이 계산한 이동평균 평단은 토스 값과 대조하는 데에만 쓴다.

### Q3. 수수료와 세금 반영

**원칙**: 체결되고 결제된 거래의 실제 비용은 토스 거래내역의 `commission`·`tax`·`netAmount`를 쓴다. 스펙에도 "계산하지 말고 이 값을 사용"하라고 적혀 있다. 앱의 공식은 주문 전 추정(주문 카드의 "예상 수수료·세금")과 세금 시뮬레이션에만 쓴다. 보유 종목의 세후 평가는 토스 `amountAfterCost`를 쓴다.

**국내 주식**

| 항목 | 2026년 값 | 출처 |

**환율 종류**

- 토스 환율 API는 1분마다 갱신되는 참고용 값이고, `dateTime`으로 과거 시점을 조회할 수 있다(OpenAPI 1.2.28).
- 토스 FAQ에 따르면 해외주식 가격에 반영하는 환율은 서울외국환중개의 오늘의 기준환율이다([토스 FAQ, 검색 결과 요약 기준](https://corp.tossinvest.com/en/faq?searchTitleKeyword=%ED%99%98%EC%A0%84)).
- 토스 `OverviewProfitLoss.rate`는 "전체 자산을 현재 환율로 원화 환산한 기준"이다. 종목별 `ProfitLoss.rate`가 원화 기준인지 달러 기준인지는 Asset 그룹 설명("손익률은 원화(KRW) 환산 기준")과 필드 설명("거래 통화 기준")이 서로 달라 **미확인**이다. 0단계 대조 항목이다.
- 외국환거래규정 원문: [외국환거래규정 제1-2조 제7호 (재정경제부고시 제2026-103호, 시행 2026-09-16)](https://www.law.go.kr/LSW/flDownload.do?flSeq=169381691)

**합산 규칙**

- `Money(KRW) + Money(USD)`는 만들 수 없다. `convert(usd, FxRate{base: USD, quote: KRW, rate, kind: Mid, as_of, source})`로 바꾼 뒤에 더한다(architecture 3.4).
- 통화별 합계(토스 `Price.krw`, `Price.usd`)는 정확값이다. 원화 환산 총액은 근사값이고 쓴 환율과 시각을 붙인다(ACC-6).

**예제 7**: KRW 10,000,000 + USD 5,000.00 × 1,375(midRate) = **16,875,000원**. 비중은 KRW 0.592593, USD 0.407407.

**환차손익 분리 수식**

보유 수량 `Q`, 달러 원가 합계 `C_usd`, 원화 원가 합계 `C_krw`(로트별 매수 금액 × 그 거래의 환율), 현재가 `P₁`, 현재 환율 `X₁`를 쓴다.

- 매입 평균 환율 `X̄ = C_krw / C_usd`
- 원화 손익 `= Q·P₁·X₁ − C_krw`
- 가격 효과 `= (Q·P₁ − C_usd) · X̄`
- 환 효과 `= Q·P₁ · (X₁ − X̄)`
- 두 효과를 더하면 원화 손익과 정확히 같다(잔여항이 없다).

**예제 6 (테스트 기준값, 토스 외화증권거래설명서 CASE3와 같은 숫자)**: 100주, $70 → $65, 환율 1,200 → 1,100. 총 −1,250,000 = 가격 효과 −600,000 + 환 효과 −650,000. 토스 문서의 분해와 일치한다. 환 효과를 매입 달러 기준으로 잡는 다른 분해(가격 −550,000, 환 −700,000)는 쓰지 않는다.

달러 현금 잔고에도 같은 방식으로 환 효과가 생긴다(`USD 현금 × (X₁ − 현금의 평균 환전 환율)`).

### Q5. 기업 행위의 영향과 처리 규칙

토스 API가 주는 단서는 다음과 같다.

- 국내 종목은 액면분할·병합 뒤 `isinCode`가 바뀔 수 있다. 거래내역에는 거래 시점의 ISIN이 남는다.
- 주식배당은 `SECURITIES_TRANSFER_IN`(수량 있음)으로 들어온다.
- 일봉은 `adjusted`(기본 true)로 수정주가를 고를 수 있다.
- 종목 상태로 `status`(SCHEDULED·ACTIVE·DELISTED), `delistDate`, `koreanMarketDetail.liquidationTrading`(정리매매), `krxTradingSuspended`가 있다.
- 단주는 원칙적으로 매도해 대금만 지급한다([토스 외화증권거래설명서](https://home-files.tossinvest.com/files/notice/4775d90a-c677-40c7-8162-32392bac613b.pdf) "유무상교부, 주식배당, 주식분할 또는 주식병합" 항목).

액면분할 자체를 알려 주는 이벤트 API는 없다.

| 사건 | 거래내역·보유 처리 | 평가·수익률 처리 | 감지 방법 |
|---|---|---|---|
| 액면분할·병합(비율 k) | 로트마다 수량 × k, 단가 ÷ k. 원가 합계와 취득일은 바꾸지 않는다 | 과거 수량 × 수정 전 가격 = 수정 수량 × 수정 가격이므로 가치 시계열은 그대로다. 위험 지표는 `adjusted=true` 일봉으로 계산한다 | 매매 없이 보유 수량이 정수배로 바뀌거나 ISIN이 바뀐다. 사용자 확인 후 `CorporateAction`을 기록한다 |

| 주식배당 | 새 로트(수량, 원가 0 또는 세법상 금액)를 만든다 | TWR에서는 내부 수익이다(외부 흐름 아님) | 위와 같은 유형이라 타사 이관과 구분하려면 사용자 분류가 필요하다 |
| 무상주·주식배당의 세법상 취득가액(의제배당 여부) | **미확인**. 앱은 세금 추정에서 이 로트를 "확인 필요"로 표시한다 | | |
| 종목 코드·이름 변경 | 앱 내부 `InstrumentId`를 기준 키로 쓰고 `Symbol`·`Isin`은 이력으로 연결한다 | 영향 없음 | 거래내역 ISIN과 현재 `/stocks/{symbol}` ISIN이 다르다 |
| 상장폐지 | 정리매매 중이면 경고를 띄우고, 폐지 후 남은 수량은 "평가 불가"로 따로 표시한다. 평가액에 0을 넣을지는 사용자가 정한다 | 마지막 체결가 이후의 수익률 계산에서 뺄지 사용자가 정한다 | `status = DELISTED`, `liquidationTrading = true` |
| 배당 재투자 | 배당은 `DIVIDEND`(현금, 내부 수익)이고, 재투자는 일반 `BUY`다 | TWR과 MWR 모두 외부 흐름이 없다 | 토스의 자동 재투자 기능 여부는 **미확인** |
| 합병·분할·교환 | 자동 처리하지 않고 수동 입력으로 받는다 | | **미확인** (토스 표현 방식 모름) |
| 미국 종목 분할 | 국내와 같은 규칙을 쓴다. ISIN이 유지되는지는 **미확인** | | |

### Q6. 쏠림 지표와 경고 기준

**수식** (가중치 `w_i = 원화 환산 평가액_i / 원화 환산 총자산`. 현금 포함 여부는 지표마다 정한다)

| 지표 | 수식 | 비고 |
|---|---|---|
| 종목 비중 | `w_i` | ETF는 한 종목으로 계산하고, 구성 종목 분해 비중은 따로 보여 준다 |
| 섹터·국가·통화 비중 | `Σ_{i∈그룹} w_i` | 통화는 거래 통화, 국가는 상장 시장 기준. 현금은 통화 비중에만 넣는다 |
| 허핀달 지수(HHI) | `Σ w_i²` (0~1, ×10,000 표기도 가능) | |
| 유효 종목 수 | `1 / HHI` | 개인에게 가장 읽기 쉬운 표현이다("사실상 n종목") |
| 상위 N 비중 | 비중 상위 N개 `w`의 합 | N = 1, 3, 5 |

**예제 8 (테스트 기준값)**: 가중치 [0.35, 0.25, 0.15, 0.10, 0.10, 0.05] → HHI = **0.2300**(2,300), 유효 종목 수 **4.347826**, 상위 3 = **0.75**. 균등 10종목이면 HHI 0.10.

**비중 합 100% 반올림 (D-06)**: 표시 단위(예: 0.01%)로 내린 값의 합이 100%가 되도록 최대 잔여법(largest remainder)으로 나머지를 나눠 준다. 이 방법은 제안이며 표준 문헌으로 확인하지는 않았다.

**경고 기준**: 개인 포트폴리오에 대한 법정 기준은 없다. 아래는 참고 기준과 그것을 바탕으로 한 제안값이다. 모두 설정(투자 원칙)에서 바꿀 수 있다.

| 지표 | 제안 기본값 | 참고한 기준 |
|---|---|---|
| 한 종목 비중 | 주의 10%, 경고 20% | 공모 집합투자기구는 동일종목 투자를 자산총액의 10% 안으로 제한한다(시행령 예외 있음) ([자본시장법 제81조 제1항 제1호 가목](https://www.law.go.kr/법령/자본시장과금융투자업에관한법률/제81조)). 20%는 design.md D5의 예시값이다 |
| 유효 종목 수 | 5 미만이면 경고(HHI > 0.20) | 미국 법무부·FTC 2023 합병 지침은 시장 HHI 1,800 초과를 "고집중"으로 본다([DOJ HHI](https://www.justice.gov/atr/herfindahl-hirschman-index)). 시장점유율 기준이라 포트폴리오에는 유추로만 쓴다 |
| 한 섹터 비중 | 경고 40% | **근거가 되는 표준 없음.** 사용자 설정값으로만 둔다 |
| 통화·국가 비중 | 경고 없이 표시만 한다 | 근거 없음 |
| 레버리지·인버스 ETF | `leverageFactor`가 1이 아니면 표시 | 토스 `StockInfo.leverageFactor` |

연구 질문의 "KRX 업종"은 2026년 하반기부터 KRICS로 바뀌는 중이다.

**추천 통합 방법**

1. 기준 축은 GICS 11 섹터로 하고, 여기에 `ETF·펀드(분해 전)`, `현금`, `미분류`를 더한다. 국내외 종목을 한 축에 놓을 수 있는 체계는 GICS뿐이다.
2. 종목별 매핑 표 `SectorAssignment{instrument, scheme: Gics|Krics|TossSector, code, source, as_of, confirmed_by_user}`를 저장소에 둔다. 체계 대 체계 자동 변환표(예: KRICS 모빌리티 → GICS)는 만들지 않는다. 일대일로 대응하지 않기 때문이다(예: KRICS "에너지·화학"은 GICS Energy와 Materials에 걸친다).
3. GICS 코드 데이터는 MSCI·S&P 라이선스 대상이라 무료 일괄 조회 경로를 확인하지 못했다(**미확인**). 그래서 보유 종목 수십 개는 처음에 사용자 확인 또는 AI 초안 후 사용자 확인으로 채우고, 출처를 남긴다.
4. 토스 섹터는 보조 정보로 함께 표시한다.

**ETF 분해**

- 토스 API는 ETF 구성 종목을 주지 않는다. `/sectors/{id}/etfs`(섹터 관련 ETF)만 있어서 ETF 하나를 대표 섹터 하나에 대략 연결할 수는 있다.
- 1단계: ETF는 하나의 항목으로 두고, 대표 섹터·국가는 사용자가 지정한다(예: KODEX 200 → 국가 KR, 섹터 "광범위").
- 2단계: 구성 종목 파일(PDF)로 분해한다. 국내 ETF는 KRX 정보데이터시스템의 PDF, 미국 ETF는 운용사가 공개하는 보유 종목 파일을 쓴다. 이용 조건과 수집 방법은 R-07과 함께 정한다(**미확인**).
- 분해 수식: `섹터 s의 노출 = Σ_직접 w_i·[i∈s] + Σ_ETF w_e · Σ_{j∈e} h_{e,j}·[j∈s]`. `h`는 ETF 안의 비중이다. 레버리지 ETF는 `leverageFactor`를 곱한 노출을 따로 보여 준다.

### Q8. 벤치마크

**토스 API로 얻을 수 있는 것**

- 지수는 `KOSPI`, `KOSDAQ`과 국채 금리 6종뿐이다(Market Indicators 심볼 카탈로그 8종). KOSPI 200, S&P 500, 나스닥 지수는 없다.
- 미국 지수 대신 ETF 일봉을 `/candles`로 받을 수 있다(예: S&P 500 추종 ETF). `adjusted=true` 수정주가에 배당 재투자가 반영되는지는 **미확인**이다. 반영되지 않으면 가격지수로 취급해야 한다.
- KOSPI는 가격지수다. 배당을 포함한 포트폴리오 TWR과 비교하면 벤치마크가 불리하게(낮게) 나온다는 점을 화면에 표시한다.

**혼합 방법**

- 미국 다리를 원화로 바꾼다: `r_US,KRW = (1 + r_US,USD)(1 + r_FX) − 1`. `r_FX`는 매매기준율 변화율이다.
- 혼합 벤치마크: `r_B,t = w_KR,t−1 · r_KR,t + w_US,t−1 · r_US,KRW,t`. 가중치는 둘 중 하나로 정한다.
  - (가) 직전 스냅샷의 실제 시장 비중(동적): "같은 국가 배분에서 시장만큼 벌었는가"를 본다.
  - (나) 사용자가 정한 목표 비중으로 매월 재조정(정적): "내 정책 대비"를 본다.
- 날짜 맞추기: KST 16:00 스냅샷 기준으로 KR은 그날 종가, US는 직전 뉴욕 정규장 종가, 환율은 그날 매매기준율을 쓴다. 포트폴리오 스냅샷과 같은 규칙을 써야 비교가 맞는다.

**예제 10 (테스트 기준값)**: KR 60%·US 40%, KOSPI +1%, S&P +0.5%(USD), USD/KRW +0.2% → 미국 다리 원화 수익률 **0.007010**, 혼합 **0.008804**.

**제안 성적표(D4)**

- 개별 제안은 그 종목 시장의 지수(KR 종목은 KOSPI 또는 KOSDAQ, US 종목은 S&P 500 프록시)를 원통화 기준으로 같은 기간 비교한다.
- 포트폴리오 전체는 혼합 벤치마크와 비교한다.
- 방법론 세부는 R-12에 넘긴다.

### Q9. 위험 지표 (일봉 기준)

**수식** (포트폴리오 일별 TWR 수익률 `r_t`. 가격 시계열이면 `r_t = P_t/P_{t−1} − 1`)

| 지표 | 수식 |
|---|---|
| 일 변동성 | 표본표준편차 `s = sqrt(Σ(r_t − r̄)² / (n − 1))` |
| 연율 변동성 | `s × sqrt(252)` (연 관측 수를 252로 고정하는 관례. 한국·미국 거래일 수 차이는 무시한다) |
| 최대 낙폭(MDD) | `min_t (V_t / max_{s≤t} V_s − 1)` |
| 베타 | `Cov(r_p, r_b) / Var(r_b)` (표본, n−1). 결정계수 `R² = Corr²`를 함께 보여 준다 |

**예제 9 (테스트 기준값)**: 포트 [100, 102, 99, 101, 104, 100, 98, 103], 벤치 [100, 101, 99.5, 100.5, 102, 100, 99, 101.5]

| 항목 | 값 |
|---|---|
| 포트 일수익률 | [0.02, −0.029412, 0.020202, 0.029703, −0.038462, −0.02, 0.05102] |
| 일 표준편차 | 0.033867 |
| 연율 변동성 | 0.537618 |
| MDD | −0.057692 (104 → 98) |
| 베타 | 1.993821 |
| 상관 | 0.999959 |
| R² | 0.999919 |

**필요한 최소 기간**

- 표준 기관의 최소 기간 규정은 찾지 못했다. Morningstar는 표준편차를 36개월 월간 수익률로 연율화해 표시한다([Morningstar 데이터 정의](https://awgmain.morningstar.com/webhelp/glossary_definitions/indexes/mfratingsandrisk.htm)).
- 정규분포를 가정하면 변동성 추정의 상대 표준오차는 약 `1/sqrt(2(n−1))`이다. 직접 계산한 값은 n=20일 때 16%, 60일 9%, 120일 6.5%, 250일 4.5%, 750일 2.6%다.
- **추천**: 변동성은 60거래일 이상일 때 표시하고, 그보다 짧으면 "표본 부족"으로 표시한다. MDD는 항상 표시하되 기간을 함께 쓴다.
- **추천**: 베타는 한국과 미국 장이 비동기라 일간 혼합 포트폴리오에서 낮게 추정될 수 있다. 그래서 주간 수익률 52주 이상으로 계산하고, R²가 낮으면(예: 0.3 미만) 흐리게 표시한다. 시장별 하위 포트폴리오의 베타는 일간 120일 이상으로 계산한다. 비동기 편의는 이론에서 알려진 현상이지만 이번에 문헌을 따로 확인하지는 않았다.

## 3. 선택지 비교표와 추천

### 3.1 화면의 대표 수익률

| 선택지 | 장점 | 단점 | 결정 |
|---|---|---|---|
| 평가 손익률만 (토스 방식) | 토스와 같고 이해하기 쉽다 | 기간 비교와 벤치마크 비교가 안 되고, 매도하면 사라진다 | 보유 표에 사용 |
| TWR만 | 벤치마크·AI 성적표와 비교할 수 있다 | 내 돈 기준 결과와 다르게 느껴질 수 있다 | |
| MWR만 | 내 경험과 맞는다 | 입출금 시점에 휘둘리고 벤치마크와 비교할 수 없다 | |
| **세 가지를 역할을 나눠 표시** | 각 숫자의 질문이 분명하다 | 화면 설명이 필요하다 | **추천** |

추천 이유: 앱의 목적인 D4(AI가 얼마나 맞았는지)에는 TWR이 꼭 필요하고, ACC-6(토스와 일치)에는 평가 손익률이 필요하다. 이 추천이 틀리는 조건은 두 가지다. 현금 원장을 재구성할 수 없어(위험 2번) 계좌 TWR이 계속 틀리면 "주식 부분 TWR"만 남긴다. 사용자가 두 숫자의 차이를 헷갈려 하면 MWR을 상세 화면으로 내린다.

### 3.2 원가 방식

| 선택지 | 장점 | 단점 | 결정 |
|---|---|---|---|
| 이동평균만 저장 | 단순하고 토스와 같은 방식일 가능성이 높다 | 선입선출 계산이 불가능하고, 로트 정보가 사라진다 | |
| 선입선출만 | 법 원칙과 같다 | 토스 신고 대행 값과 다르다 | |
| **로트 원장에서 두 방식을 계산** | 둘 다 가능하고 검증할 수 있다 | 저장 구조가 약간 복잡하다 | **추천** |

틀리는 조건: 0단계 대조에서 토스 `averagePurchasePrice`가 앱의 이동평균과 수수료나 환율 처리 때문에 계속 다르면, 화면 평단은 토스 값만 쓰고 앱 계산은 세금 추정에만 남긴다.

### 3.3 섹터 기준 축

| 선택지 | 장점 | 단점 | 결정 |
|---|---|---|---|
| 토스 섹터 | API로 바로 받는다 | 한 종목이 여러 섹터라 합산할 수 없고, 미국 커버리지가 미확인이다 | 보조 |
| KRICS | 국내 특성을 반영한다 | 미국 종목이 없다 | 보조 |
| **GICS 11 + 수동 매핑 표** | 국내외가 한 축이고 국제 비교가 쉽다 | 데이터 라이선스 때문에 수작업이 필요하다 | **추천** |

틀리는 조건: 토스 섹터의 대분류(depth 0)가 사실상 한 종목에 하나라는 것이 확인되고 미국 종목도 덮는다면, 토스 대분류를 기준 축으로 삼는 편이 유지 비용이 낮다.

### 3.4 미국 벤치마크 출처

| 선택지 | 장점 | 단점 | 결정 |
|---|---|---|---|
| **S&P 500 추종 ETF 일봉(토스 `/candles`)** | 추가 공급자가 필요 없다 | 지수가 아니고, 배당 반영 여부가 미확인이다 | **추천(1단계)** |
| 별도 지수 데이터 공급자 | 정확하다 | 새 외부 연결과 약관 검토가 필요하다(R-07, R-13) | 2단계 검토 |

틀리는 조건: 토스 `/candles`가 미국 ETF를 지원하지 않거나 수정주가 정의가 불분명하면 2단계로 넘어간다.
