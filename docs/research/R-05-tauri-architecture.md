# R-05 Tauri 2 앱 구조와 타입 생성

- 조사일: 2026-11-11 (모든 "확인" 날짜는 이 날이다)
- 조사 환경: macOS 26.5.2 (Apple M3 Max), Rust 1.95.0 (`cargo +1.95.0`), Node 24.22.0
- 실험 코드: `<세션 임시 폴더>/research/R-05/` (저장소 밖)

## 1. 요약

1. 기준 버전은 **Tauri 2.12.5**(안정)다. 3.0.0-alpha.6도 나와 있지만 공식 블로그에 3.0 일정 공지는 없다. 2.12부터 MSRV가 **Rust 1.90**이므로 `rust-toolchain.toml`로 툴체인을 고정해야 한다(이 PC 기본 stable은 1.88이다).
2. 앱 명령 권한: `build.rs`에서 `AppManifest::commands`로 앱 ACL을 켜면, 권한을 받은 명령만 WebView가 부를 수 있다. 소스 코드로 확인했다. `core:default`는 쓰지 말고, 쓰는 권한을 하나씩 나열한다. 특히 `core:event:allow-emit`은 주지 않는다.
3. 타입 생성 도구는 **tauri-specta 2.0.0-rc.28 + specta-typescript 0.0.15**를 추천한다(`=`로 고정). 명령·이벤트·Channel·Result·십진수 문자열을 생성할 수 있고, `u64` 같은 큰 정수는 내보내기를 거부한다는 것을 실행해서 확인했다. 아직 RC이고 rc.28에서 기본 오류 처리 방식이 바뀌었으므로 버전 고정과 재생성 차이 검사가 필수다.
4. 코어→UI 전송은 두 가지로 나눈다. 드문 도메인 알림은 tauri-specta 타입 이벤트로 보내고, 채팅 토큰 같은 대량 스트림은 요청마다 `tauri::ipc::Channel<T>`로 보낸다(공식 문서의 권고). 자식 프로세스는 셸 플러그인 대신 `tokio::process`로 실행하고 프로세스 그룹과 stdin 파이프로 수명을 묶는다. 부모가 SIGKILL로 죽으면 자식이 살아남는다는 것을 실험으로 확인했다.
5. 메뉴 막대 상주(`prevent_close` + 트레이 + `ActivationPolicy::Accessory`), 자동 시작(autostart 2.7.0), 알림(notification 2.8.1), Touch ID(biometric **2.5.0부터 macOS 지원**)는 모두 플러그인이나 API로 바로 된다. 업데이터와 공증은 필요 없다. 대신 ad-hoc 서명은 다시 빌드할 때마다 CDHash가 바뀐다(실험으로 확인). 그래서 키체인 접근 제어와 생체 인증을 거는 키체인 항목은 R-16에서 서명 방식과 함께 정해야 한다.

**capabilities 모델** [Capabilities 문서], [Permissions 문서]

- capability 파일은 `src-tauri/capabilities/*.json|toml`에 둔다. `identifier`, `windows`(창 **라벨** 기준), `permissions`, `platforms`, `remote.urls`를 갖는다.
- 이 폴더의 파일은 자동으로 켜진다. `tauri.conf.json`의 `app.security.capabilities`에 목록을 적으면 그 목록만 쓰인다. 저장소에 파일 하나가 몰래 추가되는 것을 막으려면 목록을 명시해야 한다.
- 창 하나가 capability 여러 개에 속하면 권한이 합쳐진다.
- 기본값으로는 "등록된 모든 앱 명령을 모든 창이 부를 수 있다". 이를 바꾸려면 `build.rs`에서 `AppManifest::commands(&[...])`를 쓴다. 그러면 명령마다 `allow-<명령>`·`deny-<명령>` 권한이 자동으로 생긴다. [AppManifest docs.rs]
- 문서는 목록에 없는 명령이 어떻게 되는지 말하지 않는다. 그래서 **소스로 확인했다**. `tauri-2.12.5/src/webview/mod.rs` 2076–2084행을 보면, 앱 ACL 매니페스트가 있거나(`has_app_acl_manifest`), 플러그인 명령이거나, 원격 출처일 때 ACL이 해석되지 않으면 요청을 거부한다(`Command {cmd} not allowed by ACL`). 앱 ACL 매니페스트가 있다는 판정은 `tauri-utils-2.10.2/src/acl/mod.rs:352`의 `acl.contains_key(APP_ACL_KEY)`다. 즉 `AppManifest::commands`나 `permissions/` 폴더가 있으면, 권한을 받지 못한 앱 명령은 전부 막힌다.
- `core:default`는 core 플러그인 전체(app, event, window, webview, path, menu, tray, image, resources)의 `default`를 묶은 것이다(`tauri-2.12.5/build.rs` 445–480행). 그 안의 `core:event:default`에는 `allow-emit`과 `allow-emit-to`가 들어 있다(`permissions/event/autogenerated/reference.md`). WebView가 이벤트를 쏠 수 있게 되므로 코어가 그 이벤트를 신뢰하면 안 된다.

**최소화 방법 (추천 구성)**

1. `build.rs`: `tauri_build::try_build(Attributes::new().app_manifest(AppManifest::new().commands(&[명령 목록])))`.
2. `capabilities/main.json`: `windows: ["main"]`. 권한은 쓰는 `allow-<명령>`과 `core:event:allow-listen`, `core:event:allow-unlisten`, 그리고 정말 필요한 창 권한만 준다. `core:default`, `shell:*`, `biometric:*`, `notification:*`, `autostart:*`는 **WebView에 주지 않는다.** 이 플러그인들은 Rust에서만 부른다.
3. `tauri.conf.json`의 `app.security.capabilities`에 `["main"]`만 명시한다. `remote`는 쓰지 않는다.
4. 하네스 검사(`xtask`)를 둔다. 세 가지가 같아야 한다: tauri-specta가 생성한 명령 이름, `build.rs`의 명령 목록, capability의 `allow-*` 목록. 승인 명령(`approve_and_submit` 계열)은 허용 목록의 위치를 고정한다.
5. 리눅스와 안드로이드에서는 iframe과 창 자신을 구분하지 못한다는 경고가 있다. macOS 전용이라 해당하지 않지만, 앱에서 iframe을 쓰지 않는다. [Capabilities 문서]

### Q2. Cargo 작업 공간 배치와 빌드 시간

- 공식 Tauri 문서에는 작업 공간 배치 가이드가 없다(미확인). 크기 최적화 문서는 `[profile.dev] incremental = true`만 언급한다. [Tauri App Size]
- 측정 (이 PC, Rust 1.95.0, `tauri 2.12.5` `default-features=false, features=["wry"]` + tauri-specta 예제 crate):
  - 처음부터 빌드: **45.93초**
  - `touch src/main.rs` 뒤 증분 빌드: **1.74초**
- 추천 배치:
  - 저장소 루트를 **가상 작업 공간**으로 만들고, `crates/*`와 `apps/desktop/src-tauri`를 멤버로 둔다. `Cargo.lock`과 `target/`은 하나만 쓴다. `[workspace.dependencies]`로 버전을 한 곳에서 고정하고, `[workspace.lints]`를 두며, 각 crate는 `lints.workspace = true`를 쓴다.
  - **`tauri` 의존성은 `src-tauri`에만 둔다.** `domain`, `application`, `order-execution`, `adapters/*`가 tauri나 wry를 끌어오지 않아야 `cargo test -p domain` 같은 핵심 테스트가 WebView 스택을 컴파일하지 않는다. 이 규칙은 아키텍처의 의존 규칙과도 맞는다.
  - IPC DTO에는 specta derive가 필요하다. 그런데 `domain`은 "표준 라이브러리와 십진수·시간 crate만" 의존할 수 있으므로 domain 타입에 직접 derive할 수 없다. 그래서 `src-tauri` 안의 `ipc` 모듈(또는 별도 `ipc-contract` crate, specta만 의존)에 DTO를 두고 domain→DTO 변환을 한다.
  - Tauri CLI(`tauri dev/build`)가 루트 작업 공간의 `target/`을 제대로 찾는지는 **미확인**이다. 뼈대 작업에서 확인한다.
- 빌드 시간의 다른 수단(보조 출처): 의존성만 `opt-level=1`로 빌드하기, rust-analyzer가 쓰는 target 폴더 분리, `MACOSX_DEPLOYMENT_TARGET` 불일치로 생기는 재빌드 막기. [dev.to 블로그(보조)]

### Q3. Rust→TS 타입 생성 도구 비교

**실행 결과 1: tauri-specta 2.0.0-rc.28** (`specta-demo/`)

입력(요약):

```rust
#[derive(Serialize, Deserialize, Type, Clone, Debug)]
pub struct Money {
    pub currency: Currency,
    #[serde(with = "rust_decimal::serde::str")]
    #[specta(type = String)]
    pub amount: rust_decimal::Decimal,
    pub plain: rust_decimal::Decimal,
}
#[derive(Serialize, Deserialize, Type, Clone, Debug)]
#[serde(tag = "kind", content = "detail", rename_all = "camelCase")]
pub enum AppError { UserFixable { message: String }, Retryable { retry_after_secs: u32 }, Bug }
#[derive(Serialize, Deserialize, Type, Clone, Debug)]
#[serde(tag = "type", rename_all = "camelCase")]
pub enum ChatChunk { Token { text: String }, ToolCall { name: String }, Done }
#[derive(Serialize, Deserialize, Type, Clone, Debug, Event)]
pub struct PortfolioSynced { pub total: Money, pub raw_krw: Krw }

#[tauri::command] #[specta::specta]
fn get_total() -> Result<Money, AppError> { Err(AppError::Bug) }
#[tauri::command] #[specta::specta]
fn stream_chat(prompt: String, on_chunk: Channel<ChatChunk>) -> Result<(), AppError> { .. }

Builder::<tauri::Wry>::new()
    .commands(collect_commands![get_total, stream_chat])
    .events(collect_events![PortfolioSynced])
    .error_handling(ErrorHandlingMode::Result)
    .export(Typescript::default(), &out)
```

생성물(발췌):

```ts
export const commands = {
	getTotal: () => typedError<Money_Serialize, AppError>(__TAURI_INVOKE("get_total")),
	streamChat: (prompt: string, onChunk: Channel<ChatChunk>) => typedError<null, AppError>(__TAURI_INVOKE("stream_chat", { prompt, onChunk })),
};
export const events = {
	portfolioSynced: makeEvent<PortfolioSynced_Serialize, PortfolioSynced_Deserialize>("portfolio-synced"),
};
export type AppError = { kind: "userFixable"; detail: { message: string, } } | { kind: "retryable"; detail: { retry_after_secs: number, } } | { kind: "bug" };
export type ChatChunk = { type: "token"; text: string } | { type: "toolCall"; name: string } | { type: "done" };
export type Currency = "Krw" | "Usd";
export type Money_Serialize = { currency: Currency, amount: string, plain: string, };
async function typedError<T, E>(result: Promise<T>): Promise<{ status: "ok"; data: T } | { status: "error"; error: E }> {
    try { return { status: "ok", data: await result }; }
    catch (e) { if (e instanceof Error) throw e; return { status: "error", error: e as any }; }
}
```

관찰:

- 두 번 내보낸 결과를 `diff`하면 같다(**결정적**). 따라서 "재생성 후 `git diff --exit-code`" 방식의 검사가 된다.
- `#[serde(with = ...)]`에 `#[specta(type = ...)]`가 없으면 내보내기가 **실패한다**: `Unsupported serde attribute at 'Money.amount': #[serde(with)] changes the wire type. Add #[specta(type = ...)]`. 실제 전송 형식과 다른 타입을 조용히 만들지 않는다는 뜻이다.
- `rust_decimal::Decimal`(specta `rust_decimal` 기능)은 `string`이 된다. 금액을 십진수 문자열로 보내는 방침과 맞는다.
- `u64` 필드를 넣으면 내보내기가 **거부된다**: `Specta forbids exporting BigInt-style types (usize, isize, i64, u64, i128, u128) to avoid precision loss.` 이 거부는 `dangerously_cast_bigints_to_number`로만 풀 수 있다. [tauri-specta docs.rs]
- 직렬화용과 역직렬화용 타입이 따로 생긴다(`X_Serialize | X_Deserialize`). rc.24부터 들어온 "serde phases" 때문이다. `Builder::disable_serde_phases`로 끌 수 있다. [tauri-specta releases]
- 생성물에 주석, `any`, `try/catch`, `throw`가 들어 있다. 하네스 TS 규칙에 걸리므로 생성 파일 경로를 린트 대상에서 빼야 한다. harness.md에 이미 "생성 파일 경로 목록" 예외가 있다.
- rc.28(2026-11-11)의 파괴적 변경은 "기본 `ErrorHandlingMode`가 `Throw`"가 된 것이다. `Result` 모드를 명시해야 `{status, data|error}`가 나온다. 문서는 **알 수 없는 명령이나 ACL 거부 같은 프레임워크 오류도 JS 쪽에서는 명령 오류와 똑같이 보일 수 있다**고 경고한다. 위 생성물에서도 거부 문자열이 `E`(=`AppError`)로 타입이 붙어 버린다. 따라서 TS 경계에서 오류 값을 스키마로 다시 파싱해야 한다. [tauri-specta docs.rs], [tauri-specta releases]
- `Channel<T>`는 명령의 직접 인자나 반환값일 때만 된다. 구조체·열거형·이벤트 안에 넣으면 거부된다(rc.28). [tauri-specta docs.rs]

**실행 결과 2: ts-rs 12.0.1** (`tsrs-demo/`, `cargo test`로 4개 파일 생성)

```ts
export type AppError = { "kind": "userFixable", "detail": { message: string, } } | { "kind": "retryable", "detail": { retry_after_secs: number, } } | { "kind": "bug" };
export type Currency = "Krw" | "Usd";
export type Money = { currency: Currency, amount: string, };
export type Reply = { result: { Ok : Money } | { Err : AppError }, id: bigint, };
```

- `u64`가 `bigint`가 된다. 그런데 `serde_json`은 `u64`를 JSON 숫자로 보내므로 실제 값은 `number`다. **타입과 전송 형식이 어긋난다.** 이 어긋남은 serde_json의 기본 동작을 근거로 한 판단이고, 실제 IPC 왕복은 돌려 보지 않았다.
- `Result<T,E>`는 serde 기본 표현인 `{Ok}|{Err}`가 된다.
- 명령 시그니처, 이벤트, Channel은 생성하지 않는다. `invoke` 래퍼를 손으로 써야 하므로 harness 5장의 "명령 시그니처도 생성"을 만족하지 못한다.

**추천: tauri-specta.** 이유는 셋이다. 명령·이벤트·Channel을 한 생성물로 묶는 도구가 사실상 이것뿐이다. 큰 정수 금지와 `serde(with)` 검사처럼 "틀린 타입을 조용히 만들지 않는" 기본값이 이 저장소의 목표와 맞는다. 그리고 Tauri 공식 조직과 가까운 specta-rs가 유지한다.

운영 규칙:

- `tauri-specta`, `specta`, `specta-typescript`는 `=` 버전으로 고정한다(릴리스 노트도 이를 요구한다).
- `ErrorHandlingMode::Result`를 명시한다.
- 생성은 앱 시작 시(`debug_assertions`)가 아니라 별도 진입점에서 한다. 예: `src-tauri`의 `gen-bindings` 바이너리나 테스트.
- CI는 재생성 후 `git diff --exit-code`로 검사한다.
- TS 쪽 오류 값은 스키마로 파싱한다.

**추천이 틀렸다고 판명될 조건**

- tauri-specta가 Tauri 3.0 안정판을 오래 따라가지 못해서 업그레이드를 막는 경우.
- RC 사이의 파괴적 변경이 분기마다 생성물을 크게 흔드는 경우.
- `Channel`이나 phase 타입에서 생성물과 실제 전송 형식이 다른 결함이 발견되는 경우.

이때의 대안은 ts-rs(타입만)와, `src-tauri`의 명령 목록에서 래퍼를 만드는 작은 자체 생성기(xtask)의 조합이다.

### Q4. 코어→UI 이벤트와 대량 스트림

[Calling the Frontend 문서]

- 이벤트(`emit`, `emit_to`, `emit_filter`): 페이로드는 항상 JSON 문자열이다. 문서는 이벤트가 "낮은 지연이나 높은 처리량용으로 설계되지 않았다", "큰 메시지에 맞지 않는다"고 쓰고, 이벤트는 capabilities 대상도 아니라고 쓴다. 대신 "순서가 있고 처리량이 큰 전달은 Channel을 고려하라"고 권한다.
- Channel 구현(`tauri-2.12.5/src/ipc/channel.rs`): JSON 페이로드가 8192바이트 미만이면 `webview.eval`로 바로 넣는다. 그보다 크면 fetch 경로로 가져가게 한다. 메시지마다 index를 붙여 순서를 지킨다.
- 창이 닫혔거나 같은 라벨의 새 WebView로 바뀐 경우, 큰 페이로드는 조용히 `Ok(())`를 반환한다. **send가 성공해도 UI가 받았다는 뜻이 아니다.**
- 추천:
  - 도메인 알림(`PortfolioSynced`, `ProposalCreated` 등): tauri-specta의 `Event`로 보낸다. 페이로드는 "무엇이 바뀌었는가"(ID와 종류)만 담고, UI는 쿼리 계층으로 다시 읽는다. 이렇게 하면 이벤트를 놓쳐도 다음 조회로 회복된다. 아키텍처의 `useSyncExternalStore` 구독 훅과도 맞는다.
  - 채팅 토큰: `stream_chat(…, on_chunk: Channel<ChatChunk>)`처럼 요청마다 Channel을 쓴다. 대화 원본은 코어가 SQLite에 저장한다. UI가 새로 고쳐지면 저장분을 읽고 새 Channel로 다시 구독한다.
  - WebView가 쏜 이벤트(`core:event:allow-emit`)는 권한을 주지 않는다. 코어는 UI에서 온 이벤트를 입력으로 받지 않고 명령만 받는다.

### Q5. 자식 프로세스(claude, codex) 실행과 수명 관리

- 셸 플러그인과 sidecar: JS에서 실행하려면 `shell:allow-spawn` 범위와 인자 검증 정규식이 필요하다. [Sidecar 문서] 이 앱은 CLI를 **Rust 코어에서만** 실행하므로 셸 플러그인이 필요 없다. `tokio::process::Command`를 쓰면 WebView에 프로세스 실행 권한이 생길 여지 자체가 없다. claude와 codex는 사용자가 설치한 CLI라서 번들할 sidecar도 아니다.
- 실험 1(`orphan.sh`): 부모 셸을 `kill -9`하면 자식 `sleep`은 **살아남고 PPID가 1이 된다**. 출력: `73117     1 sleep` / `CHILD SURVIVED parent SIGKILL`. macOS에는 리눅스의 `PR_SET_PDEATHSIG`가 없으므로 별도 장치가 필요하다.
- 실험 2(`stdin_eof.py`): 부모가 자식의 stdin 파이프를 쥐고 있다가 SIGKILL로 죽으면, 자식(`cat`)은 EOF를 받고 끝난다. 출력: `child alive: False | eof.txt: EOF_SEEN`. 그런데 claude가 `--input-format stream-json`에서 stdin EOF를 받으면 곧바로 끝나는지는 **미확인**이다(R-02 확인 항목).
- 추천 수명 관리:
  1. `Command::process_group(0)`으로 자식을 새 프로세스 그룹의 리더로 만들고, `kill_on_drop(true)`를 켠다. [tokio Command] 또는 `process-wrap 10.0.1`의 `ProcessGroup`과 `KillOnDrop`을 쓴다. [process-wrap]
  2. `env_clear()` 뒤에 허용 목록의 환경 변수만 넣는다. 작업 폴더는 전용 빈 폴더로 한다.
  3. stdin 파이프를 계속 열어 둔다. 앱이 비정상 종료하면 EOF가 신호가 된다.
  4. `RunEvent::ExitRequested`·`Exit`에서 모든 그룹에 SIGTERM을 보내고, 시간 제한 뒤 SIGKILL을 보낸다.
  5. 실행 중인 PGID를 기록해 두고, 앱이 시작할 때 남은 그룹을 정리한다. 앱이 SIGKILL로 죽은 경우를 위해서다.
  6. 더 강한 보장이 필요하면 작은 감시 프로세스가 kqueue `EVFILT_PROC`/`NOTE_EXIT`로 앱 PID를 지켜보다 그룹을 죽이게 할 수 있다. `man kqueue`로 `NOTE_EXIT`의 존재만 확인했고 구현은 미검증이다.
  7. tokio 문서도 drop에만 기대지 말라고 한다(좀비 정리는 "best-effort"). [tokio Command]
- macOS 샌드박스: 앱 샌드박스를 켜면 자식이 샌드박스를 물려받는 구조다(`com.apple.security.inherit`). [Apple: Embedding a helper tool in a sandboxed app] 그러면 사용자가 설치한 claude가 자기 설정·인증 파일과 네트워크에 접근하는 데 제약이 생긴다. App Store 배포가 아니므로 **앱 샌드박스는 켜지 않는다**. AI CLI의 격리는 CLI 옵션(R-02, R-03)과 환경 정리로 한다.
- 공증: Developer ID로 서명할 때만 필요하다. [Tauri macOS 서명 문서] 직접 빌드한 앱에는 필요 없다. 이 PC에서 빌드한 바이너리에는 `com.apple.provenance` 속성만 있고 quarantine 속성은 없었다(`xattr` 결과).

### Q6. 창을 닫아도 계속 실행, 메뉴 막대 상주, 로그인 시 자동 시작

- 창 닫기 가로채기: `WindowEvent::CloseRequested { api, .. }`에서 `api.prevent_close()`를 부르고 창을 숨긴다. 앱 종료 막기: `RunEvent::ExitRequested { code, api }`에서 `api.prevent_exit()`. `code`가 `None`이면 사용자 동작이고, `AppHandle`에서 요청한 종료는 `Some`이다. `restart`는 `prevent_exit`를 무시한다. [RunEvent docs.rs], `tauri-2.12.5/src/app.rs` 86–103행
- 메뉴 막대: `tray-icon` 기능과 `TrayIconBuilder`, `on_menu_event`, `on_tray_icon_event`를 쓴다. [System Tray 문서] Dock 아이콘을 숨기려면 `App::set_activation_policy(ActivationPolicy::Accessory)`나 `set_dock_visibility(false)`를 쓴다(macOS 전용, `app.rs` 658·678행). Dock 아이콘 클릭은 `RunEvent::Reopen`으로 받는다(`app.rs` 279행).
- 자동 시작: `tauri-plugin-autostart 2.7.0`. macOS 기본값은 `~/Library/LaunchAgents`에 Launch Agent plist를 설치하는 방식(`MacosLauncher::LaunchAgent`)이고, AppleScript 로그인 항목 방식도 고를 수 있다(플러그인 소스 `lib.rs` 26–35행). 최신 macOS에서 "백그라운드 항목 추가" 알림이 뜨는지는 **미확인**이다.
- 중복 실행 방지: `tauri-plugin-single-instance 2.5.5`를 쓴다. 두 번째 인스턴스가 스케줄러와 주문 게이트를 하나 더 띄우는 것을 막는 데 필요하다.
- 제약:
  - 앱 프로세스가 하나이므로, 앱이 꺼져 있으면 예약 작업이 돌지 않는다(design.md에 이미 적혀 있다).
  - 창을 숨기면 macOS App Nap이 타이머를 늦출 수 있다. 막는 수단은 `NSProcessInfo.beginActivity`이지만 효과에 대한 보고가 엇갈린다(보조 출처). Tauri 환경에서의 실제 영향은 **미확인**이다.

- 확인 창에 보여 줄 수 있는 것: `evaluatePolicy`의 `localizedReason` 문자열은 시스템이 그리는 창에 나온다. 그래서 코어가 계산한 주문 요약을 이 문자열로 넣을 수 있다. 표시 길이 한도와 줄바꿈 처리는 **미확인**이다(R-16).
- 키체인 구현의 제약 (Apple TN3137):
  - 파일 기반 키체인은 ACL(SecAccess)을 쓴다. 데이터 보호 키체인은 접근 그룹을 쓰는데, **"이 entitlement는 프로비저닝 프로파일로 승인돼야 한다"**. Apple은 데이터 보호 키체인을 기본으로 권한다. [TN3137]

  - 추정: ad-hoc 서명 앱은 다시 빌드할 때마다 파일 기반 키체인 ACL에서 "다른 앱"이 된다. 그러면 접근 확인 창이 뜨거나 신뢰 목록을 다시 맞춰야 할 수 있다. 실제 키체인 동작은 **미확인**이다(R-16).

### Q8. 자동 업데이트와 코드 서명의 필요 범위

- 업데이터: Tauri 업데이터는 자체 서명 키(`pubkey`, `TAURI_SIGNING_PRIVATE_KEY`)가 필수이고 "끌 수 없다". 운영 환경에서는 TLS 엔드포인트도 필요하다. [Updater 문서] 사용자 1명이 직접 빌드하는 앱이므로 **업데이터는 넣지 않는다.** 업데이트는 `git pull` 후 다시 빌드하는 것이다.
- 코드 서명:
  - Apple Silicon에서는 모든 실행 파일에 최소한 ad-hoc 서명이 필요하다. 링커가 자동으로 ad-hoc 서명한다(위 실험 확인).
  - Tauri 번들에는 `bundle.macOS.signingIdentity: "-"`로 ad-hoc 서명할 수 있다. [Tauri macOS 서명 문서]
  - 공증과 Developer ID는 배포용이므로 필요 없다.
  - 남는 문제는 키체인 ACL과 데이터 보호 키체인 entitlement를 위한 **안정된 서명 정체성**이다. 선택지는 로컬 자체 서명 인증서, 무료 또는 유료 Apple 개발 인증서다. R-16에서 정한다.

### Q9. 비동기 런타임과 장시간 백그라운드 작업

- Tauri는 tokio 런타임을 하나 쓴다(`tauri::async_runtime`). 자체 런타임을 공유하려면 `tauri::async_runtime::set(Handle)`을 쓰는데, 이미 설정돼 있으면 panic한다(`async_runtime.rs` 252–284행). 명령은 `async fn`을 권장한다.
- 추천 구성:
  1. `setup` 훅에서 스케줄러, 수집기, AI 러너를 `tauri::async_runtime::spawn`으로 띄운다. 이들은 `application`의 포트만 받는다. `AppHandle`은 `Notifier`나 이벤트 송신 같은 어댑터 구현에만 넘긴다.
  2. 종료 신호는 `CancellationToken`(tokio-util)으로 전달한다. `RunEvent::ExitRequested`에서 취소하고, 진행 중인 주문 관련 작업과 감사 로그 쓰기가 끝날 때까지 `prevent_exit`로 잠깐 미룬 뒤 `app.exit`를 부른다.
  3. 블로킹 호출(Touch ID, 키체인 확인 창)은 `spawn_blocking`에서 부른다.
  4. **벽시계 기준 스케줄러를 직접 만든다.** Rust `Instant`는 Darwin에서 `CLOCK_UPTIME_RAW`를 쓴다. [std Instant] macOS `man clock_gettime`에 따르면 이 시계는 "시스템이 잠자는 동안 증가하지 않는다". 그래서 `tokio::time::sleep(다음 08:20까지)`은 노트북이 잠들었다 깨면 그만큼 늦게 깬다. 짧은 주기(예: 30초)로 깨어 `Clock` 포트의 벽시계 시각과 비교하고, 놓친 작업은 정책(따라잡기 또는 건너뛰기)에 따라 처리한다. 그러면 고정 시계 테스트도 된다.
  5. `tokio-cron-scheduler 0.15.1`(최근 갱신 2025-10-28)은 시스템 시계를 직접 쓰므로 `Clock` 포트를 주입하기 어렵다. 쓰지 않는다. 이 판단은 문서 기준이고 소스는 확인하지 않았다.

### 3.2 crate 배치

| 선택지 | 장점 | 단점 |
|---|---|---|
| (가) 루트 가상 작업 공간, tauri는 `src-tauri`에만, IPC DTO는 `src-tauri/ipc` 모듈 | 핵심 crate 테스트가 WebView 스택 없이 돈다. lock·target·lints를 하나로 관리 | DTO 변환 코드가 늘어난다 |

**추천: (가).** 명령 시그니처 생성에는 어차피 tauri가 필요하므로 (나)의 이득이 작다. 바인딩 생성은 `src-tauri`의 `gen-bindings` 바이너리(또는 테스트)로 한다.

틀렸다고 판명될 조건:

- `src-tauri` 증분 빌드가 커져 에이전트 반복 속도를 해친다면(예: 30초 이상), DTO와 명령 구현을 `ipc` crate로 분리하는 (나)로 간다.
- Tauri CLI가 루트 작업 공간의 `target/`을 제대로 다루지 못하면 배치를 조정한다.

| 자동 시작 | `tauri-plugin-autostart`(LaunchAgent) | 사용자가 로그인 항목에 수동 등록 |
| 알림 | `tauri-plugin-notification`(Rust에서만 호출) | `objc2-user-notifications` 직접 사용(미조사) |
| Touch ID | `objc2-local-authentication`을 쓰는 자체 `UserPresence` 어댑터 | `tauri-plugin-biometric` 2.5.0의 Rust API (WebView에는 권한을 주지 않는다) |
| 자식 프로세스 | `tokio::process` + 프로세스 그룹 + stdin 파이프 + 시작 시 정리 | `process-wrap` |
| 중복 실행 | `tauri-plugin-single-instance` | 잠금 파일 |
| 업데이터, 공증 | 넣지 않음 | - |

## 4. 위험과 미확인 항목

**위험**

- tauri-specta가 아직 RC다. rc.24(phase 타입), rc.28(기본 오류 처리) 같은 파괴적 변경이 계속 있었다. 버전을 고정하고 업그레이드할 때마다 생성물 diff를 리뷰한다.
- Tauri 3.0 alpha가 진행 중이다. 안정판이 나오면 런타임 이벤트 구조가 바뀌고, tauri-specta(`tauri ^2`) 지원이 늦어질 수 있다.
- 생성물이 TS 하네스 규칙(주석, `any`, `try/catch`)을 어긴다. 생성 파일 경로 예외가 필요하다. 그 파일을 손으로 고치지 못하게 막는 것은 재생성 diff 검사가 맡는다.
- ACL 거부 오류가 TS 타입상 `AppError`로 보일 수 있다. TS 경계에서 스키마로 파싱하지 않으면 잘못된 분기를 탄다.
- Channel `send` 성공이 UI 수신을 보장하지 않는다(창 교체 시).
- 앱이 SIGKILL로 죽으면 AI CLI 자식이 고아로 남는다(실험 확인). 시작 시 정리와 stdin EOF로 줄인다.
- 스케줄러를 `Instant` 기반 sleep으로 만들면 잠자기 뒤 실행이 늦어진다.
- ad-hoc 서명은 빌드마다 CDHash가 바뀐다. 키체인 접근 동작에 영향을 줄 수 있다.

**미확인**

- 앱 ACL을 켠 상태에서 Channel 데이터 fetch 명령(`FETCH_CHANNEL_DATA_COMMAND`)은 예외로 통과한다(소스 확인). 다른 내부 명령에도 예외가 있는지는 전수 조사하지 않았다.
- Tauri CLI와 루트 가상 작업 공간을 함께 쓸 때의 동작.
- claude와 codex CLI가 stdin EOF에서 곧바로 끝나는지(R-02, R-03).
- 최신 macOS에서 Launch Agent 등록 시 시스템 알림이 뜨는지, 그리고 App Nap이 숨긴 Tauri 창의 타이머에 주는 실제 영향.
- `localizedReason` 표시 길이 한도. 무료 Apple 계정으로 데이터 보호 키체인용 프로파일을 만들 수 있는지. ad-hoc 재빌드 시 키체인 ACL의 실제 동작(R-16).
- taurpc, typeshare는 문서와 버전만 봤고 실행하지 않았다.
- capability의 `webviews` 필드 문법.
- 실제 IPC 왕복(WebView에서 생성된 클라이언트를 호출하는 것)은 이번에 돌리지 않았다. 바인딩 생성만 실행했다. 뼈대 작업이나 R-15에서 확인한다.

## 5. 이 결과로 바뀌어야 할 설계 문서 항목

1. **architecture.md 3.1 저장소 배치**: 루트 `Cargo.toml`이 가상 작업 공간임을 명시한다(`[workspace.dependencies]`, `[workspace.lints]`). `rust-toolchain.toml`(1.90 이상 고정)을 추가한다. `src-tauri` 안에 `ipc/`(DTO, 명령, 바인딩 생성 진입점)와 `platform/`(트레이, 수명 주기)을 둔다.
2. **architecture.md 3.2 의존 규칙**: "`tauri`와 `tauri-plugin-*`에 의존할 수 있는 것은 `src-tauri`뿐"을 추가한다. `specta`는 `src-tauri`(또는 `ipc-contract`)에만 둔다. domain 타입에 직렬화·specta derive를 붙이지 않고 DTO로 변환한다.
3. **architecture.md 3.3 포트 표**: `Notifier`, `UserPresence`의 구현 위치가 비어 있다. `adapters/platform-macos`(objc2 직접 사용, tauri 비의존)나 `src-tauri/platform` 중 하나로 정한다. 추천은 전자다.
4. **architecture.md 2.1**: "창을 닫아도 계속 도는 실행은 1차 범위에 없다"를 다시 판단해야 한다. 같은 프로세스 안의 메뉴 막대 상주는 구현 비용이 작고 예약 작업(design 4.3)에 필요하다. 별도 백그라운드 프로세스와는 구분해서 적는다. `single-instance`를 필수로 넣는다.
5. **architecture.md 5장 / harness.md 4.2·5장**:
   - 생성 파일(`shared/ipc/bindings.ts`)을 보호 경로와 린트 예외 목록에 넣는다.
   - 생성 진입점은 `xtask`가 아니라 `src-tauri`의 바이너리나 테스트다. `xtask`는 의존성이 없어야 하기 때문이다.
   - CI 검사는 "재생성 + `git diff --exit-code`"로 한다.
   - TS는 생성된 `commands`의 오류를 스키마로 다시 파싱한다.
   - `@tauri-apps/api` 가져오기 허용 경로에 생성 파일을 포함한다.
6. **harness.md (새 검사)**: `xtask capability-check`를 추가한다. 생성된 명령 목록, `build.rs`의 `AppManifest::commands`, capability `allow-*`가 같아야 한다. `core:default`, `core:event:allow-emit`, `shell:*`, `biometric:*` 금지. `tauri.conf.json`의 `app.security.capabilities` 명시. `remote` 금지.
7. **architecture.md 3.5 이벤트**: UI 전달 방식을 "도메인 이벤트 → ID만 담은 타입 이벤트 + 쿼리 재조회, 채팅 → 요청별 Channel"로 적는다. 코어는 WebView가 쏜 이벤트를 받지 않는다.
8. **design.md 4.1 / architecture.md 2.1 AI 러너**: 자식 프로세스 수명 규칙을 적는다. 프로세스 그룹, `env_clear`, stdin 유지, 종료 시 SIGTERM 후 SIGKILL, 시작 시 남은 그룹 정리. 앱 샌드박스는 쓰지 않는다.
9. **design.md 4.3 / scheduler**: 벽시계 비교 방식의 스케줄러(`Clock` 포트, 짧은 주기 확인, 놓친 작업 정책)를 명시한다. `Instant` 기반 장시간 sleep은 금지한다. 하네스 금지 목록 후보다.
10. **design.md SEC-8 / architecture.md 4.3**: `UserPresence` 구현은 `LAContext.evaluatePolicy`(`DeviceOwnerAuthentication`, 재사용 0초)다. 주문 요약을 `localizedReason`으로 시스템 창에 표시한다. 길이 한도는 R-16에서 확인한다.
11. **architecture.md 8장 결정 기록**: "Rust→TS 타입 생성 도구 = tauri-specta(=2.0.0-rc.28)"를 ADR로 옮긴다. "서명 정체성(ad-hoc / 자체 서명 / Apple 개발 인증서)" 항목을 R-16 결정 대상으로 추가한다. "업데이터와 공증은 쓰지 않음"도 기록한다.
