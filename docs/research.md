```
너는 개인용 macOS 데스크톱 주식 비서 앱의 사전 조사를 맡았다.

앱 개요:
- Tauri 2 + Rust 코어 + React/TypeScript UI + SQLite. 사용자는 한국 거주 개인 1명이고 배포하지 않는다.
- 토스증권 Open API로 계좌를 읽고, 사용자가 승인한 주문만 보낸다.
- AI는 사용자 PC에 설치된 Claude Code CLI(기본)나 Codex CLI를 자식 프로세스로 실행해 쓴다. 앱이 MCP 서버를 열어 도구를 제공한다.
- 목표는 "AI가 잘못된 코드를 작성할 수 없을 만큼 엄격한 개발 환경"이다.

조사 규칙:
- 오늘 날짜를 확인하고, 그 시점의 최신 공식 문서와 릴리스 노트를 1차 출처로 쓴다. 블로그는 보조로만 쓴다.
- 모든 사실에 출처 링크와 확인 날짜를 붙인다. 버전 번호를 적는다.
- 확인하지 못한 것은 "미확인"이라고 쓰고 추측으로 채우지 않는다.
- 선택지를 비교할 때는 표로 정리하고, 마지막에 하나를 추천하고 이유를 쓴다.
- 추천이 틀렸다고 판명될 조건도 쓴다.
- 직접 돌려 볼 수 있는 것은 최소 예제를 만들어 실제로 실행하고 결과를 붙인다.

산출물 형식 (마크다운):
1. 요약 (다섯 줄 이내)
2. 질문별 답
3. 선택지 비교표와 추천
4. 위험과 미확인 항목
5. 이 결과로 바뀌어야 할 설계 문서 항목
6. 출처 목록
```

## R-01 토스증권 Open API 실사용 조건

```
주제: 토스증권 Open API를 개인용 앱에서 쓸 때의 실제 조건과 동작.

자료: 저장소의 docs/toss-openapi-1.2.28.json, docs/toss-openapi-overview.md, 그리고 developers.tossinvest.com의 최신 문서와 이용약관.

질문:
1. 이용약관과 이용 가이드에서 금지하거나 제한하는 것은 무엇인가. 특히 AI·LLM 연동, 자동 주문, 데이터 저장·가공, 호출량에 대한 조항.
2. 키에 읽기 전용이나 주문 제외 같은 권한 범위를 설정할 수 있는가. 없다면 주문을 막을 수 있는 다른 수단이 있는가.
3. 허용 IP: 몇 개까지 등록되는가, 대역 등록이 되는가, 변경이 즉시 반영되는가, 가정용 유동 IP 사용자에게 권장되는 방법은 무엇인가.
4. 토큰: 유효 시간, 재발급 시 이전 토큰이 폐기되는 정확한 동작, 여러 기기에서 같은 키를 쓸 때의 영향.
5. 거래내역 API: 조회 가능한 과거 기간, 미결제 내역이 결제 내역으로 바뀔 때 중복 없이 맞추는 방법, 취소 거래 처리, 액면분할·종목 코드 변경 처리.
6. 보유 주식 API의 금액이 토스 앱 화면과 일치하는 조건 (수수료·세금 반영 여부, 환율 기준 시각).
7. 주문 API: 주문 유형과 시장별 제약, 1억 원 이상 주문 확인 값, 중복 방지 키의 동작, 전송 후 응답을 못 받았을 때 확인하는 방법, 오류 코드 전체 목록과 각 코드에서 재시도해도 되는지.
8. 웹소켓: 연결·구독 한도, 재연결 규칙, 본인 주문 이벤트의 신뢰성.
9. 스펙 버전이 얼마나 자주 바뀌는가. 하위 호환을 깨는 변경이 있었는가. 변경 공지는 어디에 올라오는가.
10. 모의 환경이나 테스트용 계좌가 있는가.
11. 주문 전에 계좌가 갖춰야 할 조건: 약관 동의, 해외 주식 거래 신청, 거래소 통합 설정 등. 스펙의 prerequisite-required, investor-exchange-not-integrated 오류가 나는 조건과 사용자가 미리 해 둘 일.
12. 예수금과 총자산을 얻는 방법. 보유 주식 API에는 현금이 없고 매수가능금액은 예수금이 아니다. 원화·달러 현금 잔고를 정확히 알 수 있는 경로가 있는가.
13. 달러 주문이 1억 원 이상인지 판정할 때 토스가 쓰는 환율.
14. 거래내역에 고유 ID가 없다. 미결제 내역이 결제 내역으로 바뀔 때와 다시 조회할 때 중복 없이 저장하는 기준.

추가 산출물: 엔드포인트별로 "속도 제한 그룹, 계좌 헤더 필요 여부, 페이징 방식, 금액 필드 형식"을 정리한 표.
```

## R-02 Claude Code를 앱에서 구동하기

```
주제: 데스크톱 앱이 사용자의 Claude 구독으로 Claude Code를 자식 프로세스로 실행해 채팅과 예약 분석 작업에 쓰는 방법.

질문:
1. 비대화형 실행의 입출력 규약: stream-json 입력·출력의 메시지 종류와 필드, 부분 출력 스트리밍, 도구 호출 이벤트, 종료 코드.
2. Claude Code CLI를 직접 실행하는 것과 Claude Agent SDK를 쓰는 것의 차이. 구독 인증으로 각각 쓸 수 있는가. Rust 앱에서 쓰기에는 어느 쪽이 맞는가.
3. 도구 제한: 내장 도구를 웹 검색·웹 읽기만 남기고 셸·파일 도구를 확실히 끄는 방법. 사용자 전역 설정, 플러그인, 훅, 프로젝트 CLAUDE.md가 섞여 들어오지 않게 격리하는 방법.
4. MCP 연결: 실행할 때 설정 파일로 MCP 서버를 지정하는 방법, 지정한 것만 쓰게 하는 방법, 로컬 HTTP 전송과 stdio 전송의 지원 상태, 인증 헤더 전달.
5. 세션: 세션 ID로 대화를 이어 가는 방법, 세션 기록이 저장되는 위치, 긴 대화의 맥락 압축 동작.
6. 모델 선택: 실행마다 모델과 추론 강도를 지정하는 방법, 구독 등급별로 쓸 수 있는 모델.
7. 구독 사용량 한도: 한도의 구조, 한도에 걸렸을 때 CLI가 내는 신호, 남은 한도를 프로그램에서 알아내는 방법, 한도가 풀리는 시각을 아는 방법.
8. 약관: 구독 인증을 본인 PC의 본인용 앱에서 자동 실행에 쓰는 것이 허용되는가. 관련 조항을 인용하라. 예약 작업을 계속 돌리는 사용 방식에 대한 제한이 있는가.
9. 여러 실행을 동시에 띄울 때의 제한과 권장 방식.
10. 프롬프트 주입 방어에 쓸 수 있는 CLI 기능.
11. 사용자 전역 설정, 훅, 플러그인, 메모리, CLAUDE.md가 섞이지 않게 하는 옵션(--setting-sources, --safe-mode, --restricted 등)이 구독 인증과 함께 동작하는가. --bare는 구독 인증을 읽지 않는다.
12. 실행 시작 시 CLI가 보고하는 도구·MCP 목록의 형식. 앱이 이것으로 격리를 매번 검증할 수 있는가.
13. CLI가 대화 기록을 디스크에 남기는 위치와 형식, 남기지 않게 하는 옵션. 남기지 않을 때 대화를 이어 가는 방법.

실행 검증: 사용자 전역 훅과 플러그인이 설치된 환경의 빈 폴더에서 셸·파일 도구 없이, 지정한 MCP 서버 하나만 연결해 질문 하나를 보내고 스트림 출력을 받는 최소 예제를 실제로 돌려 명령과 출력을 붙여라.
```

## R-04 Rust MCP 서버와 전송 방식

```
주제: Tauri 앱(Rust) 안에서 MCP 서버를 열어 Claude Code와 Codex CLI에 도구를 제공하는 방법.

질문:
1. Rust용 MCP 서버 라이브러리의 현재 상태. 공식 SDK와 주요 대안의 버전, 유지 상태, 지원하는 전송 방식과 규격 버전.
2. 전송 방식 비교: (가) 앱이 127.0.0.1에서 HTTP로 여는 방식, (나) 작은 stdio 브리지 실행 파일이 앱과 로컬 소켓으로 통신하는 방식. 보안, 두 CLI의 지원 여부, 구현 복잡도, 수명 관리.
3. 로컬 MCP 서버의 인증: 실행마다 만든 토큰을 CLI에 넘기는 안전한 방법. 같은 PC의 다른 프로세스가 접속하지 못하게 하는 방법.
4. 도구 스키마 설계: 입력 검증, 큰 결과의 페이징, 오류 표현, 구조화된 출력.
5. 도구 결과에 외부 뉴스 텍스트가 섞일 때 프롬프트 주입을 줄이는 표현 방법.
6. 도구 호출을 기록하고 재현하는 방법 (감사와 테스트용).
7. MCP 서버를 실제 CLI 없이 테스트하는 방법.

실행 검증: 도구 하나짜리 Rust MCP 서버를 만들어 Claude Code에서 호출되는 것을 확인하고 코드를 붙여라.
```

## R-07 뉴스·공시 소스의 조건과 수집 기법

```

```
