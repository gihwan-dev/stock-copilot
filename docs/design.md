# Stock Copilot 설계서 (v0.2, 2026-11-11)

토스증권 계좌를 연결해, 내 구독 AI가 내 포트폴리오를 계속 연구하고 종목별 확률을 추정하면 앱이 그 확률로 매수·매도 신호를 띄우는 개인용 데스크톱 앱.

- 사용자: 본인 1명 (배포하지 않음)
- 플랫폼: macOS 데스크톱 (Tauri + React/TypeScript + SQLite)
- AI: 이미 설치되어 로그인된 Claude Code CLI를 Claude 구독으로 쓴다 (확인 버전 2.1.322). Codex 어댑터는 구조만 두고 기본으로 끈다
- 증권사: 토스증권 Open API v1.2.28 (`docs/toss-openapi-1.2.28.json`, sha256 `c5918961335ccd6b091577e307dc06ed505b58f83e4d99f0c4617de14ceb036a`). 토스는 같은 버전 번호로 내용을 바꾼 적이 있으므로 번호가 아니라 파일 해시로 고정한다 ([R-01](research/R-01-toss-open-api.md) Q9)

v0.2는 리서치 16건([research/](research/))과 사용자 결정([open-issues.md](open-issues.md))을 반영했다. 충돌하면 open-issues.md의 결정이 앞선다. 이번에 확정한 제품 결정은 [ADR 0001](adr/0001-product-decisions.md)에 모았다.

## 1. 목표와 비목표

**목표**

1. 내 포트폴리오 현황과 균형을 한 화면에서 본다.
2. 시장 상황과 보유·관심 종목 소식을 AI가 근거와 함께 정리해 준다.
3. AI가 종목별로 "정해진 기간 안에 목표 수익률에 먼저 닿을 확률"을 추정한다. 코드가 그 확률을 임계값과 비교해 매수·매도 신호를 띄우고, 내가 승인하면 실제로 주문이 나간다.
4. 현황 화면을 보면서 AI와 채팅한다.
5. AI의 확률이 실제로 얼마나 맞았는지 숫자로 본다.

**비목표**

- 자동매매. 사람 승인 없이 나가는 주문은 없다.
- 실시간 호가창, 차트 트레이딩 도구. 그건 토스 앱을 쓴다.
- 조건주문(손절·익절 감시). 1차 범위에서 뺀다.
- 주문 정정과 취소. 1차 범위에서 뺀다. 토스증권 앱에서 한다 (6.5).
- 다른 사람에게 배포. 근거는 다음과 같다 ([R-13](research/R-13-legal-and-terms.md) Q1, Q3).
  - 보유 종목과 투자 성향을 반영한 매매 판단을 남에게 주면 투자자문업에 해당할 가능성이 높다(대법원 2018도4413의 "개별성" 기준). 미등록이면 자본시장법 제17조, 제445조 제1호로 3년 이하 징역 대상이다.
  - 토스 약관 제5조③은 시세를 제3자에게 제공·배포하지 못하게 한다.
  - Claude 구독 로그인은 본인이 수정하지 않은 CLI에 직접 로그인해 쓰는 범위에서만 허용 문구가 있다 ([R-02](research/R-02-claude-code-runtime.md) Q8).

## 2. 제품 원칙과 사용 흐름

### 2.1 단순함 원칙

사용자가 느끼기에 이 앱은 아주 단순하고 실행 절차가 거의 없어야 한다. 내부가 복잡한 것은 괜찮지만 그 복잡함이 화면에 보이면 안 된다. 다른 결정과 부딪히면 이 원칙이 앞선다. 원문은 [open-issues.md](open-issues.md) 0장이다.

| # | 규칙 | 이 문서에서 반영한 곳 |
|---|---|---|
| P-1 | 처음 실행해서 쓸 수 있게 되기까지 사용자가 할 일은 토스 키 붙여넣기와 허용 IP 등록뿐이다 | 2.5, UX-4 |
| P-2 | 이미 설치되어 로그인된 Claude Code를 앱이 찾아서 그대로 쓴다. 앱을 위한 별도 로그인을 요구하지 않는다 | 4.1 |
| P-3 | 사용자가 터미널 명령을 실행해야 하는 절차를 만들지 않는다 | 2.5, 2.6, UX-4 |
| P-4 | 모든 설정에 기본값이 있고, 건드리지 않아도 전부 동작한다 | 8장 |
| P-5 | 추가 키(DART, FRED 등)는 선택 사항이다. 없으면 그 기능만 조용히 빠진다 | 5.1, 8장 |
| P-6 | 설정 화면의 기본 항목은 토스 연결, 투자 성향, 주문 켜기뿐이다. 나머지는 "고급" 아래에 둔다 | 8장, UX-7 |
| P-7 | 앱이 스스로 상태를 점검한다. 문제가 있을 때만 무엇을 하면 되는지 한 문장으로 알려 준다 | 2.6, UX-5 |
| P-8 | 실행 분리, 격리, 작업 큐, 보정 같은 내부 장치의 이름과 상태를 화면에 드러내지 않는다 | UX-6 |
| P-9 | 본인 확인은 주문을 보낼 때만 요구한다 | 6.4, SEC-8, SEC-12 |
| P-10 | 주 화면은 하나다: 내 현황과 채팅. 신호가 생기면 그 화면에 카드로 나타난다 | 2.4 |

### 2.2 차별점과 설계

토스 앱은 모든 사용자에게 같은 콘텐츠를 보여 주고, 매매 판단은 하지 않는다. 이 앱의 차별점과 각각이 요구하는 설계는 다음과 같다.

| # | 차별점 | 설계로 옮기면 |
|---|---|---|
| D1 | 확률 신호로 매수·매도 제안 | AI는 채점할 수 있는 사건의 확률 p와 근거만 낸다. 임계값, 방향, 수량, 가격은 코드가 정한다. 신호는 주 화면에 카드로 뜨고, 승인하면 앱이 토스에 주문을 보낸다 (6장) |
| D2 | 구독이라 좋은 모델을 많이 쓸 수 있음 | 질문에 답할 때만 AI를 쓰지 않는다. 앱이 켜져 있는 동안 예약 작업이 설정한 한도 비율(AI-2) 안에서 종목 연구와 확률 추정을 계속 돌린다 (4.3). 약관 위험은 감수했다 (9장) |
| D3 | 모델 교체 가능 | AI 호출을 어댑터 하나 뒤에 둔다. 작업마다 모델을 고급 설정에서 고른다. 제공자 교체 구조도 남긴다 (4.1) |
| D4 | 추정 성적표 | 모든 추정(거래하지 않은 것 포함)을 기록하고 코드가 일봉과 1분봉으로 판정한다. 확률 구간별 적중률, 확률과 실제 빈도가 맞는 정도, 신호를 따랐을 때의 수익률을 벤치마크와 비교한다 (6.6) |
| D5 | 내 투자 성향과 원칙 반영 | 투자 성향(기간, 위험 성향, 제외, 비중 상한)이 사건 정의와 수량을 정한다. 원칙 위반은 코드가 검사한다 (6.2, 6.3) |
| D6 | 종목별 투자 논거 노트 | 노트를 반증 가능한 주장 목록으로 둔다. 새 공시·뉴스가 오면 AI가 주장 단위로 판정하고, 노트 전체의 상태는 코드가 집계한다 ([R-12](research/R-12-ai-analysis-design.md) 2.2) |

D4~D6은 D1~D3을 쓸 만하게 만드는 장치다. 확률을 내기만 하고 채점하지 않으면 AI를 믿을 근거가 없다.

### 2.3 공통 원칙

- 숫자는 코드가 계산한다. 비중, 수익률, 손익, 주문 금액, 임계값은 앱이 계산해 AI에 넘기고, 화면에도 코드가 계산한 값을 쓴다.
- AI의 모든 주장에는 출처(도구 결과, 공시 번호, 뉴스 링크, 웹 검색 결과)가 붙는다. 출처 종류를 저장해 화면에서 구분한다.
- 원본 데이터는 내 PC에만 둔다. 다만 AI에 보낸 내용(보유 종목, 비중, 손익, 거래내역, 노트)은 AI 제공자 서버에 보관된다. Claude 구독 계정은 학습 허용 설정에 따라 30일 또는 5년이다 ([R-13](research/R-13-legal-and-terms.md) Q6).
- 웹 검색어는 바깥으로 나가는 통로다. 보유 내역을 보는 실행과 웹을 쓰는 실행을 나눈다 (4.4). 보유 내역을 아는 실행은 웹 도구를 갖지 않는다.
- 외부 텍스트(뉴스, 웹, 공시 제목)는 신뢰하지 않는 데이터로 다룬다. 그 안의 지시는 실행되지 않는다.

### 2.4 주 화면

주 화면은 하나다 (P-10).

| 영역 | 내용 |
|---|---|
| 현황 | 총평가(근사 표시), 통화별 평가, 보유 종목 표, 자산배분과 쏠림, 오늘 손익 |
| 채팅 | 지금 보고 있는 종목·기간을 맥락으로 보내는 대화 패널 |
| 카드 | 신호 카드, 아침 브리핑·마감 리뷰 요약 카드, 중요 공시 카드. 현황 아래 "오늘" 묶음에 최근 것부터 쌓인다 |
| 상태 띠 | 자체 점검(2.6)에서 문제가 있을 때만 한 줄로 나타난다 |
| 종목 목록 | 창 왼쪽의 보유·관심 종목 목록(이름과 오늘 등락). 화면 전환 메뉴가 아니다. 종목을 누르면 그 종목 상세가 열린다 |

- 종목 상세, 논거 노트, 성적표, 지난 브리핑, 거래내역은 카드나 종목 이름을 눌러 여는 보조 화면이다. 보조 화면은 현황 자리에 열리고, 종목 목록과 채팅은 그대로 있다. 별도 탭 구조를 두지 않는다. 배치 구조는 [architecture.md](architecture.md) 5.1이다.
- 설정은 본문 머리줄의 설정 버튼, 메뉴 막대 아이콘, 창 메뉴(⌘,)에서 연다. 별도의 macOS 창으로 뜬다. 창 장식과 확인 창은 macOS 기본 모양을 쓴다 ([architecture.md](architecture.md) 5.1). 성적표는 머리줄의 성적표 버튼으로도 연다.
- 화면의 모양과 배치는 `design/`의 디자인 시스템(화면 예시: 주 화면 네 가지 창 폭, 첫 실행, 설정, 종목 상세, 성적표)을 따른다.

### 2.5 첫 실행

사용자가 할 일은 두 가지뿐이다 (P-1). 나머지는 앱이 알아서 한다.

| 순서 | 화면 | 사용자 | 앱 |
|---|---|---|---|
| 1 | 토스 연결 | 토스증권 WTS에서 발급한 client_id와 secret을 붙여 넣는다 | 키를 키체인에 저장하고 바로 토큰 발급을 시도한다 |
| 2 | 허용 IP (토큰 발급이 `access_denied`일 때만) | 화면에 보이는 현재 공인 IP를 복사해 WTS > 설정 > Open API > 허용 IP 관리에 등록한다 | 현재 공인 IP는 이 화면이 떠 있을 때만 공개 IP 확인 서비스에 물어서 보인다 (5.1). 화면이 열려 있는 동안 낮은 빈도로 다시 확인하고, 통과하면 다음으로 넘어간다 (REL-1) |
| 3 | 없음 | 없음 | 계좌 목록을 받는다. 종합매매 계좌 중 첫 계좌를 자동으로 고른다. 계좌가 여럿이면 고급 설정에서 바꿀 수 있다 (8장) |
| 4 | 없음 | 없음 | 보유 주식, 거래내역, 매수가능금액을 받아 현황을 그린다. 뉴스·공시 수집을 시작한다 |
| 5 | 없음 | 없음 | Claude Code를 찾아 로그인 상태와 실행 환경을 점검한다 (4.1). 통과하면 AI 기능을 켠다. 실패해도 1~4는 그대로 동작한다 |

- 투자 성향, 주문 기능, AI 모델, 예약 작업은 모두 기본값으로 시작한다 (P-4). 주문 기능은 꺼진 채로 시작한다 (ORD-5).
- AI에 데이터가 전송된다는 안내([R-13](research/R-13-legal-and-terms.md) Q7)는 채팅 패널 첫머리에 고정 문구로 보인다. 동의 단계를 따로 두지 않는다.
- 토스 계좌의 사전 요건(투자자지시 거래소 SOR 설정, 상품별 위험 고지, 달러 환전)은 첫 실행에서 묻지 않는다. 주문이 그 이유로 거절될 때만 2.6의 방식으로 알린다.
- 터미널 명령을 요구하는 단계는 없다 (P-3).

### 2.6 자체 점검

앱이 스스로 상태를 점검한다. 정상이면 아무것도 보이지 않는다. 사용자가 할 일이 있는 문제만 주 화면 상태 띠에 할 일 한 문장으로 보인다. 문제가 여럿이면 앞 순서의 것 하나만 보인다 (P-7). 사용자가 할 일이 없는 상태(6, 7번)는 주 화면에 띄우지 않고 고급 > 상태에만 남긴다.

| 순서 | 점검 | 언제 | 문제일 때 문장 (초안) | 그동안 |
|---|---|---|---|---|
| 1 | 토스 키 | 키 입력, 앱 시작, `invalid_client` | "토스 키가 맞지 않습니다. WTS의 Open API 설정에서 키를 다시 복사해 붙여 넣으세요." | 저장된 데이터로 표시 |
| 2 | 허용 IP | `ip-not-allowed`, 토큰 발급 `access_denied` | "이 컴퓨터의 IP(현재 IP)가 토스에 등록되어 있지 않습니다. WTS의 허용 IP 관리에 추가하세요." (복사 버튼) | 같음 |
| 3 | 같은 키의 중복 사용 | `token-revoked`가 재발급 1회 뒤에도 다시 옴 (API-3) | "같은 토스 키를 쓰는 다른 프로그램을 끄면 다시 연결됩니다." | 같음 |
| 4 | Claude Code 설치 | 앱 시작 | "Claude Code를 설치하면 AI 기능이 켜집니다." | AI 외 기능 동작 |
| 5 | Claude Code 로그인 | 앱 시작, 사전 점검 | "Claude Code에 로그인하면 AI 기능이 켜집니다." | 같음 |
| 6 | AI 실행 환경 | 실행마다 사전 점검 (4.1) | 주 화면에 띄우지 않는다. 고급 > 상태에 사유를 남긴다 | 같음 |
| 7 | AI 사용 한도 | 한도 신호 (REL-4) | 주 화면에 띄우지 않는다. 고급 > 상태에 재개 시각을 남긴다 | 예약 작업 대기 |
| 8 | 주문 사전 요건 | 주문 거절 (`prerequisite-required`, `investor-exchange-not-integrated`, 달러 `insufficient-buying-power`) | 오류별 한 문장. 예: "이 종목은 토스증권 앱에서 위험 안내를 먼저 확인해야 주문할 수 있습니다." | 해당 주문만 실패 |

- 뉴스·공시 소스 하나가 실패하는 것은 상태 띠에 보이지 않는다. 사용자가 할 일이 없기 때문이다. 고급 > 상태에만 남긴다 (REL-5).
- 문장에 내부 장치 이름(MCP, 세션, 격리, 큐, 보정 등)을 쓰지 않는다 (UX-6).
- 5번의 경우 앱이 Claude Code의 로그인 절차를 대신 띄울 수 있는지는 확인하지 않았다 (S-08).

## 3. 시스템 구조

- 앱은 메뉴 막대에 상주한다. 창을 닫아도 수집과 예약 작업이 계속 돈다 (REL-7).

### 3.1 MCP 도구

**공통 규칙** ([R-04](research/R-04-rust-mcp-server.md) Q4)

- 응답 하나는 3만 자를 넘지 않는다. 넘으면 `limit`과 `cursor`로 나눠 준다. CLI가 큰 도구 결과를 자기 폴더에 평문으로 저장하기 때문이다 (I-04).
- 오류는 `isError`와 구조화된 오류 코드로 준다. 읽기 도구에는 `readOnlyHint`를 붙인다. `structuredContent`와 text 블록을 함께 준다. 정렬은 결정적이다.
- 외부 텍스트는 `untrusted_text` 필드에만 담는다. 제어 문자와 폭 0 문자를 지우고, 링크를 평문으로 바꾸고, 길이를 자른다.
- 앱 MCP는 분석 실행만 연결한다. 수집 실행은 앱 MCP에 연결하지 않는다 (4.4, [architecture.md](architecture.md) 2.2). 표의 "프로필" 열이 그것이다.

| 도구 | 내용 | 프로필 |
|---|---|---|
| `get_portfolio` | 보유 종목, 비중, 손익, 통화별 매수가능금액. 토스 API에 예수금이 없으므로 현금 자리는 매수가능금액이다 (I-05) | 분석 |
| `get_allocation` | 섹터·국가·통화별 비중과 쏠림 지표 | 분석 |
| `get_transactions` | 거래내역 (매매·배당·입출금) | 분석 |

| `get_quote` / `get_candles` | 현재가, 일봉 | 분석 |
| `get_market_overview` | 국내 지수, 국채, 환율, 장 운영 상태. 미국 지수·금리·원자재·달러는 토스 미국 ETF 시세(근사)와 미 재무부·FRED 일별 값 (I-18). 근사인지 공식 값인지 표시 | 분석 |
| `get_rankings` / `get_sectors` | 거래대금·등락률·수급 랭킹, 섹터 랭킹 | 분석 |
| `get_investor_flow` | 종목별 외국인·기관 수급, 공매도 | 분석 |

| `read_article` | 수집해 둔 링크의 본문을 앱이 가져와 한 번 전달하고 버린다. 본문 읽기가 켜진 언론사 RSS 소스의 도메인에서 온 주소만 받는다. 수집 실행이 웹에서 가져온 주소, 수집 목록에 없는 주소, 본문 읽기가 꺼진 소스는 거부 (5.4). 웹 항목의 본문이 필요하면 수집 실행 안에서 요약까지 처리한다 (4.4) | 분석 |
| `get_thesis` / `update_thesis` | 논거 노트 읽기, 주장 단위 차분으로 쓰기. 출처가 웹뿐인 변경은 "확인 필요"로 보류 ([R-12](research/R-12-ai-analysis-design.md) 3.3) | 분석 |
| `get_profile` | 투자 성향과 원칙 | 분석 |
| `get_estimate_task` | 코드가 미리 만든 추정 과제를 `task_id`로 준다: 사건 정의(목표 +T%, 손절 −S%, 기간 H), 기준 확률, 기준가와 시각. 과제는 코드가 정한 대상(보유, 관심, 코드가 뽑은 후보)에만 있다. AI가 종목을 지정해 과제를 만들 수 없다 (6.1) | 분석 |
| `submit_estimate` | 추정 제출: `task_id`, 확률 p(1~99 정수 퍼센트), 근거, 반대 논거, 출처. **주문을 만들지 않는다.** 신호 여부는 코드가 정한다 | 분석 |
| `get_scorecard` | 과거 추정의 판정 결과와 적중률 | 분석 |
| `request_web_research` | 채팅 중 웹 조사가 필요할 때 수집 실행을 띄워 결과만 받는다. 인자는 앱이 아는 종목 코드 목록과 코드가 정한 주제 목록의 항목뿐이다. 사용자가 채팅에 직접 쓴 문장으로 조사할 때는 AI가 문장을 넘기지 않고, 코어가 저장된 사용자 메시지 원문을 그대로 넘긴다 (4.4, SEC-9) | 분석 |

주문 전송, 주문 취소, 설정 변경, 키 접근, 승인은 MCP에 없다. 이전 판의 `propose_order`, `propose_idea`, `get_policy`, `get_proposal_history`는 위의 추정 도구로 대체했다. 수집 실행의 웹 읽기를 앱이 대신 가져오는 도구로 줄지는 S-07의 결과로 정한다 (4.4).

## 4. AI 런타임

### 4.1 CLI 어댑터 (D3)

```
trait AiProvider {
  verify_isolation(profile) -> 점검 결과        사전 점검 (아래)
  run(profile, task, prompt, model, effort) -> 이벤트 스트림
  resume(앱 기록 재주입, message)
  interrupt()                                  단계 경계에서 멈춤 (SIGINT)
  usage() -> 남은 한도 추정
}
```

**Claude Code 실행** ([R-02](research/R-02-claude-code-runtime.md) 3.2, I-03)

| 항목 | 규칙 |
|---|---|
| 찾기 | 알려진 설치 위치와 로그인 셸의 PATH에서 `claude`를 찾는다. 사용자가 이미 로그인한 기본 설정 위치를 그대로 쓴다 (P-2). 앱 전용 `CLAUDE_CONFIG_DIR`은 별도 로그인이 필요하므로 쓰지 않는다 |
| 환경 변수 | 비운 뒤 허용 목록만 넘긴다: `HOME`, `PATH`, `USER`, `LOGNAME`, `TMPDIR`, MCP 토큰, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`. `USER`가 없으면 키체인의 구독 로그인을 읽지 못한다(실측). `ANTHROPIC_API_KEY`는 넘기지 않는다 (구독 사용) |
| 작업 폴더 | 실행마다 0700 빈 임시 폴더 |
| 명령 | `claude -p --verbose --input-format stream-json --output-format stream-json --include-partial-messages --restricted --disable-slash-commands --tools <프로필별> --allowedTools <프로필별> --permission-mode dontAsk --permission-prompts none --mcp-config <실행별 파일> --strict-mcp-config --model <설정> --effort <설정>` |
| 프로필별 도구 | 수집 실행: `--tools WebSearch`, 빈 MCP 설정(앱 MCP 없음), 결과는 `--json-schema` 구조화 출력. 웹 읽기는 S-07. 분석 실행: `--tools ""`(내장 도구 없음)와 분석용 MCP 도구 (4.4) |
| MCP 설정 | stdio 서버의 `command`는 앱에 들어 있는 브리지, 토큰은 `env`의 `${변수}` 참조로만 넘긴다. argv와 설정 파일에 토큰 값을 쓰지 않는다 ([R-04](research/R-04-rust-mcp-server.md)) |
| 기록 | 예약 작업과 채팅 모두 `--no-session-persistence`. 채팅은 대화 동안 프로세스 하나를 유지한다. 앱을 다시 켜거나 프로세스가 끝나면 앱이 저장한 대화를 새 프로세스에 다시 넣는다. `--resume`은 쓰지 않는다. 대화 원본은 앱 SQLite에 둔다. CLI가 앱 작업 폴더 이름으로 만든 폴더가 남으면 앱이 지운다 (I-04) |
| 프로세스 수명 | 프로세스 그룹으로 띄우고 stdin을 열어 둔다. 끝낼 때 SIGTERM 후 SIGKILL. 앱 시작 때 남은 그룹을 정리한다 ([R-05](research/R-05-tauri-architecture.md) Q5). 앱 샌드박스는 쓰지 않는다 |

**사전 점검** ([R-02](research/R-02-claude-code-runtime.md) Q12)

init 이벤트는 첫 사용자 메시지를 받은 뒤에야 나온다. 그래서 첫 메시지로 `/usage`를 보낸다. `--disable-slash-commands` 아래에서는 모델을 부르지 않고(`num_turns` 0, 비용 0) init만 나온다(실측). 이 init을 검사해 통과할 때만 같은 프로세스에 실제 요청을 보낸다.

| 검사 항목 | 기대값 |
|---|---|
| `tools` | 프로필의 기대 목록과 정확히 같음 |
| `mcp_servers[].status` | 분석 실행은 앱 서버가 `connected`, 수집 실행은 빈 목록. MCP 연결이 실패해도 CLI는 실행을 계속하고 종료 코드 0으로 끝나므로 반드시 검사한다 ([R-04](research/R-04-rust-mcp-server.md) 4장) |
| `plugins` | 내장 허용 목록만 |
| `skills`, `slash_commands` | 빈 목록 |
| `permissionMode` | `dontAsk` |
| `apiKeySource` | `none` (구독 인증) |
| `claude_code_version` | 기록한다. 바뀌면 REL-8 |

- 이 조합으로 사용자 훅, 플러그인, 사용자 설정, 프로젝트 CLAUDE.md가 차단되고 구독 인증이 유지됐다(R-02 실측). 사용자 메모리와 전역 CLAUDE.md가 차단되는지는 아직 확인하지 않았다 (S-04).
- 실제로 답한 모델은 `assistant.message.model`과 `modelUsage`로 기록한다. 내용에 따라 다른 모델로 자동 전환될 수 있다 (AI-6).

**사용량** (`usage()`)

- 실행 중: `rate_limit_event`의 `status`, `utilization`, `resetsAt`. 필드 이름은 문서가 아니라 실측으로 확인한 것이므로 모르는 값을 견디는 파서로 읽는다.
- 한도 초과 판정: result의 `api_error == "usage_limit_reached"` 또는 `rate_limit_event.status == "rejected"`. 재개 시각은 `resetsAt` (REL-4).

**Codex** ([R-03](research/R-03-codex-cli-runtime.md))

- 어댑터 구조는 남기되 기본으로 끈다. 사용자가 전부 Claude 구독으로 정했다 (open-issues 2.1).
- 켤 경우의 구동 방식은 `codex app-server`(stdio JSON-RPC)다. `exec --json`은 한도 신호와 글자 단위 스트림이 없다.
- R-03의 격리 구성은 앱 전용 `CODEX_HOME`(별도 로그인)을 전제로 한다. 이것은 P-2와 부딪힌다. 기존 로그인으로 격리가 되는지는 확인하지 않았다 (S-09). 확인될 때까지 고급 설정에서도 켤 수 없게 둔다.

**프롬프트** ([R-12](research/R-12-ai-analysis-design.md) 2.8)

- `prompts/<작업>/<버전>.md`에 앞머리(`id`, `version`, `task`, `inputs`, `output_schema`, `tools`)를 둔다. 본문에 제공자별 도구 이름을 쓰지 않는다.
- 구조화된 결과는 MCP 도구 호출이나 공용 JSON 스키마로 받는다.
- 기본 모델: 확률 추정과 심층 연구는 최상위 모델, 뉴스 분류·요약과 수집 실행은 빠른 모델.

### 4.2 채팅

- 채팅은 분석 실행 프로필로 돈다. 웹 도구가 없다.
- 지금 보고 있는 화면(종목, 기간)을 맥락으로 함께 보낸다.
- 사용자가 웹 검색을 시키면 채팅 실행이 `request_web_research`를 부르고, 앱이 수집 실행을 따로 띄워 결과만 돌려준다 (4.4). 사용자가 채팅에 직접 쓴 문장으로 조사할 때는 코어가 저장된 사용자 메시지 원문을 그대로 수집 실행에 넘긴다. AI가 고쳐 쓴 문장은 넘어가지 않는다.
- 대화 동안 채팅 프로세스 하나를 유지한다. 앱을 다시 켜면 앱이 저장한 대화를 새 프로세스에 다시 넣는다 (4.1 기록).
- 답변 안의 종목, 숫자, 신호는 코어 데이터로 카드를 그린다. 신호 카드는 주 화면의 카드와 같다.
- 채팅 프로세스는 미리 띄워 사전 점검을 끝내 둔다. 첫 글자 시간(PERF-2)에 사전 점검과 MCP 연결 대기가 들어가지 않게 하기 위해서다.

### 4.3 예약 작업 (D2)

예약 작업은 설정한 한도 비율(AI-2) 안에서 구독을 계속 쓴다. 한도에 걸리면 대기하고 재개 시각에 이어 간다. 채팅이 항상 먼저다 (AI-1).

| 주간 점검 | 토요일 오전 | 코드 + 분석 | 쏠림과 원칙 위반 점검, 성적표 갱신 |

- 개장 시각은 토스 장 운영 정보에서 읽는다. 서머타임과 휴장일을 직접 계산하지 않는다.
- 스케줄러는 벽시계 기준이다. 짧은 주기로 깨어 `Clock` 포트의 시각과 비교한다. `Instant` 기반의 긴 sleep은 잠자기 뒤 늦게 깨므로 쓰지 않는다 ([R-05](research/R-05-tauri-architecture.md) Q9).
- 장이 닫힌 시간에 나온 추정도 기록하고 신호를 계산한다. 주문 카드는 장이 열린 뒤에만 뜬다 (6.4).

**심층 연구** ([R-12](research/R-12-ai-analysis-design.md) 3.1 추천안 D)

| 단계 | 실행 | 하는 일 |
|---|---|---|
| 0 | 코드 | 증거 묶음: 시세, 재무, 공시, 뉴스 묶음, 수급, 논거 노트, 투자 성향. 모든 항목에 ID와 수집 시각 |
| 1 | 코드 | 검색 계획: 종목명과 주제어만 담은 검색어 목록 |
| 2 | 수집 실행 | 웹 수집. 결과는 출처 `web`으로 저장 |
| 3 | 분석 실행 두 번 | 긍정론과 부정론을 서로 보지 않고 같은 증거로 쓴다. 가능하면 다른 모델로 |
| 4 | 코드 + 분석 실행 | 주장 검증: 주장 하나씩, 초안을 보지 않고 증거 원장과 대조 |
| 5 | 분석 실행 | 결론: 노트 차분과 `submit_estimate` |
| 6 | 코드 | 원칙 검사, 출처 종류 경고, 개수 제한, 노트 상태 집계, 임계값 비교 |

- 토론 왕복은 넣지 않는다. 토론이 결론을 낫게 한다는 근거가 일관되지 않다 (R-12 2.1).
- 이 파이프라인이 단일 호출보다 나은지는 가설이다. 예산 안에서 일부 추정을 단일 호출로도 함께 돌려 기록만 하고, 성적표로 비교한다 (AI-5).
- 단계 경계마다 중간 결과를 저장해 채팅이 끼어들어도 이어 갈 수 있게 한다.

### 4.4 수집 실행과 분석 실행

보유 내역을 아는 AI가 웹 검색을 하면 검색어로 수량과 금액이 새어 나갈 수 있다. 실제 사례가 있다 ([R-12](research/R-12-ai-analysis-design.md) 2.10). 그래서 실행을 둘로 나눈다 (open-issues 3장).

| 실행 | 볼 수 있는 것 | 쓸 수 있는 도구 | 결과 |
|---|---|---|---|
| 수집 실행 | 종목명, 종목 코드, 주제어. 수량·금액·계좌는 모른다 | 내장 WebSearch만. 앱 MCP에 연결하지 않는다. 웹 읽기는 S-07 | 제목, 주소, 짧은 요약. 원장에 출처 `web`으로 저장 |
| 분석 실행 | 보유 내역 전체와 수집 실행이 모은 자료 | 분석용 MCP 도구만. 웹 도구 없음 | 브리핑, 노트 차분, 추정 |

- 수집 실행은 새어 나갈 비밀을 갖고 있지 않다. 남는 노출은 "이 종목에 관심이 있다"는 정도이고, 검색어는 Anthropic과 검색 제공자에게 간다.
- 분석 실행이 요청하는 웹 조사는 코드가 정한 주제 목록과 앱이 이미 아는 종목(보유, 관심, 코드가 뽑은 후보)의 조합만 받고, 호출 빈도를 제한한다. 분석 실행이 쓴 자유 문장은 넘기지 않는다. 코드가 만든 검색어도 SEC-9 규칙으로 검사한 뒤에만 넘긴다.
- 사용자가 채팅에 직접 쓴 문장으로 하는 웹 조사는 사용자의 문장을 그대로 수집 실행에 넘긴다. 코어가 저장된 사용자 메시지에서 꺼내므로 AI가 고쳐 쓸 수 없다. 사용자가 쓴 문장이므로 SEC-9의 거부 규칙은 적용하지 않고 감사 로그에만 남긴다.
- 분석 실행이 웹으로 직접 나가는 통로는 없다. 남는 것은 낮은 대역 통로다: 분석 실행이 `request_web_research`에서 어떤 종목과 어떤 주제를 고르는지가 수집 실행의 검색어에 드러난다. 고를 수 있는 값이 코드의 목록 안에 있고 빈도가 제한되므로 보유 수량이나 금액을 그대로 실을 수는 없다. 이 통로는 남는 위험으로 둔다 (9.1).
- 웹 항목의 본문은 분석 실행이 `read_article`로 읽을 수 없다. 본문이 필요하면 수집 실행 안에서 읽고 요약까지 처리한다 (3.1).
- 웹 읽기: 내장 WebFetch는 `--restricted`에서 빠진다. 격리를 유지하면서 수집 실행에 웹 읽기를 살리는 옵션 조합은 확인하지 않았다 (S-07). 확인될 때까지 수집 실행은 검색 결과의 제목, 주소, 요약만 낸다. 조합이 없으면 앱이 대신 가져오는 도구(소스별 본문 읽기 설정을 코드가 강제할 수 있다)를 수집 실행에 줄지 ADR로 정한다.
- 수집 실행의 결과는 분석 실행에 `untrusted_text`로만 들어간다.
- 이 분리는 화면에 드러나지 않는다 (P-8). 사용자는 "찾아봤습니다"와 결과만 본다.

|---|---|---|---|
| KIND 공시 | 2분 | 30분 | 30분. 앱 시작 때 하루치(500건)로 따라잡기 |
| DART 목록 (키가 있을 때) | 10분 | 30분 | 30분 |
| 언론사 RSS | 10분 (한경 30분) | 30분 | 30분 |
| Google 뉴스 (국내 보유 종목) | 60분 | 60분 | 60분 |
| Yahoo (미국 보유 종목) | 60분 | 30분 | 60분 |
| SEC EDGAR (미국 보유 종목) | 60분 | 15분 | 60분 |
| 한국은행·연준 RSS | 60분 | 60분 (FOMC 당일 10분) | 60분 |

- 장중 여부는 토스 장 운영 정보로 판정한다. 고정 시각을 쓰지 않는다.
- 조건부 GET은 소스마다 다르다. 304가 확인된 곳은 이데일리, 한경, 연준이다. 매경, 연합, Google, KIND, 한은은 되지 않는다.
- 거래내역은 고유 ID가 없다. 최근 14일 창을 매번 다시 받아 같은 행의 개수까지 맞춘다. 사라진 행은 지우지 않고 사라진 시각만 표시한다 (I-06).

### 5.3 AI를 깨우는 조건

| 조건 | 기본값 |
|---|---|
| 보유 종목의 긴급·높음 등급 공시 (매매거래정지, 관리종목, 유상증자, 최대주주 변경, 잠정실적 등. 등급 규칙은 [R-07](research/R-07-news-sources.md) Q8) | 즉시 |
| 보유 종목의 하루 변동 | ±5% 이상 |
| 같은 종목 뉴스 | 1시간에 5건 이상 |

- 보통 등급 공시는 브리핑에 들어가고, 낮음 등급은 수집만 한다.
- 정정 공시는 원 공시 등급을 이어받되 한 단계 낮춘다.

### 5.4 저장, 본문, 매칭, 묶음

- 저장하는 것: 제목, RSS 요약, 링크, 발행 시각, 매칭된 종목. 본문은 저장하지 않는다.
- 본문은 `read_article`이 필요할 때 가져와 한 번 전달하고 버린다. `read_article`은 본문 읽기가 켜진 언론사 RSS 소스의 도메인에서 온 주소만 받고, 수집 실행이 웹에서 가져온 주소는 거부한다. 소스별 "AI 본문 읽기"는 기본으로 끈다. 연합뉴스는 켤 수 없다. 꺼진 소스는 제목과 요약만 AI에 들어간다 ([R-07](research/R-07-news-sources.md) Q5).
- 종목 매칭 ([R-07](research/R-07-news-sources.md) Q7):
  - 사전은 종목 마스터 정식명, 약칭 표(고급 설정에서 편집), 영문명이다.
  - 영문 이름은 단어 경계, 한글 이름은 앞뒤 경계와 조사 규칙으로 거른다.
  - 일반 명사와 같은 종목명(대상, 채비 등)은 증권 문맥이 있을 때만 인정한다.
  - 그룹명 접두(SK, LG 등) 뒤에 다른 글자가 붙으면 지주사로 매칭하지 않는다. 긴 상장 계열사명을 우선한다.
  - 애매한 것만 빠른 모델에 넘긴다.
- 사건 묶음: 정규화한 URL이 같으면 같은 항목이다. 같은 종목, 48시간 안에서 제목 2-gram Jaccard 0.45 이상을 대표 기사와 비교해 묶는다. 단일 연결 군집은 다른 회사 기사를 섞으므로 쓰지 않는다.
- 공시 키는 (소스, 접수 번호)다. KIND와 DART 번호의 대응 규칙은 하루치 표본에서 나온 것이라 별도로 관리한다.

## 6. 확률 신호와 주문 (D1)

### 6.1 추정

AI가 추정하는 것은 채점할 수 있는 사건 하나다 (open-issues 1.1).

> 기간 H 안에 **목표 수익률 +T%에 먼저 닿을 확률 p**. 그 전에 손절선 −S%에 닿거나 기간이 끝나면 실패.

| 누가 | 무엇을 |
|---|---|
| 코드 | 추정 대상을 정한다: 보유, 관심, 코드가 뽑은 후보. 과제는 이 대상에만 만들고 AI는 `task_id`로만 받고 제출한다 |
| 코드 | T, S, H를 투자 성향과 그 종목의 변동성으로 정한다: T = a·σ√H, S = b·σ√H (σ는 일 변동성, H는 거래일 수, a와 b는 투자 성향별 상수). 기준가와 기준 시각을 고정한다 |
| 코드 | 기준 확률 p₀를 "기간이 끝나면 실패" 조건을 넣어 계산해 AI에게 먼저 보여 준다 (6.2) |
| AI | 근거가 있을 때만 기준 확률에서 올리거나 내린 p를 낸다. p는 1~99의 정수 퍼센트다 |
| AI | 근거, 가장 강한 반대 논거를 하나 이상, 각 근거의 출처를 낸다. 숫자는 값이 아니라 도구 결과 참조로 쓴다 |
| 코드 | 모든 추정을 기록한다. 거래하지 않은 것도 기록하고 판정한다 |

- 한 실행이 낼 수 있는 추정 개수와 같은 종목 중복 제출을 제한한다.
- `c/(T+S)`가 5%p를 넘거나 변동성 표본이 60거래일 미만인 종목에는 과제를 만들지 않는다. 그 종목은 신호가 없고, 화면에 따로 드러내지 않는다 (6.2).
- 같은 종목의 새 추정이 오면 이전 추정은 판정 대상으로 남고, 신호는 새 추정으로 다시 계산한다.

### 6.2 임계값과 신호

한 번 거래의 기대 수익은 `E = p·T − q·S + r·m − c`다 (open-issues 1.2). p는 목표, q는 손절, r은 기간 만료로 끝날 확률이고(p + q + r = 1), m은 만기로 끝났을 때의 평균 수익률, c는 왕복 수수료와 세금이다. 가정: AI의 정보는 확률을 손절에서 목표로 옮기고 만기 몫(r, m)은 바꾸지 않는다. 정보가 없으면 `p₀·T − q₀·S + r·m = 0`이다(방향 없는 무작위 움직임에서 비용을 빼기 전 기대 수익은 0). 그래서 p가 p₀보다 Δ만큼 높으면 `E = Δ·(T+S) − c`다.

| 값 | 식 | 뜻 |
|---|---|---|
| 기준 확률 p₀ | 두 경계와 기간 제한이 있는 무작위 움직임의 도달 확률. 급수 해는 [리뷰 기록 DESIGN-v0.2](reviews/DESIGN-v0.2.md) 2절 | 아무 정보가 없을 때의 확률. `S/(T+S)`는 기간 제한이 없을 때의 값이라 쓰지 않는다 |
| 손익분기 확률 | `p₀ + c/(T+S)` | 기대 수익이 0이 되는 확률 |
| 매수 임계값 | `p₀ + c/(T+S) + 여유분` | 실제 적중률을 반영한 p가 이 이상이면 매수 신호 |
| 매도 임계값 (보유 종목) | `p₀ − 여유분`, 5% 아래로 내려가지 않음 | 보유 종목의 실제 적중률을 반영한 p가 이 이하이면 매도 신호. 매도 비용은 지금 팔든 나중에 팔든 같으므로 넣지 않는다 |
| 그 사이 | - | 신호 없음 |

- T와 S가 변동성에 비례하므로 p₀는 (a, b)로 거의 정해진다. 위험 성향별 (a, b)는 p₀가 20~40% 안에 들도록 고른다. 값은 구현 단계 ADR(D-21)에서 정하고 E-92에서 조정한다.
- c는 토스 수수료 API의 계좌 요율과 세율(R-11 Q3)로 코드가 계산한다.
- `c/(T+S)`가 5%p를 넘거나 변동성 표본이 60거래일 미만이면 그 종목에는 추정 과제를 만들지 않는다 (6.1). 몇 시간 단위 기간은 T와 S가 작아 대부분 이 규칙으로 걸러진다.
- 여유분은 위험 성향에 따라 정한다. 판정된 추정이 30건이 되기 전에는 15%p로 둔다 (ORD-8). 판정 건수는 같은 종목에서 기간이 겹치지 않는 추정만 센다.
- 30건 이후에는 코드가 실제 적중률로 p를 보정한 뒤 임계값과 비교한다. 보정은 모델별, 기간별로 따로 한다. 어떤 조합이 30건 미만이면 그 조합은 보수 운용을 유지한다. 모델이 바뀌면 그 모델의 건수가 30건이 될 때까지 보수 운용으로 돌아간다. 보정 방법은 E-91의 ADR에서 추정 기록 기간(S-06)의 자료로 정하되, 표본이 적을 때 기준 확률 쪽으로 당기는 방식이어야 한다. 구간별 적중률은 성적표 표시용이다.
- 보유하지 않은 종목의 낮은 p는 아무 신호도 만들지 않는다. 공매도는 하지 않는다.
- 몇 시간 단위 기간은 기본값에서 끄고 고급 설정에서만 켠다.

**투자 성향** (open-issues 1.3, 값은 초안)

| 항목 | 선택지 | 바뀌는 것 | 기본값 |
|---|---|---|---|
| 기간 | 며칠 / 몇 주~몇 달 / 반년 이상 | H, 그리고 그 기간의 변동성으로 T와 S | 몇 주~몇 달 |
| 위험 성향 | 보수 / 중립 / 공격 | T와 S의 변동성 배수 (a, b), 여유분, 한 번에 사는 비중 | 중립 |
| 제외 | 종목 유형, 섹터 | 신호 대상에서 뺀다 | 없음 |
| 비중 상한 | 종목, 섹터 | 수량을 깎거나 신호를 막는다 | 종목 20%(10%부터 주의), 섹터 40% ([R-11](research/R-11-portfolio-math.md) Q6 제안값) |

### 6.3 방향, 수량, 가격

AI는 방향, 수량, 가격을 정하지 않는다. 코드가 정한다.

| 항목 | 규칙 |
|---|---|
| 방향 | 매수 임계값 이상이면 매수, 보유 종목이 매도 임계값 이하이면 매도 |
| 매수 수량 | 위험 성향의 "한 번에 사는 비중"으로 금액을 정하고, 비중 상한, 해당 통화의 매수가능금액, 30건 전 보수 운용(ORD-8)으로 깎은 뒤 수량으로 바꾼다. 수량이 0이면 주문 버튼 없는 카드에 이유를 한 문장으로 단다. 예: 달러 매수가능금액이 없으면 "토스증권 앱에서 환전하면 주문할 수 있어요" |
| 반복 | 같은 종목의 매수 신호는 기간 H 동안 한 번만 낸다 |
| 매도 수량 | 보유 수량과 매도가능수량 안에서 투자 성향 규칙으로 정한다 |
| 가격 | 기본은 지정가다. 지정가는 코드가 최신 호가와 호가 단위로 정한다. 시장가는 고급 설정에서 켜야 한다. 금액 주문은 토스가 미국 주식 시장가에서만 받으므로 그 경우에만 쓴다 |
| 통화 | 미국 주식 매수는 달러 매수가능금액만 본다. 토스에는 자동 환전과 API 환전이 없다 ([R-01](research/R-01-toss-open-api.md) Q7) |

수량과 가격 규칙의 세부 값(한 번에 사는 비중, 매도 비율, 지정가 산정식)은 구현 단계 ADR로 정한다.

### 6.5 규칙

- 승인은 사용자만 한다. AI, MCP, 채팅 메시지로는 승인할 수 없다.
- WebView를 신뢰하지 않는다. AI가 쓴 글이 WebView에 그려지기 때문이다. WebView는 `request_order_approval(proposal_id)`만 부를 수 있다. 코어가 저장된 주문 제안을 읽고 최신 시세로 다시 검증해 네이티브 창을 띄운다 ([architecture.md](architecture.md) 4.4).
- 본인 확인은 모든 주문에 요구하고, 주문 때만 요구한다 (P-9).
- 승인과 전송은 한 번에 끝난다. "승인된 상태"는 저장하지 않는다.
- 여러 신호를 한 번에 승인하는 기능은 두지 않는다. 한 번의 확인은 주문 하나다 ([R-13](research/R-13-legal-and-terms.md) Q4).
- 주문 제안 카드는 10분이 지나거나 카드의 기준 가격에서 변동성으로 정한 범위를 넘게 움직이면 만료된다. 제안이 만료돼도 신호는 남는다. 사용자가 주문을 누르면 최신가로 제안을 다시 만들고, 추정 기준가에서 변동성으로 정한 범위 안일 때만 낸다. 범위는 비율 고정값이 아니라 σ√H에 비례하는 값이고, 계수는 D-14의 ADR에서 정한다.
- 카드에서 수량이나 가격을 바꾸는 기능은 없다. 수량과 가격은 코드가 정한다 (6.3).
- "넘기기"는 사유를 한 줄 적을 수 있다. 사유는 기록만 하고 다음 추정의 입력에 넣지 않는다. 사용자 의견에 맞춘 확률로 쏠리는 것을 막기 위해서다 ([R-12](research/R-12-ai-analysis-design.md) 2.1 아첨).
- 금액 한도는 따로 두지 않는다. 매수는 매수가능금액, 매도는 매도가능수량이 한도다.
- 1억 원 판정: 원화 주문은 금액 그대로, 달러 주문은 토스 환율 API의 `rate`와 `midRate` 중 큰 값으로 환산한다. 1억 원의 80% 이상이면 처음부터 최종 확인(네이티브 요약 창)에서 고액 확인을 받고 `confirmHighValueOrder`를 붙인다. 그래도 토스가 고액 확인을 요구하며 거절하면 그 주문은 실패로 두고 한 문장으로 알린다. 다시 보내지 않는다. 토스의 판정 환율은 미확인이다 (S-01).
- 전송 결과를 모를 때의 처리는 ORD-2를 따른다.
- 주문 정정과 취소는 토스증권 앱에서 한다. 앱은 주문 생성만 한다. 앱이 보내는 주문은 `timeInForce` 기본값 `DAY`이고, 스펙 v1.2.28은 `DAY` 주문의 미체결분이 정규장 종료 때 자동 취소된다고 적는다.

### 6.6 판정과 성적표 (D4)

**판정** (코드가 한다. 사람이나 AI의 해석이 끼지 않는다)

- 기준가 이후의 수정주가 일봉으로 본다. 고가가 기준가 × (1 + T)에 닿으면 성공, 저가가 기준가 × (1 − S)에 닿으면 실패, 기간 H가 끝나면 실패다.
- 기준가는 판정할 때 수정주가와 같은 수정 계수로 맞춘다. 기준 시각 뒤에 액면분할이 있어도 즉시 손절로 판정되지 않게 하기 위해서다.
- 기준일(기준 시각 이전 움직임이 일봉에 섞이는 날)과 목표·손절에 모두 닿은 날은 1분봉으로 판정한다. 1분봉으로도 순서를 알 수 없으면 실패로 본다.
- 몇 시간 단위 기간은 1분봉으로만 판정한다.
- 배당락이 수정주가와 기준가에 주는 영향은 실측 S-23에서 확인하고 처리 규칙을 정한다.
- 판정 건수는 같은 종목에서 기간이 겹치지 않는 추정만 센다 (6.2).
- 판정이 끝난 결과는 바꾸지 않는다.

**가상 청산**: 성적표의 "신호를 따랐을 때의 수익률"은 가상 청산으로 계산한다. 목표가나 손절가에 닿으면 그 가격, 시가가 그 가격을 넘겨 시작한 날이면 시가, 기간이 끝나면 그날 종가에 청산한 것으로 본다. 실제 보유분은 이 규칙으로 자동 청산되지 않는다. 매도 신호와 사용자 판단으로 정리된다.

**성적표**

| 항목 | 내용 |
|---|---|
| 적중률 | 확률 구간별로 "AI가 p라고 한 것 중 실제로 맞은 비율"과 건수. 모델별, 기간별로 따로 |
| 확률과 실제 빈도 | Brier 점수와 신뢰도 도표 |
| 신호 수익률 | 신호를 따랐다면의 수익률(가상 청산, 수수료·세금 반영)과 실제로 주문한 것의 수익률. 같은 기간, 같은 통화의 벤치마크와 비교 |
| 벤치마크 | 국내 종목은 KOSPI 또는 KOSDAQ(가격지수라 배당이 빠진다는 표시), 미국 종목은 S&P 500 추종 ETF, 포트폴리오는 혼합 벤치마크 ([R-11](research/R-11-portfolio-math.md) Q8) |
| 판정 보류 | 판정된 추정이 30건 미만이면 숫자만 보여 주고 "판정 보류"를 표시한다. 30건은 표시를 시작하는 최소 기준이다. 적중률 60%를 50%와 구분하려면 약 200건이 필요하다 ([R-12](research/R-12-ai-analysis-design.md) 3.4) |
| 신뢰구간 | 30건 이상이면 날짜 단위로 묶은 부트스트랩 95% 구간을 보인다. 0을 포함하면 "우위 확인 안 됨" |
| 비교 수 | 지금까지 비교한 모델·프롬프트 조합 수를 함께 보인다 (선택 편향) |

- 신호 카드와 성적표의 화면 문구에 "보정"을 쓰지 않는다 (UX-6). "실제 적중률을 반영한 확률" 같은 말로 쓴다.

## 7. 비기능 요구사항

ID는 v0.1을 유지했다. 새 항목은 각 묶음의 뒤 번호를 썼다.

### 7.1 보안

| ID | 요구사항 |
|---|---|
| SEC-1 | 토스 `client_secret`, 액세스 토큰, DB 키는 데이터 보호 키체인에만 둔다. 앱 팀 접근 그룹, `ThisDeviceOnly` 접근성을 쓴다. SQLite, 로그, AI 프롬프트, CLI 인자와 환경 변수에 들어가지 않는다. 서명 없는 개발 빌드는 별도 서비스 이름과 가짜 키만 쓴다. 서명한 앱에서 동작하는지는 S-02, Apple 개발자 멤버십은 U-02 ([R-16](research/R-16-local-security.md) Q1) |
| SEC-2 | AI CLI는 4.1의 명령과 실행 프로필로만 띄운다. 실행 종류별 도구: 분석 실행은 내장 도구 0개와 분석용 앱 MCP 도구, 수집 실행은 내장 WebSearch 하나와 앱 MCP 없음(웹 읽기는 S-07). 실행마다 사전 점검의 검사 항목이 하나라도 다르면 실제 요청을 보내기 전에 프로세스를 끝낸다. 사용자 훅·플러그인·스킬·프로젝트 CLAUDE.md가 설치된 환경에서 init의 `skills`와 `slash_commands`가 빈 목록이고 사용자 훅 실행이 0건임을 테스트로 확인한다. 환경 변수는 허용 목록만, 작업 폴더는 0700 빈 폴더, 파일 디스크립터는 상속하지 않는다. `sandbox-exec` 프로필은 추가 겹으로만 쓰고 시작할 때 적용 여부를 스스로 점검한다 ([R-02](research/R-02-claude-code-runtime.md), [R-16](research/R-16-local-security.md) Q3) |
| SEC-3 | MCP는 stdio 브리지 → Unix 소켓으로만 연다. 0700 폴더 안의 0600 소켓, 경로 104바이트 이내, 실행마다 새 소켓과 새 토큰, 접속자 uid 일치와 부모 PID 확인. 토큰은 환경 변수로만 넘기고 실행이 끝나면 폐기한다. TCP 포트는 0개다 ([R-04](research/R-04-rust-mcp-server.md)) |
| SEC-4 | 뉴스·웹·공시 내용은 신뢰하지 않는 입력이다. `untrusted_text` 필드에만 담고 정규화한다. 그 안의 지시문이 확률 추정을 흔들어도 주문은 SEC-5가 막는다. 추정 과제는 코드가 정한 대상에만 있어 주입된 실행이 임의 종목의 확률을 낼 수 없다 (6.1). 근거가 외부 출처뿐인 신호 카드에는 경고가 붙는다. 시세·포트폴리오 도구 참조는 근거 출처로 세지 않는다 |
| SEC-5 | 주문 전송 경로는 "WebView 승인 요청 → 코어 재계산 → 네이티브 요약 창 → 본인 확인 → 감사 로그 기록 → 전송" 하나뿐이다. WebView 호출만으로는 주문이 0건이다. 승인 요청에 `proposal_id` 밖의 필드(수량, 가격, 승인 표시)를 실어 보내면 요청이 거부된다. 이 경로는 테스트로 고정한다 ([architecture.md](architecture.md) 4.6) |
| SEC-6 | SQLite는 SQLCipher로 암호화한다. 키는 256비트 난수 원시 키(KDF 없음), `TEMP_STORE=2`, WAL 포함 암호화. 키는 키체인에만 두고 메모리에서는 쓴 뒤 지운다 ([R-06](research/R-06-sqlite-store.md)) |
| SEC-7 | 계좌번호는 화면과 AI 프롬프트에서 뒤 4자리만 보인다 |
| SEC-8 | 모든 주문 전송 직전에 코어가 WebView 밖에서 네이티브 요약 창을 띄우고 `LAContext.evaluatePolicy(.deviceOwnerAuthentication)`를 부른다. 재사용 시간은 0초다. Touch ID를 쓸 수 없으면 로그인 암호로 넘어간다. 창 본문에 코드가 계산한 주문 요약을, 시스템 창 이유 문자열에 종목·방향·수량을 넣는다. 창은 한 번에 하나만 띄우고, 취소한 신호는 일정 시간 다시 요청할 수 없다. Tauri 생체 인증 플러그인은 쓰지 않는다 (I-02). 이유 문자열 길이 한도는 S-02 |
| SEC-9 | 분석 실행이 요청하는 웹 조사는 코드가 정한 주제 목록과 앱이 아는 종목의 조합만 받는다. 분석 실행이 쓴 자유 문장은 수집 실행으로 넘어가지 않는다. 숫자를 글자로 쓴 말("삼백오십")도 이 구조로 막힌다. 수집 실행으로 넘어가는 모든 검색어는 코드가 먼저 검사하고 감사 로그에 남긴다. 두 자리 이상 숫자(연도·분기 표기는 허용 목록), URL·도메인 형태, 금액·수량·계좌 단위어가 든 것은 거부한다. 보유 수량·금액·계좌가 든 검색어는 0건이어야 하고 테스트로 고정한다. 예외: 사용자가 채팅에 직접 쓴 문장은 코어가 원문 그대로 넘기고 감사 로그에만 남긴다 (4.4, [R-12](research/R-12-ai-analysis-design.md) 2.10) |
| SEC-10 | WebView: CSP를 명시한다(외부 스크립트·이미지·연결 금지), `freezePrototype`, 명령 허용 목록, WebView에 `dialog`·`shell`·`opener`·`fs`·`http` 권한 없음. AI 마크다운은 raw HTML과 외부 이미지를 렌더링하지 않는다. AI가 쓴 글의 링크는 수집 목록에 있는 주소만 링크로 만들고, 나머지는 글자로만 보인다. 외부 링크는 코어가 `https`만 열고, 수집 목록에 있는 주소나 앱이 정한 고정 주소(예: 학습 설정 바로가기)만 연다 ([R-16](research/R-16-local-security.md) Q6) |
| SEC-11 | 비밀 값은 `secrecy` 타입으로 감싸고 `Debug`·`Display`·`Serialize`·`Clone`을 구현하지 않는다. HTTP 헤더는 `set_sensitive`. 오류 메시지에 요청·응답 본문을 넣지 않는다. 가짜 비밀 문자열을 넣고 로그, 오류, SQLite 파일, MCP 응답을 검사해 0건임을 테스트한다 ([R-16](research/R-16-local-security.md) Q4) |
| SEC-12 | 위험 설정 변경(주문 기능 켜기, 시장가 허용, 몇 시간 단위 기간 허용, 비중 상한 완화, 위험 성향을 더 공격적으로 바꾸기)은 WebView 호출만으로 바뀌지 않는다. 코어가 네이티브 확인 창을 띄워 사용자가 확인해야 바뀐다. 본인 확인(Touch ID)은 요구하지 않는다 (P-9) |
| SEC-13 | AI CLI 실행 환경에 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`을 넣는다. 대화 기록을 제공자에게 보내 5년 보관되는 `/feedback` 같은 명령은 슬래시 명령이므로 `--disable-slash-commands`로 함께 꺼진다고 본다 ([R-13](research/R-13-legal-and-terms.md) Q6). 이 변수와 구독 인증이 함께 동작하는지, 피드백 명령이 실제로 꺼지는지는 S-04에서 확인한다 |

### 7.2 주문 안전성

| ID | 요구사항 |
|---|---|
| ORD-1 | 사람 승인 없는 주문 전송은 0건이어야 한다 |
| ORD-2 | 모든 주문은 `clientOrderId`를 갖고, 감사 로그에 먼저 기록한 뒤 전송한다. 감사 로그 쓰기가 실패하면 전송은 0건이다. 결과를 모르면 10분 안에는 같은 키와 같은 내용으로 다시 요청해 확정한다. 10분이 지났거나 `maintenance` 응답 뒤에는 다시 보내지 않고 주문 조회와 주문 이벤트를 (종목, 방향, 호가 유형, 가격, 수량·금액, 전송 시각 이후 `orderedAt`)으로 대조한다. 조회 결과에 `clientOrderId`가 없기 때문이다. 하나로 확정되지 않으면 "확인 불가"로 두고 같은 종목의 새 주문을 막는다 (I-07, [R-01](research/R-01-toss-open-api.md) Q7) |
| ORD-3 | 추정, 신호, 검증 결과, 승인·넘기기, 전송 요청, 응답을 변조를 탐지할 수 있는 감사 로그에 남긴다. 해시 체인 + HMAC(키는 키체인) + 키체인에 고정한 머리값 + 토스 주문 내역 대조. 중간 수정, 삭제, 꼬리 잘라내기를 테스트로 탐지한다 (I-10, [R-16](research/R-16-local-security.md) Q7, [R-06](research/R-06-sqlite-store.md)) |
| ORD-4 | 임계값, 방향, 수량, 가격, 매수가능금액·매도가능수량, 만료, 원칙 검사는 코드가 하며 AI가 우회할 수 없다. `submit_estimate`의 입력에는 방향·수량·가격 필드가 없다 |
| ORD-5 | 기본 설정에 "주문 켜기" 스위치를 둔다. 꺼져 있으면 신호 카드는 보이지만 주문 버튼이 없다. 처음 설치하면 꺼져 있다. 켜는 것은 SEC-12를 거친다 |
| ORD-6 | 주문 횟수에 코드 상한을 둔다(전체 주문 시간당 건수). 앱은 정정과 취소를 하지 않는다 (6.5). 기본값은 토스가 어뷰징 예로 든 "소액 주문 수십 분 내 수백 건"보다 충분히 낮게 구현 ADR에서 정한다. 넘으면 버튼이 사라지고 이유를 한 문장으로 보인다 ([R-13](research/R-13-legal-and-terms.md) Q2) |
| ORD-7 | 한 번의 확인으로 나가는 주문은 1건이다. 일괄 승인 경로는 0개다 |
| ORD-8 | 모델·기간 조합별로 판정된 추정(같은 종목에서 기간이 겹치지 않는 것만 센다)이 30건 미만이면 여유분 15%p와 작은 매수 비중을 코드가 강제한다. 모델이 바뀌면 새 모델의 건수로 다시 센다. 설정으로 풀 수 없다 |

### 7.3 정확성

| ID | 요구사항 |
|---|---|
| ACC-1 | 화면의 금액·비중·수익률·확률·임계값은 전부 코드 계산값이다. 구조화된 AI 출력의 숫자는 값이 아니라 도구 결과 원장 참조로 받고, 원장에 없는 참조는 거부한다. 자유 서술 속 숫자는 추출해 같은 실행의 원장과 대조하고, 맞지 않으면 "검증 안 됨"을 붙인다. 웹에서 온 값은 "미검증 웹 값"으로 표시한다 ([R-12](research/R-12-ai-analysis-design.md) 2.6) |
| ACC-2 | 금액은 문자열 십진수로 다루고 부동소수점을 쓰지 않는다. DB에도 같은 정규 문자열(STRICT TEXT + CHECK + 통화 열)로 저장하고 SQL에서 금액 산술·합산·정렬을 하지 않는다. AI가 내는 확률은 1~99 정수 퍼센트이고, 기준 확률, 보정한 확률, 임계값은 십진수로 계산한다 |
| ACC-3 | 원화·달러를 섞어 합산할 때는 매매기준율(`midRate`)을 기본으로 쓰고, 쓴 환율의 종류와 시각을 함께 보여 준다 |
| ACC-4 | 모든 데이터에 수집 시각을 붙인다. 장중에 시세가 5분 넘게 오래되면 화면에 표시한다 |
| ACC-5 | AI 분석과 추정에는 출처가 하나 이상 있어야 한다. 없으면 "출처 없음"이 붙고, 출처 없는 추정은 신호를 만들지 않는다 |
| ACC-6 | 종목별·통화별 평가액은 토스 API 값과 정확히 일치해야 한다. 원화 환산 총액과 "보유 평가액 + 매수가능금액"으로 만든 총자산은 근사값이며 그렇게 표시한다. 0단계 실측 대조 항목: 토스 앱 화면이 `amount`와 `amountAfterCost` 중 무엇과 같은지, 종목 손익률의 통화 기준, 평균단가 계산 방식, 배당 금액·세금 필드, 미국 ETF 일봉 지원 (S-01, [R-11](research/R-11-portfolio-math.md) 4장) |
| ACC-7 | 수수료·세금 계산값은 "추정"으로 표시하고, 체결·결제 뒤 토스 거래내역의 `commission`·`tax`·`netAmount`로 바꾼다 ([R-11](research/R-11-portfolio-math.md) Q3) |
| ACC-8 | 1년 미만 수익률은 연율화하지 않는다. 변동성은 60거래일 미만이면, 베타는 주간 52주 미만이면 "표본 부족"으로 표시한다 ([R-11](research/R-11-portfolio-math.md) Q9) |
| ACC-9 | 추정 판정은 6.6의 규칙으로 코드가 한다. 같은 일봉·1분봉 입력에 대해 판정 결과가 항상 같아야 하고, 판정이 끝난 기록은 바뀌지 않는다. 추정 기록의 누락은 0건이어야 한다 |

| PERF-1 | 앱 시작 후 2초 안에 저장된 데이터로 주 화면을 그린다. 최신 데이터는 뒤에서 받아 갱신한다 |

### 7.5 외부 API 준수

| ID | 요구사항 |
|---|---|
| API-1 | 토스 속도 제한을 그룹별로 지킨다. 한도의 60%까지만 쓰고, 상수가 아니라 응답 머리말의 한도 값을 따른다 |

| API-3 | 토큰은 앱 전체에서 하나만 쓰고 한 곳에서만 발급한다. 만료 전 갱신 순서는 발급 → 웹소켓 닫기 → 재연결 → 구독 재선언 → 주문 재조회다. `token-revoked`를 받으면 재발급은 1회만 하고, 다시 오면 멈추고 2.6의 3번 문장을 보인다 ([R-01](research/R-01-toss-open-api.md) Q4) |
| API-4 | 뉴스 소스는 소스당 동시 1건, 최소 간격 5초로 요청한다 |
| API-5 | DART 일일 한도의 50%를 넘으면 DART 주기를 자동으로 늘린다 |
| API-6 | 소스별 요청 머리말을 따른다. Yahoo는 브라우저형 User-Agent, SEC EDGAR는 사용자 연락처가 든 User-Agent와 초당 10회 이하. 연락처가 없으면 SEC 요청은 0건이다 |
| API-7 | 토스 스펙 파일의 정규화 해시, 공식 `versions.json`, 파일 `Last-Modified`로 변경을 감지한다. 바뀌면 생성 타입 차이를 확인하기 전까지 새 응답 필드에 의존하지 않는다. 외부 열거형은 모르는 값을 담는 변형을 갖는다 (I-08) |

### 7.6 신뢰성

| ID | 요구사항 |
|---|---|
| REL-1 | 403 `ip-not-allowed`나 토큰 발급의 `access_denied`를 받으면 현재 공인 IP와 등록 위치를 2.6의 한 문장으로 보인다. 토스 403 응답에는 IP가 없으므로, 현재 공인 IP는 이 안내가 떠 있을 때만 공개 IP 확인 서비스에 물어 얻는다(5.1). IPv4·IPv6 처리는 실측 S-22. 일반 호출은 자동 재시도하지 않는다. 안내가 떠 있는 동안에만 1분에 1회 이하로 토큰 발급을 다시 시도한다 |
| REL-2 | 네트워크가 끊겨도 저장된 데이터로 조회와 채팅 기록 열람이 된다 |
| REL-3 | 앱이 꺼져 있던 동안 놓친 예약 작업은 시작할 때 한 번만 따라잡는다. 지난 브리핑을 여러 개 만들지 않는다 |
| REL-4 | AI 구독 한도 초과(4.1의 판정 기준)는 오류로 처리하지 않는다. 작업은 대기하고 `resetsAt`에 이어 간다. 사용자가 할 일이 없으므로 주 화면에는 띄우지 않고, 재개 시각은 고급 > 상태에 보인다 |
| REL-5 | 수집 소스 하나가 실패해도 나머지는 계속 돈다. 소스별 마지막 성공 시각은 고급 > 상태에 보인다 |
| REL-6 | SQLite는 하루 한 번 쓰기 연결의 온라인 백업으로 암호화 사본을 만들고, `cipher_integrity_check`·`quick_check`·해시 체인 검증을 통과한 것만 확정한다. 7일치를 보관한다. 키를 잃으면 DB와 백업 모두 복구할 수 없다 ([R-06](research/R-06-sqlite-store.md) Q7) |
| REL-7 | 앱은 메뉴 막대에 상주하고 창을 닫아도 수집·예약 작업·판정이 돈다. 앱은 한 번에 하나만 실행된다. 잠자기에서 깨면 놓친 작업을 REL-3 규칙으로 처리한다. 빠진 날의 일별 평가는 일봉과 거래내역으로 다시 계산한다 (I-09) |
| REL-8 | Claude Code 버전이 바뀌면 사전 점검을 다시 하고 통과할 때만 AI를 쓴다. 통과하지 못하면 AI 기능만 끄고 2.6의 6번처럼 고급 > 상태에 사유를 남긴다. 확인한 버전 목록을 기록한다 |

### 7.7 AI 사용량

| ID | 요구사항 |
|---|---|
| AI-1 | 채팅이 예약 작업보다 항상 먼저다. 채팅이 시작되면 진행 중인 예약 작업은 단계 경계에서 SIGINT로 멈추고 나중에 이어 간다 |
| AI-2 | 예약 작업이 쓸 수 있는 구독 한도 비율을 둔다. 기본값 70%. `rate_limit_event`의 사용률로 판단한다 |

| AI-4 | 모델을 바꿔도 대화 기록, 논거 노트, 추정 기록, 성적표는 그대로다 |

| AI-6 | 모든 추정과 작업에 실제로 답한 모델, 추론 강도, CLI 버전, 프롬프트 ID·버전·해시, 증거 묶음 ID를 기록한다 |

| `sandbox-exec` 폐기 예정 | 프로필 언어 문서가 없고 macOS 업데이트로 바뀔 수 있다 | 없어도 안전이 성립하는 추가 겹으로만 쓴다 | 대응 |
| 네이티브 창은 인증된 화면이 아님 | 같은 모양의 창은 어느 앱이든 띄울 수 있다 | 내용은 코어 계산값, Touch ID 이유 문자열에 요약을 한 번 더 | 대응 |
| SQLCipher 공급망 | 소스가 개인이 관리하는 crate에서 온다 ([R-06](research/R-06-sqlite-store.md) 4장) | 버전 고정, 업그레이드 때 해시 비교 | 대응 |
