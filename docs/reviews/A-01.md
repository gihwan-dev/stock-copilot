구현과 수정은 Codex `gpt-6.1-sol`(T3 스레드, 작업 사본 `a-01`). 리뷰어는 회차 1에 새 Claude Opus 5.5 서브에이전트. 회차 2는 메인이 수정 보고를 읽고 평가했다. 결정은 ADR 0055에 있다.

**비판 단계를 생략했다.** 리뷰어가 OpenAPI의 GET 엔드포인트 41개를 전수 대조해 지적을 냈고 메인이 전부 수정 또는 선행 작업 등록으로 판정했다.

architecture 3.3은 포트의 역할만 적고 메서드를 적지 않았다. 구현 담당이 멈췄고, 메인이 "소비자 작업과 공급자 엔드포인트를 둘 다 댈 수 있는 메서드만" 유도하도록 정했다. 리뷰를 거친 계약을 architecture 3.3에 반영했다.

## 리뷰 (회차 1)

의존 방향(`application → domain`만), 비동기 방식(반환 Future에 `Send`, `async-trait` 없음), 시그니처에 원시 타입 없음, 과거 환율, 캘린더는 확인됐다.

| 번호 | 등급 | 지적 | 평가 |
|---|---|---|---|
| 1 | 차단 | 주문 게이트(O-01)가 쓸 읽기가 없음: 매도가능수량, 미체결 주문 조회, 매수 유의사항, 종목 마스터. `quotes`·`candles`의 입력 타입은 종목 마스터에서만 만들어지는데 그 포트가 없음 | domain 타입이 먼저 필요. "정의 대기" 15행으로 계약 표에 넣고 선행 작업 D-33~D-38과 A-20을 tasks.md에 등록 |
| 2 | 차단 | `PortError` 세 변형으로는 design 2.6의 안내 문장(자격 증명, IP 미허용, 토큰 폐기)과 대기 사유(속도 제한, 점검, 네트워크)를 가를 수 없음 | 수정: 닫힌 원인, 메서드별 엔드포인트, HTTP 상태 분류, 재시도 대기 시간. R-01 오류표 전체의 대응 표 |
| 3 | 중요 | `portfolio`가 전부 아니면 전무. 달러 매수가능금액만 실패해도 보유를 잃음 | 수정: `holdings`와 `buying_power`로 분리. 조립은 A-06 |
| 4 | 중요 | `transactions`가 미지 통화 행을 버린 오류밖에 못 냄 | 수정: 완전 증거 또는 받은 행과 격리 원문을 보존한 불완전 결과 |

| 6 | 중요 | `quote`가 한 번에 한 종목 | 수정: `quotes`(1~200개, 종목별 결과) |
| 7 | 중요 | 호가와 수수료율이 표에도 제외 표에도 없음 | 정의 대기에 등록 |

| 9 | 사소 | 기능 집합이 주문 변형의 복사, 판정이 `bool` | 수정: 읽기 기능 넷만. 판정은 닫힌 열거형 |
| 10 | 사소 | `calendar`가 미지 시장을 받음, 테스트가 컴파일만 확인 | 수정: `calendar`는 정의 대기로. 계약 테스트 7개가 성공 값과 불완전 결과를 검증 |

## 메모

- 현재 정의된 메서드는 여덟 개다: `accounts`, `holdings`, `transactions`, `quotes`, `candles`, `buying_power`(`BrokerRead`), `fx_rate`, `order_fx_rates`(`MarketInfo`).
- 포트는 `dyn`을 지원하지 않는다. 조립 루트가 제네릭으로 주입한다.
- 기능 집합의 생성자는 공개다. 호출 위치 제한은 하네스 작업으로 넘겼다.
- 이 crate는 변이 대상이 아니다. 잠금 파일 변경은 규칙대로 전체 범위가 되므로 돌리지 않았다.
- 수정분은 Opus 재리뷰를 하지 않았다. 정의 대기 메서드를 더하는 A-20에서 계약 전체를 다시 리뷰한다.
