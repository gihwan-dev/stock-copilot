## 리뷰 (회차 1)

스펙에서 다시 뽑은 코드 45개는 구현과 일치했다. 지어낸 코드, 와일드카드, 서버 메시지 누출은 없었다. 손 변형 유효 26개 중 20개 검출(생존 5개는 버그 분류 안의 세부 원인 차이).

| 번호 | 등급 | 지적 | 평가 |
|---|---|---|---|
| 1 | 중요 | overview·R-01 오류표의 코드 3개 누락 | 수정: 주문 전용 묶음에 추가. 테스트가 문서 표를 직접 읽어 대조 |
| 2 | 중요 | 미지 코드가 5xx·429에서도 버그로 가고 깨진 본문은 대기로 가 일관되지 않음 | 메인 결정: 미지 코드는 HTTP 상태 기준(5xx·429는 대기, 그 밖은 버그). OAuth 일시 장애 2개는 대기 |

## 메모

- 최종: REST 조회 경계 53개(사용자 조치 5, 대기 5, 버그 40, 데이터 없음 3), OAuth 8개. 버그 40개 중 31개는 조회 응답으로 들어온 주문 전용 코드이고, 실제 주문에서의 의미는 T-15·T-16·O-19가 정한다.
- `broker-toss`가 `application`에 의존한다(architecture 3.2의 방향. 메인 승인). `serde_json`을 일반 의존으로 옮겼다(새 패키지 아님).
- 대기 시간 파싱과 백오프는 T-03, `invalid-token`의 재발급 절차는 T-02, 커서 오류의 구분은 T-06 실측.
- 회차 2의 수정분은 Opus 재리뷰를 하지 않았다. 실제 API는 호출하지 않았다.
