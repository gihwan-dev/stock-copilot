## 비판 근거와 한계

별도 비판 사본에서 `cargo test --locked -p broker-toss --test critic_t02 critic_ -- --nocapture`로 여섯 반례를 실행했다. 결함 관측값을 확인하는 단언의 6통과는 제품 수용 기준 통과가 아니다. 취소 뒤 closes=2/Connected, 동시 8대기/발급8, 최신 three 교체 뒤 오래된 two revoked/DuplicateKey, 정상 escaped token/InvalidResponse를 실제 관측했다. 생성 DTO는 같은 JSON 영문자 이스케이프를 수용했다. 세 손 변형은 모두 컴파일 후 테스트 실패로 검출했다. 원복 후 nextest 66/66과 clean HEAD를 확인했다.

타입 실험은 비공개 lease 조립을 E0423으로 거부하고, reconnect의 임시 토큰 참조를 저장하는 시도는 수명 오류로 거부했다. 실제 T-17 교착을 실행했다고 주장하지 않는다. callback 계약의 제약 C만 확정했다.

비판 사본의 check-fast는 손 변형/미추적 재현과 겹쳐 commit-guard가 거부했다. 비판자는 원복 후 check-fast와 전체 check를 실행하지 않았으며 NOT_RUN으로 보고했다. 원본 구현의 전체 훅 통과와 구분한다.

최초 Opus 세션은 T3 child였지만 Claude 훅에 agent_type/id가 전달되지 않아 main으로 분류됐고 반례 파일 수정/정리를 main-docs-only가 거부했다. 그 세션의 반례·손 변형·harness 9 전체 대조는 미완료다. 별도 Opus 사본의 미추적 재현 파일은 원본에 가져오지 않았다. 원본은 리뷰 전후 HEAD/status가 동일했다. 비판은 그 추정을 직접 재현해 검증했으며 harness RV-1~18을 대조했다.

새 Codex gpt-6.1-sol 비판은 지적마다 반박 후 실행했다. 구현 보고서·리뷰 기록·기존 target 산출물은 읽지 않았다. 지적1과3은 원복 소스 수용시험에서 실패로 재현했고,2·4·5는 각각 실제 컴파일 변이가 기존18개를 통과한 뒤 새 시험으로 검출됐다.6은401/Connected 관측만 확정하고 계약 위반은 기각했다. 비판 사본은 임시 시험 삭제와 소스 원복 뒤76개 기본 시험 및18개 토큰 시험 통과, HEAD/status 불변을 확인했다. check-fast는 pnpm 실행 파일 누락으로 종료1이며 전체/정적 검사 통과로 세지 않는다. 훅 우회와 홈 설정 변경은 하지 않았다.

구현 사본의 새6개 시험을 포함한 대조군은 수정 전21통과·3실패였다. 공유 계획 토큰 뒤 자체 발급 기회와 그 발급 후 반복 중단, 실패로 빈 캐시의 오분류를 확인했다. 요청은 공유한 새 세대의 토큰으로 재조회할 수 있지만 그 요청의 발급은1회만 한다. 자체 발급 후 실패는 현재 lease를 비교해 최신 다른 토큰을 훼손하지 않는다. 빈 캐시에는 이미 확정된 실패를 전달한다. 실제 새 토큰이 있는 기존 Superseded 회귀도 유지했다.

ScriptedHttpServer의 기존 새 응답 게이트는 보류 응답을 끝까지 직렬 대기하지 않고 별도 scoped worker로 해제한다. 이전 GET 응답을 보류한 사이 계획 발급을 완료하고, 해제 뒤 후속 응답도 제공해 경쟁 순서를 sleep 없이 고정한다. master의 단발 LocalHttpServer는 그대로다. 처음 만든 시험 도우미의 Receiver 공유 컴파일 오류를 소유권 이동으로 고쳤다. 첫 대조 실행에서 조기 종료 경로의 서버 join이 남아 본인 실행 PID 두 개만 종료했고, 발급 횟수 선행 단언을 추가한 재실행으로 위21/3을 확인했다.

2차 수정 후 broker-toss nextest는82/82(토큰24개), 건너뜀0이다. check-fast-static은 위반0으로 완료됐다. Clippy는 새 시험/게이트의 중첩과 이름 재사용, 참조 전달을 정리해 검사 끄기 없이 통과했다. 새 손 변형은 별도 복사본에서 진행하며 완료 결과를 최종 기록에 남긴다.

## 3차 리뷰·비판과 최종 수정

새 Opus5.5는 중요 추정1·사소 추정1을 보고했다. 대상d6b71004761c6a399d2b50423d63dffa5f47abbf의24개 토큰 시험 통과와 RV-1~18의 정적 대조를 마쳤다. 실험 파일 heredoc은 main-docs-only 훅에 거부돼 반례·독립 계산·타입 우회·손 변형은 NOT_RUN이다. 우회하거나 native Agent를 추가하지 않았고 T3 격리 사본 하나만 사용했다. 원본과 리뷰 사본의 HEAD/status는 불변이다. 이 제한을 검증 완료로 확대하지 않는다.

새 Codex gpt-6.1-sol 비판은 503 실패 뒤 자동 GET200과 취소 뒤 자동 token 성공을 각각 직접 재현해3-1을 확정했다. 계약 단언을 둔 두 회귀는 원본에서 모두 Disconnected/DuplicateKey 차이로 실패했다. 비판자의 임시 가드 적용은 기존24개와 새계약2개·관측1개를 모두 통과했고, 실패 가드와 취소 가드를 각각 제거한 컴파일 변형은 대응 회귀가 잡았다. 이27개 실행의 제외2개는 결함 관측 전용 새 시험이며 기존24개는 모두 선택됐다. 공개 TokenLease 직접 조립은 E0423으로 거부됐고, 원복 뒤24개와 lib Clippy가 통과했다. 비판의 전체 check/check-fast·자동변이·실제UI/WS는 NOT_RUN이다.

3-2는 순차3요청에 발급6·조회6·갱신 콜백6·이벤트6을 관측했다. 각각 실제 Connected/Disconnected 전이이므로 같은 상태의 중복 이벤트가 아니며 요청 자체 재발급1회 계약을 지킨다. 실제 화면과 웹소켓은 조립하지 않아 깜빡임·부하를 확정하지 않는다. 확정되지 않은 요청 간 누적 제한은 추가하지 않고 T-05/T-16/J-01의 닫힌 인증 오류 재시도 조립에 인계한다.

비판자는 소스와 임시 시험 두 파일을 원복·삭제했고 HEAD/index/worktree가 불변인 것을 확인했다. 본인이 만든 ignored 빌드 디렉터리 target/review-critic-fresh 삭제는 도구 정책의 rm-f 계열 거부로 남았다. 다른 삭제 수단으로 우회하거나 구현 사본에서 대신 삭제하지 않았다. 소스 오염과 구분해 산출물 정리 한계로 기록한다.

구현 사본도 새 실패/취소 두 시험에서 수정 전24통과·2실패를 확인했다. 메인의 재개 결정에 따라 이3차 뒤 수정은4차 없이 범위·회귀·손 변형을 기록해 메인 평가 대상으로 완료 보고한다. 최종 수정분을 새 Opus가 재승인한 것으로 표현하지 않는다. 최종 병합 및 검사 결과는 정상 커밋 훅 로그와 최종 보고에서 구분한다.

최종 손 변형의 첫 실행에서는 발급 예산 소진 누락과 발급/공유 오분류2개가26개 시험 중 새 취소 회귀의 대기에서 시간 초과했다. 취소 회귀의 최초 조회에5초 유한 종료 단언을 더한 재실행은 예산 누락을 검출했으나, 발급/공유 오분류는 이전 invalid-token 재조회 회귀의 후속 조회 대기에서 다시 시간 초과했다. 그 조회에도5초 유한 종료 단언을 추가했다. 두 시도의 시간 초과는 검출로 세지 않고 target/T-02/manual-r3-attempt1과 manual-r3-attempt2에 따로 보존했다. 제품 코드는 바꾸지 않았으며 기존 단언을 유지하고 유한 종료 단언만 강화했다. 최종 전체 변형 재실행 결과는 ADR 마지막 표에 기록한다.
