1차 리뷰어는 네 손 변형을 함께 적용해 lib 19개·bin 2개의 생존을 보고했다. 빈 dist를 사용했고 일부 훅 거부 뒤 다른 준비 경로를 사용했다고 밝혔으므로 그 실행을 제품 빌드 증거로 취급하지 않는다. 비판자는 실제 frontend-build를 실행했고, 원본 lib 19개·bin 2개 및 저장소·시계·구조 검사를 통과시켰다. 네 변형은 각각 분리한 lib 19개 실행으로 생존을 재현했다. 변형 상태의 bin 실행과 실제 macOS 종료 조작은 독립 확인하지 않았다. 검사 우회는 검사 함수 실행과 실제 어댑터 타입에 대한 rustc metadata 컴파일로 확정했다.

1차 수정 중 자체 추가 반례로 모듈별 같은 별칭의 덮어쓰기도 확인했다. 원본 수정본은 해당 고정 자료에서 실패했고, 가능한 별칭 경로를 모두 보존한 뒤 통과했다. 새 반례를 포함한 16개 자료를 유지한다. 이 추가 검사는 독립 리뷰 회차로 세지 않는다.

2차 리뷰어는 훅 거부 뒤 컴파일 탐침과 손 변형을 재시도하지 않았고 composition 2개·종료 관련 lib 8개만 실행했다. 우회 지적은 추정으로 보고했다. 새 비판자는 훅 거부 없이 실제 컴파일·검사와 순서 반전 변형을 수행해 2-1과 2-4를 확정했다. 다른 네 지적의 기각을 뒤집지 않았다. 비판자의 초기 위치 검색이 제외된 ADR 절의 한 줄을 출력한 사실은 기록하되, 해당 절 본문과 구현자 보고서는 읽지 않았고 판정 근거는 실제 소스·실행이다. 실제 macOS 종료·화면 렌더링은 양쪽 모두 미검증이다.

3차 리뷰어의 우회 두 건도 훅 거부 때문에 정적 추정으로 보고됐다. 사본의 commit 시도와 환경 설정·상대 쓰기 거부를 기록했으며 실제 커밋은 만들지 않았고 원본은 깨끗했다. 이를 실행 증거로 사용하지 않는다. 새 비판자는 허용된 mktemp 사본에서 두 반례의 컴파일·Clippy·arch-check·source-check 통과와 관련 테스트를 직접 확인했다. 종료 변형의 컴파일 불가·helper 내부 검출·실제 호출부 생존을 구분했다. 추가 확정 지적은 없고 현재 제품 종료 순서 결함은 발견하지 못했다.

## 검사 중 절차 오류와 재검증

3차 수정의 첫 정상 훅은 테스트 전 source-check가 테스트 전용 함수를 테스트 모듈 밖에 둔 오류를 검출했다. 함수를 테스트 모듈로 옮기고 source-check와 좁은 회귀·Clippy를 통과시킨 뒤 정상 훅을 다시 실행한다. 이 실패를 test-diff 예외로 취급하지 않는다. 같은 수정 범위의 자체 추가 반례인 crate::부모모듈::별칭 경로도 실패·수정·변형 검출을 확인했다.

정상 재실행은 전체 1580개·커버리지 1059개가 통과했고 승인 test-diff 2건만 남았다. 별도 게이트와 뒤 단계 검사를 확인한 뒤 432c63a를 만들었다. 이후 master 병합 중 반복되는 모듈 이름의 경로도 검사하도록 순환 추적 순서를 보완한다. 자체 고정 자료에서 누락을 먼저 재현했으며, 이 추가 변경까지 최종 병합 훅의 전체 검사 대상이다. 최종 수정 전체 범위는 a400884부터 완료 보고의 최종 SHA까지이며 4차 리뷰는 없다.

추가 별칭 방어를 반영한 정상 훅 실행은 전체 테스트 중 git_hooks::tests::commit_guard_refuses_unstaged_and_untracked_changes의 staged change 단언에서 실패했다(1387/1579 실행, 1386 통과·1 실패·192 미실행). 이 실패가 승인 test-diff 예외가 아님을 확인하기 전에 예외 커밋 명령을 함께 실행한 절차 오류가 있었다. 해당 커밋은 검사 통과 증거로 인정하지 않는다. 원본 테스트를 변경하지 않고 좁은 재현을 실행했으며 단독 실행은 통과했다. 실패 원인은 확정하지 않았다. 이후 정상 amend 훅에서 전체 1579개·커버리지 1059개 통과와 승인 test-diff 2건만 남음을 출력과 별도 게이트로 확인했다. 뒤 단계 세 검사도 통과한 뒤 해당 예외로 amend해 잘못 만든 커밋을 48ba8ec로 교체했다.

## 메인 지시 S-15 통합

기준은 U-01 완료 6ce54d1d75a5f6db5438412908aa261eba138d74, 수신 master는 730e4069f9327da8e7884c845069130d542066f7이다. 지정한 S-15 병합 제목을 약 39분 대기 후 확인했고 --no-ff로 받았다. 추가 리뷰 회차는 없으며 메인이 통합 diff를 평가한다.

store-sqlite의 lib.rs는 S-15의 Clock 주입 open과 async close를 채택했다. U-01의 별도 DB/Writer shutdown과 DatabaseClosed를 지웠다. tests.rs는 S-15 테스트와 시계 준비를 모두 보존하고 U-01 종료 회귀를 close로 옮겼다. 기존 단언은 유지한다. lifecycle은 S-15 close를 직접 await하고 Closed(WriteCompleted) 결과를 보존한다. main은 같은 SystemClock Arc를 Clock 포트와 DB 팩터리에 조립하며, T-03의 HTTP 클라이언트 인자와 개발 의존을 유지했다.

S-15의 앱 종료 소유권 인계는 완료다. 실제 UI 종료 실측·사이드카 경합·동시 열기 및 재시도는 잔여다. 전체 검사와 승인 test-diff의 최종 건수·정확한 이름은 target/U-01/s15-integration-report.md와 s15-full-check.log에 기록한다.
