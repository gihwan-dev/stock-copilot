## 메인 평가

- 판정: 수용. D-52 포트(`resolve`·`lookup`·`for_id`·`ensure`·`retire`)와 발급원 포트를 SQLite로 구현했다. 발급·폐지·대응 등록은 `BEGIN IMMEDIATE` 한 트랜잭션에서 원자적이고(두 연결 경쟁 테스트), 열 때 정확 중복·원본 겹침·다른 원본이 같은 ID를 쓰는 행·변조된 트리거·깨진 발급 순번을 거부해 열기에 실패한다. 가짜 구현이 통과하는 계약 테스트를 SQLite 구현도 그대로 통과한다.
- 등급 3을 3회차까지 돌렸고, D-55가 포트 서명을 바꾼 뒤 맞춤분을 한 번 더 리뷰했다(중요 4건 수정: D-55의 봉인을 우회하던 복원 생성자 제거, 같은 순번을 두 번 내던 분리 발급원 제거 등). 변경분 변이 79개 중 놓침 0(51 검출, 28 컴파일 불가).
- 기존 테스트 변경 2건(마이그레이션 원장 수 7 → 8, 스키마 객체 수 42 → 55)은 메인이 차이를 읽고 `harness/test-diff/approvals.toml`에 승인 행으로 올렸다(각 한 줄, 단언 삭제 없음). 지적 대상이 아닌 준비 상수 2줄(다음 마이그레이션 번호 8 → 9)도 같은 성격이다.
- 정의 대기 5건에 대한 메인 결정: (1) 같은 내부 ID의 복수 원본·이력·정정 영속은 S-24에서 정한다(이 작업의 1:1 원장은 그대로 두고 고아 `superseded` 행은 거부). (2) 기존 테이블의 내부 ID 편입은 점진 전환(B): 이번에는 기존 테이블과 자료를 건드리지 않는다. (3) 종목 마스터 조회는 DB 잠금 밖에서 하고 결과를 확정할 때만 짧은 쓰기 트랜잭션을 연다(A). (4) 마스터 응답 불일치는 그 종목의 거래만 막고, DB 무결성 오류는 앱 전체를 멈추고 복구 안내를 보인다(C). (5) 연결 경쟁 대기는 지금의 5초를 유지한다(A).
