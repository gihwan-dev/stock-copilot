구현과 수정은 Codex `gpt-6.1-sol`(T3 스레드, 작업 사본 `d-32`). 리뷰어는 회차 1에 새 Claude Opus 5.5 서브에이전트. 회차 2는 메인이 수정 보고와 검증 결과를 읽고 평가했다. 결정은 ADR 0045에 있다. D-06, D-21, D-23, D-28, DS-10과 병렬로 진행했다.

**비판 단계를 생략했다.** 리뷰어가 지적을 외부 crate 코드로 재현했고 메인이 전부 수정으로 판정했다.

구현 전에 메인이 범위를 정했다. `ExecutionToken`에는 종목명, 계좌 뒤 4자리, 예상 수수료가 없다. `Proposal`을 넓히지 않고, 요약 생성 때 토큰과 봉인된 표시 사실을 함께 받아 같은 대상인지 검사한다. 수수료 "알 수 없음"은 0원이 아니다.

## 리뷰 (회차 1)

요약의 열 필드는 architecture 4.4 순서 5와 이름·순서까지 같았다. 여섯 주문 변형의 값이 토큰과 일치했고, 고액 판정은 독립 계산 3,004건과 불일치 0건, 판정 불가(환율 없음, 방향 뒤집힘, 시각 부적합, 넘침)는 모두 `Required`였다. 손 변형 15개 중 12개 검출.

| 번호 | 등급 | 지적 | 평가 |
|---|---|---|---|
| 1 | 중요 | 요약이 어떤 토큰에서 나왔는지 묶여 있지 않고 `Clone`. 토큰 A의 요약을 보여 주고 토큰 B를 보낼 수 있음 | 수정: 토큰을 소비해 토큰과 요약을 묶는 `PendingOrderConfirmation`. 요약은 참조로만 읽고 토큰은 crate 안에서만 꺼냄 |
| 2 | 중요 | 표시 사실과 환율을 호출자가 임의로 만들 수 있음. 환율 1로 100만 달러 주문이 `NotRequired` | 수정: 환율 500~5,000원 범위와 두 환율의 괴리 1.2배 이내를 검사, 벗어나면 `Required`. 계좌 표시는 조회 결과 한 건에서만. 생성 함수 호출 위치 제한은 하네스 작업으로 넘김 |
| 3 | 중요 | 시장 필드를 국내로 고정한 변이가 생존 | 수정: 여섯 변형의 독립 기대값 표 테스트 |
| 4 | 중요 | 시장가 주문의 수량을 지운 변이가 생존. 같은 요약의 접근자끼리 비교하는 단언 | 수정: 같은 표 테스트에 포함, 동어반복 단언 제거 |
| 5 | 사소 | 79,999,999.99원이 `NotRequired` | 수정: 원 단위 올림과 같은 비교로 `Required` |
| 6 | 사소 | 종목 표시 이름이 양방향 제어 문자와 폭 없는 문자를 통과 | 수정: 형식 문자, 방향 제어, 폭 없는 문자, 줄 바꿈 거부 |
| 7 | 사소 | 시장가 추정 금액에 여유 없음 | ADR 미해결에 기록 |
| 8 | 사소 | ADR이 소비자를 A-17로 적음 | 수정: O-03, O-04, O-07, O-09, O-17, O-18 |

## 메모

- domain은 IO 사실을 인증할 수 없다. 종목명·계좌 표시·환율 사실의 생성 함수는 broker 어댑터만 불러야 하고, 지금은 강제되지 않는다. 하네스 구조 검사가 필요하다.
- 사용자 확인이 필요한 초안: 환율 범위 500~5,000원과 괴리 한도 1.2배.
- 토큰을 묶음에서 꺼내는 경로는 O-03의 승인 증거가 붙을 자리다. 수수료 "확인됨"을 만드는 경로는 D-22가 정한다.
- `OrderIntent`와 `ExecutionToken`의 Debug는 계좌 키 전체를 출력한다. 요약과 표시 사실은 출력하지 않는다.
- 구현 담당이 ADR 초안을 두 개 만들었다. 병합 때 하나로 합쳤다.
- 회차 2는 변이 검사 범위를 고치는 중(H-42)이라 변이 검사를 돌리지 않고 손 변형 19개가 모두 검출됨을 확인했다. 외부 crate 실험 11건이 모두 컴파일 거부됐다. 수정분은 Opus 재리뷰를 하지 않았다.
