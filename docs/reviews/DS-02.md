## 리뷰 (회차 1)

`className` 안의 클래스 문자열 검사는 견고했다(ADR 0026 표의 모든 형태, 변수·템플릿·스프레드·임의 변형, 끄기 주석이 모두 잡힘).

| 번호 | 등급 | 지적 | 평가 |
|---|---|---|---|
| 1 | 차단 | ref 콜백으로 DOM을 직접 꾸밈(`el.style.setProperty`, `classList.add`). `shared/ds`에서 DOM 금지 규칙이 꺼져 있었음 | 수정 |
| 2 | 중요 | `shared/lib`에 JSX를 두고 DS가 렌더하면 DS 규칙 전체를 피함 | 수정: `shared/ds` 밖 shared에서 JSX와 요소 팩터리 금지 |
| 3 | 중요 | `createElement("div", {className: …})`와 계산 키가 검사를 받지 않음 | 수정 |
| 4 | 중요 | 색·길이 리터럴 검사가 좁아 SVG 표현 속성이 열려 있음 | 수정: 표현 속성 금지, 리터럴 검사 확장 |
| 5 | 중요 | 스냅샷이 `@media`·`@container` 안의 선택자를 빠뜨림 | 수정: PostCSS로 수집, 후보별 생성 여부 고정 |
| 6~11 | 사소 | `min-w-0`, 크기 토큰의 축, 스프레드 대조군, CSS 검사, 빈 허용 파일 목록 | 수정. stylelint를 빼고 로컬 검사로 대체(잠금 파일 112개 패키지 감소) |

## 메인 결정

- 기존 테스트 변경을 승인했다. `apps/desktop/tests/eslint-config.test.mjs`: 끌 수 없는 규칙 목록에 새 규칙 추가, 브라우저 전역 허용 대상에서 `shared/ds`를 뺌(금지 범위 강화). `harness/eslint-violations/cases.json`: 기존 예제의 기대 오류에 새 규칙 추가, 대조군 추가. 약해진 단언은 없다.
- `shared/ds`의 JSX 스프레드를 다시 금지했다. 스프레드로 `className`·`style`이 들어오기 때문이다. 이전에 `shared/**`에서 스프레드를 허용한 결정을 `shared/ds`에 한해 뒤집었다.
- DOM 접근 허용 파일은 `src/shared/platform/index.ts` 하나다(부팅 루트 조회). 아이콘 기하 허용 파일과 가격색·인라인 스타일 허용 파일은 비어 있다.

## 메모

- `features`·`app`의 화면 코드에는 이 규칙들이 적용되지 않는다. DS-09의 범위다.
- 대문자 컴포넌트·차트의 숫자 props는 DS-10·DS-06, 최소 크기와 넘침은 DS-11·DS-19의 범위다.
- 회차 3 수정분은 Opus 재리뷰를 하지 않았다.
- 병합 뒤 `master` 8856641의 macOS CI가 DS-02 실행 테스트 두 개에서 실패했다(Linux 작업은 이 테스트를 돌리지 않는다). 원인: `CI=true`이면 typescript-eslint가 같은 파일의 반복 린트를 자동 수정 과정으로 보고 격리 프로그램으로 바꾼다. 그 프로그램은 다른 모듈을 읽지 않아 React의 export가 사라지고 TypeScript가 오류 메시지를 만들다 죽는다. 수정(a291516): 자동 단일 실행 판정을 끄고, 임시 프로젝트를 OS 임시 폴더에 테스트마다 따로 만든다. 기존 테스트 두 개는 import만 바뀌었다. `CI=true`에서 반복 린트를 돌리는 회귀 테스트를 더했다. 깨끗한 clone에서 `CI=true just check` 전체 통과를 확인했다.
