# A-21 읽기 포트 3 리뷰 기록

## 브리프

A-21은 D-41의 투자자별 랭킹·섹터 목록/상세/랭킹·관련 ETF 조회를 MarketInfo에 추가한다. D-37/D-41 봉인 타입과 A-01/A-20의 Send Future·오류·capability 관례를 유지한다. 프로그램·공매도·신용·대차 수급은 정의 대기다. domain 계산/타입·testkit·tasks·progress는 변경하지 않는다. 기존 FakeBroker에 필수 메서드를 더하는 기계적 impl 변경만 사전 승인됐다. ADR은 무번호 초안이다. 실제 API·키·계좌 사용, push·PR·master 이동은 금지다.

## 비판과 실험 근거

- Opus는 application 테스트 79개 통과 및 OpenAPI 대조를 실행했다. 별도 target·복사 실험은 해당 세션 하네스의 environment/dynamic-target/git-alias 거절로 실행하지 못했다. 이를 우회하지 않았고 손 변형/타입 우회 검증 완료로 주장하지 않았다.
- Codex 비판은 별도 복사본에서 ADR 행 삭제와 입력 변경이 계약 테스트를 통과함을 확인한 뒤, 현재 29행과 실제 trait 29개 입출력이 일치함도 별도 대조했다. 직접 ADR을 읽어야 한다는 주장은 규칙에 반하므로 기각했다.
- SectorId는 ../accounts, 쿼리/fragment 문자, 41·64바이트 문자열을 실제로 허용했다. HTTP 구현은 이번 diff에 없어 경로 조작 발생은 확정하지 않았다.
- 기존 SectorRankingItem::sector, SectorCatalog::sectors, SectorMetadata::id/depth로 계층을 결합하는 외부 호출자 코드를 컴파일했다. 새 domain 타입은 필요하지 않았다.
- query 구조체 리터럴은 E0451, Default는 E0599, 필드 직접 변경은 E0616으로 거부됐고 정상 생성자는 컴파일됐다.
- 가짜 상세 시장 KR 고정은 기존 A-21 예제를 통과했다. query 시장 KR 고정은 두 테스트에서 실패했고 Unknown 종류 허용도 조합 테스트에서 실패했다. 원본 복구 후 통과했다.
- 비판자도 application 79개 통과를 확인했고 원본 HEAD/status를 보존했다. 실험 복사본은 제거했다. 전체 just check와 실제 API는 비판 범위에서 실행하지 않았다.

## 회차 2 독립 실행과 평가

새 Opus 5.5는 대상 94a1440에서 application 80개 통과, query 직접 생성 E0451, 원시 문자열/정수 입력 E0308, dyn 포트 E0038과 새 다섯 Future의 제네릭 Send 컴파일 성공을 확인했다. 실제 API는 사용하지 않았다. 별도 target/복사 실험은 해당 세션 하네스가 거절했고 우회하지 않았다. check-fast는 다른 전체 검사와 동시에 실행되던 중 10분 제한·종료 143으로 끊겨 통과 증거에서 제외한다. 전후 HEAD/status와 원본 파일을 보존했다.

새 Codex 비판자는 집중 테스트 21개 통과와 ready의 정상/Rc 대조군, 다섯 제네릭 Future Send 컴파일, query 직접 생성 거부를 실행했다. Send 지적은 기각했고, 기존 문서 정리는 메인 채택 인계로, 승인 선행 로그 확인은 불확실로 구분했다. 추가 제품 결함은 없었다. 비판자는 구현자 target/보고서/리뷰 기록을 읽지 않고 전체 검사를 반복하지 않았다. xtask test-diff-selected의 내부 nextest list가 지정 target을 전달하지 않아 자신의 기본 target에도 빌드된 격리 이탈을 보고했다. 이 실행을 격리 유지 증거로 사용하지 않는다. 소스/테스트/문서·HEAD/status는 보존됐다.

Opus 두 회차의 도구 executedModel은 claude-opus-5-5로 확인됐다. Codex 두 회차는 gpt-6.1-sol 지정과 도구 model이 일치하며, 별도 executedModel 필드는 제공되지 않았다. 각 비판자의 실행 결과와 구현 담당의 실제 훅 로그를 별도 증거로 취급한다. 비판자의 기각을 뒤집은 항목은 없다.

선행 조건을 재확인한 실제 로그는 target/A-21/commit2.log(1396/1047, coverage 통과, 승인 test-diff 1), post-checks.log(후속 통과), review-commit.log(1397/1048, coverage 통과, 동일 승인 1), review-post-checks.log(후속 통과)다. 두 정상 훅은 test-diff에 도달하기 전 모든 검사를 통과했다. 전체 명령의 종료 자체는 해당 한 건으로 비정상이었음을 유지한다. 두 커밋 메시지에도 해당 커밋 한정 LEFTHOOK=0 사유가 있다. 원시 로그는 별도 증거이며 비판자에게 제시되지 않았다는 한계를 지우지 않는다.

## 구현 검사와 승인된 변경

- 시작 기준 master는 735ea38189edbf15d34238dd14ac49bb02c9e94f다. pnpm frozen/ignore-scripts 설치와 lefthook install을 실행했다. 프로젝트 파일 hooks=true는 확인했으나 프로젝트 신뢰·세션 훅 실제 적용은 별도 확인 불가다. 홈 설정/자격 증명은 읽거나 변경하지 않았다.
- 첫 정상 훅은 matches! 금지를 발견했다. 규칙을 끄지 않고 소진 match로 고쳤다. 좁은 Clippy도 통과했다.
- 구현 커밋의 정상 훅은 전체 검사로 승격되어 workspace 1396개와 coverage 1047개를 통과했고 coverage-check 위반은 없었다. 이후 test-diff가 승인된 FakeBroker MarketInfo impl 추가 한 건만 지적했다. 후속 disable-report, 새 끄기 0, hooks-installed도 별도로 통과했다. 사용자 지시에 따라 이 커밋만 LEFTHOOK=0으로 만들고 사유를 메시지에 기록했다. 전체 just check 명령 자체의 종료는 해당 승인 항목으로 비정상이며 무조건 통과라고 보고하지 않는다.
- 승인 test-diff: crates/application/tests/ports.rs의 FakeBroker MarketInfo impl에 필수 5개 메서드 추가. 기존 master 테스트 함수 16개 본문 및 단언은 동일하다. 이번 브랜치의 새 테스트는 보강할 수 있다.
- 보호 생성물: .codex/config.toml은 새 ADR 읽기 전용 경로 등록, harness/claude-hooks/hashes.json은 해당 생성 설정 해시 갱신이다. 저장소 스크립트로 생성했다. 규칙/범위를 느슨하게 하지 않았다. 외부 의존성 추가와 검사 끄기는 없다.
- just mutants-diff를 기준 SHA로 한 번 실행했다. 선행 test-diff의 동일 승인 1건으로 종료되어 자동 변이는 NOT_RUN이다. 0개 검출이나 변이 통과로 세지 않는다.
- 최종 소스의 손 변형은 별도 빌드 디렉터리와 임시 복사본에서 27개 모두 실제 컴파일 성공 후 검출했다. 매 로그의 재컴파일, 원본 clean/recompile 기준 통과와 임시 소스 제거를 확인했다. 앞선 공유 빌드 디렉터리 실험은 최종 집계에서 제외한다. 변형별 표는 ADR 끝에 있다. 증거는 작업 사본 target/A-21/final-hand-NN.log, final-hand-results.json, isolated-baseline.log다.

## 최신 master 통합과 최종 검사 대상

받는 master는 e2b940598678ecc91d49267a3d4c02ccef4c819c(H-47)다. git merge --no-ff --no-edit master를 실행했고 생성 설정·해시 두 파일만 충돌했다. master 쪽 생성물을 바탕으로 config → sandbox fragment → hashes 공식 스크립트로 다시 만들었다. 병합으로 받은 하네스·문서·테스트 변경은 H-47 소유이며 A-21이 수정하거나 약화하지 않았다. A-21 제품 소스는 재리뷰 대상 94a1440과 동일하다. 이 기록과 ADR의 메인 인계만 최종 병합 트리에 더했다. 최종 검사 로그는 target/A-21/final-merge-commit.log와 후속 검사 로그로 보존하고, 실제 최종 SHA/종료 결과는 최종 보고에서 명시한다.

## 메인 인계

A-21 초안을 채택·번호 부여할 때 architecture 3.3의 포트 역할/메서드와 ADR 0082의 정의 대기 투자자·섹터·ETF 행을 갱신한다. 이는 ADR 0082가 메인에 남긴 기존 인계다. 프로그램·공매도·신용·대차 선행 domain 작업 ID는 메인이 등록한다. A-04는 가짜 구현, T-09/T-10은 HTTP·식별·완전성/계층·ID 검증, A-09/G-07/M-04는 표시/후보 선택, A-15/E-08은 기존 벤치마크 경로를 이어 받는다.

## 최종 병합 검사 중 비재현 실패

첫 최종 정상 훅은 workspace 1408개 중 1208개를 실행하여 1207개 통과·1개 실패, 200개 미실행으로 종료됐다. 실패는 H-47에서 받은 기존 xtask git_hooks::tests::commit_hook_runs_the_check_and_rejects_violating_commits의 clean commit is accepted 단언이다. 승인된 test-diff 예외에 포함하지 않았고 훅을 생략해 병합하지 않았다. 당시 fixture hook.log는 fresh-build와 commit-guard까지만 남아 있었다.

같은 소스에서 해당 테스트만 nextest로 실행하니 1개 통과했고(hook-repro.log), 남아 있던 실패 fixture의 정상 커밋을 그대로 재실행해도 commit-guard와 check가 모두 통과했다(hook-fixture-replay.log). 원인은 확정하지 못했다. 관련 xtask 테스트 소스는 incoming master와 동일하며 검사/단언/동시성 설정을 변경하지 않았다. 첫 전체 실패 로그 final-merge-commit.log를 보존하고 동일한 최종 트리를 정상 훅으로 다시 검사한다(final-merge-retry.log). 단독 통과를 전체 검사 통과로 대신하지 않는다.
