1차 리뷰는 쓰기 훅의 role-without-edits 거부, 2차 리뷰는 dynamic-target 거부로 새 반례·손 변형을 실행하지 못했다. 두 리뷰 모두 기존 계약 테스트 6개를 실행했다. 비판자는 제품을 수정하지 않은 외부 소비자에서 반례를 실행했으며 훅 거부가 관측되지 않았다. 1차 리뷰는 일부 필수 문서를 읽지 못했다고 보고했고, 2차 리뷰와 두 비판은 필수 문서를 읽었다.

1차 비판은 341개 요청 묶음을 독립 집합 모형과 대조하고 봉인 ID 직접 생성·소비 상태 변경의 컴파일 거부를 확인했다. 2차 비판은 기간 불일치 기록 생성, 신호의 HorizonMismatch, 과제 기간 FewDays의 판정 사실, 잘못된 기간 표의 MismatchedCombination을 구분해 실행했다. 증거 묶음의 직접 대입은 E0308이지만 as_estimate_id 경로로 조회·발급할 수 있음도 확인했다. 영구 저장·동시성·UI·실제 모델 연결은 실행하지 않았다.

초기 구현은 테스트 우선 작성 순서를 지키지 못했다. 두 수정은 해시 정규화와 기간 불일치에 대해 수정 전 실패를 실행하고 수정 후 통과를 확인했다. 기간 검사는 기본 설정의 기간 3종과 키 기간 4종의 12개 조합을 대조한다. 증거 묶음 파서는 빈 값·65바이트·공백·비ASCII·개행을 거부하고 1·64바이트 및 독립 값을 보존한다.

초기 커밋과 첫 수정 커밋의 정상 훅은 Xcode 라이선스 R4 테스트 1건만 실패했다. 출력에 You have not agreed to the Xcode license가 있고 각각 Codex 훅 테스트 61개 중 60개가 통과했다. 지시문의 환경 예외에 따라 check-ts의 남은 단계와 check 본문의 fmt·clippy·deny·arch-check·source-check·sql-check·sqlcipher·migration-check·capability-check·generated-files·gen-schema·raw-types·disable-check·nextest·coverage-check·test-diff·disable-report·hooks-installed를 직접 실행했다. 초기 측정의 테스트 전용 파일 배치로 생긴 미측정 커버리지는 소스 모듈 안 cfg(test)로 옮겨 해결했고, 중첩 린트는 보조 함수로 해결했다. 다른 실패를 남겨 두고 예외 커밋하지 않았다. 각 커밋 메시지에 사유를 남겼다.

첫 수정 커밋 검증: 전체 nextest 1836개, 커버리지 1081개 통과. 변경분 변이는 44개 중 검출 19·컴파일 불가 25·생존 0·시간 초과 0이다. 기간·묶음 경계 수정은 새 계약 테스트 8개와 clippy·source-check·raw-types가 통과했다. 손 변형 28개 중 컴파일 성공 26개가 모두 검출됐고, 컴파일 불가 2개는 집계에서 제외했다. 변형별 표는 ADR에 있다.

master f4b7e4ff0d048a049f3b52f512c0e64e1ed5a042를 --no-ff 병합 중이다. config와 hashes 충돌은 한쪽을 선택한 뒤 공식 생성 스크립트 세 개를 순서대로 실행해 해결했다. application·tasks·progress 및 다른 작업의 테스트 변경은 이 master에서 받은 것이며 D-47이 직접 편집하지 않았다. D-47 자체 변경 범위는 domain의 두 새 모듈·lib.rs 등록·ADR·이 리뷰 기록과 필요한 생성물이다.

병합된 기간·묶음 수정의 검사: 전체 nextest 1893개 통과(건너뜀 0), 커버리지용 1088개 통과와 coverage-check 위반 없음. 정상 커밋 훅은 같은 R4 환경 테스트 1건만 실패했다. check-ts의 나머지 단계와 check 본문을 실행했다. 수동 test-diff의 기본 ancestor 문맥은 아직 HEAD에 없는 병합 부모 f4b7e4ff를 거부했다. 정상 commit-check가 사용하는 STOCK_COPILOT_BASE_USE=commit 문맥으로 남은 test-diff·disable-report·hooks-installed를 실행해 통과했다. 이 공식 문맥은 실제 MERGE_HEAD가 정확한 로컬 master 끝인지 검사하며 조상 검사를 임의로 해제하지 않는다. 설정이나 하네스 규칙을 바꾸지 않았다. 새 검사 끄기와 승인 test-diff 예외는 0건이다.


3차 리뷰와 비판 모두 첫 diff 출력에서 ADR의 검증·손 변형 절이 노출됐다고 보고했다. 이후 해당 결과를 판단 근거로 사용하지 않았다고 보고했으나 노출 자체는 독립성의 한계로 남긴다. 이전 리뷰 기록은 읽지 않았다. 비판자는 실제 신호 거부, 모의 비교 교체 한 번 성공, application 구체 타입 결합, 봉인 ID 생성 거부를 실행했다. News·Disclosure false 변형 두 개는 기존 8개 테스트에서 실제 생존했고 3차 후 테스트 보강 대상으로 확정했다.

## 보호 파일 승인과 환경 예외 종료

3차 비판의 보호 정책 차단은 무서명이라는 사실과 사용자의 사전 승인을 분리해 평가했다. 원문 full-D-47.txt는 "보호 파일: 이 작업의 완료 기준을 채우는 데 꼭 필요한 보호 파일 변경 ... 생성물·스냅샷·해시는 승인된 것으로 보고 진행"하도록 했고, "작업 절의 구체적인 승인이 공통 규칙의 일반 문장보다 우선"한다고 명시했다. 구현 지침도 해당 생성물을 공식 스크립트로 재생성하도록 한다. 따라서 일반 AGENTS.md의 서명 문장만 적용한 차단 판정은 이 작업의 직접 승인을 반영하지 못했다. 이 사전 승인 문장이 위임 브리프에 빠져 있었다. 이 기록은 서명 검증 성공을 주장하지 않는다.
