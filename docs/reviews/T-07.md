## 환경 예외와 검사 증거

초기 정상 커밋 훅은 harness/codex-hooks/tests/session-r1.test.mjs의 R4 git environment cannot redirect session identity and R6 worktree hook tampering is ignored 한 건만 실패했다.61개 중60통과/1실패이며 You have not agreed to the Xcode license 문구가 있다. 지시문의 환경 예외 조건대로 남은 check-ts와 check 본문 전부를 차례로 실행했고1815개·커버리지1069개, coverage-check/test-diff·나머지 검사가 모두 통과했다. 그 뒤 해당 커밋에 한해 LEFTHOOK=0으로 만들고 메시지에 사유를 기록했다. 원래 check-fast 명령 자체가 종료0이었다고 보고하지 않는다.

증거는 target/T-07/implementation-commit.log, implementation-remaining-checks.log, remaining-checks.sh다. 부모의 초기 손 변형 집계는 initial-mutation-results.json에 보존한다. 수정본34개 집계와 개별 로그는 mutation-results.json, mutation-01.log~mutation-34.log 및 기준/복구 로그다. 초기 일괄 실행의 가짜 서버 대기·시간 초과를 검출로 세지 않고 변형별 관련 시험으로 별도 재실행한 결과다. 수정 소스의 변형 결과와 합산하지 않는다.

1차 수정의 두 회귀 red는 target/T-07/review1-red.log, 수정 후 계약과 Clippy는 review1-green.log/review1-clippy.log다. 이후 커밋과 최종 병합의 검사·변이 결과는 실행한 뒤 추가한다.

1차 수정의 정상 커밋 훅도 동일한 Xcode R4 한 건만 실패했다.61개 중60통과/1실패와 라이선스 문구를 확인했다. 남은 check-ts와 check 본문 전부를 다시 차례로 실행하여1826/1826, 커버리지1069/1069, coverage-check/test-diff·그 뒤 모든 검사가 통과했다. 증거는 target/T-07/review1-commit.log와 review1-remaining-checks.log다. 이 조건을 확인한 수정 커밋 한 건에만 환경 예외를 사용하며 원래 정상 훅의 종료1을 숨기지 않는다.

## 2차 리뷰·비판 증거

Opus는 기존 broker-toss 172개와 Clippy를 실행했다. role-without-edits/inline-code 거부로 새 재현·손 변형은 실행하지 못했으며 정적 대조로만 지적했다. Codex는 격리 사본 target의 경로 의존 패키지에서 새 반례 3개와 기존 회귀 4개를 선택 실행했다. 7개 통과·28개 필터 제외이며 전체 기존 시험·전체 검사를 반복한 결과로 세지 않는다. 창 안 두 봉 성공, 창 밖 한 봉 추가 시 Unsupported, 그 날짜 세션까지 주입 시 성공의 세 대조군으로 2-1을 확정했다. 역사 상하한 주입 여부 대조로 합성 성공 경로와 실제 공급 공백을 구별했다. 실제 API·계좌·키는 사용하지 않았다.

부모의 2차 수정 전 두 회귀는 target/T-07/review2-red.log에서 컴파일 후 실패했다. 신규 domain API 부재의 컴파일 red는 review2-domain-red.log다. 부모의 수정 전후 결과는 독립 리뷰어의 실행과 합산하지 않는다. 2차 수정의 정책·제약과 최종 손 변형별 증거는 ADR에 기록한다.

2차 수정본의 손 변형 43개는 모두 컴파일 후 관련 시험 실패로 검출됐다. 복구 대조 35개가 통과했고 제품 소스 7개는 부모 원본과 바이트가 일치했다. 개별 변형표는 ADR 끝에 있으며 1차 결과와 합산하지 않는다. 외부 타입 경계의 정상/복구 컴파일과 네 기대 오류도 현재 소스에서 다시 확인했다. 구조·원시 타입·소스 검사는 위반이 없었다.

2차 수정의 정상 커밋 훅은 문서 변경 때문에 check-fast에서 전체 check로 승격됐고, 동일한 Xcode R4 한 건으로 종료1이었다. 61개 중60통과/1실패와 라이선스 문구를 확인했다. 지시문의 환경 예외에 따라 남은 check-ts와 check 본문을 모두 차례로 실행하여 전체1835/1835, 커버리지1075/1075, coverage-check/test-diff 및 마지막 hooks-installed까지 통과했다. 새 검사 끄기와 승인 test-diff는0건이다. 증거는 target/T-07/review2-commit.log, review2-remaining-checks.log와 remaining-checks.sh다. 그 조건을 확인한 2차 수정 커밋 한 건에만 LEFTHOOK=0을 사용하고 메시지에 같은 이유를 적는다. 정상 훅 자체의 종료1을 전체 명령 성공으로 바꾸어 보고하지 않는다.

## 3차 독립 검증

대상40f9ef50의 Opus는 broker-toss175개, domain price_limits14개와 Clippy·정적 검사를 통과했다. 새 재현·손 변형·타입 실험은 role-without-edits/inline-code/dynamic-target/git-alias 거부로 미실행이다. 거부 뒤 같은 목적의 다른 쓰기 수단을 시도한 사실도 리뷰 한계로 보존한다. 부모는 해당 결과를 새로운 실행 재현으로 세지 않는다.

새 Codex 비판은 공개 포트 합성 검증7개(독립 산술75쌍 포함), 기존 domain 관련14개/adapter35개, 타입 위조 E0451과 격리 손 변형2개를 실행했다. 상한 정각 거부 변형과 Stock→Etf 변형 모두 컴파일 후 검출됐으며 부모의43개와 합산하지 않는다. 실제 API·계좌·신호·역사 사건은 미검증이다. 양쪽 check-fast는 알려진 R4 라이선스 한 건으로 종료1이고, 비판자는 환경 예외를 쓰거나 커밋하지 않았다. 부모의 추적 파일·인덱스·HEAD·브랜치 참조는 리뷰·비판 전후 모두 동일했다.

3회차를 마쳤으므로 4차 독립 리뷰는 열지 않는다. 남은 범위·제품 정책은 ADR의 메인 인계에 명시한다. 현재 지원 계약 불일치가 해결됐다고 보고하지 않는다. 후속 정리와 공식 변이·최신 master 병합의 검사 증거는 실제 실행 후 기록한다.

3차 후속 정리본도 새 복사본에서 손 변형45개를 모두 컴파일 후 검출했다. 기준/복구35개 통과와 제품 소스7개의 바이트 일치를 확인했다. 기존 결과와 합산하지 않는다. 공식 변경분 변이는 최종 병합 소스에서 별도로 실행하며 증거는 target/T-07/official-mutants.log와 최종 보고로 남긴다. 메인의 domain 범위 채택과 종목 유형별 지원·오류 계약 결정이 완료됐다고 주장하지 않는다.

3차 후속 정리의 정상 커밋 훅도 동일한 Xcode R4 한 건만 실패했다(61개 중60통과/1실패, 라이선스 문구). 남은 check-ts와 check 본문을 전부 직접 실행하여 통과한 경우에만 해당 커밋 한 건에 환경 예외를 적용한다. 정상 훅 로그는 target/T-07/final-commit.log, 후속 검사 로그는 final-remaining-checks.log다.

최종 master 수신에도 정상 훅을 먼저 실행한다. 동일한 R4 한 건만 실패한다면 지시문의 같은 환경 예외 조건을 적용하며, 그 사유는 라이선스 미동의로 환경을 비운 /usr/bin/git 호출이 실패하기 때문이다. 실제 받은 master SHA와 병합 검사·예외 사용 여부는 병합 커밋 메시지 및 target/T-07/merge-*.log와 최종 보고에 남긴다. 다른 실패가 있으면 이 예외를 쓰지 않는다. 공식 변경분 변이는 최종 병합 HEAD에서 별도로 실행하며 완주·부분 실행·미검출을 구별해 보고한다.

3차 후속 정리 범위는40f9ef50→f7e07a5e다. 정상 훅의 R4 단일 실패 뒤 남은 전체 검사1835/1835와 커버리지1075/1075, coverage-check/test-diff 및 hooks-installed가 모두 통과한 것을 확인하고 그 커밋 한 건에 환경 예외를 적용했다. source7개 SHA와 손 변형45개 복구 대조를 확인했다. 4차 독립 리뷰를 실행한 것이 아니다.

최초 최종 수신 시도는 T-06을 포함한7a3fa7cf9ba7a4570abc07665b444341887aa06c였다. lib.rs와 생성물 두 파일이 충돌했다. 두 모듈 선언을 모두 보존하고 생성물은 공식 스크립트로 재생성했다. 첫 후속 검사는 fmt의 모듈 알파벳순 불일치로 종료1이었고 환경 예외를 쓰지 않았다. 정렬안을 검토한 뒤, 빈 줄로 선언 그룹을 나누면 기존 T-06 순서와 새 T-07 끝 추가를 모두 유지하면서 rustfmt가 보존함을 별도 입력으로 확인했다. 최종 lib.rs는 받은 파일의 내용 뒤에 그룹 구분 빈 줄과 market_read 선언 한 줄만 추가한다. 검사 끄기나 내용 재배치는 없다. 이 최종 형식의 fmt를 직접 확인한 뒤 정상 훅부터 다시 실행한다. transactions/T-11 본문은 받은 master와 같다. 실제 최종 검사·변이 결과는 병합 로그와 최종 보고를 따른다.

위 입력의 정상 훅 실행 중 master가 A-16을 병합한f4b7e4ff0d048a049f3b52f512c0e64e1ed5a042로 전진했다. 검사 뒤 입력 SHA와 현재 master가 다름을 확인해 환경 예외를 쓰지 않았고, 자기 미완료 병합만 취소했다. T-07 기록을 보존한 뒤 새 master를 원래 --no-ff 명령으로 다시 받았다. 현재 병합 입력은 f4b7e4ff이며, 두 모듈 선언은 처음부터 빈 줄 그룹으로 기존 내용과 끝 추가를 보존한다. 앞 시도의 R4·fmt 결과를 최종 병합 통과로 세지 않는다. 재시도 증거는 target/T-07/merge2*.log와 최종 보고에 남긴다.

## 메인 평가

보고가 메인 채택을 요청한 두 가지를 정한다. (1) domain 세 파일 추가(`price_limits/history.rs` 등: 인접 일봉의 전일 수정 종가 대비 고가·저가 검사)는 T-07 범위로 채택한다. 어댑터가 가격 계산을 직접 하지 않게 하려면 domain에 있어야 하고, 2·3차 리뷰가 이 코드를 대상으로 했다. (2) 국내 비주식 유형의 수정 일봉이 지원 선언 뒤 `Unsupported → Bug`가 되는 계약 문제는 이 작업에서 고치지 않고 T-13(실측)과 포트 계약 표 정리로 넘긴다: 닫힌 실패라 잘못된 값이 나가지는 않는다. 3차 뒤 후속 정리(`40f9ef5 → f7e07a5`)는 상태 소진과 문서 정리다. Xcode 라이선스 미동의로 훅 자가 테스트 한 건이 환경 탓에 실패해, 메인이 그 한 건만 예외로 둔 전체 검사를 병합 트리에서 다시 돌린 뒤 병합한다.
