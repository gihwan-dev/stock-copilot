## 평가

- 1회차 1·3·4·5·6·7은 수정 지시. 허용 목록 승인 해석을 넓히지 않고 예외 자체를 제거했다. 정책 저장 복원 경계를 실제 Policy와 함께 봉인하고 소비형 변환을 추가했다. 반올림·미국·상하한 테스트와 enum 처리도 보강했다.
- 1회차 2·8의 기각을 수용했다. 2회차 2·4·5의 기각도 수용한다. 시장가 설정의 저장 진위·위험 설정 확인은 A17/O14/S10, 승인 직전 정책 검사는 O01/O04의 책임이다. 기존 OrderIntent 직접 생성만으로 승인·전송이 허용되는 것은 아니다.
- 2회차 1은 보수적 거부 정책으로 유지한다. 주문 계산이 아직 도래하지 않은 관측 시각을 현재 사실로 인증하지 않도록 한다. ADR 0067은 보존과 계산을 구분하며 브리프가 보수적 초안 결정을 허용한다. 일정한 시계 차이에서 매번 즉시 새 조회하면 실패가 반복된다는 가용성 한계는 확정 사실이다. O01/O04는 이를 인계받아 무조건 즉시 재조회만 반복하지 않아야 한다. 2초 즉시 계산 허용으로 완화하지 않는다. 미래 시각도 StaleFact인 명칭의 한계를 기록한다.
- 2회차 3은 후속 개선으로 보류한다. 현재 불변식에서는 오류 결과가 올바르며 도달 불가능한 분기나 기존 타입 변경을 추가하지 않는다. 향후 수량 검증 사유 확장 시 원래 오류 보존 또는 exhaustive 매핑을 함께 검토해야 한다.
- 추가 차단 결함은 확인되지 않았다. D26 계산 범위는 수용한다. 실제 계좌·API·저장소 진위·주문 승인/전송의 런타임 검증을 완료했다는 판정은 아니다.

## 작업 D-26
`docs/tasks.md`의 D-26 행 그대로: 매도 수량과 지정가 계산. 완료 기준: 매도 수량은 보유 수량과 매도가능수량 안. 지정가는 최신 호가와 호가 단위로 정함. 시장가는 설정이 켜졌을 때만(design 6.3).
- **매도 수량**: 입력은 신호·정책이 정한 매도 목표(전량/비율 등 design 6.3 문장대로), 보유 수량, D-34의 `SellableQuantityFact`(같은 계좌·같은 종목이어야 함). 결과 수량 ≤ min(보유 수량, 매도가능수량). 소수 주식·단주 규칙은 D-25·D-34와 일관되게(국내 소수 매도는 D-34가 거부). 0이 되면 닫힌 "매도 불가" 이유. 사실의 신선도 판정은 O-01의 몫이면 인계.
- **지정가**: 입력은 D-35의 `Orderbook`(같은 종목)과 `TickTable`, `PriceLimits`, 주문 방향. design 6.3이 정한 규칙(예: 매수는 최우선 매도호가 기준, 매도는 최우선 매수호가 기준, 몇 틱 여유 등 — **문서 문장 그대로**)으로 가격을 정하고 호가 단위에 맞춘다(매수는 불리하지 않은 방향의 반올림 규칙을 문서대로, 없으면 매수는 내림·매도는 올림이 아니라 **체결 가능성을 해치지 않으면서 사용자에게 불리하지 않은 쪽**을 design 문장으로 확인해 정하고 ADR에 근거). 상·하한가 밖이면 닫힌 오류. 호가가 비었거나 단위가 `Unavailable`이면 계산 불가(임의 가격을 만들지 않는다).
- **시장가**: 정책(D-12)의 시장가 허용이 켜졌을 때만 시장가 주문 의도를 만들 수 있다. 꺼져 있으면 타입으로 만들 수 없거나 닫힌 오류. 불리언 인자가 아니라 정책 타입을 받는다.
- 출력은 D-13의 `OrderIntent`(또는 그 입력이 되는 봉인된 값)로 이어지게 한다. 수량·가격·방향·종목·계좌가 한 값에 묶인다.
- 예제: design 6.3·R 문서의 예제 값을 테스트로 고정. 독립 계산과 대조하는 속성 테스트(저장소의 횟수 관례): 결과 수량이 두 상한 이하, 지정가가 항상 호가 단위의 배수이고 상·하한 안, 가격대 경계를 넘는 경우.
- 봉인된 생성자, 오류에 입력값 없음, 닫힌 열거형, `Debug`에 금액 원문 없음. 다른 종목·다른 계좌의 사실이 섞이면 거부.
- 새 모듈 파일(`sell_quantity*.rs`, `limit_price*.rs`)에 두고 `lib.rs`에는 파일 끝에 줄만 더한다. ADR 초안: `docs/adr/d-26-sell-quantity-and-limit-price.md`.

## 규칙
- 네 작업 사본에서만 일한다. `master`를 옮기지 않는다. 푸시·PR 없음. 홈 폴더 설정(`~/.codex`, `~/.claude`) 수정 금지, 자격 증명 파일 읽기 금지. 실제 토스 키·실제 계좌 자료를 다루지 않고 실제 API를 호출하지 않는다. 소스에 주석을 쓰지 않는다. 저장소 파일에 사용자별 절대 경로를 쓰지 않는다.
- 의존성: 저장소에 없는 **새 외부 패키지**는 넣지 않는다(꼭 필요하면 넣지 말고 "막힘:"으로 보고). 워크스페이스 내부 crate 의존(architecture 3.2가 허용하는 방향)과, 저장소가 이미 쓰는 패키지를 같은 버전으로 다른 crate의 (개발) 의존성에 더하는 것은 된다. 그에 따른 허용 목록 등록도 된다(보고에 적는다).
- 시작: `PATH="$HOME/Library/pnpm:$PATH"`를 두고(커밋 명령에도) `pnpm install --frozen-lockfile --ignore-scripts`, `lefthook install`. 시작 확인용 전체 검사는 생략한다(master는 방금 전체 검사를 통과했다). 구현 중에는 좁은 범위(`cargo test -p <crate> <필터>`, 프런트는 해당 테스트 파일만)로 돌리고, 전체 검사는 최종 커밋의 훅에서 한 번만 돈다.
- 기존 테스트 본문과 기존 `impl`은 바꾸지 않는다. 꼭 필요하면 최소로 하고, `test-diff`가 막으면 훅을 건너뛰지 말고 멈춰서 "막힘:"으로 무엇을 왜 바꿔야 하는지 보고한다.
- 끝내기 전에 `git merge --no-ff --no-edit master`로 최신 `master`를 받는다(정상 훅으로 통과한다. `lib.rs` 충돌은 양쪽 줄을 모두 살린다). 그 뒤 전체 검사를 통과한 커밋이 최종이다.
- **질문 창을 띄우고 기다리지 않는다.** 문서에 없는 세부는 가장 단순하고 보수적인 쪽으로 정해 ADR 초안의 "결정"에 근거와 함께 적고 계속한다(사용자 확인 대기로 남기지 않는다. 이 프로젝트의 결정은 메인이 하고, 최상위 목표는 단순하고 직관적인 UI/UX다). 멈추는 것은 하네스 규칙을 약하게 해야만 할 때나 지시가 서로 모순될 때뿐이고, 그때는 최종 보고 첫 줄을 "막힘:"으로 쓴다.
- ADR 초안은 파일 하나(`docs/adr/`에는 `.md`만), 둘째 줄 아래에 `- 상태: 초안` 줄. 번호는 붙이지 않는다. `docs/tasks.md`와 `docs/progress.md`는 고치지 않고, 다른 작업에 넘길 일은 ADR의 "인계"에 받는 작업 ID와 함께 적는다.
- 변이: 자동 변이 검사는 하네스 개편(H-46) 중이라 돌리지 않는다. 새 코드의 분기·경계·연산자를 바꾸는 **손 변형 20개 이상**을 `mktemp -d` 복사본에서 실제로 돌리고, 변형별로 (바꾼 것, 잡은 테스트 또는 "생존")를 ADR 끝의 표에 남긴다. 컴파일되지 않는 변형은 세지 않는다. "N/N"이라고 쓰려면 전부 실제 실행한 결과여야 한다(지난 작업들에서 이 보고가 재현되지 않은 일이 있었다). 테스트는 필드마다 서로 다른 값을 써서 필드가 뒤바뀌는 변형을 잡게 한다.
- 프로세스를 종료할 때는 네가 띄운 PID만(이름 기준 종료 금지). `/tmp` 바로 아래에 파일을 만들지 않는다. 다른 스레드가 같은 기계에서 일한다.
