구현과 수정은 Codex `gpt-6.1-sol`(T3 스레드, 작업 사본 `d-25`). 리뷰어는 회차 1에 새 Claude Opus 5.5 서브에이전트. 회차 2는 메인이 수정 보고와 검증 결과를 읽고 평가했다. 결정은 ADR 0060에 있다. D-09, D-17, D-33, D-36, DS-04와 병렬로 진행했다.

**비판 단계를 생략했다.** 중요 지적 넷 가운데 둘은 리뷰어가 수치로 재현했고, 나머지는 문서 문장으로 판정할 수 있어 메인이 전부 수정으로 정했다.

## 리뷰 (회차 1)

리뷰어의 독립 계산과 1,018건을 대조해 구현이 더 많이 사는 경우도 덜 사는 경우도 없었다. 목표 금액 내림, 큰 환율 선택, 달러 매수가능금액, 보수 운용 절반, 불완전 총자산 차단, `Debug` 가림을 확인했다. 손 변형 16개 중 14개 검출.

| 번호 | 등급 | 지적 | 평가 |
|---|---|---|---|
| 1 | 중요 | 반복 제한이 첫 과제의 생성부터 만기까지라, 만기 직전 신호의 제한이 곧바로 풀림 | 수정: `[신호 시각, 신호 시각에서 H 거래일 뒤 정규장 마감)`. 캘린더가 부족하면 주문 없음 |
| 2 | 중요 | 원칙 한도 비교에 수수료가 빠져 현금 최소 비중을 수수료만큼 넘겨 삼 | 수정: 탐색과 최종 검사 모두 수수료 포함 총비용. 국내·미국 재현을 테스트로 고정 |
| 3 | 중요 | 더 높은 지정가로 주문하면 목표 비중을 넘을 수 있음, 오래된 매수가능금액을 막지 않음 | 수정: 계획이 산정 단가와 총비용 상한을 보존, `check_buy_plan_order_price`가 봉인된 `PriceBoundBuyPlan`을 냄. 매수가능금액은 60초까지 |
| 4 | 중요 | 고가주는 정수 주로 살 수 없어 주문이 영원히 없음 | 구현 유지(ADR 0032). ADR에 총자산·성향별 최대 주가 표와 대안. 주문 없음 이유에 필요 금액과 목표 금액의 표시용 값 |
| 5 | 사소 | 두 환율이 같은 픽스처, 최종 검사 실패 이유가 `Indeterminate`뿐, 달러가 조금뿐일 때의 안내, 과제와 정책의 성향 불일치, 최종 검사를 잡는 테스트 부족 | 수정: 두 환율이 다른 픽스처, `PolicyReduced`·`PolicyBlocked`, 환전 안내, 더 보수적인 성향 적용, 신호 뒤 원칙 변경 테스트 |

## 메모

- 사용자 확인 대상: 목표 비중과 절반 축소율, 반복 제한의 해석, 매수가능금액 60초, 고가주를 정수 주로 살 수 없는 결과와 미국 금액 지정 시장가 대안.
- 미체결 주문에 묶인 금액의 의미는 T-13 실측, 조회와 최종 검증은 D-34·O-01의 몫이다. `PriceBoundBuyPlan`을 주문 게이트가 요구하게 하는 것은 D-26·O-01이 한다. D-36의 현금 관측 연결은 A-08이 한다.
- 수정 회차의 자동 변이 검사는 작업 스레드가 커밋 훅의 `cargo clean`과 겹쳐 시작해 범위 계산 전에 종료됐다(실행되지 않음). 손 변형 27개가 모두 검출됨을 확인했다. 밤 변이 검사가 전체를 다시 본다. 수정분은 Opus 재리뷰를 하지 않았다.
