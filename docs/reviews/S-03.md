## 비판

비판자는 지적마다 먼저 반박하고 실행으로 확인했다. 1.1은 상태 비교만 삭제한 변형이107개 통과했지만 새 교차 호출 반례에서는 실패했고, 원본은 같은 반례를 통과했다. 1.3은 정상 이력1개 뒤 legacy Partial(empty)을 저장하면 이력0개가 되는 것을 재현했다. 현재 제품에 legacy record 호출자는 없어 두 항목의 등급은 사소다.

1.2의 H=2000/R=0 단일 debug 표본은 적재5회, 정규화 복원20000행, 원본 존재 점 조회20000회, 삽입4000행, 1851ms였다. 이 표본으로 UI 정지나 대기 자원 한도 위반을 주장하지 않는다. D-46의 미상 시작일 비용은 기존 계약이고 실제 전체 실행은 A-25 연결 전이다. 저장소가 추가하는 상태 복제 비용과 구분한다.

Opus 리뷰어는 기존107개 테스트를 통과시켰지만 dynamic-target/git-alias/inline-code/role-without-edits 차단으로 독립 계산 스크립트·타입 우회 컴파일·손 변형을 실행하지 못했다. 우회하지 않았으며 NOT_RUN이다. Codex 비판자는 자기 사본 target에서 실제 삭제 변형·반례·비용 계측을 실행했다. 비판자의 준비 과정에서 잠금/하네스 자료 누락 실패가 있었고, 대상과 같은 manifest/lock을 갖춘 뒤 최종 결과를 구분해 기록했다. 리뷰어의 막힘과 비판자의 실행 증거를 합쳐 독립 리뷰 전부가 실행됐다고 표시하지 않는다.

## 검사

Codex는 외부 트리거 반례·중복 사전검사 삭제·같은 시각 경계 변경·history 제외 삭제·모드 변경·Latest 복원 변형을 실행했다. 단순 Latest 치환의 컴파일 불가는 집계에서 제외하고 사용하지 않는 선언까지 제거한 컴파일 가능한 변형으로 판정했다. 중간 공유 target의116개 출력은 원본 증거에서 제외하고 별도 빌드 디렉터리의112개를 사용했다. 첫 fixture 실행은 기본 임시 경로를 써 target 한정 조건을 엄밀히 지키지 못했으며 이후 TMPDIR를 사본 target로 한정하고 자기 fixture는 자동 정리됐다.

3차 리뷰·비판 전후 원본 추적파일4021개·인덱스·HEAD·ref 스냅샷은 각각 동일했다. 최대3회차를 완료하며 4차 리뷰는 하지 않는다. 5afa0f8b 이후 제품 저장 코드 변경 없이 새 동률 회귀만 보강하고 master d2d12e38bfa556418c53fc7c1bb8b99100b083a0을 --no-ff 통합한다. 충돌 두 생성물은 공식 명령으로 재생성한다. 통합된 A-25는 D-46 완료값의 시각을 그대로 CAS에 넘기지만 실제 SQLite 조립·제품 규모 성능 검증은 별도다. 최종 통합 전체 검사 결과는 최종 커밋 메시지와 보고에 남긴다.

2차 Opus 리뷰는 전체110개를 통과시켰고 차단·중요0, 사소1과 비용 관찰1을 보고했다. 세 손 변형은 inline-code 하네스 차단으로 NOT_RUN이다. 새 Codex 비판은 원본27개를 통과시키고 격리 복사본에서 공유 transaction_latest 시나리오를 실제 SQLite에 연결해 오래된 두 번째 쓰기의 오류를 재현했다. 문서에 거부 의도만 적어 계약을 바꾸는 대안은 채택하지 않는다. 과거 입력도 남기도록 별도 history를 사용한다. 최신 summary의 Partial은 이전 정상 상태와 같아야 하며, 과거 Partial의 값은 과거 입력 스냅샷으로만 남아 현재 정상 상태를 바꾸지 않는다.

비판자는 상태 CAS 삭제와 Partial 읽기 검사 삭제, Partial 쓰기·읽기 결합 복원을 각각 컴파일해 검출했다. Partial 쓰기만 되돌린 단독 변형은 읽기 재검증이 대신 막아 테스트가 통과했다. 이를 단독 검출로 세지 않는다. 현행 계약 결함은 아니며 중복 방어에 의한 생존이다. 불투명 원문의 공백·CR/LF·NUL·한글 왕복과 교차 호출도 비판자의 별도 테스트에서 통과했다. 두 번째 리뷰·비판 전후 원본 추적 파일4021개·인덱스·HEAD·ref 스냅샷은 각각 일치했다.
