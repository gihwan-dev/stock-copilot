구현과 수정은 Codex `gpt-6.1-sol`(T3 스레드, 작업 사본 `d-36`). 리뷰어는 회차 1에 새 Claude Opus 5.5 서브에이전트. 회차 2는 메인이 수정 보고와 검증 결과를 읽고 평가했다. 결정은 ADR 0061에 있다. D-09, D-17, D-25, D-33, DS-04와 병렬로 진행했다.

## 리뷰 (회차 1)

조회에 실패한 현금이 0원으로 보이는 경로가 없음(보유 평가와 통화별 합계는 완전, 총자산은 불완전, 실패한 통화의 금액 접근은 오류), 계좌 유형 대응, 전체 계좌번호가 남지 않음, 빈 목록과 미지 유형의 구분을 확인했다. 손 변형 12개 중 11개 검출.

| 번호 | 등급 | 지적 | 평가 |
|---|---|---|---|
| 1 | 차단 | 완료 기준 "계좌 표시 사실이 계좌 행에서만 만들어짐" 미충족: D-32의 공개 생성자 둘이 남았고, 새 경로도 한 행의 키에 다른 행의 가린 번호를 붙일 수 있음 | 수정: 행 생성자가 응답 한 행의 원시 값을 받아 안에서 가림. 가린 번호를 꺼내는 접근자 제거. D-32 생성자 둘을 crate 안으로 닫음. `application`의 기존 테스트 도우미를 새 경로로 옮김 |
| 2 | 중요 | 조회 실패가 D-06·D-12에서 실제 음수 현금과 같은 오류로 나오고, 두 통화가 모두 실패하면 원화만 보고됨 | 수정: `CashObservationFailed`(원화 / 달러 / 둘 다, 이유 보존)를 별도 변형으로. D-06 → D-12 → D-24 연동 테스트 |
| 3 | 사소 | 실패 이유가 세 종류뿐이라 A-01 `PortError`의 구분을 잃음, 이름이 ADR 0055와 다름 | 수정: `CashObservationFailure`로 통일하고 A-01의 닫힌 원인과 재시도 대기 시간을 보존. 대응 표를 ADR에 |
| 4 | 사소 | 같은 계좌 키의 중복 행, 키 기반 선택 함수 없음 | 수정: `BrokerAccountRows`가 중복을 거부, 목록 안 종합매매 계좌만 키로 선택 |
| 5 | 사소 | 실패 관측의 통화를 자리 통화로 덮는 변이가 생존 | 수정: 반대 통화 자리에 넣으면 `CurrencyMismatch` |
| 6 | 사소 | 실패 관측 시각과 보유 조회 시각의 차이 검사 | ADR에 A-08의 몫으로 기록 |

## 승인한 기존 테스트 변경과 훅을 건너뛴 커밋

`crates/application/tests/ports.rs`의 `use domain::{…}` 줄(제거와 추가로 두 항목)과 도우미 `account`: 닫은 D-32 생성자 대신 `BrokerAccountRow`를 만들어 `display_fact()`로 계좌 표시 사실을 얻도록 바꿨다. 단언은 그대로다. `test-diff`가 이 세 항목을 막으므로, 메인이 그 외 전체 검사 통과를 확인한 뒤 훅 없이 병합했다.

## 메모

- 종합매매 계좌는 스키마의 `BROKERAGE`다. "첫 계좌"는 응답 순서를 따른다(ADR 0055의 서버 순서 보존 계약).
- 원시 계좌번호 문자열을 넣는 곳은 어댑터의 신뢰 경계다. 생성 함수의 호출 위치 제한은 하네스 작업이다.
- 실제 `PortError`에서 `CashObservationFailure`로의 변환은 A-06, 관측 시각 차이 검사는 A-08이 한다.
- 승인된 `test-diff` 항목 때문에 자동 변이 검사가 사전 조건에서 멈췄다. 손 변형 23개가 모두 검출됨을 확인했다. 수정분은 Opus 재리뷰를 하지 않았다.
- D-33 병합 뒤 작업 스레드가 `master`를 다시 병합해 `ports.rs`와 `lib.rs`의 충돌을 풀었다.
