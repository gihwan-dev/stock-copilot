## 메인 평가

- 판정: 수용. Antigravity 세션에도 세션 훅이 걸린다. `.agents/hooks.json`은 Claude·Codex 훅과 같은 정책 원본에서 생성되고, 보호 경로 쓰기·홈 설정과 자격 증명 읽기·실제 주문과 토스 API 명령·리뷰 역할의 쓰기와 위임을 같은 판정 코드로 막는다. 훅 실행이 실패하면 도구 호출이 막힌다(닫힌 실패).
- 메인이 진행 중에 내린 결정: 구현 담당 역할(최상위 스레드 + xhigh + 별도 작업 사본 + 보호되지 않은 이름의 브랜치)에게만 `git push origin <현재 브랜치>`, `git merge --no-ff --no-edit master|origin/master`, `git merge --ff-only origin/<현재 브랜치>`, 리뷰어·비판자 위임을 허용한다. 훅 끄기(`LEFTHOOK=0`)는 계속 막고, 컨테이너 런타임이 없는 기기의 작업 브랜치 푸시는 `push-check`가 가벼운 검사로 보낸다(전체 검사는 병합 커밋에서).
- 리뷰는 세 차례 받았다(초기 2회차 + 후속 보완 1회). 후속 보완 리뷰에서 차단 1건(병합 허용 규칙의 전역 옵션·참조 가리기 우회)과 중요 3건이 나와 모두 고쳤다. 손 변형 누적 112/112.
- **이 작업에서 드러난 운영상 빈틈(문서와 `known-gaps`에 기록됨)**: (1) 세션 훅은 주 작업 트리의 규칙을 읽으므로 허용을 넓히는 변경은 master 병합과 주 작업 트리 갱신 뒤에야 적용된다(의도된 성질). (2) 구현 담당이 변경을 스테이징한 채로는 master를 받을 방법이 없고(보관 명령이 막힘), 종료 훅이 미커밋 종료를 막아 막힘 보고가 반복된다. 이번에는 메인이 훅 밖에서 세 번 풀어 주었고 그 가운데 한 번은 세 시간 가까이 놓쳤다. 후속 작업으로 넘긴다.
- 기존 테스트 변경 1건(`push-check` 레시피 문자열을 고정한 훅 테스트 한 줄)은 승인 행으로 해소된다.
- 인계: H-67(스테이징 상태에서 master를 받는 정식 경로와 막힘 보고 뒤 종료 허용), `PostToolUse`가 편집 직후 검사 결과를 되돌리지 못하는 한계.
