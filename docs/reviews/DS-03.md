# 리뷰 기록 DS-03 (기본 컴포넌트 1)

## 커밋

구현과 수정은 Codex `gpt-6.1-sol`(T3 스레드, 작업 사본 `ds-03`). 리뷰어는 회차 1에 새 Claude Opus 5.5 서브에이전트. 회차 2는 메인이 수정 보고와 검증 결과를 읽고 평가했다. 결정은 ADR 0056에 있다. 도메인 작업들과 병렬로 진행했다.

**비판 단계를 생략했다.** 리뷰어가 지적을 실제 앱 린트 설정으로 재현했고 메인이 전부 수정으로 판정했다.

구현 중에 구현 담당이 한 번 멈췄다. 기존 테스트 두 곳이 새 컴포넌트 등록을 막았고 린트 규칙(DS-10, DS-02)이 Base UI를 감싼 정상 컴포넌트를 거부했다. 메인이 정했다: 기존 테스트의 기대값은 이번에 더하는 파일만 정확히 더한다. 규칙은 "공개 계약은 유지하고 내부 구현의 오탐만 좁힌다"는 원칙으로 고치고 위반·대조군 예제를 함께 둔다. DOM 값 읽기는 `shared/platform`의 경계 함수로 모은다.

## 리뷰 (회차 1)

DS-10의 위반 예제와 손 변형 15개는 모두 계속 실패했다. 클래스 조건식 허용은 뚫리지 않았다(각 분기의 리터럴이 토큰 검사를 받음). 기존 테스트 변경은 정확 일치를 유지했고 공개 props에 불리언이 없었다. 새 의존성에 설치 스크립트가 없었다.

| 번호 | 등급 | 지적 | 평가 |
|---|---|---|---|
| 1 | 중요 | `ds/no-dom-exports`가 React 타입 선언을 통째로 건너뛰게 돼 `SyntheticEvent`를 내보내는 함수가 통과. ADR에 없는 약화 | 수정: 건너뛰는 대상을 ES 표준 라이브러리로 좁힘. 위반 예제 고정 |
| 2 | 중요 | 매수·매도 버튼 변형을 아무 화면에서나 쓸 수 있음(design: SignalCard에만) | 수정: 공개 `Button`에서 `buy`·`sell` 제거. SignalCard 작업이 내부 전용으로 만듦 |
| 3 | 중요 | 화면 코드가 클립보드 읽기 함수를 가져올 수 있음 | 수정: 입력 경계 함수를 `shared/platform/input.ts`로 분리, `TextField`와 `Select`만 가져올 수 있음 |
| 4 | 중요 | 테스트가 Chromium을 띄우는데 브라우저 공급 단계가 없음. 이 기계의 캐시에 우연히 있어 통과 | 수정: Testing Library와 jsdom으로 바꾸고 Playwright 제거. 브라우저가 없는 환경에서 전체 검사 통과 확인. 실제 브라우저 검증은 DS-15로 |
| 5 | 사소 | Base UI의 이벤트 세부 객체를 통째로 바깥 콜백에 넘기는 형태가 통과 | 수정: 가공 없이 넘기는 형태(변수, 구조 분해, 객체 포장 경유 포함)를 거부 |
| 6 | 사소 | Select의 접근 이름에 도움말과 오류가 섞임 | 수정: 라벨만 연결, 정확 일치로 검사 |
| 7 | 사소 | 한글 조합 중 Enter의 `keyCode 229`와 조합 종료 직후 | 수정 |
| 8 | 사소 | 비밀 입력의 보기 상태가 값을 지운 뒤에도 남음 | 수정 |
| 9 | 사소 | 산출물에 없는 props(TextField `onCommit` 등), Disclosure 표시 | 수정: 제거, 산출물대로 |
| 10 | 사소 | 운영 배럴이 이야기 자료를 내보냄 | 수정: 별도 진입점 |

## 메모

- 컴포넌트 열한 개: Heading, Text, Button, IconButton, TextField, Select, Checkbox, Switch, SegmentedControl, Disclosure, Icon. 이야기 393항목.
- 새 의존성: `@base-ui/react` 1.9.0(운영), `@testing-library/react` 16.3.3, `@testing-library/user-event` 14.6.10, `jsdom` 31.0.1(개발). 사용자 확인 대상이다.
- 기존 테스트 변경을 승인했다. 회차 1: `ds-final-review.test.mjs`(아이콘 기하 허용 파일 넷), `ds-internal-review.test.mjs`, `ds-generation.test.mjs`(유틸리티 선언), `knip.test.mjs`(공개 컴포넌트의 유예), `ds-screen-bootstrap.test.mjs`, `local-allowlists.test.mjs`. 회차 2: `boundaries.test.mjs`(옵션 제거 변형 목록에 한 항목), `ds-generation.test.mjs`(회전·전환 선언), `ds-internal-review.test.mjs`(가격색 목록을 빈 목록으로 복구, DOM 목록에 `input.ts`), `ds-screen-bootstrap.test.mjs`(공개 목록 복구, 입력 함수 반환형 검사), `local-allowlists.test.mjs`, `knip.test.mjs`(정확한 유예 48개). 리뷰어가 회차 1의 변경에 약해진 단언이 없음을 확인했다.
- 규칙 변경: DS-10은 Base UI 선언에서 온 내부 문맥 타입을 공개 계약 검사에서 제외. DS-02는 두 분기가 모두 리터럴인 클래스 조건식과 산출물 근거가 있는 클래스 여섯 개를 허용.
- 한글 줄바꿈 클래스(`break-keep`, `wrap-anywhere`)는 산출물에 근거가 없어 더하지 않았다. 사용자 확인 대상이다.
- React는 제어 입력의 값을 DOM 속성으로 동기화한다. 비밀 입력에도 해당한다. ADR에 적었다.
- 넘긴 검증: Storybook 실행(DS-07), 실제 CSS와 양 테마의 시각 검증(DS-15), WKWebView의 한글 입력과 운영체제 목록(DS-16), 넘침(DS-20).
- 회차 2 수정분은 Opus 재리뷰를 하지 않았다.
