> ## 작업 DS-22
>
> 리뷰 등급: 2
> `docs/tasks.md`의 DS-22 행 그대로: 부하 이야기의 남은 넘침 판정 해소.
>
> - 먼저 현재 실행기를 돌려 남은 판정을 전부 목록으로 만들고 원인별로 분류한다(실제 넘침 / 검사가 잘못 잡음 / 겉모습·공개 props 변경 필요).
> - 실제 넘침은 토큰과 기존 계약 안에서 고친다(새 토큰·임의 px 금지, 공개 props 불변). 검사가 잘못 잡는 것(숨긴 접근성 표, 1px 글꼴 지표, 입력 내부 스크롤)은 검사 쪽을 **좁게** 고치고, 좁힌 조건마다 "이 조건이 실제 넘침을 놓치지 않는다"는 회귀 사례(일부러 넘치게 만든 fixture가 여전히 잡힘)를 둔다. 통째로 건너뛰는 예외 목록은 만들지 않는다.
> - 겉모습이나 공개 props가 바뀌어야 하는 것은 고치지 말고 목록으로 보고한다(메인이 정한다). 이 때문에 종료 0이 안 되면 그 항목만 근거와 함께 명시적 보류 표(이야기, 조건, 이유)로 두고 실행기는 보류 표와 정확히 일치할 때만 통과하게 한다(보류가 늘거나 줄면 실패).
> - 실행기를 `ds-check`가 돌릴 수 있는 형태로 정리해 연결한다. 소요 시간을 측정해 보고한다.
> - 목표는 단순하고 직관적인 UI/UX다. 넘침을 숨기려고 글자를 자르는 것보다 정보가 보이는 쪽을 택하되, 어느 쪽인지 고친 항목마다 적는다.
> - ADR 초안: `docs/adr/ds-22-overflow-verdicts.md`.

> ## 규칙
>
> - 네 작업 사본에서만 일한다. `master`를 옮기지 않는다. 푸시·PR 없음. 홈 폴더 설정(`~/.codex`, `~/.claude`) 수정 금지, 자격 증명 파일 읽기 금지. 실제 토스 키·실제 계좌 자료를 다루지 않고 실제 API를 호출하지 않는다. 소스에 주석을 쓰지 않는다. 저장소 파일에 사용자별 절대 경로를 쓰지 않는다.
> - 의존성: 이 지시문의 작업 절이 이름을 들어 승인한 패키지(설계 문서가 정한 것)와 **그것이 요구하는 전이 의존성**은 저장소의 의존성 절차(정확한 버전 고정, 허용 목록, `deny`·arch-check 등록)대로 추가한다 — 이것은 아래 금지의 예외이고 모순이 아니다. 그 밖에 저장소에 없는 **새 외부 패키지**는 넣지 않는다(꼭 필요하면 넣지 말고 "막힘:"으로 보고). 워크스페이스 내부 crate 의존(architecture 3.2가 허용하는 방향)과, 저장소가 이미 쓰는 패키지를 같은 버전으로 다른 crate의 (개발) 의존성에 더하는 것은 된다. 그에 따른 허용 목록 등록도 된다(보고에 적는다).
> - 시작: `PATH="$HOME/Library/pnpm:$PATH"`를 두고(커밋 명령에도) `pnpm install --frozen-lockfile --ignore-scripts`, `lefthook install`. 시작 확인용 전체 검사는 생략한다(master는 방금 전체 검사를 통과했다). 구현 중에는 좁은 범위(`cargo test -p <crate> <필터>`, 프런트는 해당 테스트 파일만)로 돌린다. 전체 검사를 손으로 여러 번 돌리지 않는다.
> - 기존 테스트와 기존 `impl`: 단언을 지우거나 느슨하게 하는 변경(와일드카드 추가, 단언 삭제, 범위 완화)은 하지 않는다. 그런 변경이 꼭 필요하면 "막힘:"으로 보고한다. 반면 **이 작업의 설계가 기계적으로 요구하는 기존 테스트 변경은 미리 승인돼 있으니 멈추지 말고 진행한다**: (a) 닫힌 열거형에 변형을 더할 때 소진 `match`·기대 목록에 그 변형의 분기·항목 추가, (b) 승인된 이름·서명 변경에 따른 호출부 수정(단언은 그대로), (c) 고정 목록·개수 기대값을 새 정확한 값으로 갱신. 바꾼 항목은 보고에 (파일, 테스트, 전 → 후)로 적고, `test-diff`가 그것만 지적하면 그 외 검사 통과를 확인한 뒤 그 커밋만 `LEFTHOOK=0`으로 만든다(사유를 커밋 메시지에).
> - 보호 파일: 이 작업의 완료 기준을 채우는 데 꼭 필요한 보호 파일 변경(진입점·경계 파일의 추가 등록, 허용 목록에 이 작업의 새 파일 한정 항목, 생성물·스냅샷·해시)은 승인된 것으로 보고 진행하되 보고에 (파일, 이유)를 적는다. 검사를 느슨하게 만드는 변경(규칙 삭제, 허용 범위를 다른 코드로 넓힘)만 "막힘:"으로 보고한다.
> - 지시문의 문장끼리 사소하게 어긋나 보이면 멈추지 말고 **작업 절의 구체적인 승인이 공통 규칙의 일반 문장보다 우선**한다고 읽고(구체적인 것이 일반적인 것을 이긴다), 그래도 판단이 안 서면 더 엄격한 쪽 또는 저장소의 훅이 요구하는 쪽을 따르고 보고에 적는다. 정상 커밋 훅이 돌리는 검사는 몇 번이든 그대로 받는다(훅을 건너뛰지 않는다).
> - 끝내기 전에 `git merge --no-ff --no-edit master`로 최신 `master`를 받는다(정상 훅으로 통과한다. `lib.rs` 충돌은 양쪽 줄을 모두 살린다). 그 뒤 전체 검사를 통과한 커밋이 최종이다.
> - **질문 창을 띄우고 기다리지 않는다.** 문서에 없는 세부는 가장 단순하고 보수적인 쪽으로 정해 ADR 초안의 "결정"에 근거와 함께 적고 계속한다(사용자 확인 대기로 남기지 않는다. 이 프로젝트의 결정은 메인이 하고, 최상위 목표는 단순하고 직관적인 UI/UX다). 멈추는 것은 하네스 규칙을 약하게 해야만 할 때나 지시가 서로 모순될 때뿐이고, 그때는 최종 보고 첫 줄을 "막힘:"으로 쓴다.
> - ADR 초안은 파일 하나(`docs/adr/`에는 `.md`만), 둘째 줄 아래에 `- 상태: 초안` 줄. 번호는 붙이지 않는다. `docs/tasks.md`와 `docs/progress.md`는 고치지 않고, 다른 작업에 넘길 일은 ADR의 "인계"에 받는 작업 ID와 함께 적는다.
> - 하위 에이전트에 구현을 넘기지 않는다(하위 스레드는 이 지시와 승인을 받지 못해 같은 자리에서 멈춘다).
> - **리뷰와 비판은 네가 직접 돌린다**(`docs/agents/implementer.md`의 절차): 구현을 커밋한 뒤 새 Claude Opus 하위 에이전트에 적대적 리뷰를 맡기고(구현 보고서는 주지 않는다. 작업 행·관련 문서·diff만 준다. 독립 계산, 타입 우회 컴파일 실험, 손 변형 직접 실행, "사용자에게 잘못 보이는 경우"를 찾게 한다), 새 Codex 하위 에이전트에 그 지적의 비판을 맡긴 뒤, 타당한 지적을 고치고 한 번 더 리뷰를 받는다(차단·중요가 0이 될 때까지, 최대 3회차). 결과를 `docs/reviews/<작업 ID>.md`에 쓴다: `## 커밋`(표: `| 회차 | 기준 SHA | 대상 SHA |`), `## 리뷰`(표: `| 번호 | 등급 | 지적 | 평가 |`), `## 측정`(표: `| 항목 | 값 |`) 절이 반드시 있어야 한다(`node harness/ci/review-records/check.mjs`의 형식. 이미 병합된 `docs/reviews/D-38.md`를 본으로 삼는다). 최종 보고에 지적 표를 요약해 붙인다.
> - 검사(H-46 이후): 작업 브랜치의 커밋 훅은 빠른 검사(`check-fast`)다. 손으로 확인할 때도 `just check-fast base=<master SHA>`를 쓴다(전체 `just check`는 메인이 병합 때 돌린다). 속성 테스트 횟수는 숫자 리터럴을 쓰지 않고 `with_cases(testkit::property_cases())`로 쓴다(dev 의존성에 `testkit`이 없으면 추가).
> - 변이: 최종 보고 전에 `just mutants-diff`(저장소가 정한 변경분 변이 명령. 이름은 justfile에서 확인)를 한 번 돌려 결과를 보고한다. 미검출이 있으면 테스트를 더해 잡는다. 20분 제한에 걸리면 그 사실을 보고하고 손 변형으로 보완한다. 새 코드의 분기·경계·연산자를 바꾸는 **손 변형 20개 이상**을 `mktemp -d` 복사본에서 실제로 돌리고, 변형별로 (바꾼 것, 잡은 테스트 또는 "생존")를 ADR 끝의 표에 남긴다. 컴파일되지 않는 변형은 세지 않는다. "N/N"이라고 쓰려면 전부 실제 실행한 결과여야 한다(지난 작업들에서 이 보고가 재현되지 않은 일이 있었다). 테스트는 필드마다 서로 다른 값을 써서 필드가 뒤바뀌는 변형을 잡게 한다.
> - 프로세스를 종료할 때는 네가 띄운 PID만(이름 기준 종료 금지). `/tmp` 바로 아래에 파일을 만들지 않는다. 다른 스레드가 같은 기계에서 일한다.
> - 세션 훅 신뢰 확인(AGENTS.md의 시작 절차)이 실패하거나 확인할 수 없어도 멈추지 않는다. 결과를 보고와 리뷰 기록에 사실대로 적고 진행한다(이 환경에서는 스레드가 설정할 수 없다. 강제되는 문은 Git 커밋 훅과 메인의 병합 검사다). 세션 훅이 막아 줬어야 할 일은 이 규칙들로 스스로 지킨다.
> - 지시문 내용을 작업 사본의 `target/<작업 ID>/brief.md`에 요약해 두어 기계가 재시작돼도 이어갈 수 있게 한다.
> - 리뷰 기록(`docs/reviews/<ID>.md`)의 `## 커밋` 표 회차 칸은 `숫자` 또는 `숫자 (설명)` 형식만 쓴다(예: `4 (3차 수정)`). 다른 글자로 시작하면 병합 때 기록 검사가 실패한다.
> - 사전 승인 (d): 이 작업의 설계가 요구하는 동작 변경 때문에 기존 테스트의 **준비 부분**(fixture, 생성자 인자, 가짜 시계·가짜 대기 주입, 여러 응답을 주는 서버로 교체)만 바뀌고 **단언은 그대로**인 변경. 멈추지 말고 진행한 뒤 보고에 목록과 건수를 적고, 그 커밋에만 `LEFTHOOK=0` 예외를 쓴다. 단언을 지우거나 느슨하게 해야 할 때만 "막힘:"이다.
> - 리뷰는 최대 3회차다. 3회차 리뷰·비판에서 **실행으로 재현된** 차단·중요 지적은 고치고, 그 수정에 대한 4회차 독립 리뷰는 돌리지 않는다: 수정 범위(기준 SHA → 수정 SHA)와 회귀 테스트·변이 결과를 기록에 적고 **완료로 보고**한다(메인이 그 수정분을 직접 평가한다). 이것은 "막힘:"이 아니다.
> - 리뷰·비판을 맡길 때 **메인 저장소(`Documents/Projects/stock-copilot`) 안에 작업 사본을 만들지 않는다**(`.claude/worktrees/` 포함). 메인 저장소 안의 사본은 master 병합 검사를 깨뜨린다. 리뷰어의 별도 사본은 T3의 `delegate_task` 작업 사본 격리만 쓰고, 리뷰어에게도 하위 에이전트를 작업 사본 격리로 띄우지 말라고 지시한다.
> - 리뷰 기록의 `## 커밋` 표에는 기준 SHA가 대상 SHA의 엄격한 조상인 회차만 싣는다. 코드가 없는 사전 검토(기준=대상)는 표에 넣지 않고 본문에만 적는다.
> - **리뷰 회차 등급(2026-11-17 사용자 결정, 위의 "최대 3회차" 문장보다 우선)**: 작업 절에 `리뷰 등급: N`이 적혀 있으면 독립 리뷰·비판은 최대 N회차다. 등급 3(하네스, 보안·권한, 금액·수량·환율 계산, 주문 관련): 지금처럼 차단·중요가 0이 될 때까지 최대 3회차. 등급 2(일반 유스케이스, 저장소, 외부 연동): 최대 2회차. 등급 1(문서, 기계적 연결, 화면 배치·표시): 1회차. 마지막 회차에서 실행으로 재현된 차단·중요 지적은 고치고, 추가 독립 리뷰 없이 수정 범위(기준 SHA → 수정 SHA)와 회귀 테스트·변이 결과를 기록에 적고 완료로 보고한다. 등급이 적혀 있지 않으면 3이다. 작업 중 범위가 계산·보안에 닿는 것으로 드러나면 스스로 등급을 올리고 보고에 적는다(내리지는 않는다).
> - **부하 제한**: 같은 기계에서 여러 스레드가 돈다(16코어). cargo·nextest를 돌릴 때 `CARGO_BUILD_JOBS=4`와 `NEXTEST_TEST_THREADS=4`를 환경에 둔다(커밋 훅이 도는 `git commit`에도). 하위 에이전트에게도 같은 값을 쓰게 한다. 변이 실행의 병렬도도 2 이하로 둔다.
> - **최종 검사 영수증**: 최신 `master`를 받은 최종 커밋이 정상 훅의 전체 검사(`check`)를 통과하면, 그 직후 작업 사본의 `target/<작업 ID>/final-check.json`에 `{"head": "<최종 커밋 전체 SHA>", "recipe": "check", "exit": 0}`을 쓴다(훅이 실제로 `check`를 돌려 통과한 경우에만. `LEFTHOOK=0` 예외를 쓴 커밋이면 쓰지 않는다). 메인은 이 영수증이 있고 병합 결과가 문서·생성 등록만 다르면 병합 때 전체 검사를 다시 돌리지 않는다. 사실과 다른 영수증은 쓰지 않는다.
> - **홈 파일 열람 금지(하위 에이전트 포함)**: 사용자 홈의 설정·메모리·자격 증명(`~/.codex/**`, `~/.claude*/**`, `MEMORY.md` 류, 키체인, 셸 기록)은 읽지 않는다. 리뷰·비판·조사를 맡길 때 브리프에 이 문장을 그대로 넣는다.
> - 리뷰 기록 `## 커밋` 표의 기준·대상 SHA는 **최종 브랜치 끝에서 도달할 수 있는 커밋**이어야 한다. 리뷰를 받은 커밋을 나중에 합치거나(squash) 다시 쓰지 않는다(rebase·amend 금지). 원격 CI는 master에서 도달할 수 없는 SHA를 "저장소에 없는 커밋"으로 거부한다(T-03에서 실제로 CI가 하루 넘게 실패했다).
> - **리뷰 기록 형식(H-52, ADR 0128 이후. 위의 옛 형식 설명보다 우선)**: `docs/workflow.md`의 리뷰 기록 절과 본보기 `docs/reviews/H-52.md`를 따른다. `## 측정` 표에 `리뷰 등급`과 `리뷰 회차` 행을 각각 한 번 적고, 회차마다 `## 리뷰 (회차 N)` 절을 순서대로 둔다. 커밋 표의 실제 리뷰 회차 수와 측정의 회차가 같고 등급을 넘지 않는다. 마지막 회차 뒤 수정은 `N (… 수정)` 행이다. 최종 검사 영수증(`final-check.json`)은 계속 쓰되, 메인은 서명자 등록 전까지 그것만으로 병합 검사를 생략하지 않는다.
> - **빠진 계약을 만났을 때(2026-11-18 메인 결정, 작업 절의 "만들지 말고 정의 대기" 문장보다 우선)**: 작업을 통째로 정의 대기로 끝내지 않는다. (가) application의 포트에 메서드를 더하거나, 기존 포트 메서드의 반환 타입을 호출자가 필요한 사실을 담도록 넓히거나(예: 단위 성공값 → 바뀜/같음), 최소한의 새 포트 trait를 두는 것은 **직접 한다**: 가짜·기존 구현·호출부를 함께 맞추고, 무엇을 왜 바꿨는지 ADR의 "결정"에 적고, 그에 따른 기존 테스트의 준비·호출부 변경은 사전 승인 (b)·(d)로 처리한다. (나) domain에 값을 나르는 타입이나 이미 문서가 정한 규칙을 옮기는 함수를 더하는 것도 직접 한다. (다) **문서에 없는 계산 규칙·정책을 새로 정해야 하는 경우**(금액·수량·확률·시각 판정, 무엇을 같은 것으로 볼지 등)만 그 부분을 정의 대기로 남기고, 그 부분을 뺀 나머지는 구현한다. 그때도 가장 보수적이고 단순한 규칙을 ADR에 "제안"으로 적어 메인이 바로 승인할 수 있게 한다. 구현이 하나도 없는 "분석만 한" 결과는 완료가 아니다.

> - **쓸 수 있는 제공자는 둘뿐이다(사용자 지시 2026-11-23)**: Codex(`providerInstanceId: codex`)와 Claude2(`providerInstanceId: claudeAgent_claude2`). 적대적 리뷰의 Claude Opus 5.5는 반드시 `claudeAgent_claude2`로 띄운다. `claudeAgent`(첫 번째 Claude 계정), Antigravity 등 다른 제공자는 쓰지 않는다. 지정한 제공자를 쓸 수 없으면 다른 것으로 바꾸지 말고 "막힘:"으로 보고한다.

메인의 입력 판정 결정: 편집 가능한 글자 입력 input의 자기 가로 내용 초과와 계산된 overflow-y가 auto·scroll인 편집 가능한 textarea의 자기 세로 내용 초과만 면제한다. 입력 상자의 부모 밖 넘침, textarea 가로 초과와 hidden·visible 세로 초과, 일반 요소와 레이블·도움말·오류 문구는 계속 검출한다.
