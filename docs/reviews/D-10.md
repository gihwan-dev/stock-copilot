# 리뷰 기록 D-10 (MarketSession 장 상태 판정, 도메인 시간 타입)

## 커밋

| 회차 | 기준 SHA | 대상 SHA |
|---|---|---|
| 1 | 827fb73 | 9026dd9 |

구현과 수정은 Codex `gpt-6.1-sol`(T3 스레드, 작업 사본 `d-10`). 리뷰어는 회차 1에 새 Claude Opus 5.5 서브에이전트. 회차 2는 메인이 공개 API와 구현 담당의 변형 결과를 읽고 평가했다. 결정은 ADR 0028에 있다. D-02, D-16, D-19, DS-02와 병렬로 진행했다.

**비판 단계를 생략했다.** 리뷰어가 지적을 임시 crate에서 재현했고 메인이 전부 판정했다.

## 의존성

`time` 0.3.55를 `domain`에 더했다(기본 기능 끔, 추가 기능 없음). 이미 잠금 파일에 있던 버전이고 새 잠금 패키지는 없다. 시간대 DB는 더하지 않았다. 토스 캘린더가 오프셋이 붙은 시각을 주므로 서머타임을 그 값으로 처리한다.

## 리뷰 (회차 1)

| 번호 | 등급 | 지적 | 평가 |
|---|---|---|---|
| 1 | 중요 | 행 하나만 받아 잘못 고른 행·낡은 행에도 그럴듯한 상태가 나옴(3/25 10:00 KST에 3/24 행은 `Ended`, 3/25 행은 `DayMarket`) | 수정: 세 행을 받는 `MarketCalendar`가 행을 고르고 범위 밖은 `Unknown` |
| 2 | 중요 | 세션 시각과 다음 전이 시각을 꺼낼 수 없고 기간 타입과 checked 산술이 없음 | 수정: 다음 전이, 세션 접근자, `TimeSpan`, checked 더하기·빼기 |
| 3 | 중요 | `time`의 serde 기능을 켜도 arch-check가 잡지 못함 | 수정: `feature-allowlist`에 `time`과 `rust_decimal` |
| 4 | 사소 | 같은 시점·다른 오프셋이 `==`인데 날짜가 다름 | 수정: 접근자 이름에 "오프셋 기준"을 드러냄 |
| 5 | 사소 | 세션 순서를 필드 순서로 고정 검사 | 수정: 시작 시각으로 정렬 후 겹침 검사 |
| 6 | 사소 | `date`와 세션 시각의 정합 미검사 | 수정: 24시간 상한, 국내는 KST 날짜 일치, 미국은 보수적 범위 |
| 7 | 사소 | 단일가 시각 세 개를 표현할 수 없음 | 수정: 선택 필드로 보존 |
| 8 | 사소 | 시장 정보 이중 보관 | 수정: 변형에서 유도 |
| 9 | 사소 | 어댑터가 `time` 타입을 직접 만들어 넘겨야 함 | 수정: 공개 API에서 `time` 타입 제거, 구성 요소에서 검증 생성 |
| 10~11 | 사소 | 약한 속성 테스트, 항진명제인 DST 일요일 테스트 | 수정: 독립 기준과 대조, 4,096회 |
| 12 | 사소 | `now` 직접 호출은 source-check 하나로만 막힘 | 그대로. 검사가 잡음을 리뷰어가 확인 |

## 메모

- 회차 2: `just mutants-diff` 318개 중 209개 검출, 109개 컴파일 불가, 생존 0개. 수동 변형 7개 모두 검출. 첫 자동 변이에서 살아남은 5개는 경계 테스트를 보강해 없앴다.
- 세션 밖의 시각은 세 행의 첫 세션 시작부터 마지막 종료 전까지 `Closed`, 그 밖은 `Unknown`이다.
- 실제 토스 응답 녹화로 서머타임 전후를 검증하는 것은 T-08에 넘겼다.
- 회차 2 수정분은 Opus 재리뷰를 하지 않았다.
