# 리뷰 기록 H-43 (변이 검사 범위: 매크로 해석과 추가 전용 변경)

## 커밋

|---|---|---|
| 1 | 4c46c32 | 78e5ad5 |
| 2 | 78e5ad5 | 41c8da7 |

구현과 수정은 Codex `gpt-6.1-sol`(T3 스레드, H-42와 같은 작업 사본의 브랜치 `h-43`). 리뷰어는 회차 1에 새 Claude Opus 5.5 서브에이전트. 회차 2는 메인이 수정 보고와 검증 결과를 읽고 평가했다. 결정은 ADR 0054에 있다.

**비판 단계를 생략했다.** 리뷰어가 차단 지적을 변이 생존까지 재현했고 메인이 전부 수정으로 판정했다.

## 배경

H-42 뒤에도 `crates/domain`의 어떤 변경이든 변이 범위가 crate 전체였다. 테스트의 매크로 안 참조를 해석하지 못했고, 흔한 변경인 "새 모듈 파일 추가와 `lib.rs` 등록"이 전체로 넓혀졌다. 이 작업은 두 가지를 더했다. 매크로의 토큰을 보수적으로 읽어 참조 그래프에 넣는다. 기존 항목을 하나도 바꾸지 않고 새 항목만 더한 변경은 새 코드가 있는 파일만 변이한다(기존 코드가 그대로이고 기존 테스트의 변경은 `test-diff`가 같은 기준으로 막으므로 기존 파일의 변이 결과가 달라질 수 없다).

## 리뷰 (회차 1)

리뷰어가 추가 전용 판정을 속이는 변경 열두 가지를 시도했다. 불확실하면 넓은 쪽으로 가는 분기, 혼합 변경의 합집합, `test-diff`와의 연결(끌 수 있는 인자 없음)은 확인됐다. 손 변형 31개 중 22개 검출.

| 번호 | 등급 | 지적 | 평가 |
|---|---|---|---|
| 1 | 차단 | 열 번호(문자 단위)를 바이트 위치로 써서, 한글이 든 기존 항목이 바뀌어도 "그대로"로 판정. 그 상수를 쓰는 파일이 범위에서 빠지고 변이가 생존 | 수정: 원문을 자르지 않고 파싱한 항목의 토큰을 비교. 한글·이모지·결합 문자·raw 문자열 회귀 테스트 |
| 2 | 중요 | `r#drop`, `r#Option` 같은 raw 식별자가 "새 이름" 검사를 통과해 기존 코드의 이름 해석을 바꿀 수 있음 | 수정: 모든 이름 비교에서 `r#`를 정규화. 표준 prelude와 외부 이름과 겹치면 추가 전용이 아님 |
| 3 | 중요 | ADR에 규칙의 전제가 빠졌고, 건전성 대조의 표본 대부분이 사실상 crate 전체라 증거가 약함 | 수정: 전제 목록. 위치 매크로가 있는 파일과 blanket impl·trait 객체는 넓힘. 좁게 선택된 이력에서 빠진 파일의 변이를 직접 대조 |
| 4 | 사소 | 생존 손 변형 다섯 개 | 수정: 회귀 테스트 |
| 5 | 사소 | `build.rs`·`examples`·`benches`를 더하면 선택이 빈 집합 | 수정: crate 전체로 넓힘 |
| 6 | 사소 | `mod core;` 같은 외부 이름의 모듈 등록 | 수정: 추가 전용이 아님 |

## 메모

- 효과(각 병합 커밋의 첫 부모 대비 변경에 적용): D-20은 1,200개에서 76개(4개 파일, 실행 7분 13초), D-23은 1,289개에서 89개(1개 파일, 5분 8초). 기존 `impl` 블록이나 테스트 모듈 구조를 건드린 D-05, D-06, D-28, D-32는 여전히 99% 이상이다. 구현 담당에게 "기존 `impl`에 메서드를 더하지 말고 새 파일에 둔다"를 안내한다.
- 건전성 증거: D-20과 D-23에서 범위에서 빠진 파일(45개, 49개)의 변이 표본 453개를 기준 커밋과 변경 뒤 커밋에서 각각 돌렸다(총 906회). 결과 차이 0, 새 생존 0, 시간 초과 0.
- 남는 구멍: 다른 crate를 거치는 영향, crate 밖 입력과 환경, 매크로 버전이 바뀔 때의 허용 표. 밤 전체 변이 검사가 보완한다.
- 리뷰어 환경에서 `weak_test_example_leaves_surviving_mutants`가 한 번 실패했다. 재현되지 않았다. 부하 때문인지 단정할 수 없다.
- 회차 3: `master`와 병합하자 실제 `crates/domain` 소스를 입력으로 쓰던 회귀 테스트가 깨졌다(새 파일의 `#[should_panic]` 속성을 그래프가 해석하지 못해 넓은 쪽으로 갔는데 테스트가 "넓히지 않는다"고 단정). 실제 소스에 기대는 테스트를 고정 소스로 바꿨다. `should_panic`을 알려진 속성으로 등록하는 것은 후속이다(지금은 그 파일이 있으면 범위가 넓어진다).
- 회차 2와 3의 수정분은 Opus 재리뷰를 하지 않았다.
