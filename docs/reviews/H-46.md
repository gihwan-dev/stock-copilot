구현과 수정은 Codex `gpt-6.1-sol`(T3 스레드, 작업 사본 `h-46`). 리뷰어는 회차 1에 새 Claude Opus 5.5 서브에이전트. 회차 2는 메인이 수정 보고를 읽고 평가했고, 회차 3은 그 사이 `master`에 들어온 D-26·A-19를 받아 맞춘 것이다. 결정은 ADR 0078에 있다.

**비판 단계를 생략했다.** 리뷰어가 임시 저장소 실험으로 재현했고 메인이 지적 전부를 수정 또는 규칙으로 판정했다.

## 배경

작업 스레드의 커밋마다 전체 검사(10~30분)가 돌았고 여러 스레드가 겹치면 서로를 느리게 했다. 사용자가 하네스·설계 결정을 메인에 위임했고, 메인이 "`master`에 들어가는 시점의 검사 강도는 그대로 두고 그 앞을 빠르게"로 정했다.

## 리뷰 (회차 1)

우회 30여 가지에서 `master`의 커밋이 빠른 검사로 빠지는 길은 없었다. 속성 테스트 치환 97곳은 횟수 인자만 바뀌었다. 손 변형 유효 14개 중 10개 검출.

| 번호 | 등급 | 지적 | 평가 |
|---|---|---|---|
| 1 | 차단 | 횟수 도우미 본문 한 줄로 전체 검사의 속성 테스트를 4096회에서 256회로 낮출 수 있고 `test-diff`가 못 잡음 | 수정: 공개 함수를 실제 환경에서 단언하는 테스트, 도우미 파일을 `test-diff` 지원 파일로 등록, 그 파일이 바뀌면 전체로 승격 |
| 2 | 중요 | `master`가 fast-forward·`branch -f`·`update-ref`로 훅 없이 전진할 수 있음 | 메인 결정: 장치를 더하지 않고 규칙으로 닫음. `master`는 메인만 움직이고 `--no-ff` 병합 커밋이나 직접 커밋으로만 전진. 한계를 문서에 사실대로 적음. 구현 담당 가드가 해당 명령을 막는지 확인 |
| 3 | 중요 | 밤 전체 변이가 한 번도 완주하지 못했다는 사실이 문서에 없음 | 수정: 사실대로 기록, H-47로 인계. 변이 실행은 기본 256회 |
| 4 | 중요 | 삭제한 테스트 가운데 선택기와 무관한 계약이 대체 없이 사라짐 | 수정: 넷 복원(조각 허용 범위, 환경 키, diff 포함 범위, 변이 전 `test-diff` 요구) |
| 5 | 사소 | 문서만 바뀐 변경의 범위, 고정 안 된 분기 둘, 남은 횟수 리터럴, 훅 통합 테스트가 두 경로를 구분 못 함 | 수정: `docs/**`는 전체로 승격, 숫자 `with_cases` 리터럴을 막는 소스 검사 |

## 승인한 기존 테스트 변경과 훅을 건너뛴 커밋

메인이 사전 승인한 변경: 제품 테스트의 속성 테스트 횟수 표현 치환(인자만), 제거한 변이 선택기의 테스트 80개 삭제, 새 설계에 맞게 같은 강도로 고친 하네스 테스트. `test-diff`가 이 304건을 막으므로 작업 스레드의 해당 커밋들과 이 병합은, 그 외 전체 검사 통과를 확인한 뒤 훅 없이 만들었다.

## 메모

- 작업 브랜치의 커밋 훅은 `check-fast`(바뀐 crate와 역의존 crate의 clippy·테스트, 정적 검사, `test-diff` 등), `master`의 커밋·푸시·CI는 전체 검사다. 하네스·설정·문서·판정할 수 없는 경로가 바뀌면 전체로 승격한다.
- 느렸던 `arch_check` 테스트는 101초에서 28초로 줄었다.
- 과거 변경의 변이 실측에서 미검출이 나왔다(D-29 15건과 시간 초과 3건, D-37 4건). 테스트 보강은 D-42.
- 밤 전체 변이는 완주 기록이 없다(조각이 120분에 취소, macOS 전체 검사 실패). H-47.
- 회차 2·3의 수정분은 Opus 재리뷰를 하지 않았다. 손 변형 18개 모두 검출.
