## 리뷰 (회차 1)

### 차단 수정분 좁은 확인 (Claude Opus 5.5, `46d519a5` → `f04c65e6`)

- 4·5·7·8·9번: **닫힘** 확인. 1·2번: 보호 경로(`crates/xtask`)와 기존 테스트 4개 파일 제약 범위 안에서 상태 머신 보강·`proven_*` D-38 계약·문서·인계 완료 확인. 새 결함·회귀·규칙 위반 없음 확인.
- 좁은 확인에서 남은 지적 3건 조치:
  - **R-1 [중요]** (`ClosedOrderSet::new` 제거 및 `xtask arch-check` 호출 제한): `docs/tasks.md` 및 `crates/xtask`·기존 테스트 변경 권한은 메인 몫이므로 ADR 인계와 최종 보고에 H-64 선례 기반 후속 작업 등록 요청을 명시했다.
  - **R-2 [사소]** (`order_read.rs` 행 상한이 유효 행만 세어 전부 미식별/중복 행이면 8192페이지 진행 가능): `50cc15ec`에서 `open_orders`·`closed_orders` 모두 전체 읽은 행(`seen_rows`)을 4096 상한에 산입하고 4097건 미식별 행 중단 테스트(`closed_orders_row_limit_counts_rejected_rows_to_stop_pagination`)를 추가했다.
  - **R-3 [사소]** (`net_purchase.rs::validate_query`에서 `verify_for_period` 뒤 기존 `covered` 검사가 중복되어 변이 생존 우려): `50cc15ec`에서 `if let Some(proof) = orders.completeness_proof() { return proof.verify_for_period(period); }` 단일 경로로 분리해 중복을 제거했고, 후속 `mutants-daily`에서 `net_purchase.rs` 미검출 0건으로 검증했다.

## 메인 평가

- 판정: 수용. 주문 한 건, 미체결 목록, 종료 주문 목록 조회를 구현했다(GET만). 종료 주문 조회는 필터 없이 페이지 끝까지 읽고, 거부·식별 불가·중복·부분 체결 혼입·미래 시각 행이 없고, 관측 시각이 평가 구간 끝 이후일 때만 "완전"으로 선언된다. 완전성 증거는 외부에서 만들 수 없는 타입이고, 순매수 계산(D-38)은 증명된 집합만 받는 경로가 생겼다. 필터를 건 미체결 조회는 완전한 집합으로 선언되지 않는다.
- 1회차 리뷰에서 차단 지적(수집기를 밖에서 불러 "완전"을 만들 수 있음, 증거가 실제로 소비되지 않음)이 나와 고쳤고 확인 리뷰를 받았다. 다만 수집기의 시작 함수는 아직 어느 크레이트에서나 부를 수 있다(어댑터 신뢰 경계). 호출 위치 제한은 H-69로, 기존 `ClosedOrderSet::new` 제거는 D-59로 넘긴다.
- 정의 대기 4건의 메인 결정: 전부 현행 유지(페이지 끝 도달로 완전 선언하되 보관 기간은 T-13 실측으로 보강, 종료 목록의 부분 체결 행은 거부해 불완전으로, 체결 수수료·세금·결제일은 어댑터에서 검증만, 상장폐지 종목의 과거 주문은 불완전으로).
- 금액 주문 응답의 수량 등 실제 키가 필요한 실측은 T-13에서 사용자가 한다.
- 인계: H-69(수집기 시작 함수의 호출 위치 제한), D-59(증명된 집합으로 이행하고 공개 생성자 제거), T-13(실측).
