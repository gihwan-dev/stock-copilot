## 실제 실행

GitHub Actions에서 `h-16` 브랜치 푸시 4회(0d77ed9, a39c224, 09b3538, 2d3995a)의 서명 작업과 Linux 작업이 성공했다. Linux 작업은 약 4분 30초, 네트워크 이름공간 안에서 Rust 테스트 209개. 서명 작업은 기준 `master`에 검증 스크립트가 없어 "비활성"을 출력했다.

## 병합 뒤 macOS 러너에서 드러난 실패

`master` 푸시에서만 도는 macOS 전체 검사가 세 번 실패했고 네 번째 실행(299c20d)에서 서명·Linux·macOS 작업이 모두 성공했다. 셋 다 검사가 개발 컴퓨터의 환경에 기대고 있던 것이다.

| 실패 | 원인 | 수정 |
|---|---|---|
| Vitest 설정 키 빼기 테스트 | `allowOnly` 기본값이 `CI` 변수에 따라 달라짐 | Vitest에 허용 목록 환경만 넘김 (ae1b2f3) |
| 훅의 오프라인 설치 테스트 | 러너의 `pnpm`은 corepack이라 고정 버전이 캐시에 없으면 네트워크를 찾음 | CI가 고정 버전을 corepack 전역 기본으로 먼저 설치 (4c19b98) |
| 서명 기준 셸 테스트 3개 | 러너에서 가짜 `gh` 대신 진짜 `gh`가 실행됨(셸 설정 파일이 `PATH`를 바꾼 것으로 추정) | 자식 프로세스에 허용 목록 환경, `bash --noprofile --norc`, 임시 `HOME`. 임시 폴더 경쟁 상태도 수정 (68b0baa) |

이 세 수정은 리뷰하지 않았다.

## 훅을 건너뛴 푸시

a39c224 푸시 한 번. 푸시 훅이 원격 브랜치의 이전 끝을 기준으로 삼아, 이 브랜치에서 새로 만든 테스트를 수정 회차에 고친 것을 기존 테스트 변경으로 막았다. 커밋 훅의 전체 검사는 통과한 상태였다. 회차 3에서 `master`가 아닌 브랜치의 푸시 기준을 `origin/master`와의 병합 기준으로 바꿨다.

## 메모

- 리뷰 기록 9개가 리베이스 전 커밋을 적고 있어 새 클론에서 검사가 실패했다. `master`의 같은 제목 커밋으로 바꿨다.
- 회차 3 수정분은 재리뷰하지 않았다.
- 작업 흐름 파일 자체를 같은 푸시에서 바꾸면 CI 검사를 피할 수 있다(ADR 0020 남는 빈틈). 알려진 빈틈은 50건이다.
- 디스크가 가득 차(남은 공간 185MB) 회차 1 리뷰의 일부 실험을 돌리지 못했다. 병합된 작업 사본의 `target/`을 지웠다.
