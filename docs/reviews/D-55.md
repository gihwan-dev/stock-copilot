## 메인 평가

- 판정: 수용. (1) 사용자가 확인한 코드·ISIN 변경만 기존 내부 ID의 이력에 잇는다. 확인 사실은 복제·위조할 수 없는 일회성 값이고, 증거가 부족하거나 출처가 증권사 관측·AI 제안이면 지금처럼 `IdentityUncertain`이다. 충돌(다른 ID에 묶인 원본, 부분 겹침, 시장 불일치)은 상태를 바꾸지 않고 거부하며, 잘못 기록한 폐지·연결은 증거를 갖춘 확인으로만 되돌리고 감사 이력은 남긴다. (2) 후보 내부 ID는 독립 발급원만 만들 수 있는 일회성 값이라 심볼·임의 ID를 후보로 넘기는 호출은 컴파일되지 않는다(컴파일 실패 프로브 18개).
- 등급 3 가운데 2회차에서 끝냈다(2회차에 새 차단·중요 지적 없음).
- 기존 테스트 변경 30건(`support-modified` 7, `modified` 23, 파일 5개)은 메인이 차이를 직접 읽고 승인했다: `ensure`·`issue`가 발급된 후보 타입을 받게 되면서 준비 코드의 후보 생성과 호출 인자만 바뀌었고, 각 테스트의 단언과 기대 결과는 그대로다. 구조 보존 규칙이 승인 목록으로 해소하지 못하는 형태라(H-62에서 절차를 정한다) 이 병합은 병합 커밋을 따로 전체 검사해 `test-diff`가 정확히 이 30건만 보고하는 것을 확인한 뒤 훅 없이 커밋한다.
- 정의 대기 11건에 대한 메인 결정: 모두 현재 구현의 보수적인 쪽을 유지한다(확인에는 공시 + 기업행위 + 사유, 정정에는 공시 + 사유, 연결 정정은 가장 최근 연결만, 폐지 뒤 같은 심볼의 다른 법인은 `IdentityUncertain`, 합병·교환 등 미확정 기업행위는 `IdentityUncertain`). 확인 화면에서 실제 사용 사례가 나오면 넓힌다. 발급원의 영속 형식(10번)은 S-21이 SQLite 단조 순번 + 복원 생성자로 맞춘다. 감사 이력의 시각 역행(11번)은 순번을 우선하고 시각은 검증하지 않는다.
- 인계: S-21(바뀐 포트 서명 `issue`·`ensure`에 맞춤, 이력·정정의 영속), 확인 화면과 그 유스케이스(확인 값을 발급하는 유일한 경로), H-62.
