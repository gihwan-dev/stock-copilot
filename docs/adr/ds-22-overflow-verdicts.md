# DS-22 부하 이야기 넘침 판정

- 상태: 초안

## 배경

DS-20의 고정 Chromium 실행에서 1,034개 테마 이야기 중 174개 이야기의 544조건에 판정이 있었다. 한 조건에 여러 판정이 겹칠 수 있다. 이번 변경은 기존 이야기와 부하 자료를 줄이지 않는다.

## 결정

- 메인 결정에 따라 편집 가능한 한 줄 텍스트·숫자 입력의 가로 내용 스크롤과 편집 가능한 textarea의 실제로 스크롤 가능한 세로 내용 초과만 해당 축의 내용 크기 판정에서 면제한다. 숫자 입력도 숫자를 직접 치면 자체 가로 스크롤이 생긴다. input 타입은 브라우저가 해석한 값을 써서 알 수 없는 타입의 text 대체 동작도 따른다. 읽기 전용·비활성 입력과 실제 inert 입력은 면제하지 않는다. 네이티브 모달 밖은 inert이며 모달 안에서는 모달 자신의 inert와 그 내부 조상의 inert만 적용된다. 속성과 CSS interactivity를 모달 경계까지 검사한다. Base UI의 aria-hidden과 data-base-ui-inert 표식만으로 네이티브 inert를 추정하지 않는다. 글자를 받지 않는 입력 타입, textarea 가로 초과, 스크롤할 수 없는 textarea 세로 초과, 컨트롤 상자와 주변 문구의 넘침은 계속 검사한다. 입력과 textarea는 생략 표식이 있어도 실제 초과를 검사한다. ADR 0129의 의도된 입력 내부 스크롤 인계를 해소한다.
- IBM Plex Sans KR의 텍스트 노드에서 실제 줄 사각형이 첫 줄 위와 마지막 줄 아래에 각각 최대 1px만 뻗고 글줄과 요소 자신을 포함한 모든 관련 자르기 경계가 창 안에 있는 경우, 이 글꼴 지표만 내용 크기 오탐에서 제외한다. 여러 줄도 각 사각형을 검사한다. 같은 1px 지표가 부모로 전파되는 경우 단일 자식, 자식 상자의 실제 경계, 가상 요소와 자르기 여부를 확인한다. 다른 축의 초과, 자르는 자신이나 조상, 마스크, 1px 실제 자식 넘침과 가상 요소는 면제하지 않는다. 마스크 모양을 해석하지 않고 값이 있으면 예외를 주지 않는다. body 스크롤 잠금이 뷰포트에 전파되는 경우의 고정 대화 상자는 실제 뷰포트 경계로 판정한다.
- 화면 읽기용으로 완전히 숨긴 표는 정확한 표·래퍼 구조와 계산된 크기·자르기 스타일을 모두 확인하고 해당 표의 내용 크기와 잘림만 제외한다. 나머지 판정은 그대로 실행한다. 보이는 가짜 표식, 부분 clip-path, 표 밖의 실제 넘침과 숨긴 비표 요소는 계속 보고한다.
- EmptyState, TextField, Checkbox, Switch, Heading, Select의 텍스트는 기존 status-sentence 유틸리티로 줄을 바꾼다. 공개 속성이나 토큰을 바꾸지 않고 긴 글을 자르지 않는다. 버튼 높이, 숫자 줄바꿈과 표·차트의 스크롤 배치처럼 겉모습의 결정이 필요한 항목은 고치지 않는다.
- just ds-check는 카탈로그·브라우저 타입·보류 대조 회귀와 고정 브라우저 전체 실행을 차례로 수행한다. 카탈로그 판정 대상은 기존 태그·id와 문서 루트부터의 nth-child 구조 경로를 함께 기록해 같은 태그라도 서로 구분한다. 보류 표의 이야기 ID, 폭, 글자 크기와 판정 종류·요소가 관찰과 정확히 일치해야만 성공한다. 보류가 늘거나 줄거나 판정이 바뀌면 실패한다. 보류 일치는 잔여 UI 문제가 없다는 뜻이 아니다.
- 네이티브 모달이 하나면 그 요소를 쓰고, 여러 개면 현재 포커스를 가진 모달을 쓴다. 여러 모달이 열렸지만 포커스로 최상단을 식별할 수 없는 데 자체 내용 스크롤 판정이 필요한 컨트롤이 있으면 layout-unavailable을 보고하고 나머지 넘침 검사도 계속한다. 보류 비교기는 layout-unavailable을 허용하지 않으므로 불확실성을 성공으로 바꿀 수 없다. 검사를 위해 포커스를 이동하지 않는다.

[HTML 표준의 모달과 inert 규칙](https://html.spec.whatwg.org/multipage/interaction.html#modal-dialogs-and-inert-subtrees)은 최상단 모달의 바깥을 비활성화하고 모달이 조상의 inert를 벗어나게 한다. 모달 순서는 DOM 순서가 아니다.

## 인계

- DS-11: 표·차트·긴 본문과 줄바꿈 없는 숫자가 놓일 스크롤 영역 및 좁은 폭의 배치를 결정한다.
- DS-12: 정식 공개 목록 잠금과 화면 상태 검사에 ds-check를 연결할 때 보류 표를 그대로 통과 판정으로 오해하지 않는다.
- DS-12: 현재 검사기는 문서의 일반 DOM을 순회한다. 열린·닫힌 shadow root 안의 네이티브 모달이 바깥 일반 DOM 입력을 inert로 만들어도 모달이 없는 것으로 보아 해당 입력의 자체 초과를 면제할 수 있다. slot을 통한 inert 조상도 일반 DOM 조상 탐색에 보이지 않는다. 실제 Chromium에서 두 경계를 확인했다. 앱 직접 소스에서는 shadow root와 네이티브 모달 사용을 찾지 못했으나 의존성 전체에 대한 증명은 아니다. 닫힌 root를 관찰하는 방법, 최상단 모달 순서와 포커스 이동의 부작용을 포함해 측정 계약과 브라우저 지원을 따로 정한다.
- 메인: 고정 높이 버튼, 체크 표시기, 상태 띠, 배지 및 대화 상자의 긴 문구 처리와 보류 표의 각 표시 결정을 검토한다.

## 검증

고정 브라우저 회귀에는 각 입력 축의 허용·비허용, 레이블·도움말·오류 문구, 실제 500행 접근성 표, 거짓 숨김 표식, 실제 1px 넘침, 스크롤 잠금된 대화 상자와 paint 자르기 반례가 있다. 입력 자체 스크롤의 독립 사례 8건, 실제 두 차트의 숨긴 표 2건, 여러 줄 글꼴과 대화 상자의 글꼴 사례, 긴 제목·선택 문구 사례는 수정 전 실패를 확인했다. ds-check는 406초에 종료 0이었고 전체 1,034개 이야기의 224조건이 보류 표와 일치했다. 이 실행의 브라우저 예제는 118개였다. 이후 비활성 입력과 표시된 textarea 반례를 더하고 EmptyState의 기존 클래스 단언을 유지하도록 수정한 뒤, 별도 실행한 브라우저 예제 120개와 DS-19 기존 테스트가 통과했다. EmptyState가 포함된 840번 배치의 34조건도 보류 표와 다시 일치했다.

별도 복사본의 고정 Chromium 반례에서는 생략 표식이 붙은 textarea의 가로·세로 초과 두 건이 수정 전 누락되고 수정 후 보고됐다. 숫자 input과 브라우저가 text로 대체하는 미지원 타입의 자체 스크롤 두 건도 수정 전 잘못 보고되고 수정 후 면제됐다. 이 반례를 추가한 판정 예제 124개가 통과했다. 이후 ds-check 재실행은 482.59초에 종료 0이었고 1,034개 이야기의 보류 224조건과 정확히 일치했다.

1차 독립 리뷰와 비판에서 글꼴 지표의 부모 전파, 같은 태그 사이의 판정 대상 이동, 요소 자신이 자르는 글꼴 지표, 자신이나 조상이 inert인 입력을 재현했다. 수정 전 새 고정 브라우저 회귀는 133개 중 위 네 종류에 해당하는 8개가 실패했다. 수정 후 ds-check는 385.98초에 종료 0이었고 예제 146개와 전체 1,034개 이야기를 실행했다. 보류는 224조건·600건으로 일치했으며, 이전 판정의 종류·태그·id로 다시 대조해 모든 조건의 다중집합과 이유가 같음을 확인했다. 구조 경로를 더한 같은 조건의 판정은 종류와 경로의 조합으로 서로 구별된다.

2차 리뷰와 비판은 네이티브 모달 바깥의 input·textarea 누락과 inert 조상 안 모달의 정상 입력 오탐을 각각 재현했다. DOM 순서와 모달을 연 순서가 다를 수 있으며, 서로 다른 순서의 모달 두 개에서 포커스를 지우면 DOM·activeElement가 같아도 편집 가능한 입력이 달라짐을 고정 Chromium에서 확인했다. 이 경우의 layout-unavailable은 확인되지 않은 순서를 추측하지 않기 위한 보수적 실패다. 2차 수정 전 회귀는 166개 중 14개가 실패했다. 투명 마스크의 실제 글자 소실도 비판자가 픽셀로 확인했으나 불투명 마스크 사례의 글자 획이 잘렸다는 결론은 내리지 않았다.

첫 모달 수정에서는 172개 예제와 1,034개 이야기의 224조건이 427.54초에 일치했다. 이어서 순서 미확정과 무관하게 판정 가능한 읽기 전용·비활성 입력과 숨겨진 세로·가로만 넘치는 textarea도 layout-unavailable을 받는 반례 4개를 새로 확인했다. 해당 네 사례는 수정 전 실패했고, 내용 스크롤 면제에 실제로 필요한 축과 컨트롤만 불확실성 검사에 포함한 후 최종 ds-check가 436.72초에 종료 0이었다. 예제 180개와 1,034개 이야기를 실행했고 보류 224조건과 정확히 일치했다.

이후 CSS interactivity를 지원하지 않는 환경의 inert 속성 회귀를 추가해 고정 Chromium 예제 181개를 별도로 통과했다. 그 한 사례는 Chromium에서 계산 스타일 반환만 미지원 환경처럼 대체하며, 실제 WKWebView에서도 같은 속성 검사의 원본·변형을 비교했다. 카탈로그 이야기나 판정 코드는 직전 ds-check 이후 바꾸지 않았다.

macOS WKWebView의 기존 기하 예제 24개가 통과했다. 별도 다섯 사례에서 모달 안팎, inert 조상을 벗어난 모달과 초점 없는 모달 순서의 보수적 실패를 확인했다. 이 WebKit에서는 CSS interactivity 계산값이 빈 문자열이었고 해당 CSS를 지정한 입력의 포커스가 가능했다. Chromium에서 지원하는 CSS interactivity의 비활성 동작과 혼동하지 않는다. 마스크의 표준·접두 속성은 두 경로 모두 계산값을 반환함을 확인했다.

3차 비판에서 `-webkit-mask-box-image`가 자신이나 부모의 글자를 가려도 글꼴 지표를 면제하는 사례가 재현됐다. 고정 Chromium에서 무마스크·자신·부모 세 사례 중 뒤의 두 사례가 수정 전 실패하고 수정 후 모두 통과했다. 표준 mask-border-source와 WebKit 접두 마스크 원본의 계산값을 자르기 경계에 포함했다. 실제 WKWebView에서도 이 속성을 지원하며 두 마스크의 자르기 경계가 수정 전 허용에서 수정 후 거부로 바뀌었다. 이 WebKit의 같은 글꼴 상자는 16/16이어서 실제 넘침 판정의 전후 비교로 세지 않는다.

마지막 `just ds-check`는 451.41초에 종료 0이었다. 고정 Chromium 예제 183개와 1,034개 이야기를 실행했고 보류 224조건과 정확히 일치했다.

고정 환경의 visual-check는 16.43초에 종료 0이었고 기준 이미지 8쌍이 바이트 단위로 일치했다. 이 여덟 쌍은 전체 부하 이야기의 시각 검토를 뜻하지 않는다.

고정 Chromium은 textarea에 overflow-y: visible을 지정해도 계산값을 auto로 바꾼다. visible 분기는 실제 내용이 넘치는 textarea의 계산 스타일 반환만 대체해 검증했다. hidden 분기와 auto·scroll 허용은 실제 계산값으로 검증했다.

## 병합 시 기존 테스트 준비

H-53~H-55를 받는 병합 중 H-54의 `로컬 master가 없는 브랜치 복제본에서 훅 진입 테스트가 통과한다`는 이전 HEAD의 복제본에 최신 agent-stop 테스트만 복사했다. 최신 테스트가 새로 가져오는 test-temp와 managed-temp 모듈이 복제본에 없어 모듈 로딩이 실패했다. 기존 테스트 한 건의 준비 단계에 두 모듈 복사를 추가하고 모든 기존 단언을 유지했다. 병합 후 HEAD에는 두 모듈이 이미 있으므로 복사 직전 복제본에서 각각 제거해 병합 전과 같은 준비 조건을 만든다. 수정 전 실패와 수정 후 통과, 병합된 HEAD에서 두 복사를 각각 제거한 변형의 실패를 확인했다. 파일 `harness/ci/tests/h54-branch-master.test.mjs`의 master 기준 SHA-256은 76150354bbf03d4b35d8a8f2ec7e493f246d8c06e7fb2c6b52b3fa7449ac98d7, 변경 후는 2cf7dae6638ae1980c914ba2c82c38c8182f83f95ba090a42e19cae9eaa57e00다. 이 준비 변경은 지시문의 기존 테스트 준비 사전 승인에 따르며 검사를 끄지 않는다. 훅 진입을 검증하는 하네스 테스트가 범위에 추가되어 리뷰 등급을 2에서 3으로 올린다.

## 손 변형

1~28번은 mktemp -d 복사본에서 TypeScript 컴파일을 통과한 뒤 고정 Chromium의 해당 회귀를 실제로 실행했다. 기준 복사본의 전체 예제가 먼저 통과했다. 29~37번은 별도 복사본에서 node --check와 보류 대조 Node 테스트를 실제로 실행했다. 38~40번은 보완 후 다른 복사본에서 TypeScript 컴파일과 고정 Chromium의 해당 회귀를 실행했다. 41~42번은 병합된 HEAD의 복제본에서 node --check와 H-54 테스트를 실행했다. 43~62번은 1차 리뷰 수정 뒤 다시 만든 복사본에서 TypeScript 컴파일과 고정 Chromium의 해당 회귀를 실행했다. 63번은 카탈로그 호출에서 구조 경로를 빼고 별도 복사본의 첫 60개 이야기를 실행한 뒤 실제 보류 대조를 수행했다. 8조건에 대해 새 판정 8건과 사라진 보류 8건이 각각 검출됐다. 64~85번은 2차 리뷰 수정 뒤 각각 TypeScript 컴파일과 고정 Chromium 회귀를 실행했다. 네 변형은 처음에 이름 축약으로 테스트가 선택되지 않아 제외한 뒤 올바른 이름으로 재실행했다. 70번은 재실행 때 Chromium이 inert 속성을 계산값에도 반영해 생존했다. CSS interactivity 미지원 회귀를 추가해 검출했고, 실제 WKWebView에서도 원본 검출과 변이 누락을 확인했다. 86번은 3차 리뷰 수정 뒤 별도 복사본을 TypeScript 컴파일하고 고정 Chromium에서 저장소의 새 자신·부모 회귀를 실행해 원본 2개 통과와 변형 2개 실패를 확인했다. 독립 무마스크·자신·부모 세 사례에서도 같은 변형을 검출했다. 병렬 변이는 사용하지 않았다.
