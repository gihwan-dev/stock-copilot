# D-19 초안: 확률 입력과 AI 추정치의 구분

- 상태: 초안
- 날짜: 2026-11-13
- 관련 작업: D-19, D-02, D-21~D-24, D-17, DS-05, E-02, E-06, E-91

## 근거와 결정

ACC-2와 design 6.1은 AI 입력만 1~99 정수 퍼센트로 제한하고, 기준 확률·보정 결과·임계값은 십진수로 계산한다. design 6.2와 open-issues 1.4는 원래 추정을 보존하고 실제 적중률을 반영한 확률로 신호를 판단한다. E-06은 두 값을 함께 표시한다. 따라서 원래 추정치를 일반 확률과 구분하는 타입이 필요하다.

`Probability`는 비공개 Decimal 필드와 범위를 검사하는 `try_new`만 갖는다. 범위는 닫힌 구간 [0, 1]이다. D-17의 구간 적중률은 전부 실패 또는 전부 성공일 수 있고, D-23 보정 결과도 끝점을 배제한다는 요구가 없다. AI 입력의 끝점 금지를 코드 계산값에 적용하지 않는다. 음수 0은 수치상 0으로 받아들인다. 범위 밖 값을 잘라서 성공시키지 않는다.

`AiProbability`는 비공개 Probability 필드와 문자열 파서만 갖는다. `AiProbabilityInput`은 길이만 검사한 경계 newtype이다. try_new가 길이를 먼저 확인하므로 입력을 복사하거나 긴 숫자를 순회·파싱하지 않고 1~2바이트 밖을 거부한다. 성공하면 최대 2바이트만 소유하고 AiProbability::parse가 나머지 문법을 검사한다. 빌린 str 필드는 기존 원시 타입 허용 목록의 newtype 대상이 아니므로 사용하지 않는다. ASCII 숫자만 받고 선행 0을 거부한다. 이 조건을 통과한 정수는 반드시 1~99이며 Decimal의 계수와 스케일 2로 정확히 구성한다. 오류에는 입력을 싣지 않는다.

AI 추정치에서 일반 확률로 가는 API는 `into_probability` 하나다. 암묵적인 From·Deref나 역변환은 없다. D-23은 원래 AiProbability를 기록에 남기고 명시적으로 변환한 값을 계산에 사용해야 한다. 이 변환이 보정을 수행하거나 보정 완료를 증명하는 것은 아니다. 보정 전후의 전체 상태와 모델·기간별 표본 정책은 D-23이 구현한다. 기준 확률·임계값·보정 결과 각각을 위한 추가 래퍼는 이번 작업에서 만들지 않는다.

## 표시와 연산 범위

Probability는 정확한 0~1 십진수 접근과 같은 타입끼리의 순서 비교만 제공한다. D-24의 임계값 비교에 Ord를 쓰고, 여사건·덧셈·곱·나눗셈 API는 현재 소비자가 없어 추가하지 않는다. AI 파싱의 백분율 환산은 정수 계수와 고정 스케일로 구성하므로 곱·나눗셈이 필요 없다.

D-01의 반올림 함수와 decimal-methods 허용 목록을 바꾸지 않는다. DS-05는 받은 자릿수의 숫자 문자열에 부호·쉼표·단위만 붙인다. 퍼센트 문자열의 자릿수 선택이나 확률 구간 표시는 이번 D-19 완료 기준에 없으므로 표시 API를 선행 설계하지 않는다. 후속 퍼센트 표시는 domain에서 100배 환산과 표시 반올림을 수행해야 하며 TypeScript가 산술하지 않는다. 필요한 연산은 확률의 정확한 백분율 환산이며, 반올림은 표시 파일에서 D-01의 MidpointAwayFromZero 정책과 허용 목록을 따라야 한다. 곱·나눗셈을 우회하는 문자열 산술도 추가하지 않는다.

D-02 병합 뒤 연결할 지점: 현재 Probability는 자체 Decimal을 보유한다. Ratio가 생겨도 범위를 보장하는 생성자를 거쳐 연결하고 AI 생성 경로를 합치지 않는다. D-21의 기준 확률, D-22의 임계값 계산, D-23의 보정과 D-17의 Brier 점수에서 필요한 정확 산술은 해당 작업의 전용 API와 허용 목록에서 결정한다. R-12의 초기 5% 단위 제안보다 확정 문서의 1~99 정수 요구가 우선한다.

## 검증

- 1~99 전수 검사는 독립적인 `0.NN` 기대 문자열과 대조한다.
- 일반 확률의 범위 속성 검사는 원시 96비트 계수와 10의 정수 거듭제곱을 대조한다. Decimal의 범위 비교나 Probability 생성 결과를 기준으로 쓰지 않는다.
- 임의 바이트 문자열은 별도로 만든 99개 정규 문자열 집합에 속하는지와 대조한다. 범위 밖 양수와 음수도 무작위로 검사한다.
- 모든 속성 테스트는 `Config::with_cases(4096)`을 명시한다.
- 새 의존성, 검사 끄기, 기존 테스트 변경은 없다.

## 버린 대안과 한계

- 단일 Probability 파서에 입력 종류 옵션을 넣으면 AI 원래 값의 출처가 사라져 버렸다.
- AiProbability에서 Decimal을 직접 꺼내거나 일반 확률에서 AI 타입을 만들면 명시적 변환 경계가 흐려져 제공하지 않는다.
- 타입 구분은 실수 방지다. 어댑터가 AI 문자열을 독자적으로 파싱하여 코드용 생성자에 넣는 악의적 우회까지 막지는 않는다. E-02 경계는 반드시 AiProbability::parse를 사용해야 한다.
- 이 작업은 주문·보정 알고리즘·모델 성능·실계좌 동작을 검증하지 않는다.
