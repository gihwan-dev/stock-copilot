# D-16: 주장 판정과 추가 전용 논거 이력

- 상태: 초안
- 기준: 4499e0af3cd9185b279a96181d25e49d19048942, 브랜치 d-16
- 근거: R-12 2.2, 2.5, 3.3, ADR 0022·0024

## 결정

Thesis의 생성 상태는 빈 주장 목록과 빈 이력이다. 주장 추가와 판정만 주장 단위 차분으로 받는다. 전체 상태 입력·이력 복원 생성자·수정/삭제 접근자·직렬화·Thesis 복제는 제공하지 않는다. 공개 이력은 불변 슬라이스이고 모든 필드는 비공개다. 변경은 기준 버전을 확인한 뒤 검증을 마치고 한 항목을 추가한다. 버전은 이력 길이, 순번은 1부터 시작하며 호출자가 정하지 않는다. 실패는 현재 주장과 이력을 모두 보존한다.

주장에는 ID, 역할, 문구, 측정 지표, 기대 범위, 관측 경로, 반증 조건이 필요하다. 내용의 경제적 타당성과 실제 반증 가능성까지 문자열 타입이 증명하지는 않는다. 측정 숫자의 평가기는 이 작업 범위가 아니며 AI 서술형 판정을 수용한다. 매도 조건은 '이 조건이 발생하지 않는다'라는 불변 주장으로 나타내고 KillCriterion의 Broken을 조건 충족으로 해석한다. 주문은 생성하지 않는다.

AI 문구·근거 설명에 별도 문자열 타입을 만들지 않고 D-15 UntrustedText를 재사용한다. 모든 문구와 모델·프롬프트 버전은 비어 있지 않은 비신뢰 텍스트이며 최대 65536바이트다. Debug는 D-15의 길이만 보이는 표현을 따른다. ClaimId는 ASCII 영숫자·밑줄·하이픈 1~64바이트, 대소문자 구분이다. 오류는 입력값을 싣지 않는다. 문자열은 자르거나 정규화하지 않는다.

근거는 D-15 CollectedItem의 1~32개 목록이다. 따라서 출처 종류와 정규화 URL이 함께 있고 출처 없는 변경은 불가능하다. 같은 출처와 URL의 중복은 거부한다. 목록 순서는 원래 근거 제시 순서로 보존하며 출처 종류만 비교하는 집계에는 영향을 주지 않는다. InformationSource::Web만 있으면 NeedsReview이며 현재 주장 목록과 집계에 적용하지 않는다. 뉴스·공시가 섞이면 적용한다. 웹 전용 여부는 호출자가 전달할 수 없다.

사용자 확인은 confirm_by_user가 원 연산과 근거를 새 항목으로 복사하고 confirms에 원 순번을 붙인다. 원 항목의 NeedsReview는 역사적 사실로 보존한다. 한 번 확인한 항목, 적용된 항목, 없는 순번은 거부한다. 같은 주장에 후속 변경이 있으면 Superseded로 거부하며, 최신 상태를 근거로 새 변경을 만들어야 한다. MCP 입력으로 확인 여부를 받지 않는 것은 J-02·J-08의 책임이다. domain 메서드 자체는 사용자 인증을 증명하지 않는다.

주장은 최대 128개, 이력은 4096개다. 상한은 문서가 정한 제품 수치가 아닌 임시 자원 정책이다. 상한에서 과거 이력을 버리지 않고 실패한다. 출처·텍스트 상한과 함께 무제한 보관을 막는다. 빈 노트는 허용하되 전체 상태는 확인 필요다. 새 주장은 Unverifiable로 시작하며 판정 없이 Intact가 되지 않는다.

## 집계 표

R-12가 명시한 위험 조건이 있으면 깨짐 의심, 나머지는 확인 필요다. 아래 행은 핵심 주장, 열은 다른 핵심 주장 또는 매도 조건 주장이다. 보조 주장의 네 판정은 표를 바꾸지 않는다. 주장 순서를 바꿔도 결과는 같다.

| 핵심 / 핵심 또는 매도 조건 | Intact | Weakened | Broken | Unverifiable |
|---|---|---|---|---|
| Intact | 확인 필요 | 확인 필요 | 깨짐 의심 | 확인 필요 |
| Weakened | 확인 필요 | 확인 필요 | 깨짐 의심 | 확인 필요 |
| Broken | 깨짐 의심 | 깨짐 의심 | 깨짐 의심 | 깨짐 의심 |
| Unverifiable | 확인 필요 | 확인 필요 | 깨짐 의심 | 확인 필요 |

보류 중인 웹 변경은 표의 입력에 들어가지 않는다. 이미 확인된 Broken을 웹 전용 Intact 변경이 덮지도 않는다.

## 미해결과 후속

- R-12에는 전체 상태의 완전한 집합과 나머지 조합의 집계 규칙이 없다. 확정된 정상 상태를 발명하지 않고 NeedsReview로 보수 처리했다. 상태 집합·우선순위·상한·매도 조건 표현은 메인 평가에서 확정해야 한다.
- 시각, 다음 확인 시점은 D-01 병합 뒤 추가. 현재 순번은 순서·기준 버전·확인 참조·불변성에 충분하다. 시각 기반 예약과 감사 시각은 아직 제공하지 않는다.
- 요약·예정 사건·위험 목록·비중·가격 수준과 자동 지표 평가는 D-16 완료 기준인 주장 목록·판정·이력보다 넓어 이번 차분에 넣지 않았다. J-02가 필요로 하는 연산은 별도로 확장해야 한다.
- S-06은 외부에서 과거 이력을 덮어쓰는 복원 API를 추가하지 말고 검증된 연산을 순서대로 재생하는 경계를 설계해야 한다. DB의 변조 탐지는 이 타입만으로 보장하지 않는다.
- 실제 프로젝트 신뢰·훅 신뢰의 세션 적용 여부는 이 세션에서 독립적으로 확인할 수 없다. 저장소 설정의 hooks=true 및 훅 파일은 확인했고 실제 just check와 커밋 훅으로 검사한다. 홈 설정·자격 증명은 읽지 않는다.
- 새 의존성·검사 끄기 없음. 속성 검사는 의존성을 추가하지 않고 유한한 연산열을 생성해 모든 접두사의 보존을 검사한다. 임의 무작위 입력에 대한 proptest는 아니다.

## 검증 설계

기대값은 R-12의 핵심 Broken·조건 충족 규칙과 미정 조합의 보수 정책에서 표로 작성했다. 구현 출력을 기대값으로 복사하지 않았다. 표의 16개 칸 각각에 보조 주장의 네 판정을 더한 64개 조합과 역할 순서 교환을 검사한다. 길이 0~63의 생성 연산열에서 모든 추가 전후 이력 접두사를 비교하며 사용자 확인도 원본 보존을 검사한다. 외부 rustc 검사에서 이력 접근·항목 변경·필드 직접 생성은 E0616/E0451로 거부됐다. 이 일회성 컴파일 검사 자료는 target/d16에만 있으며 영속 하네스 회귀 테스트는 아니다.
