## 상태와 매도 조건

노트 상태는 SuspectedBroken과 NoBreakSignal이다. 후자는 정상·유효 판정이 아니라 현재 적용된 판정에서 문서가 정한 파손 신호가 없다는 뜻이다. 확인 필요는 웹 전용 변경의 NeedsReview에만 쓴다. 핵심 주장 Broken 또는 매도 조건 Met이 하나라도 있으면 SuspectedBroken이다. 보조 주장은 단독으로 이 신호를 만들지 않는다.

| 핵심 주장 / 매도 조건 | NotMet | Met | Unverifiable |
|---|---|---|---|
| Intact | NoBreakSignal | SuspectedBroken | NoBreakSignal |
| Weakened | NoBreakSignal | SuspectedBroken | NoBreakSignal |
| Broken | SuspectedBroken | SuspectedBroken | SuspectedBroken |
| Unverifiable | NoBreakSignal | SuspectedBroken | NoBreakSignal |

KillCriterion은 claims와 별도 목록이다. Narrative는 서술형 비신뢰 조건, Machine은 지표 ID(CriterionMetric)·비교(이상/이하/같음)·십진수 임계값이다. metric()·comparison()·threshold()와 CriterionValue::as_decimal()로 코드형 조건의 모든 정보를 읽을 수 있다. 이력과 현재 상태를 저장할 때 숨은 필드를 추측하거나 Debug를 파싱할 필요가 없다.

코드형 판정 입력은 CriterionAssessment::Observed(CriterionObservation)이다. 관측값에는 지표 ID·값·도구 호출 참조가 필수이며 모두 공개 접근자로 읽는다. 조건과 관측값의 CriterionMetric이 정확히 같아야 하고, 다르면 MetricMismatch다. 지표는 ASCII 영숫자·밑줄·점·하이픈 1~64바이트의 내부 식별자이며 대소문자를 구분한다. 도구 호출 참조는 관측 회차마다 달라질 수 있으므로 지표 ID와 별개다.

호출자가 Code(Met) 같은 판정 결과를 넣는 변형은 제거했다. domain이 관측값을 비교해 비공개 ValidatedOperation의 판정을 만들고 적용한다. 코드형에 AI 판정, 서술형에 코드 관측을 붙이면 각각 AiMachineJudgment·CodeNarrativeJudgment로 거부한다. 판정 이력에는 결과만 남기는 대신 원 관측값·지표·도구 참조가 남아 조건을 다시 평가할 수 있다. 도구 참조가 실제로 그 값을 냈는지는 domain이 증명하지 못한다. M-03·M-04 또는 J-02가 도구 호출 원장의 지표·값·출처를 대조하고 관측 입력을 만들어야 한다.

## 변경·보류·복원

ThesisPatch는 기준 버전 하나와 연산 1~16개를 받는다. 각 연산에는 근거와 모델 사유가 있다. 작업 중간 상태에서 순서대로 검증하고 하나라도 실패하면 현재 상태와 이력을 모두 보존한다. 한 연산당 한 이력 항목·한 순번이 생긴다. 웹·비웹이 섞인 묶음은 연산별로 비웹을 적용하고 웹을 보류하며, 하나라도 실패하면 적용과 보류 기록을 모두 취소한다. 묶음 경계는 이력에 남지 않는다. 순서대로 상태를 재생하는 데 경계 정보는 필요하지 않다. 묶음 안에서 추가한 주장을 뒤 연산이 판정할 수 있다. add_catalyst·edit_summary는 이번 범위 밖이다.

보류 중이고 대체·거절·확인되지 않은 항목만 pending()으로 돌려준다. 같은 대상의 보류 항목은 하나, 전체 활성 보류는 8개다. 주장과 매도 조건은 ID 이름 공간을 구분한다. 보류 8개가 찬 동안 다른 대상의 정당한 웹 변경도 TooManyPending으로 거부하고 저장하지 않는다. 사용자가 기존 보류를 결정해야 새 보류를 받을 수 있다. 같은 대상의 새 웹 변경은 PendingTarget으로 거부하고, 비웹 변경은 적용하면서 기존 보류를 대체한다. 확인·거절은 원 항목을 바꾸지 않고 원 순번·사용자 행위·UserReason을 새 항목으로 추가한다. 사용자 사유에는 모델·프롬프트 필드가 없다. 이미 해결·대체된 항목은 다시 확인·거절할 수 없다.

이력 상한은 6144개다. 웹 보류는 이력 길이 6112 미만에서만 추가하여 마지막 32개를 남긴다. 이 중 24개는 비웹 모델 변경도 쓰며, 마지막 8개(6136~6144)는 사용자 확인·거절 전용이다. 모든 모델 연산(코드 관측 포함)은 6136개에서 UserHistoryReserved로 거부된다. 활성 보류 상한이 8개이므로 6136개에 도달해도 남은 보류를 모두 확인하거나 거절할 공간이 있다. 보류를 모두 거절해도 모델 영역을 다시 늘리거나 옛 이력을 지우지 않는다.

같은 대상에 웹 Judge 12287번을 보내도 첫 보류 뒤 모두 거부되어 실제 Broken을 차단하지 않는다. 이력은 전체 상한에서 HistoryFull, 웹 예약 경계에서는 WebHistoryFull로 실패한다. 문서에는 상한 뒤 자동 새 노트 연결·복구 규칙이 없다. 노트 이어가기 정책은 미해결이며 J-02·S-06에서 정해야 한다. 유한한 이력이 영구히 모든 변경을 받을 수 있다고 주장하지 않는다.

ThesisVersion은 0~6144의 외부 정수를 검증해서 받고 as_usize()에서 저장/JSON 변환용 순번을 읽는다. 버전은 시각이 아니라 이력 항목 수다. S-06은 HistoryAction을 순서대로 공개 적용·확인·거절 API에 재생해 복원한다. 혼합 연산열 속성 검사가 이력·현재 상태·보류 목록의 동일성을 검증한다. 이력 필드와 항목은 비공개이며 수정·삭제 경로, 직렬화 복원 생성자, 공개 Thesis Clone은 없다.

## 출처 키와 입력 경계

EvidenceRef는 Web(정규화 URL), News(뉴스 출처·정규화 URL), Disclosure(DisclosureKey·정규화 URL), Tool(ToolReference)의 닫힌 집합이다. 공시의 출처와 접수번호를 잃지 않는다. 도구 ID는 R-12의 tool: 접두사와 ASCII 영숫자·밑줄·하이픈·#·/·. 문법을 보존한다. 호출자가 정하던 ToolPurpose는 제거했다. SEC-4를 보수적으로 적용해 모든 도구 참조를 일반 변경의 실질 근거 출처에서 제외한다. 도구 참조는 R-12 3.3의 근거 기록으로 보관한다.

| 일반 변경의 근거 조합 | 결과 |
|---|---|
| 없음 | EmptyEvidence로 거부 |
| 웹만 | 확인 필요로 보류 |
| 도구만 | 확인 필요로 보류 |
| 웹 + 도구 | 확인 필요로 보류 |
| 뉴스 키 또는 공시 키가 하나 이상 | 적용. 다른 웹·도구 참조가 함께 있어도 같음 |

도구만 있는 경우를 거부하는 대신 보류로 선택했다. R-12 2.5는 비검증 자료가 노트를 오염시키지 않게 하고 SEC-4는 도구 참조 자체를 실질 출처로 세지 않는다. 사용자 확인 전에는 현재 노트·분석 입력·집계에서 제외하므로 이 원칙을 유지하면서 도구 참조를 근거 기록으로 남긴다.

예외는 코드형 매도 조건의 Observed 연산이다. 이 경우 관측값과 그 도구 참조가 연산 자체의 근거이며, domain이 지표 일치와 비교를 수행하므로 일반 변경의 웹 전용 보류 규칙을 적용하지 않는다. 추가 Evidence는 맥락 기록이고 판정 결과를 결정하지 않는다. 잘못된 지표·조건 종류는 근거 조합과 무관하게 거부한다. 관측 출처의 진위는 앞서 정한 도구 원장 대조 책임으로 남는다.

동일 키 중복은 거부한다. 서로 다른 출처가 동일 URL을 주장하는 항목도 한 근거 집합에서는 거부한다. 근거 순서는 제시 순서로 보존한다. R-12는 출처 ID를 요구하고 본문 복사를 요구하지 않으므로 이력에는 키만 보관한다. URL Debug 노출은 ADR 0024와 동일하게 유지한다. AI 텍스트는 UntrustedText를 재사용하고 다음 모듈별 상한을 추가한다. 조용한 자르기나 신뢰 텍스트 승격은 없다. 오류에는 입력값이 없다.

| 항목 | 바이트 또는 개수 상한 | 근거 |
|---|---|---|
| 주장 문구 | 1024바이트 | R-12 한 문장 주장에 대한 보수적 내부 자원 정책 |
| 측정 지표 | 128바이트 | 짧은 지표 이름 |
| 기대 범위·관측 경로 | 각각 256바이트 | 짧은 범위·경로 설명 |
| 반증 조건·서술형 매도 조건·모델/사용자 사유 | 각각 512바이트 | 단락 하나의 설명 |
| 모델·프롬프트 버전·주장/조건/지표 ID | 각각 64바이트 | 짧은 메타데이터·불투명 ID |
| 도구 참조 | 128바이트 | 도구 원장 키 제한 |
| 근거 URL | 2048바이트 | 출처 키 보관 크기를 제한하는 내부 정책 |
| 근거·주장·매도 조건·묶음·이력 | 각각 8·32·16·16·6144개 | 단일 개인 노트의 자원 상한 |

최악의 텍스트/키 페이로드를 넉넉하게 잡으면 항목당 근거 8×(2048+128), 주장 2240, 사유 640 = 20288바이트다. 이력 상한 6144개를 곱하면 124,649,472바이트(118.875MiB), 현재 주장/조건을 48×2240으로 과대 계산해 더하면 124,756,992바이트(약 118.98MiB)다. 구조체·Vec·Box·할당기 메타데이터는 별도다. 원자적 검증의 임시 상태가 이 전체를 복제하는 경우 두 상태의 페이로드 합은 약 237.96MiB다. 근거·묶음은 boxed slice로 남는 입력 Vec capacity를 제거한다. 이 계산은 단일 노트의 논리 페이로드 상한이며 실측 전체 앱 메모리 보장은 아니다.

주장 5개와 매도 조건 3개를 각각 주 1회 판정하면 주당 이력 8개다. 연 53주를 보수적으로 적용해도 초기 항목 8개 + 8×53×10년 = 4248개이므로 6144개는 10년 목표에 1896개의 여유를 둔다. 추가 사용자 행위·웹 보류도 이력을 소비하므로 판정 외 기록이 많으면 실제 보관 연수는 짧아진다. 4096개는 이 10년 계산에도 부족하다. 8192개의 이력 페이로드는 166,199,296바이트(158.5MiB)로 커지므로, 10년 이상의 판정 이력과 메모리 사이에서 6144개를 선택한다. 마지막 32개 중 8개는 사용자 행위 전용으로 두고, 대상별 보류 1개·전체 보류 8개를 유지한다. 상한 이후 이어가기 정책은 계속 미해결이다.

## 검증

기존 길이 0~63의 단건 혼합 속성 검사(Config::with_cases(256))를 유지한다. 별도로 Config::with_cases(128)의 상태 기반 속성 검사를 추가한다. 각 단계는 1~16개 묶음과 임의 실패 위치, 올바른/틀린 기준 버전, 실제 pending()에서 뽑은 확인·거절 대상, 코드형 조건의 추가·관측을 섞는다. 알려진 유효 묶음의 임의 중간 위치에 없는 대상을 주입해 실패 종류와 전체 롤백을 검사한다. 보류를 비웹 변경으로 대체한 뒤 옛 순번의 확인을 거부하는 속성도 매 생성 사례에 포함한다.

복원은 공개 접근자로 조건·비교·임계값·관측값·출처를 다시 구성한 뒤 공개 적용/확인/거절 API로 재생한다. 원 객체를 통째로 복제해 숨은 필드 누락을 가리지 않는다. 두 속성 검사 모두 접두사 불변·실패 원자성·재생 상태와 보류 목록 동일성·보류 격리를 검사한다. 큰 이력 경계는 별도 결정적 테스트에서 최대 16개씩 공개 묶음 API로 채우고 재생하여 검증한다. 채우는 각 묶음 뒤 순번이 연산 수만큼 증가했는지도 단언하여, 무동작 변형이 무한 대기로 남지 않고 즉시 테스트 실패가 되게 한다. 검사 횟수는 전수 보장을 뜻하지 않는다. 손 변형 두 개(묶음 롤백 제거, 대체된 보류의 확인 허용)를 각각 넣고 새 상태 기반 속성 테스트 하나만 실행했을 때 두 번 모두 실행 중 단언 실패로 검출됐다. 컴파일 실패로 센 결과가 아니다. 원복 후 같은 속성 테스트가 통과했다. 외부 rustc 검사에서도 공개 접근자만으로 조건·관측을 재구성하는 프로그램이 컴파일·실행됐고, CriterionAssessment::Code(Met) 직접 생성은 E0599로 거부됐다. 일회성 검사 로그는 target/d16/final-review에 있다.

## 위험·후속 작업과 미해결

- 뉴스 키나 공시 키 하나만 섞여도 확인 없이 적용된다. domain은 근거와 주장의 관련성을 알 수 없다. J-02가 주장-근거 연결·수집 원장 대조를 검사해야 한다.
- 출처 표시는 어댑터가 정한다. N-02·N-03·N-05·N-07·N-20이 뉴스/공시/웹 수집 키를 만들고 S-05에 보관한다. M-02는 도구 호출 원장, M-03·M-04는 도구 지표·관측값과 호출 ID, N-13은 뉴스·공시 키를 제공한다. J-02가 이 원장들을 대조해 EvidenceRef로 바꾼다. 공개 NewsItem::new·Disclosure::new와 EvidenceRef 생성 자체는 출처 진위를 증명하지 않는다.
- 사용자 확인·거절 함수는 domain에서 호출자를 증명하지 못한다. J-08 또는 후속 하네스 작업에 MCP 서버 계열 crate가 이 함수에 접근하지 못하는 구조 검사를 넘긴다. 이 검사는 이번 범위 밖이다.
- 순번은 노트 ID에 묶이지 않아 다른 노트에서 같은 숫자가 통과할 수 있다. J-02가 thesis_id와 저장소 버전을 함께 검증해야 한다. 노트 식별자에 묶인 버전 타입은 미해결이다.
- 주장/조건 ID는 ASCII 대소문자를 구분한다. R-12는 핵심 주장 최소 1개를 요구하지 않는다. 모든 주장이 보조인 노트의 경고·핵심 지정 정책은 미해결이며 임의로 강제하지 않는다.
- 시간 타입은 이번 master의 D-10 병합으로 포함됐다. D-16의 시각·다음 확인 시점 필드는 이번 수정 범위 밖이며 후속으로 추가한다. 현재 이력 순서는 계속 순번만 쓴다.
- 상한 이후 새 노트 연결·보관/복구 정책, 자원 수치의 제품 운용 적정성은 미해결이다.
