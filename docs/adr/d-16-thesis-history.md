# D-16: 주장·매도 조건과 추가 전용 논거 이력

- 상태: 초안, 적대적 리뷰 후 수정
- 최초 기준: 4499e0af3cd9185b279a96181d25e49d19048942
- 수정 기준: c42ccf8200e2c644f673eab1abc644b137643982, 브랜치 d-16
- 근거: R-12 2.2·2.5·3.3, design SEC-4, ADR 0022·0024·0025

## 상태와 매도 조건

노트 상태는 SuspectedBroken과 NoBreakSignal이다. 후자는 정상·유효 판정이 아니라 현재 적용된 판정에서 문서가 정한 파손 신호가 없다는 뜻이다. 확인 필요는 웹 전용 변경의 NeedsReview에만 쓴다. 핵심 주장 Broken 또는 매도 조건 Met이 하나라도 있으면 SuspectedBroken이다. 보조 주장은 단독으로 이 신호를 만들지 않는다.

| 핵심 주장 / 매도 조건 | NotMet | Met | Unverifiable |
|---|---|---|---|
| Intact | NoBreakSignal | SuspectedBroken | NoBreakSignal |
| Weakened | NoBreakSignal | SuspectedBroken | NoBreakSignal |
| Broken | SuspectedBroken | SuspectedBroken | SuspectedBroken |
| Unverifiable | NoBreakSignal | SuspectedBroken | NoBreakSignal |

KillCriterion은 claims와 별도 목록이다. Narrative는 서술형 비신뢰 조건, Machine은 도구 참조·비교(이상/이하/같음)·십진수 임계값이다. MachineCondition::evaluate는 관측값을 코드로 비교해 Code 판정을 만든다. Machine 대상의 Ai 판정은 거부한다. 원장 관측값과 지표 참조의 연결은 어댑터·J-02의 책임이며 Code라는 열거값 자체가 호출자의 신원을 증명하지 않는다. 판정 집합은 Met·NotMet·Unverifiable이며 Weakened 등 주장 판정과 섞이지 않는다.

## 변경·보류·복원

ThesisPatch는 기준 버전 하나와 연산 1~16개를 받는다. 각 연산에는 근거와 모델 사유가 있다. 작업 중간 상태에서 순서대로 검증하고 하나라도 실패하면 현재 상태와 이력을 모두 보존한다. 한 연산당 한 이력 항목·한 순번이 생긴다. 묶음 안에서 추가한 주장을 뒤 연산이 판정할 수 있다. add_catalyst·edit_summary는 이번 범위 밖이다.

보류 중이고 대체·거절·확인되지 않은 항목만 pending()으로 돌려준다. 같은 대상의 보류 항목은 하나, 전체 활성 보류는 8개다. 주장과 매도 조건은 ID 이름 공간을 구분한다. 같은 대상의 새 웹 변경은 PendingTarget으로 거부하고, 비웹 변경은 적용하면서 기존 보류를 대체한다. 확인·거절은 원 항목을 바꾸지 않고 원 순번·사용자 행위·UserReason을 새 항목으로 추가한다. 사용자 사유에는 모델·프롬프트 필드가 없다. 이미 해결·대체된 항목은 다시 확인·거절할 수 없다.

이력 상한은 6144개다. 웹 보류는 이력 길이 6112 미만에서만 추가하여 최소 32개의 비웹/사용자 행위용 공간을 남긴다. 같은 대상에 웹 Judge 12287번을 보내도 첫 보류 뒤 모두 거부되어 실제 Broken을 차단하지 않는다. 활성 보류 상한은 대상 순환 공격도 제한한다. 이력은 상한에서 삭제·압축하지 않고 HistoryFull, 웹 예약 경계에서는 WebHistoryFull로 실패한다. 문서에는 상한 뒤 자동 새 노트 연결·복구 규칙이 없다. 노트 이어가기 정책은 미해결이며 J-02·S-06에서 정해야 한다. 유한한 이력이 영구히 모든 변경을 받을 수 있다고 주장하지 않는다.

ThesisVersion은 0~6144의 외부 정수를 검증해서 받고 as_usize()에서 저장/JSON 변환용 순번을 읽는다. 버전은 시각이 아니라 이력 항목 수다. S-06은 HistoryAction을 순서대로 공개 적용·확인·거절 API에 재생해 복원한다. 혼합 연산열 속성 검사가 이력·현재 상태·보류 목록의 동일성을 검증한다. 이력 필드와 항목은 비공개이며 수정·삭제 경로, 직렬화 복원 생성자, 공개 Thesis Clone은 없다.

## 출처 키와 입력 경계

EvidenceRef는 Web(정규화 URL), News(뉴스 출처·정규화 URL), Disclosure(DisclosureKey·정규화 URL), Tool(ToolReference·용도)의 닫힌 집합이다. 공시의 출처와 접수번호를 잃지 않는다. 도구 ID는 R-12의 tool: 접두사와 ASCII 영숫자·밑줄·하이픈·#·/·. 문법을 보존한다. 도구 용도는 Quote·Portfolio·Research다. SEC-4에 따라 Quote·Portfolio는 실질 근거 출처에서 제외한다. 웹과 이 두 도구만 섞이면 보류이며, 이 두 도구만 있으면 NoSubstantiveEvidence로 거부한다. News·Disclosure·Research가 있으면 비웹 근거로 센다.

동일 키 중복은 거부한다. 서로 다른 출처가 동일 URL을 주장하는 항목도 한 근거 집합에서는 거부한다. 근거 순서는 제시 순서로 보존한다. R-12는 출처 ID를 요구하고 본문 복사를 요구하지 않으므로 이력에는 키만 보관한다. URL Debug 노출은 ADR 0024와 동일하게 유지한다. AI 텍스트는 UntrustedText를 재사용하고 다음 모듈별 상한을 추가한다. 조용한 자르기나 신뢰 텍스트 승격은 없다. 오류에는 입력값이 없다.

| 항목 | 바이트 또는 개수 상한 | 근거 |
|---|---|---|
| 주장 문구 | 1024바이트 | R-12 한 문장 주장에 대한 보수적 내부 자원 정책 |
| 측정 지표 | 128바이트 | 짧은 지표 이름 |
| 기대 범위·관측 경로 | 각각 256바이트 | 짧은 범위·경로 설명 |
| 반증 조건·서술형 매도 조건·모델/사용자 사유 | 각각 512바이트 | 단락 하나의 설명 |
| 모델·프롬프트 버전·주장/조건 ID | 각각 64바이트 | 짧은 메타데이터·불투명 ID |
| 도구 참조 | 128바이트 | 도구 원장 키 제한 |
| 근거 URL | 2048바이트 | 출처 키 보관 크기를 제한하는 내부 정책 |
| 근거·주장·매도 조건·묶음·이력 | 각각 8·32·16·16·6144개 | 단일 개인 노트의 자원 상한 |

최악의 텍스트/키 페이로드를 넉넉하게 잡으면 항목당 근거 8×(2048+128), 주장 2240, 사유 640 = 20288바이트다. 이력 상한 6144개를 곱하면 124,649,472바이트(118.875MiB), 현재 주장/조건을 48×2240으로 과대 계산해 더하면 124,756,992바이트(약 118.98MiB)다. 구조체·Vec·Box·할당기 메타데이터는 별도다. 원자적 검증의 임시 상태가 이 전체를 복제하는 경우 두 상태의 페이로드 합은 약 237.96MiB다. 근거·묶음은 boxed slice로 남는 입력 Vec capacity를 제거한다. 이 계산은 단일 노트의 논리 페이로드 상한이며 실측 전체 앱 메모리 보장은 아니다.

주장 5개와 매도 조건 3개를 각각 주 1회 판정하면 주당 이력 8개다. 연 53주를 보수적으로 적용해도 초기 항목 8개 + 8×53×10년 = 4248개이므로 6144개는 10년 목표에 1896개의 여유를 둔다. 추가 사용자 행위·웹 보류도 이력을 소비하므로 판정 외 기록이 많으면 실제 보관 연수는 짧아진다. 4096개는 이 10년 계산에도 부족하다. 8192개의 이력 페이로드는 166,199,296바이트(158.5MiB)로 커지므로, 10년 이상의 판정 이력과 메모리 사이에서 6144개를 선택한다. 비웹/사용자 행위용 마지막 32개와 대상별 보류 1개·전체 보류 8개는 유지한다. 상한 이후 이어가기 정책은 계속 미해결이다.

## 검증 비용

혼합 연산열은 길이 0~63, 연산 종류 10개, 대상 키 8개이므로 64회로 조합을 충분히 다뤘다고 주장할 수 없다. Config::with_cases(256)으로 네 배 늘리고, 접두사 불변·실패 원자성·단건/묶음 공개 API 재생·보류 격리를 함께 검사한다. 이는 전수 검사가 아니며 큰 이력 상한은 별도 결정적 경계 테스트로 검증한다. 경계 테스트는 최대 16개씩 공개 묶음 API로 이력을 채우고 재생하여 임시 상태 복제 횟수를 줄인다. 큰 이력을 테스트 안에서 직접 주입하거나 단언을 줄이지 않는다. 이번 로컬 실행에서 혼합 속성 테스트는 64회 약 0.12초에서 256회와 두 재생 경로를 검사할 때 약 0.39초였고, 새 상한 경계 테스트를 포함한 domain 79개는 약 1.01초였다. 환경에 따른 실행 시간 차이는 있으며 전체 앱 성능 보장을 뜻하지 않는다.

## 위험·후속 작업과 미해결

- R-12 그대로 비웹 근거 하나만 섞여도 확인 없이 적용된다. domain은 근거와 주장의 관련성을 알 수 없다. J-02가 주장-근거 연결·수집 원장 대조를 검사해야 한다.
- 출처 표시는 어댑터가 정한다. N-02·N-03·N-05·N-07·N-20이 뉴스/공시/웹 수집 키를 만들고 S-05에 보관한다. M-02는 도구 호출 원장, M-03·M-04는 도구 용도와 호출 ID, N-13은 뉴스·공시 키를 제공한다. J-02가 이 원장들을 대조해 EvidenceRef로 바꾼다. 공개 NewsItem::new·Disclosure::new와 EvidenceRef 생성 자체는 출처 진위를 증명하지 않는다.
- 사용자 확인·거절 함수는 domain에서 호출자를 증명하지 못한다. J-08 또는 후속 하네스 작업에 MCP 서버 계열 crate가 이 함수에 접근하지 못하는 구조 검사를 넘긴다. 이 검사는 이번 범위 밖이다.
- 순번은 노트 ID에 묶이지 않아 다른 노트에서 같은 숫자가 통과할 수 있다. J-02가 thesis_id와 저장소 버전을 함께 검증해야 한다. 노트 식별자에 묶인 버전 타입은 미해결이다.
- 주장/조건 ID는 ASCII 대소문자를 구분한다. R-12는 핵심 주장 최소 1개를 요구하지 않는다. 모든 주장이 보조인 노트의 경고·핵심 지정 정책은 미해결이며 임의로 강제하지 않는다.
- 시각·다음 확인 시점은 D-10 병합 뒤 추가한다. 이번에는 시간 crate를 추가하지 않고 순번만 쓴다.
- 상한 이후 새 노트 연결·보관/복구 정책, 자원 수치의 제품 운용 적정성은 미해결이다.
