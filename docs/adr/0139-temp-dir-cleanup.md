# ADR 0139: H-53 테스트·검사가 만든 임시 폴더를 남기지 않음

- 상태: 확정 (2026-11-23)


## 배경

테스트와 검사에서 만든 임시 폴더가 성공 또는 실패 뒤 남아 시스템 저장 공간을 차지했다. 서로 다른 스레드의 실행 결과를 하나의 전역 접두사 집계로 판정하면 다른 실행을 누출로 오인할 수 있다.

## 결정

Node 임시 폴더 생성은 공통 관리자에서 추적한다. 테스트는 러너의 종료 훅에서 추적한 폴더를 정리하고, 프로세스 종료와 신호에서도 정리한다. 직접 해제할 수 있는 검사 도우미는 예외가 나도 `finally`에서 정리한다. 전체 검사 실측은 별도의 임시 상위 폴더를 만들고 자식에게 임시 환경을 전달해 전후 항목을 비교한다. 새로운 항목이 있으면 정리하기 전에 실패로 보고한다. 접두사 목록은 표시용으로 한곳에 두며, 격리 공간의 목록 밖 항목도 실패시킨다. 다른 실행의 폴더는 집계하거나 지우지 않는다.

`main-hook-context`는 전체 체크아웃을 가진 공유 Git 복제본이다. 별도 실측에서 32MB였으며 그중 `harness`가 13MB, `crates`가 7.1MB, `docs`가 5.9MB였다. 훅 테스트가 실제 경로와 추적 파일을 다루므로 체크아웃을 임의로 줄이지 않고 종료 시 정리한다.

## 검증과 한계

성공·실패·의도적 누출·중단과 예외를 회귀 테스트한다. 전체 검사 전후 실측 및 리뷰 결과는 실행 뒤 기록한다. 강제 종료(SIGKILL)나 시스템 정전은 프로세스 내부 정리 훅이 실행되지 않는다.

## 인계

전체 검사와 원격 실행 결과를 메인이 확인한다.

## 1차 리뷰 후 보강

SQLite 테스트의 각 임시 공간은 바로 임시 상위 폴더 아래에서 생성하고 소유자가 전체 공간을 지운다. 전체 `just check`는 실행별 감사 공간에서 동작하고 종료되지 않은 소유 프로세스 그룹의 자손도 실패로 판정한다. Node 버전은 감사기 실행 전에 검사한다. Node 자체 컴파일 캐시는 해당 실행의 공간에 지정하고 종료 시 지운 뒤 나머지를 비교한다. 실행 공간 밖으로 스스로 새 세션을 만들어 이탈하는 자손까지 프로세스 그룹으로 식별한다고 주장하지 않는다.

첫 전체 범위 검사에서 기존 Node 버전 실패 사례 2건과 Node 컴파일 캐시를 확인했다. 해당 사례를 고친 뒤 Node 버전·임시 감사 회귀 13개가 통과했다. SQLite 전체 114개 테스트를 격리된 임시 감사에서 실행해 전후 `before=0 after=0`이었다.

전체 범위 검사 중 Node 버전만 출력하는 실행 파일이 새로운 감사 진입점을 건너뛰는 반례를 확인해 명령 실행 확인을 추가했다. Node 컴파일 캐시와 실행 공간의 pnpm 저장소는 해당 실행이 소유한 곳만 정리한다. CI 하네스 142개는 격리 감사에서 모두 통과했고 전후 항목은 0개였다.

## 2차 리뷰 후 보강

테스트의 고정 경로를 실행마다 소유한 고유 디렉터리로 바꾸고 역순으로 정리한다. 같은 이름을 병행해도 다른 실행의 디렉터리를 지우지 않는다. 오래된 폴더 자동 정리는 현재 프로세스 이름 범위로 제한한다. 예전 이름의 고아 폴더와 이미 끝난 다른 프로세스의 폴더는 자동 정리하지 않는다. 감사기는 표준 Python의 세션 조회로 같은 세션 안에서 새 프로세스 그룹을 만든 자손도 찾아 종료하고 실패를 기록한다. Python 또는 세션 조회가 불가능하거나 결과 형식이 틀리면 통과하지 않고 확인되지 않은 프로세스 그룹에는 신호를 보내지 않는다. 빈 결과를 정상 응답으로 오인하는 반례는 수정 전 실패와 수정 후 통과를 확인했다. 그 경우 잔존 자손의 정리는 보장하지 않는다. 스스로 새 세션을 만든 자손은 소유 세션으로 식별하지 못한다.

## 3차 리뷰의 범위

감사는 전달한 TMPDIR 아래와 같은 세션에 속한 자손만 다룬다. 독립 비판은 TMPDIR 밖에 남긴 파일과 새 세션의 자손을 각각 실행으로 재현했다. 따라서 시스템 임시 폴더 전체에 누출이 없거나 모든 자손이 종료된다는 뜻이 아니다. 소유 프로세스와 상위 감사기가 모두 강제 종료되어 남은 다른 PID의 폴더는 자동 회수하지 않는다. PID 재사용, 살아 있는 자손과 확인·삭제 사이의 경합 때문에 PID 부재만으로 다른 작업의 폴더를 삭제하지 않는다.

정상 훅의 전체 실행에서 Rust nextest 2,217개와 커버리지 1,147개, Node 검사 뒤 감사 공간의 전후 항목은 각각 0개였다. 이 수치는 해당 실행의 격리 공간에 한정된다.

## 등록 인계

메인은 초안을 저장소에 등록하고 보호 설정 생성물에 현재 이름을 기록하도록 결정했다. 메인이 병합 때 번호를 부여한 뒤 저장소 절차대로 보호 생성물을 다시 만든다. 테스트와 검사 코드는 초안 이름을 참조하지 않는다.

## 3차 수정 검증

수정 범위는 8609b825d8915a2eb8a56873b557afe27bce3144 → 77ab38679a1de07b312f56e619e2a7d3607e4e19다. 정상 훅은 Node 992개, Rust nextest 2,223개와 커버리지 1,147개를 통과했으나 test-diff는 기존 테스트 변경 8건에 대한 별도 master 승인 부재로 실패했다. 이어 남은 끄기 보고와 훅 설치 검사는 따로 통과했고 감사 공간은 전후 0개였다. 이 커밋에 한해 지시문이 허용한 예외를 적용했으며, 변경분 변이는 같은 사전 조건에서 멈춰 실행되지 않았다.

## 최신 master 병합 시도

3bdca225c839fac1e2a6ef793977f3fde08683ba를 정상 훅으로 병합하려 했고 병합 트리 85384f1605fe05768b5931e4e1275d9d13c45122에서 Node 992개, Rust nextest 2,339개, 커버리지 1,192개가 통과했다. 기존 테스트 변경 8건의 별도 master 승인 부재로 test-diff가 실패해 병합을 취소했다. 실행별 임시 공간은 before=0 after=0이었다. 변경분 변이는 실행되지 않았고 원격 결과도 없다.
