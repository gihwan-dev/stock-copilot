# fin-hold 묶음 설계 결정 기록

| 작업 | 정한 것 | 다른 선택지 |
|---|---|---|
| 진행 | 하위 에이전트 목록 도구가 세션 훅(`[orchestration]`)에 막혀 모든 행을 한 스레드가 직접 구현했다 | 병렬 위임 |
| T-21 조립 | 토스 읽기 어댑터(`TossAccountRead`)가 가진 종목 마스터를 실행 중에 바꿔 끼울 수 있게 했다(`replace_market_master`, 내부는 `RwLock<Arc<…>>`). 마스터 조회는 같은 어댑터의 공개 메서드 `instrument_master(권한, 발급원, 시장)`로 하고, 토큰 관리자를 하나만 둔다 | `TossInstrumentRead`로 감싸 포트 타입 교체(시장 정보 포트를 다시 구현해야 함), 어댑터 두 개(토큰 두 벌) |
| T-21 조립 | 마스터 권한(`InstrumentMasterAuthority`)과 내부 ID 발급원은 `SqliteRepositories`가 S-21의 대응 원장(`instrument_mappings`)과 단조 순번 발급원으로 구현한다. 세션은 DB 읽기 잠금을 오래 쥐지 않고 연산마다 잡는다(앱 종료의 DB 닫기를 막지 않음) | 세션이 잠금을 계속 쥠 |
| T-21 조립 | 관측 확인(`verify_observation`)은 DB가 열려 있는지만 본다. 목록 요청의 상태 기본값(`ACTIVE`)이 전체 상장 상태를 덮는지는 실측 대기이고, 상장 폐지 종목은 목록에 없으므로 마스터에 없을 뿐 다른 종목으로 오인되지 않는다(대응은 시장·심볼·ISIN 단위이고 충돌은 `instrument_source_conflicts`가 막는다). 주문 쓰기 경로는 조립하지 않아 이 판단이 주문에 닿지 않는다 | 실측 전까지 닫힌 실패(보유가 영영 안 보임) |
| T-21 조립 | 시장별(국내·미국) 마스터 중 `Available` 항목만 모아 하나의 `MasterInstrumentFacts`로 설치한다. 한 시장이 실패해도 다른 시장은 설치하고, 실패한 시장만 다음 확인 때 다시 받는다. 성공한 시장은 24시간 동안 다시 받지 않는다(하루 1회) | 모든 항목이 가용일 때만 설치(`complete_facts`, 종목 하나만 막혀도 전체 실패) |
| T-21 조립 | 마스터 갱신 계기는 토스 연결 성공이다(키 저장 직후, 시작 직후 확인, 화면의 연결 확인, 그리고 1시간마다 도는 백그라운드 연결 확인). 갱신은 연결 확인 응답을 막지 않도록 백그라운드에서 돌고, 동시에 두 번 돌지 않는다. 갱신이 실제로 일어나면 곧바로 보유 동기화를 한 번 돌린다 | 예약 작업 표(`ScheduledJobId`)에 새 작업 추가(설정 화면 작업 목록이 늘어남, P-1) |
| T-21 조립 | 종목명 조회용 `InstrumentDirectory`(심볼 → 시장·이름)를 마스터 설치와 함께 채운다. 국내(숫자 6자리 계열)와 미국(영문) 심볼이 겹치지 않으므로 심볼 하나로 찾는다 | 시장까지 키로 씀(웹 조사 도구가 심볼만 받음) |
| S-02 조립 | `PortfolioRepository` 실제 구현 `SqlitePortfolioStore`: 동기화 기록마다 보유 스냅샷을 SQLite(`holdings_snapshots`, S-02)에 남기고, 화면·도구가 읽는 최신 기록은 메모리에 계좌별로 둔다. 앱을 다시 켜면 첫 동기화(마스터 적재 직후)까지는 "불러오는 중"이다. 보유 행에는 종목 마스터 사실(주문 식별)이 들어 있어 저장된 심볼만으로 복원하면 주문 가능 사실을 지어내게 되기 때문이다 | 스냅샷에서 `Portfolio` 복원(마스터 없이 주문 종목 타입을 만들 수 없음), 새 테이블에 직렬화 |
| S-02 조립 | 최신 기록은 성공·실패와 상관없이 마지막 기록이다(가짜 저장소와 같은 의미). 실패 기록은 스냅샷을 남기지 않는다 | 실패가 직전 성공을 덮지 않게 함(A-08 "직전 성공 자료 병행 표시"가 정의 대기) |
| U-08 | 보유 동기화 예약 작업(5분)의 장 운영 달력은 기존대로 `NoMarketCalendar`(장중 여부 모름 → 5분마다)다. 토스 장 운영 정보 연결은 이 묶음 밖이다 | 장 운영 정보 조립 |
| U-09 | 현황 IPC는 `get_portfolio`·`get_allocation` 두 명령이다(요청 `{ scope: "current" }`). 금액·비율·방향 글자는 domain 표시 함수(`display_money`·`display_change`·`display_percent`·`display_quotient_percent`)가 만들고, 비중은 domain 배분의 0.01% 단위 표시값을 그대로 옮긴다. 화면은 표시만 한다 | 화면에서 비율·비중 계산 |
| U-09 | 자료 없음(계좌 미선택·첫 동기화 전)은 `no-data`로 답해 현황 빈 상태("토스증권 계좌 자료를 받으면 여기에 현황이 보여요")를 띄운다. 마지막 동기화가 실패면 `retryable`, 접근 거부(IP·권한)면 `user-fixable`이고 화면은 "설정에서 연결 상태를 확인해 주세요"를 덧붙인다 | 실패해도 직전 성공 표시(정의 대기) |
| U-09 | 환율을 아직 받지 못해 달러 자산이 총평가에서 빠지면 `total_coverage: partial`로 알리고 화면에 한 줄로 적는다. 오늘 손익이 없으면 0을 지어내지 않고 "아직 받지 못했어요"로 둔다. 배분의 0% 행은 뺀다. 섹터 배분은 섹터 대응(D-06 저장)이 조립되지 않아 비어 있다 | 0으로 채움 |
| M-03 | MCP 포트폴리오 도구 4종은 `StoredPortfolioTools`(보유 저장소·시장 자료·거래내역 저장소·선택 계좌·종목명)로 읽는다. 계좌 표시는 계좌 선택 때 받은 계좌번호 뒤 4자리(`BrokerAccountRow::masked_number`, SEC-7)다. `get_performance`는 일별 평가 이력으로 수익률을 계산하는 경로가 없어 "표본 부족"으로 답한다. 집중도 수치(최대 비중·상위 5·HHI)는 domain 값이 비율 타입으로 나오지 않아 비워 둔다 | 화면 문자열을 다시 비율로 파싱 |
| N-18 | 웹 조사 대상은 관심 종목 ∪ 보유 종목이다. 검색어의 종목 이름은 종목 마스터 이름(국내는 한글 이름)으로 만들어 SEC-9(두 자리 이상 숫자 거부)를 통과한다. 마스터에 없으면 기존대로 심볼을 쓴다 | - |
