- 상태: 초안 (2026-11-14), 아래 미해결 규칙은 사용자·메인 확인 대상

- 근거: tasks D-23·D-24·D-17·D-22·E-91, design 6.2·6.6·ORD-8, open-issues 1.4, R-12 2.3·2.4, ADR 0022·0027·0028·0029·0039

## 입력과 책임

CalibrationFact는 종목 InstrumentId, CalibrationKey(모델 식별과 Horizon), 원래 과제 구간 TimeInterval, 예측 Probability, 성공/실패 CalibrationOutcome만 담는 최소 판정 사실이다. estimated_at은 구간 시작을 반환한다. 서로 모순되는 별도 추정 시각을 받지 않는다. 여기서 추정 시각은 과제가 고정한 기준 시각이며 AI 응답 완료 시각이 아니다. 구간 끝은 목표·손절 조기 도달 시각이 아니라 원래 과제의 만기다.

D-27이 EstimateOutcome을 판정한 뒤 이 타입을 만들거나 대체한다. Hit는 Hit로, StoppedOut·Expired는 Miss로 옮긴다. 이 작업은 목표가·손절가·거래일 달력이나 판정 시점을 계산하지 않는다. D-21이 거래일 H와 시장 달력으로 정한 원래 구간을 공급한다. 아직 판정되지 않은 추정을 성공/실패로 지어내 넣지 않는다. 입력의 판정 완료 여부와 출처 인증은 D-27·A-15 책임이다. 전체 이력을 저장하는 S 작업과 달리 Calibration은 한 번 받은 사실 집합의 불변 스냅샷이다.

모델 식별은 제공자·모델 이름·모델 버전을 별도 ModelIdentityPart로 보존한다. R-12 2.8의 provider·model 메타데이터와 design 6.2의 모델 변경 분리를 따른다. 이름이 같은 다른 제공자와 다른 버전은 다른 조합이다. 실제 모델 버전을 알 수 없는 별칭을 고정 버전이라고 꾸며서는 안 된다. ADR 0022의 불투명 식별자 관례에 맞춰 각 부분은 ASCII 표시 문자 1~64바이트이며 정규화하지 않는다. 오류에는 입력값을 담지 않는다. 프롬프트 비교 수·버전·추론 강도 등 실행 메타데이터는 D-17과 AI 기록 책임이며 모델 식별에 임의로 합치지 않는다.

## 집계와 후속 소비자

조합을 먼저 분리하고 같은 종목의 겹침 연결 성분마다 한 건을 센다. 입력은 종목, 시작 오름차순, 끝 내림차순, 실패 우선, 예측 확률 오름차순으로 정렬한다. 연결 성분의 첫 추정만 대표로 남기되, 제외된 구간도 성분의 끝을 늘린다. 따라서 A와 B, B와 C가 겹치면 A와 C가 직접 겹치지 않아도 한 건이다. 완전히 같은 사실의 중복도 한 건이다. 다른 종목·모델·기간은 서로 억제하지 않는다. 선택된 사실 접근자를 제공해 D-17이 같은 표본을 사용할 수 있게 한다.

판정 수와 구간별 적중 수는 정수 CalibrationCount다. 구간 적중률은 0건이면 None이며, 그 밖에는 ADR 0029의 RatioQuotient(정확/근사)를 보존한다. 근사 값을 정확한 비율로 재구성하지 않는다. 적중률은 표시용이며 보정 함수의 대체 구현이 아니다.

CalibratedProbability의 필드는 비공개다. 공개 생성자·Default·From·역직렬화·가변 접근자가 없고 Calibration::calibrate 하나만 원래 Probability에서 이 타입을 만든다. 결과는 확률·조합·판정 수·닫힌 상태를 보존한다. 0~29건은 NotCalibratedInsufficientSamples와 Conservative, 30건 이상은 IdentityBeforeE91와 MinimumReached다. 두 상태 모두 E-91 전에는 원래 값을 정확히 반환한다. 아직 존재하지 않는 보정 알고리즘의 Calibrated 상태를 미리 성공으로 표시하지 않는다.

D-24는 CalibratedProbability만 받는다. D-22·D-25는 결과의 조합과 판정 수를 유지해 30건 미만의 15%p·작은 매수 비중 강제를 적용해야 한다. D-17은 Conservative를 판정 보류로 표시해야 한다. 이 작업은 임계값·주문·화면 문구를 구현하지 않는다. 30건이 실력을 증명한다는 뜻도 아니다. E-91은 기존 항등 계약 테스트 변경에 사용자 승인이 필요한 후속 작업이다.

## 미해결: 근거가 없는 세부 규칙의 보수적 초안

| 항목 | 적용한 초안 | 근거와 남은 확인 |
|---|---|---|
| 겹침 끝점 | 양 끝 포함 [시작, 만기]. 맞닿은 구간도 겹침 | design 6.2는 겹치지 않는 것만 세라고 하지만 끝점은 미정. ADR 0028의 장 세션 [시작, 끝)과 달리 판정 수를 적게 세는 쪽을 선택 |
| 시간 축 | 공급받은 원래 전체 구간의 절대 Timestamp 비교 | ADR 0028 시간 타입, ADR 0039는 Horizon을 실제 거래일 길이로 환산하지 말라고 명시. 주말·휴장을 빼서 겹침을 줄이지 않음 |
| 대표 | 겹침 연결 성분당 첫 시작, 동시 시작은 긴 만기, 이후 실패·낮은 확률 우선 | 선택 순서는 문서에 없음. 독립 표본 수를 부풀리지 않는 결정적 초안. 연결 사슬은 비겹침 최대 부분집합보다 적게 셀 수 있음 |
| 확률 구간 | [0,50%), [50,60%), [60,70%), [70,100%] 네 구간 | R-12 2.3은 “예: 50~60%, 60~70%, 70% 이상”으로만 제시. 확정 경계·개수는 없음. 예시 경계를 보존하고 나머지 50% 미만은 세분화하지 않은 표시용 초안. 경계는 오른쪽 구간, 100%는 마지막 |
| 모델 식별 | 제공자·이름·버전 각각 1~64바이트, 대소문자 구별 | ADR 0022 관례. 모델 전용 길이·별칭 해소·버전 획득 방식은 미정. 자동 갱신 별칭의 숨은 변경은 이 타입이 탐지하지 못함 |

## 검증과 한계

완료 기준을 테스트로 먼저 추가해 구현 API가 없어 컴파일 실패하는 것을 확인했다. 29/30·0건·없는 조합, 제공자·이름·버전·Horizon 분리, 끝점·연결 사슬·대표 동률, 모든 구간 경계·100%, 1/3의 근사 비율과 빈 구간, ID·최대 입력을 검사한다. 4096회 속성 테스트는 정렬 스캔과 별개인 구간 그래프 연결 성분 기준으로 선택 사실 전체를 대조하고 입력 역순에서도 동일함을 검사한다.

공개 필드 봉인은 타입 경계이며 악의적인 코드나 잘못된 판정 사실을 인증하는 장치는 아니다. D-24 호출 서명, D-27 판정, 실제 거래일 만기 계산, 화면 표시, E-91의 실제 보정·Brier 개선은 이번 작업의 검증 범위 밖이다. 프로젝트 신뢰·Codex 훅 신뢰의 실제 런타임 적용 증거는 확보하지 못했으며, 전체 검사와 설치한 Git 훅의 결과를 별도로 확인한다. 새 의존성·검사 끄기·기존 테스트 변경은 없다.

외부 rustc 임시 소비자에서 calibrate를 통한 생성은 컴파일 성공했다. 필드 직접 생성은 E0451, Default는 E0599, Probability의 Into 변환은 E0277로 실패했다. 이는 현재 API의 수동 컴파일 검증이며 영속 compile-fail 회귀 테스트는 아니다(ADR 0022의 하네스 인계와 동일). 초기 표적 테스트는 6개 모두 통과했고 커버리지 검사도 위반 없음이었다. 최종 검증 수치는 구현자 보고서에 적는다.
