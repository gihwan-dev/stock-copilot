# ADR 0017: Claude Code 편집·셸 훅, 권한 규칙, 에이전트 쓰기 허용 목록

- 상태: 제안
- 날짜: 2026-11-12
- 결정한 사람: 메인 에이전트(사용자 확인 대기)
- 관련 작업: H-15
- 반영한 문서: 없음(이 ADR만 추가. harness.md 7.2·7.3과 다른 점은 아래 "문서와 다른 점"에 모았다)
- 개정: 2026-11-12 리뷰 반영(아래 "리뷰 반영"이 앞의 결정보다 앞선다)

## 맥락

harness.md 7.1은 에이전트 쓰기 허용 목록을 `harness/agent-writable.txt` 한 파일에 두라고 했고, 7.2·7.3은 권한 `deny`, `PreToolUse`(Edit|Write|NotebookEdit, Bash), `PostToolUse`(Edit|Write), `ConfigChange` 훅을 정했다. ADR 0005·0013·0015는 훅으로 넘긴 것(`git update-index` 표시, `.git/info/` 쓰기, `LEFTHOOK*`, `CARGO_HOME`, `--no-verify`, `core.hooksPath`, 하위 `.gitignore`, 서브에이전트의 병합 계열 명령, `just lint-file`)을 H-15에 남겼다. 정할 것: 허용 목록의 형식, 역할 판정, 훅 언어와 위치, 셸 명령을 문자열로 검사하는 범위, 남은 하네스 작업이 보호 파일을 만들 수 있게 하는 방법.

## 실측

환경: macOS 26 (Apple Silicon), Claude Code 2.1.322, Node 24.22.0, `claude -p --model haiku --setting-sources project --permission-mode acceptEdits --no-session-persistence`(구독 로그인). 실험은 이 판을 scratchpad에 복사한 임시 저장소에서 했다.

| 항목 | 명령 | 결과 |
|---|---|---|
| 셸 훅 | 메인이 `git commit --no-verify -m probe` | `PreToolUse:Bash hook error: [git-no-verify] …` 로 실행되지 않음 |
| 편집 훅(메인) | 메인이 `crates/domain/src/probe.rs` Write | `[main-docs-only]` 거부 |
| 잠금 꺼짐 | 메인이 `docs/harness.md` Write | 쓰기 허용, `PreToolUse:Write hook additional context: [protected-path] … 경고만 한다`가 모델에 보임 |
| 권한 거부 | `.claude/settings.local.json` Write, `printf … > .claude/settings.local.json` | 둘 다 "denied by your permission settings". 셸 리다이렉트도 `Edit(/…)` 규칙에 걸림(R-10 실험 1과 같다) |
| 역할 판정 | `--agents`로 정의한 `implementer`가 Write와 `git push` | 훅 입력의 `agent_type: "implementer"`로 구현자로 판정. `git push`는 `[git-subcommands] 서브에이전트는 git push를 하지 않는다`로 거부 |
| 린트 훅 | implementer가 `pub fn probe() {} // note` Write | `PostToolUse:Write hook blocking error … just lint-file … source-check: 위반 … comment`가 서브에이전트에 돌아감 |
| ConfigChange | 세션 중 다른 프로세스가 `.claude/settings.local.json`을 만듦 | 디버그 로그: `ConfigChange:local_settings … completed`, `ConfigChange hook blocked change to …/settings.local.json` |
| `.claude/settings.json` Edit | 메인이 Edit(잠금 꺼짐) | 훅은 경고만 냈지만 Claude Code 자체가 "permissions to write … you haven't granted it yet"으로 막음(`acceptEdits`에서도 설정 파일은 따로 묻는다) |
| 잠금 켜짐 | `lock.txt`를 `on`으로 바꾼 복사본에서 Write `docs/harness.md`, `echo probe > justfile`, Write `lock.txt` | 앞의 둘은 `[protected-path]` 거부, 셋째는 권한 `deny` |
| S-17 | `--setting-sources project,local`로 `-p` 실행 | 구독 로그인으로 동작(ConfigChange 실험). 대화형 세션은 `expect`로 pty를 띄웠지만 작업 공간 신뢰 대화상자에서 선택이 넘어가지 않고 종료되어 확인하지 못했다(미확인으로 남김) |

## 리뷰 반영 (2026-11-12)

### 원칙

- 셸 훅은 "해석하지 못하면 거부"로 닫는다. 명령 이름·git 하위 명령·쓰기 대상에 동적 낱말(변수, 명령 치환, 글롭, 중괄호 확장, 숫자 이스케이프가 든 `$'…'`)이 있거나, `env`의 모르는 옵션, `env -S`가 명령 하나로 풀리지 않거나, 현재 폴더를 모르는 상대 경로 쓰기, 하네스가 풀지 못하는 실행기(`watch`, `ssh`, `parallel`, `flock` 등 목록 밖 명령)의 인자에 감시 대상 이름(`git`, `cargo`, `just`, `lefthook`, `rustc`, `rustup`, `claude`, `gh`, `hub`, 셸, `eval`, `env`, `pnpm`, `npm`, `npx`, `node`)이 낱말로 들어 있으면 거부한다.
- **셸 문자열 검사는 흔한 실수와 알려진 우회를 막는 겹이다. 보호 경로 쓰기의 실제 강제는 샌드박스(H-35)와 CI의 서명 검사(H-26)다.** 훅은 명령 문자열만 보고, 실행된 프로그램이 하는 일은 보지 못한다.
- 인터프리터 빈틈의 실제 크기: 메인의 `python -c`·`node -e` 등은 낱말 검사만 받으므로 코드는 무엇이든 할 수 있다(파일 쓰기, 프로세스 실행, 네트워크). 서브에이전트는 인라인 코드를 아예 쓸 수 없지만, 쓸 수 있는 경로에 스크립트 파일을 만들어 실행하면(`python3 tools/x.py`, `node x.mjs`, `bash x.sh`) 그 스크립트가 하는 일은 훅이 전혀 보지 못한다. 그 파일은 편집 훅과 린트를 거칠 뿐이다. 이 빈틈은 H-35가 막는다.

## 문서와 다른 점

- 훅 언어: harness 7.2는 `python3 -I`, 이 결정은 Node ESM이다(위 근거).
- 7.3 "git 설정"의 `git -c`는 `commit.gpgsign=false` 하나만 예외다.
- 7.1의 "보호 파일 편집 거부"는 잠금 스위치가 켜졌을 때만 거부이고 지금은 경고다. 7.3이 정한 셸 금지 명령, 린트 훅, 역할 제한(메인의 코드 편집, 리뷰어 편집), 경로 안전 검사, `.git`·cargo 설정·하위 `.gitignore`는 지금도 거부다.
- 권한 `deny`는 두 항목뿐이다. R-10 3.2의 목록은 H-20에서 넣는다.

## 결과

- 병합하면 이 저장소에서 연 Claude Code 세션(프로젝트 설정의 훅은 작업 공간 신뢰를 받아들인 뒤에만 돈다)에 바로 적용된다. 메인 에이전트는 `docs/**`, 임시 폴더, Claude Code의 메모리·계획 폴더 밖을 편집 도구로 쓸 수 없고 셸로도 저장소의 `docs/**` 밖에 쓸 수 없다. 리뷰어·비판자와 정의 밖 서브에이전트(`general-purpose`, `Explore` 등)는 편집 도구를 쓸 수 없고 셸로는 임시 폴더와 빌드 산출물 폴더에만 쓴다. `git rebase`(`--abort` 제외), `git config`, `commit.gpgsign=false` 밖의 `-c`, `alias` 정의, 서브에이전트의 `push`·`pull`·`cherry-pick`·`revert`·`am`·`gh`와 인라인 인터프리터 코드, 구현자의 `git merge master` 밖의 병합이 거부된다. 하위 폴더의 설정 파일은 편집 훅과 `just check`가 거부한다. 편집마다 `just lint-file`이 돈다(약 1초, 정리 직후에는 xtask 빌드).
- 보호 경로 편집은 지금 경고만 낸다. H-20이 `lock.txt`를 `on`으로 바꾸면(사용자 서명 커밋) 거부된다. 그때 경로 고정 테스트 파일, `testkit`의 `ScriptedPresence`, UX-6 목록, 시각 회귀 기준 이미지가 생겼으면 제외 줄을 더해야 한다(지금은 파일이 없다).
- 새 ADR 파일은 원본 저장소 `HEAD`에 없는 번호일 때만 쓸 수 있고, 병합되면 추적된 파일이라 자동으로 보호된다.
- 후속: H-25(서브에이전트 훅은 `lib/roles.mjs`, `lib/project.mjs`를 쓴다), H-35(샌드박스, 위 빈틈), H-20(잠금, 긴 `deny`), H-36(Claude Code를 올릴 때 이 ADR의 실측 다시 돌리기). S-17의 대화형 확인은 사용자가 한다.
- 바뀌면 다시 볼 조건: Claude Code가 훅 입력의 `agent_type`·`agent_id`, `onFailure`, `ConfigChange` 동작, 설정 파일 편집 확인을 바꿀 때.
