# fin-flow 묶음 결정 기록

경량 절차(ADR 0173)로 `fin-flow` 묶음(추정 과제 생성 → AI 추정 → 추정 저장 → 신호 평가 → 제안 초안 → 신호 카드 이벤트를 제품 경로로 잇기)을 구현하며 문서가 정하지 않아 정한 것이다.

## 정한 것

| 작업 | 정한 것 | 다른 선택지 |
|---|---|---|
| FF-1 | 과제 만기(비용 기간 끝)를 판정과 같은 규칙(`schedule`: 기준 시각 뒤 정규장 기준 H 거래일의 정규장 종료, 몇 시간 단위는 첫 정규장 길이의 1/4)으로 domain `estimate_maturity`가 계산한다. 달력이 모자라면 `Calendar` 실패 | 조립 루트에서 날짜 더하기 |
| FF-2 | 단일 추정 실행 `RunSingleEstimate`(application): 재료 포트 → 만기용 달력 → `CreateEstimateTask` → 실행 맥락 등록 → 분석 실행(프롬프트에는 과제 ID와 종목 식별자만) → 맥락 해제 → 과제가 소비됐으면 `Submitted`. 재료·달력이 없거나 과제가 건너뛰어지면 AI를 띄우지 않는다 | 과제를 만들지 않고 AI가 종목을 고름(SEC-4 위반) |
| FF-2 | 실행·과제 ID는 `est-<계기>-<종목 ID 앞 24자>-<UTC 초>`로 같은 문자열을 쓴다(과제 ID 64자 제한). 같은 종목·같은 초의 두 번째 발급은 `AlreadyIssued`로 실패 | 난수 ID(application에서 난수 금지) |
| FF-2 | 추정 프롬프트는 application 상수(`prompts/estimate/v1.md`의 요지)로 두고, 기록용 `EstimatePrompt`는 id `estimate`, 버전 `v1`, 해시는 상수 원문의 SHA-256이다. 배포 앱에 프롬프트 파일이 들어가지 않아 파일을 읽지 않는다 | 실행 때 파일 읽기 |
| FF-3 | 종목 추정 순환은 스케줄러 AI 작업(`EstimateCycleJob`, 매일 01:00 KST, 놓치면 한 번 따라잡음)이다. 종목마다 예약 작업 한도를 다시 본다(AI 대기열 `evaluate_scheduled_quota`): 채팅 중이거나 한도·속도 제한이면 멈추고 다음 실행이 멈춘 종목 다음부터 잇는다 | 시각 없이 한도가 남을 때마다 실행(채팅 선점과 겹침) |
| FF-2 | 보정 조합의 모델 식별은 `claude-code`/`default`/`cli`로 고정한다. 실행 중 `ActualModel` 이벤트와 MCP 제출이 경쟁해 같은 실행의 모델이 어긋날 수 있어서다. 실제 모델별 분리는 후속 | 실제 모델 이벤트로 갱신 |
| FF-4 | 조립: `EstimateRunBook`(실행 ID → 추정 실행 맥락)을 MCP `submit_estimate`의 맥락 원본으로 쓴다(전에는 늘 미연결). 순환·장중 감시 실행은 `EstimateFlowSlot`(Tauri 상태)을 거쳐 `RunSingleEstimate`를 부르고, 순환 대상은 저장된 보유(계좌별 최신 동기화) + 관심 종목, 종목 식별은 종목 마스터 디렉터리(시장·심볼 → 종목 ID → 마스터) | 화면 상태에서 대상 받기 |
| FF-4 | 장중 감시의 가격 급변·뉴스 급증은 추정 과제를 만들어 논거 갱신과 추정을 한 실행으로 한다. 과제를 만들 수 없으면(대상 아님·재료 없음) 기존 논거 점검 실행으로 넘긴다. 긴급 공시는 공시 키에서 종목을 찾는 경로가 없어 기존 논거 점검만 한다 | 공시마다 종목 검색 |
| FF-4 | 세율은 토스 API에 없어 R-11의 2026 시행 법령값을 시장별 고정 사실로 둔다: 국내 매도 0.20%(코스피 거래세 0.05%+농특세 0.15%, 코스닥 0.20%), 매수 0. 미국 매도 0.02%(SEC 수수료·FINRA TAF의 보수적 상한), 매수 0. ETF 면제는 반영하지 않아 비용을 넘치게 잡는다 | 세율 미상으로 과제 없음(ADR 0050 원문, 기능 전체가 멈춤) |
| FF-4 | 변동성 일봉은 과제 시각 기준 150일 창, 수정주가 기준 시각 = 과제 시각, 과제 시각의 날짜 봉은 뺀다(확정 전후로 표본이 달라지지 않게). 신호 평가의 복원 근거는 같은 창을 다시 받아 domain `EstimateRestoreEvidence::capture`로 재현을 확인하고, 다르면 복원 근거 없음으로 신호를 막는다 | 과제 근거를 새 표에 저장(이주 번호가 다른 묶음과 겹칠 위험) |
| FF-5 | 추정 제출(`EstimateSubmitted`)을 구독하는 늦게 묶는 슬롯(`SignalPipelineSlot`)이 비동기로 `EvaluateSignals` → 현재 신호가 있으면 `DraftProposal`을 부른다. 장이 닫혀 있으면 다음 정규장 시작까지 60초 간격으로 `Clock`을 보고 다시 초안을 만든다(최대 3번). 초안의 재추정 예약은 장중 감시 경로(가격 급변 계기)로 한 번 돌린다. 신호·제안 이벤트(`SignalRaised`·`ProposalCreated` 등)는 기존 UI·알림 구독자로 그대로 간다 | 장 개장 이벤트(아직 발행처 없음) 대기 |
| FF-5 | 판정이 한 건도 없는 조합은 SQLite에 보정표 행이 없어 신호가 늘 "보정표 없음"으로 막혔다. 첫 평가 때 빈 보정표를 위치 0으로 기록해 "정상적인 빈 표 → 보수 운용"이 되게 한다(같은 해시는 다시 쓰지 않음) | 저장소가 행 없음을 빈 표로 해석(기존 판정 경로 의미 변경) |
| FF-5 | 신호 평가 입력: 정책은 저장된 투자 성향만(`Policy::new`, 투자 원칙 미반영), 섹터 분류는 토스 섹터 목록의 대분류 구성을 시장별로 하루 캐시해 domain `sector_assignment_from_compositions`로 만들고, 실패한 종목은 미분류로 둔다(미분류는 신호를 막음). 평가 시세·복원 근거의 주문 방향은 매수 기준 | 섹터 조회 없이 전부 미분류(신호가 절대 안 남) |
| FF-5 | 저장소 `SqliteRepositories`에 신호 무효화 포트(`SignalInvalidationRepository`) 위임을 더한다(신호 저장소에는 있었으나 공유 저장소에 빠져 있었음) | - |
