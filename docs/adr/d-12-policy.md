기간·위험 성향은 과제·임계값·수량의 입력이며 별도의 원칙을 더하지 않는다. 반복 매수 제한은 D-25, 주문 잔고·시장·승인 검사는 O-01에 남긴다.

## 판정과 후속 계약

현재 상태와 매수 후보 검사는 별개다. 현재 비중이 상한과 같으면 초과 위반은 아니지만 추가 매수는 차단한다. 주의 기준은 등호를 포함한다. 매도는 비중과 제외 검사로 막지 않는다. design 6.3의 매도 수량 규칙과 비중 감소 목적에 따른 해석이며, 다른 주문 검사를 면제하지 않는다.

비중 비교에는 AssetAllocation과 AssetWeight::cmp_profile_weight만 쓴다. 정확한 여유 산출에는 같은 평가 스냅샷의 원화 평가액을 사용한다. 보유 구성비나 표시 반올림 비중은 받지 않는다. 원화 상한 타입은 Money·Ratio·Decimal로 공개 변환하지 않으며 비용과 비교하는 연산만 제공한다. D-25는 주문 비용을 이 상한 이하로 내리는 수량을 선택해야 한다. 미국 주문은 D-25가 환율·통화 매수가능금액과 함께 별도로 제한한다.

불완전 평가, 음수 현금, 산술 실패, 모르는 유형·섹터는 통과하지 않는다. ETF/펀드와 미분류 버킷의 섹터 상한 면제 근거가 없으므로 매수 차단한다. 분류와 평가의 불일치를 피하도록 사전 검사가 같은 SectorAssignments로 Allocation을 만든다.

## 미해결

- design 6.2는 축소와 차단의 세부 경계를 명시하지 않는다. 양수 여유가 있으면 축소, 없으면 차단을 design 6.3의 “깎은 뒤 수량으로 바꾼다”에 따라 채택했다.
- 자유 서술 원칙의 실행 가능한 표현, 현금 최소 비중의 분모·기본값, 쏠림 경고를 주문 게이트에 반영하는 정확한 규칙은 G-01에서 확정해야 한다. D-07과 동시 작업이므로 그 타입을 추측하지 않는다.
- ETF/펀드 버킷의 상한 정책과 섹터 제외 적용은 별도 문서 결정이 필요하다. 현재는 판정 불가다.
- 평가액은 근사다. 전용 상한은 주어진 스냅샷 내 한도이며 실제 체결 금액의 보증이 아니다. D-25/O-01이 최신 시세·비용으로 다시 검사한다.
- 프로젝트 설정 hooks=true와 Git 훅 설치는 확인했으나 현재 세션의 프로젝트·훅 신뢰 적용 여부는 확정할 증거가 없다. 직접 실행한 검사와 커밋 훅 결과를 보고한다.

## 공개 API와 작업 경계

- `Policy::new(InvestorProfile)`는 D-20의 기본 투자 성향 원칙을 검사한다. `profile()`로 입력 프로필을 읽는다.
- `check_current(valuation, assignments, security_types)`는 현재 상태의 위반·주의 목록 또는 판정 불가 오류를 반환한다. 상한 초과와 주의 기준은 구분한다.
- `PolicyCandidate::new(&ResolvedOrderInstrument, Option<ExcludedSecurityType>, requested_krw)`는 양수 원화 후보 비용만 받는다. 종목·유형·후보 비용 읽기 접근자가 있다. 유형 부재는 검사 때 차단한다. 종목 마스터 정보의 사실성은 T-09/O-01 책임이다.
- `check_buy`는 `Pass / Reduce(PolicyBuyLimit) / Block(PolicyViolation)`만 반환한다. 같은 평가·분류로 `AssetAllocation`을 만들며, 다른 보유에 미분류·ETF/펀드 버킷이 있어도 섹터 노출을 확정할 수 없어 차단한다.
- `PolicyBuyLimit::compare_krw_cost(Money)`는 `WithinLimit / AboveLimit / InvalidCost`다. 원화 상한을 돈·수량으로 꺼내는 접근자나 변환이 없다. D-25는 정확한 후보 비용을 비교하면서 정수 수량을 내리는 탐색에 사용할 수 있다. 이 비교를 통과한 수량만 선택하고, 상한 자체를 주문 금액으로 사용하지 않는다. 통화 매수가능금액·주문 비용·환율·반복 제한은 D-25/O-01의 추가 제약이다.
- `Policy::check_sell()`은 `Allowed`다. 이 결과는 다른 주문 검사의 면제가 아니다.
- G-01 설정이 존재하지만 아직 결정적 평가 계약이 없으면 `with_unresolved_principle(FreeText / MinimumCash / ConcentrationWarning)`로 넘긴다. 그러면 현재 검사는 판정 불가이고 매수는 차단한다. D-07 쏠림 계산을 중복 구현하지 않는다. 기본 `Policy`의 빈 위반 목록은 D-20 프로필 규칙 범위의 결과이며 G-01 전체 검사를 완료했다는 뜻이 아니다. G-01 통합은 별도 후속 작업이다.

내부 원화 평가액 경로는 allocation.rs의 `policy_krw_holding_values` 하나다. 기존 변환 함수를 재사용한다. 비중 상한 비교는 AssetWeight 전용 함수로, 실제 여유 계산은 정확 곱·차로 한다. 표현 정밀도 손실은 차단한다. 입력의 총자산·평가가 불완전하면 원화 부분합으로 한도를 허용하지 않는다.

검증 기준은 1원 단위 정수 기준 4,096회, 가변 총자산·상한을 쓰는 1/100원 유리수 기준 4,096회, 정보 부재·음수 현금 512회다. 정수 기준에는 두 보유의 입력 순열을 대조한다. 최소 양수·MAX·상한과 같은 현재 비중·9개 제외 유형·새 매수 종목·다른 섹터·공개 접근자·음수와 다른 통화 비용을 고정 예제로 검증한다. 테스트 함수 이름과 최종 검사 결과는 구현 보고에 남긴다.
