# A-13: 제출된 추정의 신호 평가
- 상태: 초안

## 결정

`EvaluateSignals`는 종목의 스냅숏과 제출 목록을 다시 읽어 마지막 제출 ID가 같을 때만 평가한다. 과제 원장에서 발급된 과제를 찾아 도메인의 보정, 임계값과 신호 판정을 적용한다. 출처는 제출 내용으로 구성하지 않고 A-27의 독립 원장을 읽는다. 저장 충돌이나 제출 조회 시점 차이는 최대 세 번 처음부터 다시 읽고, 폐기된 제출은 즉시 중단한다. 커밋이 돌려준 이벤트만 성공 뒤 순서대로 발행하며 각 전송 결과를 반환한다. 제출 기록은 변경하지 않는다.

새 포트 `SignalEvaluationData::inputs`는 제출별 보정 스냅숏과 별도 최신 원장 위치, 보유 평가, 투자 원칙, 종목·업종 분류, 대상 가격, 캘린더 및 수량 계산에 필요한 비용 사실을 제공한다. 표와 원장 위치는 각각 부재를 표현한다. 정상 빈 표는 부재가 아니다. A-15의 `ResolutionCalibration`은 표와 위치가 둘 다 있는 경우의 공급원이며, 실제 어댑터는 별도 위치도 정확히 조회해야 한다. 표 부재·오래됨·다른 조합은 D-51의 각 사유로 신호 없음을 커밋한다. 포트 오류 자체는 오류로 돌려주고 이벤트를 내지 않는다.

매수 발생 ID는 호출자가 제공하며 저장소는 ID 충돌을 거부한다. 새 매수 발생과 방향 변경에만 도메인이 발생 기록을 만든다. 유지·내용 갱신은 기존 발생을 이어 쓴다. A-27 발생 이력을 `calculate_buy_quantity`에 그대로 전달하고 현재 발생의 자기 제외는 도메인에 맡긴다. 대상 가격은 도메인의 종목 ID 검증을 통과한 관측을 수량 계산에도 전달한다. 비용 사실이 없으면 수량은 `Indeterminate`이며 판단한 신호 자체는 기록한다. 계획과 수량 불가 사유는 평가 결과로 돌려준다. 이 결과는 주문 승인이나 주문 전송 권한이 아니다.

기존 `Thresholds::compare`를 공개해 정확한 도메인 비교 결과를 관측할 수 있게 했다. 새 계산이나 정책은 추가하지 않았다. 여유분은 임의 입력을 받지 않고 현재 투자 원칙의 위험 성향을 `Margin::for_appetite`에 전달한다. 테스트는 과제에 연결된 비용을 조정해 제출 가능한 정수 확률과 임계값이 정확히 같은 점을 도메인 비교 결과로 찾고 그 바로 아래·같음·바로 위를 유스케이스에 넣는다.

| 전이 | 커밋 성공 뒤 이벤트 |
|---|---|
| 없음 → 발생 | SignalRaised |
| 동일 내용 유지 | 없음 |
| 같은 방향 내용 갱신 | 없음 |
| 발생 → 없음 | SignalCleared |
| 매수 ↔ 매도 | SignalCleared, SignalRaised 순서 |
| 충돌·폐기·저장 실패 | 없음 |

## 검증과 한계

가짜 저장소의 동시성은 단일 프로세스 메모리 계약 검증이다. 실제 계좌, 키, API 및 SQLite 저장은 사용하지 않았다. 프로젝트 신뢰와 이 세션에 훅 신뢰가 적용됐는지는 확인할 수 없다. 세션 신뢰와 별도로 Git 훅 및 명시적으로 실행한 검사 결과를 리뷰 기록에 남긴다.
