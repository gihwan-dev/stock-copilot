# ADR 0173: 경량 절차로 전환

- 상태: 확정 (2026-11-24, 사용자 결정)

## 배경

작업 하나가 구현에서 착륙까지 4~8시간 걸렸고, 병합 한 번의 전체 검사가 90분을 넘었다. 세션 훅이 훅 끄기를 막은 뒤로는 문서가 든 커밋마다 전체 검사가 돌았다. 385개 작업 중 197개가 남은 시점에 사용자가 "너무 느리고 과하다, 하네스를 대폭 완화하고 큰 단위로 끝내고 병합하자, AI 관련 부분만 작게 꼼꼼하게 하고 나머지는 빠르게"라고 결정했다.

## 결정

1. 커밋 훅은 `cargo fmt --all --check`만 돈다. 병합 커밋 훅과 푸시 훅은 없앤다.
2. 병합 판정은 `just check-lite`다: 타입 검사, ESLint, 프런트 빌드와 테스트, `cargo fmt`, Clippy, 구조·소스·SQL·마이그레이션·권한 검사, 생성물 검사, 작업 공간 테스트(속성 테스트 256회, `xtask` 제외). 커버리지 하한, 기존 테스트 변경 검사(`test-diff`), 변이 검사, 리뷰 기록 검사, 시각 기준 화면 비교, 검사 끄기 보고는 병합 판정에서 뺀다. `just check`는 남겨 두되 병합을 막지 않는다.
3. 작업은 묶음 단위로 한 스레드가 여러 행을 이어서 구현하고, 묶음이 끝나면 한 번에 병합한다.
4. 리뷰는 두 갈래다.
   - AI 관련(AI 러너 `AI-*`, MCP 서버 `M-*`와 그 경계): 작업을 작게 나누고 적대적 리뷰와 독립 비판을 최대 2회차, 손 변형 20개 이상을 유지한다.
   - 그 밖: 외부 리뷰 없이 구현 담당이 테스트와 `check-lite`로 확인한다. 주문 묶음은 묶음 끝에 리뷰를 한 번 받는다.
5. 작업별 ADR과 리뷰 기록은 AI 관련 작업에만 쓴다. 그 밖의 묶음은 문서가 정하지 않은 것을 정했을 때만 묶음당 ADR 하나에 결정 표로 남긴다.
6. 구현 담당은 보호 파일의 추가형 변경(허용 목록, 잠금 파일에 이미 있는 패키지의 전이 예외, 고정 목록의 새 항목)과 그에 따른 기존 고정 테스트 갱신을 묻지 않고 한다.

## 바뀌지 않는 것

- 실제 주문 API와 실제 토스 API를 에이전트가 부르지 않는다. 실제 키와 실제 계좌 자료를 에이전트가 다루지 않는다.
- 사용자 홈의 설정·자격 증명 파일을 읽거나 고치지 않는다. 세션 훅의 이 차단은 그대로 둔다.
- 새 외부 패키지는 문서와 ADR이 이미 정한 것만 들인다.
- 구조 경계(`arch-check`), 금액 타입 규칙, 주문 타입 봉인 같은 컴파일·구조 수준의 방어는 그대로 돈다.

## 결과

- `xtask`의 하네스 자체 테스트 중 훅 구성과 `justfile`을 고정하는 것은 이 변경과 어긋나 실패할 수 있다. `check-lite`가 `xtask` 테스트를 빼는 이유다. 정리는 뒤로 미룬다.
- 커버리지·변이·기존 테스트 변경 검사가 병합을 막지 않으므로 약한 테스트가 들어올 수 있다. AI 관련 경로는 리뷰와 손 변형으로 보완하고, 나머지는 기능을 다 만든 뒤 한 번에 점검한다.
