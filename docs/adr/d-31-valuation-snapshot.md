# D-31 일별 평가와 오늘 손익

- 상태: 초안
- 기준: e7a2064afc584dd464cad73f845d35fb6669d76e
- 근거: I-09, R-11 Q1·Q4·Q5, ADR 0028·0029·0031·0034·0035·0038·0044

## 일별 평가

`ValuationSnapshot`의 생성은 실제 포트 조회 결과를 받는 `observe`와 거래 원장으로 계산하는 `recalculate`로 나눈다. 재계산 출처를 관측 출처로 바꾸는 API는 없다. 조회·재계산 수행 시각과 시장별 평가 날짜를 각각 보존한다. 필드는 비공개이고 읽기 접근자만 제공한다.

| 항목 | 규칙과 근거 문장 |
|---|---|
| 거래일 | ADR 0028의 “국내 date는 KST 영업일, 미국 date는 미국 현지 영업일”을 보존한다. 두 시장 캘린더의 today와 previousBusinessDay를 각각 기록한다. KST 오늘에서 미국 날짜를 추측하지 않는다. 휴장인 today는 ClosedDay로 거부하며 대체 날짜는 application이 해당 시장 캘린더에서 선택한다. |
| 수량 | D-28 LotBook을 평가 날짜마다 다시 만든다. ADR 0044의 “입력은 SettledRowSet::active_settled_for_calculation뿐”을 따른다. 결제일 기준이며 미래 결제·미결제·취소·사라진 행은 포함하지 않는다. |
| 가격 | R-11 Q1의 “수정 전 일봉(adjusted=false)과 그날 환율을 곱한다”를 따른다. 날짜·InstrumentId·통화가 같은 확정된 원주가 일봉 하나만 받는다. 중복은 임의 선택하지 않는다. |
| 기업 행사 | 평가 날짜까지의 행사만 D-28에 전달한다. 분할 전 수량에는 분할 전 원주가, 이후 수량에는 이후 원주가를 쓴다. 원가 미상은 LotBook에 그대로 보존하며 평가에 원가 0을 대입하지 않는다. 단주 현금 정산 대기와 상장폐지는 불완전이다. |
| 현금 | R-11 Q1의 “현금은 거래내역의 netAmount를 부호에 맞춰 누적해 원장을 만든다”에 따라 재구성 현금 입력이 필요하다. D-30 미병합 상태이므로 SnapshotCashInput으로 받는다. 대조를 마쳤다는 입력 증언이며 실제 현금을 인증하는 타입은 아니다. |
| 환율 | R-11 Q4의 “원화 합산 평가와 비중의 기본값”인 Mid만 사용한다. 환율의 보존 오프셋 날짜가 미국 평가 날짜와 다르면 불완전으로 거부한다. FxRate 전체(종류·시각·출처·유효 구간)를 보존한다. 역사 평가는 현재 유효 구간 검사를 적용하지 않는다. |
| 누락·산술 | 가격·환율·현금·로트 계산 실패를 오류로 보존하고 불완전으로 둔다. 보유 수량이 실제 0인 종목은 시세 없이 0으로 평가할 수 있다. 오류를 0으로 치환하지 않는다. 통화별 오류와 종목별 로트·봉·오류를 읽을 수 있다. 부분 합을 완전 합으로 노출하지 않는다. |
| 근사 | 통화별 값은 정확 Money다. 환산값은 KrwValuation이고 Mid 환산이 들어가면 Approximate와 사용 환율 목록이 유지된다. |

입력 목록은 종목·행사·봉마다 4096개까지다. 종목 이력은 InstrumentId로 정렬하며 중복 ID는 거부한다. 입력 순서와 무관하게 같은 결과가 나온다. 모든 보유 종목과 기업 행사 이력을 전달하는 책임은 application에 있다. 빈 이력을 완전한 거래 수집의 증명으로 해석하지 않는다.

## 오늘 손익

R-11과 design 2.4는 오늘 손익 표시를 요구하지만 별도의 오늘 손익 식과 전용 수치 예제는 없다. 이번 사용자 브리프의 기본식과 R-11 Q1의 기간 손익 정의를 일일 구간에 적용한다.

`통화별 오늘 손익 = 오늘 (주식 평가 + 현금) − 전일 (주식 평가 + 현금) − 당일 순외부유입`

`원화 오늘 손익 = 오늘 원화 평가 − 전일 당시 환율의 원화 평가 − 오늘 환율로 환산한 당일 순외부유입`

입금은 양수, 출금은 음수다. 매매·배당·이자·수수료·계좌 내 환전은 외부 흐름이 아니다(R-11 Q1 분류표). 증권 이관은 분류가 필요하며 분류할 수 없으면 흐름 입력을 unavailable로 넘긴다. 전일은 두 시장의 previousBusinessDay와 일치해야 한다. 당일 흐름 입력도 같은 날짜 쌍이어야 한다.

원화 차이는 각 날의 평가를 먼저 환산하므로 가격 효과와 환율 효과를 모두 포함한다. R-11 예제 6은 7000 USD×1200에서 6500 USD×1100으로 변하여 −1,250,000원이다. 통화별 −500 USD를 오늘 환율로만 환산한 −550,000원을 전체 손익으로 사용하지 않는다.

전일 누락·재계산·불완전을 SnapshotPrevious로 노출하고 현재 출처도 보존한다. 재계산으로 얻은 숫자를 완전한 실제 관측으로 주장하지 않는다. 통화별 계산은 환산 누락과 독립적으로 남을 수 있다.

ADR 0038의 “토스 값이 있으면 제공값을 선택”을 적용하여 통화별 선택값·출처·계산값·Matches/Different/Unavailable/NotProvided를 함께 제공한다. 표시 정밀도 대조는 D-05의 공통 함수를 그대로 사용한다. 원본 PortfolioDailyProfitLoss의 율과 기준도 그대로 보존한다. 원화 선택 합은 제공된 통화별 정본을 오늘 환율로 환산한다. 토스 서버의 실제 사용 환율이 없으므로 원화 대조는 Unavailable이다. 통화별 대조로 차이를 드러내고, 서버 환율을 추측하여 원화 일치를 선언하지 않는다.

## 임시 입력과 인계

| 현재 타입 | 인계 |
|---|---|
| SnapshotCashInput | D-30의 대조용 현금 타입으로 바꾼다. reconciled 증언에 실제 신뢰 상태와 날짜 범위를 연결하고 낮은 신뢰는 MissingCash로 유지한다. |
| SnapshotExternalFlows | D-30 ExternalFlow의 분류·증권 이관·입출금 합을 받는 경계로 바꾼다. 합계만 입력하는 현재 경계는 흐름의 분류 사실을 검증하지 않는다. |
| SnapshotCalendar | A-16·J-11은 시장별 거래일을 선택하고 빠진 날마다 호출한다. S-18은 관측·재계산 기록을 추가만 하며 기존 관측으로 덮어쓰지 않는다. |
| ValuationSnapshot | D-09는 상태·출처·현금 신뢰·로트 가정 표지를 확인한 뒤 기간 성과에 사용한다. 주식 부분 수익률로의 전환은 이번 범위 밖이다. |

## 미해결

- 오늘 손익 전용 식은 기존 문서에 없다. 위 식과 순외부유입의 당일 환율 사용은 보수적인 초안이다. 흐름 시점별 환율 및 환전의 세부 분해는 D-30·D-09에서 연결한다.
- 미국 평가일과 KST 환율 날짜가 다른 실제 응답은 현재 보수적으로 불완전이다. 시장 마감 시각에 해당하는 과거 환율 사실의 날짜 연결을 T-08·A-16에서 확정해야 한다. 타임존을 추측해 값을 수락하지 않는다.
- 양국 휴장일이 다른 날의 전체 포트폴리오 평가는 각 시장의 마지막 완료 거래일 선택 규칙이 필요하다. 현재 명시적 휴장 today는 거부한다.
- D-28의 미래 코드 변경 이력·행사 입고 지연과 기준일의 관계는 caller가 그날의 identity를 넘겨야 한다. 원가 미상·순서 가정은 종목별 LotBook에서 읽는다.
- `observe`는 조회 결과의 실제 네트워크 획득을 증명하지 않는다. A-08이 보유·현금·환율의 시각 정합을 확인해야 한다.
- 현재 세션 프로젝트 신뢰·훅 신뢰의 실제 적용은 증명하지 못했다. hooks=true, lefthook 설치와 직접 실행한 just check를 별도 증거로 사용한다.

새 의존성·주석·검사 끄기는 없다. 기존 테스트와 보호 규칙은 변경하지 않는다.
