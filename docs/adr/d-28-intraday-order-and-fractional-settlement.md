# D-28 후속: 같은 날 취득 순서와 단주 처리의 구분

- 상태: 초안
- 기준 구현: cda11c530bbd44396e38e649df692cdbc8c79d2e
- 근거: R-11 Q2·Q5, ADR 0034의 결제 멀티셋. 앞선 D-28 초안의 순서 정책을 보강한다.

## 취득 순서

같은 결제일의 내용이 서로 다른 행은 거래 종류가 같아도 순서를 알아야 한다. 예를 들어 1주 100원과 1주 200원을 같은 날 매수하고 뒤에 1주를 팔면 FIFO 손익은 매수 순서에 따라 달라진다. 처리 시각이 없거나 같은 경우에는 입력 벡터 순서를 근거로 정하지 않고 AmbiguousOrder로 거부한다. 시각이 다르면 그 시각으로 정렬한다. 내용이 완전히 같은 여러 행은 순서가 결과를 바꾸지 않으므로 멀티셋 개수 그대로 허용한다.

## 단주 처리

분할과 무상증자는 소수 수량을 유지하고 병합만 종목 전체 단주를 현금 정산 대기 청구량으로 구분한다. 행사 종류가 내부 닫힌 열거형 RetainShares/CashInLieu를 전달한다. 배수와 1을 다시 비교해 행사 종류를 추론하지 않는다. 단주 현금액을 추정하지 않는 앞선 초안의 정책은 유지한다.

## 변이와 회귀 근거

기준 구현에서 전체 자동 변이를 한 번 실행했다. 1,331개를 46분 동안 검사해 검출 711개, 컴파일 불가 614개, 생존 6개, 시간 초과 0개였다. 이 실행은 통과가 아니다.

생존 5개는 행사 기준일의 포함 경계, 일반·미상 취득의 세금 확인 상태, 시장·상품·종목·미래 결제 필터 단언 부족이었다. 회귀를 추가하고 각 생존 변이를 직접 주입해 테스트 실패를 확인했다.

나머지 배수 `< 1`에서 `<= 1`로의 변이는 공개 경로상 동치다. 분할 생성자는 배수 1 이하를 거부하고 병합 생성자는 0 이하·1 이상을 거부한다. 무상증자의 r은 양수이며 1+r의 정확 합이 실패하면 행사를 적용하지 않으므로 배수 1이 나오지 않는다. 보호된 생존 허용 목록을 늘리지 않고 행사 종류에 따른 열거형으로 수치 분류를 제거했다.

위 5개와 새 순서 조건·단주 정책·결제일 포함 경계를 합쳐 손 변이 11개를 주입했다. 모두 컴파일된 테스트의 단언 실패로 검출했고 원본을 복원한 뒤 D-28 테스트 36개가 통과했다. 전체 자동 변이의 1회 제한에 따라 수정 후 전체 실행은 반복하지 않는다. 최종 SHA의 전체 자동 변이 생존 0 판정을 주장하지 않는다.

절차상 한계: 예제 2·미상 입고·보유 초과, 원화 세금 원가·코드 변경 후 입고·동시각 매수 회귀는 구현 전에 실패를 확인했지만, 일부 행사 상세 테스트는 첫 구현 뒤 보강했다. 모든 완료 기준을 처음부터 테스트 우선으로 진행한 것은 아니다.
