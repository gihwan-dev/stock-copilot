## 맥락과 근거

architecture 3.4는 Quantity·Price·Ratio와 Probability를 별개 값 타입으로 열거한다. design 6.3은 수량이 0이면 주문이 없다고 정하고, 가격은 통화별 호가 단위로 정한다. tasks D-13은 소수점 수량을 토스 스펙이 허용하는 주문 조합으로 제한하는 작업이다. D-05는 평가, D-06은 비중과 표시 합 100%, D-09는 수익률, D-21은 변동성을 사용한다.

확인한 로컬 근거는 R-01 Q7 및 docs/toss-openapi-1.2.28.json의 OrderCreateRequest.oneOf[0].properties.quantity·price, OrderModifyRequest.quantity, HoldingsItem.quantity·averagePurchasePrice, ProfitLoss.rate다. 실계좌나 서버 호출은 하지 않았다. 주문 수량은 기본 양의 정수이고 미국 MARKET SELL만 소수 6자리까지 받는다. KR 가격은 원 단위 정수와 호가 단위가 필요하며, US는 1달러 미만 4자리·이상 2자리다. MARKET 주문의 가격은 0이 아니라 부재다. 보유 수량·평단은 거래 통화와 함께 받는다.

## 결정

| 타입     | 값 범위                                                          | 근거와 경계                                                                                                                                                                                                                               |
| -------- | ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Quantity | 0 이상 Decimal::MAX 이하. 소수 28자리까지 정확 표현 가능한 값    | design 6.3·D-25에서 계산 결과 0이 필요하다. 공매도를 하지 않으므로 음수 수량은 거부한다. 소수 수량을 타입 자체에서 정수·6자리로 제한하면 계산·보유·분할 결과를 일찍 잃는다. D-13에서 시장·방향·호가 유형·시간·자릿수·양수 조건을 검사한다 |
| Price    | 0 초과 Decimal::MAX 이하. 소수 28자리까지 정확 표현 가능한 Money | 통화를 없애면 KRW와 USD 단가를 혼동한다. Money를 비공개로 감싸고 통화를 보존한다. 통화를 추론하거나 기본값을 두지 않는다. 생성자가 호가 단위를 맞추거나 절삭하지 않는다. 평균 단가·수정주가는 주문 호가보다 정밀할 수 있다                |
| Ratio    | Decimal::MIN 이상 Decimal::MAX 이하의 부호 있는 소수 비율        | R-11 2장의 0.1516 = 15.16% 표현. D-09 수익률은 음수와 100% 초과가 가능하다. D-05·D-06 비중, D-07 쏠림, D-12 상한, D-21 σ 등 각 의미의 범위는 소비 타입이 검증한다. Probability(D-19)의 0~1 제약을 이 타입에 적용하지 않는다               |

0 단가 허용에 대한 명시 규칙은 찾지 못했다. 가장 보수적으로 Price는 양수만 허용한다. 무상 취득의 원가 0은 Amount·Money로 표현할 수 있으나 Price로 바꾸려면 후속 의미 검토가 필요하다. Ratio는 일반 비율이므로 수익률의 경제적 하한 -1도 일괄 적용하지 않는다.

세 타입은 비공개 필드만 가지며 공개 생성자 또는 검증한 기존 값의 복사로만 얻는다. Default·역직렬화·가변 접근자를 제공하지 않는다. Quantity·Ratio는 값 비교를 제공하며 Price는 통화가 다른 값의 크기 비교를 제공하지 않는다. Money로 꺼내는 읽기 접근자는 통화를 보존한다. Quantity·Ratio의 Decimal 접근자는 복사이므로 원래 값을 바꿀 수 없다.

문자열은 공유 NumericInput(String)을 통해 받는다. 비정상적으로 긴 입력을 차단하는 자원 상한으로 복사 전에 최대 256바이트를 검사한다. 이는 숫자의 정규형 길이나 토스 API의 필드 상한이 아니다. 선행 0이 붙은 정상 값도 여유 있게 받으며 토스 전송 필드의 maxLength 30은 전송 경계가 따로 검사한다. D-01 Amount::parse가 ASCII 정규형 `^-?[0-9]+(\.[0-9]+)?$` 검사 후 from_str_exact로 파싱한다. 선행 0·후행 0·음수 0은 값으로 허용한다. 지수·플러스·공백·밑줄·유니코드 숫자·범위 초과·소수 29자리는 거부한다. 오류 열거형은 입력을 담지 않는다. Amount::new(Decimal)과 Ratio::new(Decimal)은 crate 내부용이다. 어댑터가 쓸 공개 경계는 문자열 파서다. 현재 domain 밖 Rust 호출처가 없고 D-01 기존 단위 테스트는 같은 crate 안이므로 생성자 공개 범위를 줄일 수 있었다.

## 산술 결정: 메인의 후속 정책

메인은 1차 구현 확인 뒤 이번 수정에서 산술을 추가하도록 결정했다. architecture 3.4와 R-11의 “저장과 중간 계산에서는 반올림하지 않는다”는 원 단위·소수 두 자리 같은 **표시 자릿수로의 중간 반올림 금지**로 해석한다. 유한 십진수로 표현할 수 없는 몫의 **표현 정밀도 반올림**은 이와 구분한다. 이 해석은 **메인이 문서에 반영할 것**이며 구현 담당은 architecture·R-11을 수정하지 않는다.

| 연산과 공개 API                                     | 정책                                                                                          | 실패                                                                                                            |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Price × Quantity → Money: Price::checked_mul        | 통화를 보존하고 정확히 표현할 수 있을 때만 성공                                               | 실제 절댓값이 MAX 초과면 MoneyError::Overflow, 범위 안의 표현 손실은 PrecisionLoss                              |
| Money × Ratio → Money: Money::checked_mul           | 음수 금액·비율도 같은 정확 곱셈 정책                                                          | Overflow 또는 PrecisionLoss                                                                                     |
| Money ÷ Money → RatioQuotient: Money::checked_ratio | 같은 통화만 허용. 최대 정밀도 몫. 정확하면 Exact(Ratio), 아니면 Approximate(ApproximateRatio) | CurrencyMismatch, DivisionByZero, Overflow. 통화 검사를 먼저 하므로 다른 통화의 0으로 나누기도 CurrencyMismatch |
| Ratio 더하기·빼기: checked_add·checked_sub          | exact_arithmetic의 crate 내부 함수에서 D-01 Amount의 기존 combine 판정을 재사용               | D-01과 같은 Overflow·PrecisionLoss                                                                              |

이 밖의 연산은 추가하지 않는다. 금액을 수로 나누어 평단가를 얻는 정책, 통화 환산, 비중 표시 합 100%, 퍼센트 표시는 후속 작업이다.

Decimal checked_mul·checked_div 호출은 exact_arithmetic.rs에만 두고 decimal-arithmetic 허용 목록에 이 파일 하나만 등록한다. 새 의존성·기능은 없다. money.rs의 기존 더하기·빼기 구현과 기존 테스트는 바꾸지 않는다.

### 곱셈의 정확 판정

96비트 계수 두 개를 32비트 limb 12개인 384비트 정수로 곱한다. 먼저 실제 곱과 MAX × 10^(두 스케일 합)을 비교해 범위 초과를 판정한다. Decimal checked_mul의 후보와 원래 정수 곱을 공통 스케일로 맞춰 계수가 같을 때만 성공한다. 반올림된 Some이나 0으로 축소된 후보는 PrecisionLoss다. 최대 비교 항은 192비트 곱에 10^28을 곱한 286비트 미만이며 384비트 안에 들어간다.

자리 연산은 u32 자리 두 개의 곱에 현재 자리와 올림을 더한다. 최댓값은 (2^32−1)^2 + 2(2^32−1) = 2^64−1이므로 u64 안에서 정확하다. 이 bounded word 연산에 쓰는 wrapping_mul·wrapping_add에는 실제 wrap이 발생하지 않으며, 결과를 바이트로 나눠 낮은 자리와 올림을 얻는다. 10배 스케일 확대의 한 자리 합도 10(2^32−1)+9 이하이고 마지막 올림이 남으면 용량 초과로 거부한다. 스케일 합은 유효 Decimal의 0~28 두 개이므로 56 이하이며 정수 saturating_add가 포화하는 경로는 없다. Decimal 산술에는 wrapping·saturating을 사용하지 않는다.

테스트의 기준은 다른 표현과 알고리즘인 십진 숫자 벡터의 정수 곱이다. 정확한 원시 곱을 얻고 소수 0을 제거한 뒤 96비트·스케일 28 제한과 대조한다. 구현의 후보 결과를 기대값으로 사용하지 않는다.

### 최대 정밀도 몫과 근사 표지

고정 rust_decimal 1.43.0의 checked_div는 표현 한계에서 최근접 값으로 반올림하고 정확한 동률은 짝수 계수를 택한다. 이 표현 정밀도 반올림은 소수 2자리 등 표시 반올림 API를 호출하는 것이 아니다. 정확한 몫이면 Exact를 반환한다. 그렇지 않으면 후보에 값의 변화 없이 0을 덧붙여, 스케일 28 또는 다음 스케일의 계수가 96비트를 넘는 최대 스케일까지 유지한다. 라이브러리가 underflow 결과 0을 스케일 0으로 돌려주는 경우에도 Approximate의 스케일은 28이다.

나눗셈 전에는 넓은 정수로 실제 몫의 절댓값이 MAX를 넘는지 검사한다. 후보 × 분모와 원래 분자를 공통 스케일의 넓은 정수로 대조해 정확성을 정한다. 근사인지 여부를 나눗셈의 Some이나 후보 0 여부로 추측하지 않는다.

RatioQuotient는 Exact(Ratio) / Approximate(ApproximateRatio) 열거형이다. ApproximateRatio::as_decimal은 pub(crate)로 닫고 Ratio·Amount의 Decimal 생성자도 pub(crate)로 닫는다. domain 밖에서는 근사를 Ratio나 Amount로 다시 만들어 금액 산술에 넣을 수 없다. 자동 변환·Deref·공통 Ratio 접근자는 없다.

D-07의 근사 비중 정렬과 D-12의 정확한 비중 상한 비교에 필요한 최소 API로 근사끼리 Ord·PartialOrd, 근사와 정확 Ratio 사이 cmp_ratio를 제공한다. 이 비교는 저장된 최대 정밀도 근사값을 비교한다. 같은 수치로 근사된 두 참값의 엄밀한 대소를 알아내는 API는 아니므로 같다는 결과를 참값의 완전한 동등성으로 해석하지 않는다. 산술 API는 제공하지 않는다. 이후 D-07의 쏠림 전용 내부 통계는 `concentration_arithmetic`에서만 수행하며, 보유 구성비를 봉인 입력으로 받아 봉인 결과를 반환하고 `Amount`·`Money`·`Ratio`·`Decimal` 변환이나 일반 산술 API는 제공하지 않는다(ADR 0049).

ApproximateRatio::original_direction은 원래 몫의 부호를 Up·Down으로 돌려준다. Approximate는 참값이 0이 아닌 경우에만 발생하므로 Flat은 없다. 근사값이 0이어도 원래 부호를 Decimal의 부호 비트에 보존한다. 수치 비교에서 음수 0과 양수 0은 같고, 원래 방향은 별도로 얻는다. 최대 스케일의 자리 채움은 try_from_i128_with_scale로 검사한 정확한 10배 계수만 받는다. 이전의 계수 상한 <=를 <로 바꾸는 변형은 10배 정수의 끝자리가 0이고 MAX의 끝자리는 5이므로 동치였다. 이 비교 지점을 checked 생성자로 교체했으며 MAX 계수의 근사 몫도 고정 예제로 검사한다.

독립 속성 테스트는 A·10^(sb+sq)와 Q·B·10^sa의 정수 차이 R을 구한다. A·B·Q는 절댓값 계수이고 sa·sb·sq는 각 스케일이다. R=0일 때만 Exact여야 한다. 근사이면 2R ≤ B·10^sa로 마지막 자리 단위의 절반 이하 오차를 검사한다. 동률에서는 Q가 짝수여야 하며, 스케일 28 또는 Q·10 > MAX 조건도 확인한다. 부호와 범위 초과도 별도 정수 기준으로 검증한다. 매우 작은 양수 몫이 0이 되어도 Approximate 표지를 유지한다.

## 검증 설계

고정 테스트는 0·음수 0·음수·소수 7자리·최소 양수(1e-28)·최댓값·최솟값·256/257바이트·대형 입력·잘못된 문법·28/29자리 경계를 검사한다. 원화 소수 단가도 보존하며 0 이하 가격은 거부한다.

속성 테스트 independent_integer_coefficients_preserve_exact_values_and_ranges는 Config::with_cases(4096)를 사용한다. Decimal의 96비트 범위에 해당하는 i128 정수 계수, 0~28 자릿수, 통화를 생성한다. 정수의 문자열에 소수점을 직접 삽입해 입력을 만들고, 독립적인 Decimal::from_i128_with_scale로 만든 기대값과 대조한다. 구현 파서의 출력이나 to_string으로 입력·기대값을 생성하지 않는다. 범위 판단도 정수 계수의 부호로 한다.

## 미해결과 후속 범위

- Price의 0 금지는 명시된 상품 제약이 아닌 보수적인 초안 정책이다. 무상 취득 평단·특수 시세 0을 받아야 하는지 D-05·D-11에서 확인한다.
- D-13의 주문 조합·수량 양수·소수 6자리·전송 길이, D-26의 호가 맞춤은 이번 타입의 유효성만으로 보장되지 않는다.
- 아래 후속 작업의 계산·표시 API는 이번 수정에 추가하지 않는다.
- 생성자 외 구성 차단의 영속 compile-fail 회귀는 ADR 0022와 같은 제약이 있다. doc 속성·주석을 추가하지 않으며 trybuild 의존성도 추가하지 않는다. 비공개 필드 및 외부 rustc 실패 실험으로 확인하고 별도 하네스 작업에 맡긴다.
- 새 의존성·검사 끄기·실제 키·계좌 접근은 없다. 프로젝트 설정과 hooks=true는 확인했지만 현재 세션의 프로젝트 신뢰·훅 신뢰 적용은 확정하지 못했다. Git 훅 설치와 직접 실행한 just check 결과를 별도 증거로 사용한다.

### 산술 속성·변형 검증

곱셈과 몫 각각 Config::with_cases(4096)를 사용한다. 96비트 전체 계수·부호·스케일과 0·MIN·MAX·최소 양수를 생성한다. 곱셈은 두 공개 API 모두, 몫은 독립 십진 정수 잔차·최대 스케일·동률 짝수를 검증한다. Ratio의 더하기·빼기에는 D-01과 같은 경계 반례를 적용한다. 손 변형은 곱셈 정확 판정 뒤집기, 근사 표지 제거, 통화 검사 제거, 0 나누기 허용의 네 가지를 만들고 해당 계약 테스트가 실패하는지 확인한 뒤 원본을 복구한다.

## 적대적 리뷰 후 속성 테스트 보강

기존 전체 96비트 계수 생성기에 작은 계수·끝자리 0·2^k·5^j 분모를 추가했다. 별도의 범주 테스트는 아래 각 범주를 Config::with_cases(4096)로 실행한다. 성공 결과가 0이 아닌 건수와 양쪽 입력이 모두 ±1이 아닌 성공 건수를 각각 세고 둘 다 4096이어야 통과한다. 기대값은 기존의 독립 십진 정수 곱·정수 잔차 기준 및 구성 시 사용한 정수식으로 계산한다.

| 범주          | 구성                                                                                         | 검사할 성공 경로                                                                              |
| ------------- | -------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 작은 계수     | 끝자리 3·7인 작은 계수와 0~12 스케일                                                         | 0이 아닌 정확한 곱                                                                            |
| x·10^k        | 작은 계수에 1~8자리 0을 붙이고 스케일을 다양하게 구성                                        | 0이 아닌 정확한 곱                                                                            |
| 고스케일 축소 | 두 입력 모두 스케일 28, 계수 뒤 14~20자리 0                                                  | 스케일 합 56이 끝자리 0 제거로 정확히 표현되는 곱                                             |
| 2^k·5^j 분모  | k·j는 1~12, 분자 스케일은 0~8                                                                | 0이 아닌 Exact 몫                                                                             |
| q·b / b       | q·b를 넓은 정수 곱으로 먼저 구성하고 q·b의 스케일을 합침                                     | 생성한 q와 정확히 같은 Exact 몫                                                               |
| MAX±½ 근처    | D=10^28, j∈{1030,2507,149,1328}, k=round(MAX·j/D), 분자 계수 MAX−k, 분모 계수 D−j, 스케일 28 | 몫×10^s가 MAX±0.499~0.5 사이에 놓이는 Approximate 몫. s는 1~28이며 반올림 계수가 MAX임을 검사 |

고정 회귀는 MAX×1, MAX÷1, (MAX−8)/(10^28−1)의 MAX 계수 근사, -1e-28÷3과 부호 조합, 긴 선행 0 입력을 포함한다. 경계 손 변형은 곱셈 넘침·몫 넘침의 is_gt→is_ge와 자리 채움의 스케일 <=→<를 계약 테스트로 검출한다. 기존 계수 <=→<의 동치성은 위 근거와 원본 변형 실행으로 기록한다.
