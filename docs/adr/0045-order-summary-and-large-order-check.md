# ADR 0045: D-32 주문 요약과 고액 판정

- 상태: 확정 (2026-11-14)
- 기준: 기준 af70b46fc6c62a0d1a7b036c9977b3d2f3d47366. 사용자 후속 결정 반영.

## 생성 경계와 표시 사실

OrderSummary::from_execution은 ExecutionToken과 봉인된 표시 사실만 받는다. 코드·시장·방향·수량·지정가·금액·주문 키를 따로 받는 생성자는 없다. 필드는 architecture 4.4 순서 5의 종목명, 코드, 시장, 방향, 수량, 지정가, 예상 금액, 예상 수수료, 계좌 뒤 네 자리, 키 앞 여덟 자리 순서다. 구조 분해 테스트는 나머지 패턴 없이 열 필드를 전부 사용한다.

InstrumentNameFact는 T-09 종목 마스터 결과의 ResolvedOrderInstrument와 DisplayInstrumentName을 봉인한다. 이름은 빈 값과 256바이트 초과, 제어 문자를 거부한다. 이 상한은 자원 제한 초안이다. 요약은 코드·시장을 토큰과 대조한다. 조회 결과 생성자는 IO 사실을 인증하지 않으며 어댑터가 정확한 응답을 전달할 책임이 있다.

AccountDisplayFact는 계좌 조회 어댑터가 AccountId와 MaskedAccountNumber로 만든다. accountSeq는 계좌번호가 아니다. 계좌번호 전체를 보관하지 않고 기존 MaskedAccountNumber의 네 자리만 보관한다. Debug는 계좌 키를 숨긴다. 요약 생성 시 계좌 키가 토큰과 일치해야 한다. 실제 계좌번호 형식 확인은 ADR 0022에서 어댑터로 넘긴 T 작업 몫이다. D-32는 기존 마스킹 타입의 입력 정책을 변경하지 않는다.

EstimatedOrderFee는 Unknown 또는 Confirmed(ConfirmedOrderFee)다. ConfirmedOrderFee의 튜플 생성자는 crate 내부에서만 접근하며 주문 키와 Money를 함께 봉인한다. D-22 TradeCost가 공개 생성 경로를 정하고 그 유일한 생산자가 되어야 한다. 요약은 주문 키·주문 통화 일치와 음수 아님을 검사한다. 표시 계층은 Unknown을 '미확인'으로 보여야 하며 0원으로 표시하지 않는다. 확인된 금액도 예상 수수료이며 체결 확정값이 아니다. 고액 판정에는 수수료를 넣지 않는다.

A-17/O-03과 네이티브 확인 창은 이 요약만 사용한다. 표시 사실을 불러오거나 화면에서 주문 내용을 재조립하지 않는다. A-17은 기존 tasks에서 위험 설정 확인 역할도 있으므로 주문 요약 소비 지시는 주문 확인 경로에만 적용한다. 순서 7의 지연 후 재확인은 동일 토큰의 recheck로 하고, 요약을 재계산한 다른 주문으로 바꿔 보내지 않는다.

## 금액과 고액 판정

지정가 금액은 Price::checked_mul의 정확 곱이며 Overflow·PrecisionLoss는 요약 생성 오류, 주문 불가다. 시장가 수량 주문은 토큰 execution_observation의 가격으로 추정하며 Estimated를 보존한다. 미국 금액 지정 매수는 지정 금액 그대로다. 금액 주문의 수량과 시장가의 지정가는 닫힌 Absent 변형이다. 키가 여덟 자보다 짧으면 있는 만큼 표시한다.

매수·매도 모두 원화 금액 80,000,000원 이상이면 Required다. design 6.5는 별도 금액 한도를 두지 않으므로 1억 원 초과 자체를 거부하지 않는다. 매수가능금액·매도가능수량 검증은 O-01 책임이다.

달러 주문은 Buy(rate)·Mid(midRate)가 모두 USD/KRW 방향이고 토큰 checked_at 시각에 유효해야 한다. 시작 시각은 포함, 종료 시각은 제외한다. 둘 중 큰 값을 사용하며 같은 값이면 rate를 보존한다. 환산은 기존 D-04 정확 곱을 사용하되 경제적 환산 결과는 Approximate이고 선택 환율·출처·유효 시각이 남는다. 주문 금액·수량 산술로 환산액을 재사용하지 않는다.

환율 부재, 종류·방향 불일치, 미래·만료 시각, 환산 Overflow·PrecisionLoss는 Unavailable에 이유를 남기며 반드시 Required다. 작은 유효 환율 하나만으로 판정을 낮추지 않도록 두 환율 모두 검사한다. 판정은 Required/NotRequired의 닫힌 열거형이다.

## 검증과 후속

속성 테스트는 Config::with_cases(4096)를 명시하며 KRW 임계값과 USD 두 환율 선택·곱을 독립 정수 계산과 대조한다. 외부 crate 실험으로 맨 OrderIntent 입력, Summary 필드 위조, 확인된 수수료 위조를 거부하는지 확인한다. 새 의존성과 검사 끄기는 없다. 기존 master 테스트 본문은 변경하지 않는다.

OrderIntent Debug를 가리는 변경은 기존 master 테스트가 AccountId 전체 출력을 요구하여 적용하지 않는다. 요약과 AccountDisplayFact의 Debug에는 전체 계좌번호·계좌 키가 없다. 별도 사용자 결정으로 기존 테스트 계약을 바꿔야 OrderIntent Debug도 바꿀 수 있다.

미해결: 이름 상한 실측, T-09·계좌 조회 어댑터 연결, D-22의 확인된 수수료 공개 생성 경로, 토스의 실제 고액 판정 환율(S-01), 주문 시 환율 유효 기간의 어댑터 정책. 현재는 공급된 두 유효 구간의 교집합만 허용하고 부적합하면 고액 확인을 요구한다. 전송까지 지연되면 O-18이 token.recheck를 호출해야 하며 과거 checked_at의 환율 판정을 현재 유효성으로 간주하지 않는다.

## 확인 대기 주문

PendingOrderConfirmation은 ExecutionToken과 OrderSummary를 비공개 필드로 함께 소유한다. 공개 from_execution은 토큰을 소비하고 봉인된 표시 사실의 대상을 대조한 뒤 묶음만 반환한다. 공개 summary는 &OrderSummary만 반환한다. OrderSummary의 단독 생성 함수는 모듈 내부에만 있으며 Clone을 제공하지 않는다. 묶음은 Clone, Copy, Default, 직렬화, 역직렬화, 가변 접근자와 공개 필드가 없다.

공개 recheck는 묶음을 소비해 토큰의 시각·관측 재확인을 수행하고 같은 주문과 기존 요약을 보존한 묶음만 돌려준다. 실패하면 토큰이나 요약이 나오지 않는다. 요약을 재계산하거나 외부 요약을 받는 경로는 없다. crate 내부 into_execution_parts는 묶음을 소비해 고정된 토큰과 요약을 함께 반환한다. 이 경로는 현재 내부 재확인에만 사용한다. O-03은 승인 증거를 받아야만 토큰이 실행 경계로 나가는 공개 경로를 설계해야 하며, 이 메서드를 그대로 공개해서는 안 된다.

주문 요약의 소비자는 tasks의 O-04(요약 계산), O-07(네이티브 요약 창과 본인 확인), O-09(고액 확인), O-03·O-17(승인 타입과 승인 전송), O-18(본인 확인 뒤 재확인과 전송)이다. 이들은 묶음의 요약 참조만 사용해야 한다. A-17은 위험 설정 확인 작업이며 주문 요약 소비자가 아니다.

## IO 사실과 강제할 호출 위치

**종목명·계좌 표시·환율 사실의 생성 함수는 broker 어댑터만 부른다. 호출 위치 제한은 하네스 구조 검사로 강제한다(담당: 하네스 작업, 메인이 등록).** 현재 domain은 IO 사실의 진위를 인증하지 않는다. 외부 crate에서 어댑터용 생성자를 호출하는 것은 아직 컴파일된다. 이번 수정에서 하네스가 이미 이를 차단했다고 주장하지 않는다.

| 생성 경로 | 사실을 만드는 담당 | 확인할 결합 |
|---|---|---|
| InstrumentNameFact::from_master_lookup_result | T-09 종목 마스터 어댑터 | 조회 결과의 코드·시장과 표시 이름 |
| AccountLookupDisplayRow::from_broker_account_result | 계좌 조회 어댑터 | 한 응답 행에 함께 온 accountSeq와 마스킹한 accountNo |
| AccountDisplayFact::from_account_lookup_result | 계좌 조회 어댑터 | 위 조회 행 입력 타입 하나만 받음 |
| FxRate::parse, OrderFxRates::from_broker_fx_result | T-08 환율 어댑터 | 방향·종류·출처·시각과 한 응답의 rate·midRate |
| ConfirmedOrderFee의 crate 내부 생성 경로 | D-22 TradeCost | 주문 키·거래 통화·예상 비용 |

AccountLookupDisplayRow와 AccountDisplayFact에는 전체 계좌번호가 없고 Debug도 뒤 네 자리만 출력한다. 계좌 키를 번호로 잘라 표시하지 않는다. 실제 계좌번호 형식은 ADR 0022대로 T 작업이 확인한다. 입력 타입 생성과 두 응답 필드의 사실성도 어댑터 책임이며, 타입 하나로 받는 것 자체가 IO 인증은 아니다. 하네스는 생성 함수 정의와 domain 단위 테스트를 제외한 운영 호출 위치를 broker 어댑터로 한정해야 한다. D-22의 확인된 수수료 공개 경로는 후속 설계 대상이며 Unknown은 '미확인'으로 표시하고 0원으로 바꾸지 않는다.

## 사용자 확인 대상: 보수적 환율 초안과 원 단위 올림

두 USD/KRW 값 모두 500~5,000원(양 끝 포함)이어야 한다. 큰 값이 작은 값의 1.2배를 넘으면 판정 불가다. 정확히 20% 괴리는 허용한다. 이 상식 범위와 괴리 상한은 금융 시장에서 실측해 확정한 기준이 아니라 사용자가 검토할 보수적 초안이다. 범위·괴리 검사는 종류·방향·시각 검사와 별개로 두 값 모두에 적용한다. 괴리 상한의 정확 산술에 정밀도 손실이 나도 판정 불가로 처리한다. 판정 불가는 모두 Required다. 환율 1로 100만 달러 주문을 낮게 분류할 수 없다.

양수 원화 금액을 원 단위로 올린 결과가 80,000,000원 이상인지 판정한다. 금액을 바꾸지 않고 동치인 `원화 금액 > 79,999,999`로 비교하므로 산술 오버플로와 표시용 반올림 정책의 변경이 없다. 79,999,999원은 NotRequired, 79,999,999.99원과 80,000,000원은 Required다. 환산액은 근사 표시·판정에만 사용하고 수수료는 판정에서 제외한다.

미해결: 토스의 실제 고액 판정 환율과 원 단위 처리 방식은 연동 테스트(S-01)에서 실측한다. 시장가 추정 금액에 추가 가격 여유는 두지 않았다. 문서에 여유 정책이 없으므로 실행 관측 가격으로 추정하고, 토스가 고액 확인으로 거절하면 O-09대로 실패로 끝내며 재전송하지 않는다. 환율 유효 기간의 어댑터 정책과 신뢰 경계의 하네스 강제, O-03의 승인 증거 연결, D-22의 공개 생성 경로가 후속이다.

## 검증

여섯 주문 변형을 시장·방향·수량·지정가·통화·금액의 독립 기대값 표와 대조한다. 구조 분해 테스트는 열 필드를 모두 열거하며 자기 접근자와의 비교를 없앴다. 경계·괴리·문자 거부 회귀와 소비형 묶음 재확인 테스트를 둔다. 외부 crate 실험으로 묶음 위조, 복제·Default, 토큰 추출, 소비한 토큰 재사용과 요약 복제를 확인한다. 자동 변이 검사는 사용자 지시로 중단하고 기존 결과를 폐기했으며 이번 회차에는 재실행하지 않는다. 새 코드의 분기 제거를 포함한 손 변형을 개별 테스트로 검증하고 복원한다. 결과와 최종 SHA는 구현 보고에 남긴다.
