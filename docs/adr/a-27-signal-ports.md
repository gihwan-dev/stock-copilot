# A-27: 신호 평가 저장·조회 포트
- 상태: 초안
- 기준: `10bf351a1b1b3e85caa3981f41beed5bdca9e16a`
- 관련 작업: A-12, A-13, A-14, A-15, A-27, D-51, S-07, S-18

## 결정

`SignalRepository`의 무조건 `replace`를 없앤다. 종목별 `snapshot`은 현재 신호와 그 신호가 근거로 삼은 제출 ID, 최신 제출 ID, 저장소 발급 상태 리비전을 함께 읽는다. 조건부 `commit`은 읽은 스냅숏 전체가 여전히 같을 때만 적용한다. 리비전은 종목별 비음수 단조 순번이며 상태가 같은 값으로 돌아와도 재사용하지 않는다. 순번 고갈은 오류로 처리한다. 호출자가 오래된 상태를 다시 읽지 않고 쓴 결과는 `Conflict`이고 이벤트를 주지 않는다. 충돌 뒤에는 제출부터 다시 읽고 다시 판정한다.

제출 버전은 그 종목에서 저장 순서상 마지막으로 성공한 `IssuedEstimateTaskId`다. 제출이 없으면 `None`이다. 발급 ID는 중복 소비할 수 없고 다시 쓰지 않는다는 A-12/D-47 계약을 전제로 한다. 같은 종목의 여러 제출이 한 원자 묶음에 있으면 `records` 순서의 마지막 ID다. A-12의 과제 소비와 모든 제출 기록 저장, 최신 제출 버전의 전진은 같은 트랜잭션이다. 실패나 충돌은 어느 것도 전진시키지 않는다. 이전 제출은 판정 대상으로 보존한다. 기록 조회와 스냅숏 조회가 서로 다른 시점이라면 마지막 기록 ID와 스냅숏의 제출 ID를 대조해 다를 때 재조회한다. 같은 DB를 다루는 기존 제출 쓰기 경로도 이 경계에 참가해야 한다.

평가는 실제로 읽어 판정한 제출의 과제 ID를 스냅숏과 별도로 담아 D-51의 `SignalDecision`과 `signal_transition` 결과를 제출한다. 저장소는 이 근거 ID가 스냅숏과 저장 시 최신 ID에 모두 같은지 검사한다. 제출 내용이 우연히 같아도 이전 과제의 평가를 새 과제에 연결할 수 없다. 어댑터는 도메인 함수를 이용해 전이의 일치와 제출·종목·보정 위치를 검증하고 규칙을 따로 계산하지 않는다. 보정 원장 위치는 해당 모델·기간의 실제 최신 위치와 같은 트랜잭션에서 대조한다. 생성된 매수·매도 신호가 보정에 실제 쓴 위치도 요청 위치와 일치해야 한다. 원장이 도중에 증가하면 거부한다. A-15가 만드는 판정·보정표 원자 저장 계약은 재정의하지 않는다. A-15 저장과 이 비교가 같은 직렬화 경계를 공유하는 실제 어댑터의 구현은 S-18에 인계한다.

A-14의 가격 범위 이탈 폐기는 같은 조건부 커밋을 사용하고 실제 현재 신호에 연결된 과제 ID를 폐기 원장에 기록한다. 같은 과제의 재평가는 현재 신호를 다시 읽어도 거부한다. 새 제출이 이미 있다면 이전 신호의 과제만 폐기하므로 새 과제는 재평가할 수 있다. 제안 만료는 이 폐기와 다르다. 현재 신호가 없을 때 `Unchanged` 폐기는 상태나 이벤트가 없는 성공이고, 다른 폐기 전이는 거부한다.

매수 발생 때 D-51이 만든 `BuySignalRecord`를 현재 신호와 같은 원자 작업으로 저장한다. 발생 ID 충돌과 신호·발생 종목 불일치를 거부한다. 같은 방향 내용 갱신은 기존 ID·발생 시각·H를 보존하고 새 이력을 만들지 않는다. 해제 뒤에도 이력은 남는다. 조회는 내부 종목 ID 또는 시장·심볼 중 하나가 같은 기록을 포함한다. 현재 발생의 자기 제외는 D-51에 맡긴다. 도메인 전이 이벤트는 커밋 성공 결과에만 순서대로 담고 발행은 A-13이 한다. 이 포트는 영속 이벤트 전달을 보장하지 않는다.

출처 조회는 제출 과제 ID에 연결된 별도 저장 원장의 수집 항목·공시·도구 참조를 소유 값으로 반환한다. 호출자는 `ledger()`를 만들어 D-51에 전달한다. 제출의 참조를 출처 원장으로 복사해 존재를 증명하지 않는다. 조회 실패와 비어 있는 정상 원장은 구별한다. 신호가 없는 `NoSignalReason`은 성공 결과에 전달하며 별도 영속 저장은 요구하지 않는다.

가짜는 A-12 제출, 신호 상태·발생 이력, 폐기 표식과 테스트용 보정 원장 위치를 하나의 잠금으로 보호한다. 출처 자료는 제출과 독립적으로 주입한다. 테스트용 보정 위치 갱신은 경쟁을 재현하는 장치이며 A-15의 저장 포트 구현이나 실제 DB 트랜잭션의 증거가 아니다. 실제 저장소의 영속성·프로세스 간 직렬화와 수집 원장의 완전성은 S-07·S-18·S-05 등의 작업에서 검증한다.

## 인계

- A-13: 같은 스냅숏의 최신 제출·보정 위치·출처·현재 상태를 읽고 D-51 전이를 전달한다. 충돌 시 처음부터 다시 읽는다. 성공 결과에 담긴 이벤트만 발행하고 사유를 반환한다. 내용 갱신의 화면 재조회와 이벤트 유실 복구는 별도 연결한다.
- A-14: 가격 범위 이탈은 현재 발생에 연결된 과제를 조건부 폐기한다. 제안 만료만으로 신호를 폐기하지 않는다.
- A-15·S-18: 판정과 표의 계약은 A-15 것을 사용한다. 그 저장이 신호 커밋의 최신 보정 위치 비교와 원자적으로 직렬화되어야 한다. 이 작업의 가짜 보정 위치 주입만으로 실저장을 증명하지 않는다.
- S-07·S-18: 제출 ID의 전역 고유성·저장 순서, 단조 리비전, 폐기 기록, 현재 신호와 발생 이력의 일체 저장, ID 충돌 거부 및 서로 다른 프로세스 간 경쟁을 구현·검증한다.
- S-05·S-09·M-02·AI-14·E-02: 제출별 수집 원장을 독립 사실로 보존하고 누락 없이 조회한다.
