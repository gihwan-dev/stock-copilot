# ADR 0016: Rust→TS IPC 타입 생성과 차이 검사 (H-13)

- 상태: 제안
- 날짜: 2026-11-12
- 결정한 사람: 메인 에이전트(사용자 확인 대기). 보호 설정 변경은 잠금 전 메인 승인
- 관련 작업: H-13 (ADR 0004, 0011, 0012, 0014에서 넘어온 항목)
- 반영한 문서: 없음 (architecture.md 3.6·5장·5.2·5.3, harness.md 2장·4.2·5장을 따르고 문서가 정하지 않았거나 실측과 어긋난 곳만 적는다)

## 맥락

architecture 3.6은 tauri-specta `=2.0.0-rc.28`, `specta-typescript =0.0.15`, `ErrorHandlingMode::Result`, `src-tauri`의 `gen-bindings` 바이너리, 생성물 네 가지(`bindings.ts`, `MockCommandHandlers`·`mockCommands`, 명령 목록 파일, capability 명령 허용 항목), `build.rs`가 명령 목록을 읽기, 재생성 차이 검사를 정했다. harness 5장은 명령별 대표 응답 JSON을 `insta`로 내보내 TS 가짜가 쓰게 했다. ADR 0011은 `build.rs` 판정을 "등록 명령 = 명령 목록 = 권한 묶음" 대조와 `build.rs` 본문 고정으로 바꾸는 일을, ADR 0004는 앱 묶음에 `gen-bindings`가 들어가는 문제를 넘겼다. 워크스페이스 린트(ADR 0005)와 끄기 통제(ADR 0010, H-40)가 서드파티 매크로 확장과 부딪혔다.

## 결과

- 명령을 추가하는 절차: `src/ipc/<명령>.rs`에 명령과 DTO, `registry.rs`의 `collect_commands!`에 한 줄, `ipc/responses/<명령>.json`에 기록 응답, `src/ipc/tests.rs`에 응답 비교 테스트, `just gen-bindings`. 보호 파일은 바뀌지 않는다.
- 끄기는 Rust 3건 → 6건(`registry.rs`의 `trivial_casts`, `app_version.rs`의 `needless_pass_by_value`·`unnecessary_wraps`, 기존 `main.rs` 3건), TS 0건 그대로다(리뷰 반영 뒤). 모두 `disable-report`에 나온다. 명령 하나마다 Rust 끄기가 최대 2건씩 늘고, 기존 xtask 테스트가 `src/ipc` 안의 끄기를 "명령 모음 함수의 `trivial_casts` 하나 + 명령마다 정해진 두 린트 각 하나 이하"로 묶는다.
