# ADR 0050: D-22 거래 비용과 임계값

- 상태: 확정 (2026-11-14)
- 수정 기준: 9be0cdc4af07e49462f02f49a4b5d49c4636522b
- 근거: open-issues 1.2~1.4, design 6.2·6.3·ORD-8, R-01 Commission, R-11 Q3, ADR 0027·0029·0041·0045·0046, 사용자 리뷰 수정 결정

## AI 호출 전 비용 적격성

`CostEligibleTask::assess(EstimateTask, &TradeCost)`는 AI 확률이나 보정 결과 없이 비용을 검사한다. 정확히 5%p는 허용하고 초과는 거부한다. 공개 생성자가 없는 비용 적격 과제를 반환하며 `Thresholds::create`는 이 타입만 받는다. E 작업은 AI 호출·과제 저장·추정 기록의 진입점에서 이 타입을 요구해야 한다. 부적격 과제를 AI에 보내거나 추정·판정·30건 집계에 넣지 않는다.

`EstimateTask`에는 거래일 H만 있고 미래 거래소 만기가 없다. H를 달력일이나 초로 임의 환산하지 않는다. E 작업은 거래소 캘린더로 계산한 실제 만기를 `EstimateCostPeriod::from_calendar_result`에 전달한다. 이 사실은 생성 시각부터 만기까지의 증가 구간과 원래 과제를 봉인한다. domain은 캘린더 응답의 진위를 인증하지 않는다. E 작업이 사실의 정확한 만기와 과제 연결을 보장한다. 비용 적격 판정은 비용 사실의 원래 과제 전체와 입력 과제가 같은지도 대조한다.

E 작업이 과제·제출 추정·보정 결과의 제공자·모델·버전·기간 일치를 보장한다. 과제 자체에는 모델이 없으므로 domain이 모델 출처를 추정하지 않는다. Thresholds는 과제 H와 보정 Horizon을 대조하고 생성 때의 보정 결과 전체를 보존한다. 다른 보정 결과에는 다시 계산해야 한다.

## 식, 등호, 봉인

손익분기는 p₀+c/(T+S), 매수는 손익분기+매수 여유분, 매도는 max(p₀−매도 여유분,0.05)다. 비용 초과는 나눗셈 반올림 전에 c×20과 T+S를 비교한다. 근사 T·S·p₀는 D-21 봉인 타입에서만 오고 계산은 thresholds_arithmetic에 있다. Decimal·Ratio·금액을 꺼내는 공개 경로와 역직렬화·Default 생성자는 없다. Thresholds와 내부 수치의 Debug는 값을 가린다.

D-24는 `buy_condition`과 `sell_condition`의 닫힌 SignalCondition::Met/Unmet를 쓴다. 매수는 p≥매수 임계값, 매도는 p≤매도 임계값으로 등호를 포함한다. Ordering 비교는 crate 내부로 닫는다. 보유 여부·제외·출처 판정은 D-24 책임이며 이 조건 충족만으로 주문을 만들지 않는다.

## 여유분: 사용자 확인 대상

사용자 리뷰 결정: 0~29건의 InsufficientSamples에서는 매수 여유분을 max(설정,15%p), 매도 여유분을 정확히 15%p로 둔다. 매수 설정 20%p를 15%p로 완화하지 않는다. 매도는 문서의 정확한 값을 따르며 설정이 커도 15%p다. 30건 이상은 양쪽 모두 설정을 쓴다. 판정 수나 보수 운용 불린을 호출자가 따로 넣지 않는다. 이 비대칭 규칙은 사용자 확인 대상이며 기존 “양쪽 정확히 15%p” 초안을 대체한다.

일반 설정 범위 5~25%p, 기본 15%p, 보수/중립/공격 20/15/10%p는 여전히 초안이다. 문서에 없는 수치이므로 E-92와 사용자 확인 대상으로 남긴다. 설정 화면이나 추가 사용자 절차를 만들지 않는다.

## 비용 구성과 적용 기간

| 시장·통화 | 매수 | 매도 |
|---|---|---|
| 국내 KRW | 계좌 Commission 요율 + 매수 세율 사실 | 계좌 Commission 요율 + 거래세·농특세 등 매도 세율 사실 |
| 미국 USD | 계좌 Commission 요율 + 매수 부담률 사실 | 계좌 Commission 요율 + SEC 등 전체 매도 부담률 사실 |

계좌 요율은 `/commissions`의 소수 비율과 startDate·endDate 사실을 함께 받는다. 날짜는 스키마의 KST 날짜이며 양 끝 날짜를 포함하고 null은 해당 방향으로 무제한이다. 적용 전이거나 과제 만기 전에 끝나는 요율은 UnknownComponent로 비용 생성을 거부한다. 반년 과제 중간에 할인 요율이 끝나면 현재 할인율을 기간 전체에 쓰지 않는다. 기간을 모르면 과제 비용 사실을 만들 수 없다.

세율은 적용 시장·종목 분류·날짜에 맞는 조회 결과다. R-11의 세율을 현행 상수로 박지 않는다. 면제도 명시적 0 사실이 필요하고 누락은 0이 아니다. 미국 최소액·수량 기반 부담 등을 유효 부담률로 확정할 수 없으면 비용 미상이다. 양도소득세·배당세는 한 번 거래대금에 비례하는 c에 넣지 않는다. 미국은 보유 달러로 주문하며 자동 환전 비용은 없다. 외부 사실의 완전성과 생성자 호출 위치 강제는 T·하네스 인계다.

## D-32 수수료 연결

공개 `CommissionRateFact::estimate_order_fee`는 ExecutionToken만 받아 같은 토큰의 주문 키와 예상 금액을 직접 읽는다. 호출자가 키와 금액을 따로 넣던 계산은 crate 내부로 닫는다. 정확 곱셈 뒤 KRW 1원·USD 1센트로 올린다. 수수료율의 시장과 토큰 확인 시점의 적용 기간도 검사한다. 금액 곱셈 실패는 수수료 계산 실패다.

`PendingOrderConfirmation::from_execution_with_commission`이 소비할 토큰에서 안쪽으로 계산한다. D-32의 기존 생성 경로와 master 테스트는 유지한다. O 작업은 새 경로를 쓴다. 시장가는 execution_observation의 가격으로 추정하고 OrderExpectedAmount::Estimated를 유지한다. ConfirmedOrderFee는 요율이 확인된 예상 수수료이며 실제 체결 수수료가 아니다. 실제 비용은 거래내역으로 교체한다.

## 표시와 검증

공개 표시는 백분율 소수 첫째 자리다. 매수·손익분기는 올리고 매도는 내려, 표시값에 도달한 확률이 조건을 실제로 만족하게 한다. 문서 예 표는 별도의 테스트 도우미에서 가장 가까운 값으로 반올림해 대조한다. H=0.25·5·40·120 네 행의 문서 반올림 결과는 그대로 일치한다. 반년 D-21 기본 H=126과 예 표 H=120은 구분한다.

실제 생성 경로에서 29/30건·설정 5~25%p·확률을 Config::with_cases(4096)으로 독립 기준과 대조한다. 종류별 표시·경계 양쪽 확률·등호, AI 호출 전 비용 거부, 기간의 양 끝·반년 할인 종료·잘못된 과제 연결, 1천만 원 토큰의 수수료·시장가 추정·잘못된 시장·적용 전 요율·금액 넘침을 고정한다. 자동 변이 도구는 실행하지 않는다. 리뷰 생존 세 경로를 포함한 손 변형과 최종 전체 검사 결과는 구현자 보고에 남긴다.

새 의존성·검사 끄기·master 기존 테스트 본문 변경은 없다. 프로젝트 신뢰·Codex 훅 신뢰의 런타임 적용은 미확정이며 실제 Git 훅과 전체 검사 결과를 확인한다.
