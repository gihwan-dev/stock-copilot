# fin-core 묶음 설계 결정 기록

| 작업 | 정한 것 | 다른 선택지 |
|---|---|---|
| 진행 | 하위 에이전트 위임이 세션 훅(`[orchestration]`)에 막혀 모든 행을 한 스레드가 직접 구현했다 | 병렬 위임 |
| U-06 | 키 저장 명령 `submit_toss_keys`와 연결 확인 명령 `check_toss_connection`을 새로 둔다. 둘 다 `{ state }` 하나로 답하고 값은 화면이 이미 쓰는 7가지(`needs-keys`·`connected`·`ip-not-allowed`·`invalid-key`·`forbidden`·`account-not-found`·`key-in-use`)다. 첫 실행 게이트는 `get_settings`의 키 유무 대신 이 확인 명령을 쓴다 | `get_settings`의 `toss_connection`에 상태를 더함(설정 화면 계약 변경) |
| U-06 | 붙여 넣은 키는 앞뒤 공백만 지운다. 비었거나 512바이트를 넘거나 공백·제어·비ASCII 글자가 섞이면 저장하지 않고 `invalid-key`로 답한다. 정상이면 client_id·secret을 키체인(배포는 로그인 키체인 `product_login`, 개발은 개발 프로필)에 저장한 뒤 보관 토큰을 버리고 바로 토큰 발급을 한 번 시도한다 | 저장 전 토큰 발급(키가 남지 않아 다시 띄우면 처음부터) |
| U-06 | 토큰 발급이 키 오류(`invalid_client` 등)로 끝나도 저장한 키는 지우지 않는다. 다음 실행에서 키 화면이 "키 확인" 문제로 다시 뜨고, 새로 붙여 넣으면 덮어쓴다 | 실패 시 키 삭제 |
| U-06 | 연결 실패(네트워크·서버 오류)는 상태가 아니라 재시도 가능 오류로 답한다. 게이트는 오류면 주 화면으로 넘어간다(fin-ux 동작 그대로) | `needs-keys`로 되돌림 |
| U-06 | 키 값은 IPC 요청을 받자마자 `SecretValue`로 바꾸고, 요청·연결 타입의 `Debug`는 값을 가린다. 응답·오류 문구·로그에 키가 들어가는 경로가 없다. 웹뷰 쪽은 입력 폼 상태만 갖고 응답에는 키가 없다 | - |
| U-07 | 실패한 연결 확인 결과는 1분 동안 재사용해 토스 토큰 발급을 1분에 1회 이하로 묶는다(화면의 60초 재확인과 같은 상한을 코어에서도 지킨다). 키를 새로 붙여 넣으면 바로 다시 시도한다 | 화면 쪽 주기만 믿음 |
| U-06 | 웹소켓 갱신 연결은 아직 조립하지 않아 토큰 관리자의 갱신 훅은 아무것도 하지 않는 `NoStreamRenewal`을 쓴다 | 웹소켓 조립(이 묶음 밖) |
| 조립 | 토스 읽기 어댑터(`TossAccountRead`, 운영 주소)를 시작 때 키 유무와 상관없이 한 번 만든다. 토큰 관리자가 발급할 때마다 키체인에서 키를 읽으므로 키를 저장한 뒤 어댑터를 바꿔 끼울 필요가 없다. 같은 인스턴스를 `BrokerRead`·`MarketInfo` 포트, 연결 확인, MCP 시세 도구가 함께 쓴다. 주문 쓰기 어댑터(`broker-toss-trade`)는 조립하지 않아 주문 경로는 그대로 꺼져 있다 | 키 저장 뒤 어댑터 교체(포트 타입이 정적이라 감싸는 계층이 늘어남) |
| 조립 | 어댑터·토큰 오류 변환·`TokenRenewal` 구현은 `adapter-construction` 규칙에 따라 조립 루트(`main.rs`)에만 두고, `toss_link`·`broker_link`는 토스 타입을 모르는 포트(`TossProbe`, `ProbeFailure`)만 쓴다 | - |
| U-22 | 연결이 성공할 때마다(키 저장 직후, 시작 직후 백그라운드 확인, 화면의 연결 확인) 계좌 목록을 받아 종합매매(`BROKERAGE`) 계좌 중 첫 계좌를 고른다. 선택이 바뀌면 `AccountSelectionChanged`를 낸다. 선택은 저장하지 않고 실행마다 다시 고른다. 계좌 바꾸기 화면(고급 > 시스템)은 이 묶음 밖이다 | 선택 저장 테이블 추가(마이그레이션) |
| 조립 | `saved_accounts`를 고정 목록에서 실행 중에 바뀌는 공유 슬롯(`AccountSlot`)으로 바꿨다. 예약 작업·설정 화면·시작 화면은 읽는 시점의 선택을 쓴다 | - |
| 조립 | MCP 시장 도구 중 `quote`만 실제 시세 조회로 잇는다(종목 코드와 시장으로 조회). 캔들·시장 개요·순위·섹터·수급과 포트폴리오 도구는 아직 "사용 불가"다. 보유 종목 변환에는 종목 마스터(주문 가능 사실 포함)가 필요한데 마스터 동기화가 조립되지 않아, 지금은 보유가 있는 계좌의 보유 조회가 실패한다(현황·포트폴리오 도구 미연결). 마스터 조립은 다음 묶음 몫으로 남긴다 | 빈 마스터로 보유를 억지 변환(주문 가능 사실을 지어냄) |
| 조립 | 운영 HTTP 클라이언트 생성 실패(TLS 구성 실패)는 시작 오류로 올린다. 정적 포트 타입이라 "사용 불가" 대역으로 바꿔 끼울 수 없다 | 감싸는 열거형 포트 |
| U-07 | 공개 IP 확인 서비스는 `https://api.ipify.org`(본문이 IPv4 주소 한 줄인 평문 응답, 인증·쿠키 없음)로 정한다. 토스 허용 IP 등록은 IPv4가 일반적이라 IPv4 전용 주소를 쓴다. IPv6만 쓰는 회선은 실측 S-22 몫이다. 주소 리터럴은 조립 루트(`main.rs`)에만 있고 HTTP 클라이언트는 `sources::PublicIpClient`(GET 한 번, 리다이렉트·64바이트 초과·사설/루프백 주소 거부, 사용자 정보 없는 고정 User-Agent)다 | `icanhazip.com`, `ifconfig.me`, 클라우드플레어 trace(본문 파싱 필요) |
| 설정 | (사용자 지시) 편집 영역(작업별 모델·예약 작업, 수집 소스·선택 키, 나의 투자 원칙, 시스템, 투자 성향과 주문 설정 바꾸기)을 기존 "고급" 접기 안, 요약 카드 뒤로 옮겼다. "고급" 접기는 설정 조회가 불러오는 중·실패여도 같은 자리에 늘 그려(요약 카드만 빠짐) 펼친 상태가 조회 완료로 닫히지 않는다. 앱 업데이트와 앱 정보는 접지 않는다. 이를 가정한 기존 화면 시험 7개는 설정 화면을 그린 뒤 "고급"을 누르는 단계(`tests/settings-advanced.mjs`)를 더했고, 접힘을 확인하는 시험을 새로 뒀다 | "고급"을 둘로 나눔(같은 이름의 토글 두 개) |
| U-07 | 조회는 화면의 `get_public_ip` 명령으로만 일어나며(허용 IP 화면만 부름), 코어가 성공·실패 결과를 1분 동안 재사용해 1분에 1회 이하로 묶는다 | 화면 쪽 주기만 믿음 |
| U-07 | "IP 복사"는 코어 명령 `copy_text`가 macOS `/usr/bin/pbcopy`에 표준 입력으로 넘긴다. 받는 값은 IP 주소로 해석되는 문자열만이며 그 밖의 값은 거부한다(임의 문자열을 클립보드에 쓰는 통로를 만들지 않음) | `tauri-plugin-clipboard-manager`(문서가 정하지 않은 새 패키지), 웹 `navigator.clipboard`(웹 API 직접 사용 금지) |
