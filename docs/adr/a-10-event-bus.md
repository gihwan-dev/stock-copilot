# A-10: 조립 뒤 불변인 application 이벤트 버스

- 상태: 초안
- 관련 작업: A-10, D-18, T-02, A-19, J-01, N-12, U-02
- 수정 기준: 구현 82fdf4dd27cf6f5836c144cdf44da096b14f2e63, master 2929bf6411453cfb74570a8b8b221ce54eba2b2a 병합, 메인의 A-10 리뷰 수정 결정

## 최종 결정과 근거

architecture 3.5의 “새 반응을 추가할 때 기존 코드를 고치지 않고 구독자를 추가한다”에 따라 EventSubscriber 구현과 EventBusBuilder::subscribe 등록만으로 구독자를 더한다. build가 빌더를 소비해 조립을 끝낸다. EventBus에는 구독 추가·해제나 가변 발행 메서드가 없다. 빈 버스의 Default도 완성된 불변 버스다. EventSubscriber는 Send + Sync이며 on_event(&self, &DomainEvent)는 닫힌 SubscriberFailure를 반환한다. Debug 구현을 구독자에 요구하지 않는다.

EventBus는 Send + Sync이고 Arc<EventBus>로 공유한다. 버스 내부에 잠금, RefCell, Mutex, 공유 가변 상태가 없다. 종류별 등록표는 BTreeMap<DomainEventKind, BTreeSet<SubscriptionId>>이며 ADR 0065의 Ord를 쓴다. 구독자는 단독 소유한 등록 목록 순서대로 호출한다. 등록 ID는 이 버스 안에서만 구분하며 같은 구현을 두 번 등록하면 별개 등록이다. 빈 종류 집합은 아무것도 받지 않는다. publish(&self, DomainEvent)는 받은 이벤트를 동기 전달하며 연속 중복도 합치지 않는다. 동시에 들어온 서로 다른 발행 사이의 전역 순서는 정의하지 않고, 각 발행 안의 등록 순서를 보장한다.

DeliveryReport는 그 발행에서 실패한 등록의 ID와 닫힌 원인만 담는다. 하나의 Err는 이후 구독자 호출을 막지 않는다. 정상 발행에는 빈 목록을 반환한다. 보고서가 소유권 있는 반환값이므로 다음 발행에 실패가 섞이거나 회수 시점을 관리할 상태가 없다. 호출자는 자신이 발행한 이벤트와 반환 보고서를 함께 처리한다. 실패 구독자의 재시도·자동 해제는 추가하지 않는다.

페이로드는 DomainEvent뿐이다. domain과 기존 식별자를 바꾸지 않고 금액·수량·본문의 범용 봉투를 추가하지 않는다. 주문 전송이나 승인 포트와 연결하지 않는다. UI DTO는 이 변경의 범위 밖이다.

## 삭제한 기능과 이유

메인의 확정 결정에 따라 이전 구현의 다음 기능을 제거한다.

| 삭제 | 이유 |
|---|---|
| EventPublisher, 콜백 재발행, FIFO 큐 | architecture 3.5의 이벤트는 “상태 변경이 저장·반영된 뒤 내는 변경 알림”이다. 구독자는 일을 예약하고 반환하며 상태를 저장한 유스케이스가 후속 이벤트를 발행한다. 소비자가 없는 재발행 장치와 큐·순환·순서 정책을 유지하지 않는다. |
| catch_unwind, AssertUnwindSafe, Panicked 원인 | architecture 3.8과 ADR 0035는 제품에 패닉 회복 경로를 두지 않는다. Err는 보고하지만 패닉은 구독자의 버그로 그대로 전파된다. |
| 버스 안의 실패 누적과 take_failures | 발행별 DeliveryReport 반환으로 충분하다. 실패 보존·회수·메모리 상한 정책을 만들지 않는다. |
| publish_broker_connection_change | 상태 전이 판단과 같은 사건의 중복 방지는 상태를 저장하는 발행자 T-02의 책임이다. 일반 버스는 사건을 합치지 않는다. |

버스 소스는 132줄에서 79줄로 줄었다. 스레드나 비동기 런타임을 새로 만들지 않는다. 다른 스레드에서 Arc<EventBus>를 사용하는 것은 기존 표준 라이브러리만으로 검증한다.

## 구독자 계약과 인계

모든 구독자 구현은 Send + Sync다. on_event는 동기이고 짧게 끝나야 한다. 오래 걸리는 일은 자기 작업 큐에 넣고 반환한다. 구독자 안에서 발행하지 않는다. 새 이벤트는 상태를 저장·반영한 유스케이스가 발행한다. 버스는 이 계약을 위해 발행 핸들을 콜백에 제공하지 않으며 구독자의 외부 참조를 통한 우회 호출을 감시하는 장치는 추가하지 않는다.

- J-01: 스케줄러 구독자를 등록한다. 콜백은 트리거 작업을 작업 큐에 넣고 반환한다. 실제 실행과 그 결과 저장 뒤 후속 이벤트 발행은 해당 유스케이스에서 한다.
- N-12: 가격·뉴스·공시 판정 작업을 큐에 예약한다. 판정·저장을 마친 유스케이스가 architecture 3.5의 트리거 이벤트를 발행한다. 콜백 안에서 판정 후 재발행하는 경로를 만들지 않는다.
- U-02: UI 전달 구독자를 등록한다. 계좌 키와 accountSeq 문자열을 DTO에서 제거하고 종류와 허용된 ID만 전달한다. 동기 콜백은 짧게 끝내며 긴 전달 작업은 자기 큐에 둔다. 새 이벤트를 발행하지 않는다.
- T-02: 상태가 같으면 내지 않으며 차단·만료·사용자 조치·차단 해제·재발급 성공 한 전이를 저장한 뒤 BrokerConnectionChanged 하나만 낸다. 단일 상태 관리자가 중복 관측을 정리한다. 버스에 비교나 중복 제거를 맡기지 않는다.
- A-19: 같은 토스 연결 사건에 SelfCheckChanged를 함께 내지 않는다. 자체 점검 이벤트는 토스 연결 밖 항목에만 쓴다.
- A-06, A-07, A-12, A-13, A-15, A-16, S-11: 결과 저장·반영 뒤 발행하고 그 호출의 DeliveryReport를 처리한다. 이벤트는 승인이나 주문 전송 권한이 아니다.
- U-05: 종류·키에 맞춰 재조회한다. 설정 변경은 설정 전체, 선택 계좌 변경은 계좌 조회 전체, 저장소 교체는 저장 데이터 조회 전체를 무효화한다.

## 검사와 의존성

통합 테스트는 38개 종류의 exhaustive 기대 함수, 종류별 필터·페이로드 보존, 등록·발행 순서, 빈 집합과 중복 등록, 실패 격리·발행별 보고서, 새 구독자 등록, Send + Sync 컴파일 단언과 Arc를 다른 스레드로 보내는 발행, 패닉 전파를 검사한다. Config::with_cases(4096) 속성 검사는 임의 발행 열의 각 이벤트를 연속 두 번씩 발행하고 각 구독자의 수신 열이 종류로 거른 중복 보존 열과 같은지 비교한다.

이번 수정은 새 의존성·기능·잠금 파일 변경을 추가하지 않는다. 이전 회차에 승인된 개발 의존성 proptest =1.12.0(default-features=false, std)과 그 위치 허용 목록을 유지한다. 기존 master 테스트는 수정하지 않고 이 작업이 추가한 테스트만 새 계약에 맞게 바꾼다.
