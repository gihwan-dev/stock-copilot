# A-10: application 이벤트 버스

- 상태: 초안
- 관련 작업: A-10, D-18, T-02, A-19, U-02
- 기준: master cb38274a4152d4171928b36c65e3f3a8407a65d7을 정상 훅으로 병합한 40c2d0c0bff4003325e12516fd13b7824d1c6d48

## 근거와 결정

architecture 3.5의 “새 반응을 추가할 때 기존 코드를 고치지 않고 구독자를 추가한다”에 따라 EventSubscriber 한 트레이트와 EventBus::subscribe를 둔다. 별도 통합 테스트의 AdditionalSubscriber는 새 구현과 등록만으로 참여한다. 버스는 구독자를 단독 소유하며 등록 목록은 Vec, 종류별 등록표는 BTreeMap<DomainEventKind, BTreeSet<SubscriptionId>>다. 종류는 ADR 0065의 Ord를 사용하고 같은 종류에서는 등록 목록 순서대로 호출한다. 빈 종류 집합은 아무것도 받지 않으며 같은 구독자를 별도 등록하면 등록마다 한 번씩 호출한다. SubscriptionId는 버스 인스턴스 안에서만 구분하는 불투명 식별자다.

architecture 3.5와 3.7은 코어 버스의 동기·큐·실패·재발행 순서를 지정하지 않는다. A-10 지시문의 기본 계약을 적용해 발행 호출 안에서 FIFO 큐를 끝까지 처리한다. 콜백에는 현재 발행의 후속 이벤트를 넣는 EventPublisher만 주며 버스 자체를 주지 않는다. 현재 이벤트의 모든 구독자가 끝난 뒤 후속 이벤트를 큐 끝에 붙인다. 이미 대기 중인 형제 이벤트가 새 자식 이벤트보다 먼저 간다. 스레드, 비동기 런타임, 타이머를 만들지 않는다.

발행은 Result를 반환하지 않는다. 구독자의 닫힌 SubscriberError와 unwind 패닉은 각각 DeliveryFailureCause::Subscriber, Panicked로 수집한다. 실패한 구독자 뒤의 다른 구독자와 이미 예약한 후속 이벤트도 전달한다. 오류 본문과 패닉 본문은 진단 값에 담지 않는다. EventDeliveryFailure는 등록 ID, 원래 DomainEvent, 닫힌 원인만 담고 take_failures가 누적 순서대로 꺼낸다. 콜백은 재시도하거나 자동 해제하지 않는다. AssertUnwindSafe는 버스가 단독 소유한 등록표와 큐를 콜백에 노출하지 않는 경계를 감싼다. 구독자 내부 상태와 외부 부수 효과의 원복을 보장하는 뜻은 아니다.

버스와 후속 발행 API는 DomainEvent만 받는다. domain 타입과 페이로드는 바꾸지 않으며 금액·수량·본문을 받는 범용 봉투를 추가하지 않는다. architecture 3.5의 “상태 변경이 저장·반영된 뒤 내는 변경 알림이며 승인이나 주문 전송 권한이 아니다”를 유지한다. 주문 전송 포트·승인 경로와 연결하지 않는다.

## 토스 연결 계약

ADR 0065와 architecture 3.5의 한 상태 변경에 BrokerConnectionChanged 하나, 회복도 같은 이벤트, SelfCheckChanged와 중복 발행하지 않는 계약을 따른다. publish_broker_connection_change는 발행자가 소유한 상태 타입의 이전·이후 값을 Eq로 비교한다. 같으면 내지 않고 다르면 BrokerConnectionChanged 하나만 낸다. 이 함수는 SelfCheckChanged를 내지 않는다. 버스에서 새로운 연결 상태 목록을 정의하지 않는다.

일반 publish는 이벤트를 합치거나 버리지 않는다. 전역 이벤트에는 사건 ID가 없으므로 서로 다른 발행자의 두 알림이 같은 사건인지 판단할 수 없다. 전용 함수 역시 발행자가 전달한 상태 쌍을 비교할 뿐 최신 상태를 저장하거나 인증하지 않는다. 거짓 상태 쌍·오래된 상태 쌍, 두 관리자의 중복 관측, 별도 경로의 SelfCheckChanged까지 막았다고 주장하지 않는다.

## 인계

- T-02: 상태 변경을 저장한 뒤 이전·이후의 같은 불변 상태 타입으로 전용 함수를 호출한다. 차단 원인 변경·만료·사용자 조치·차단 해제·재발급 성공이 Eq에 반영되어야 한다. 단일 토큰 관리자가 전이를 직렬화하며 같은 관측 오류마다 재발행하지 않는다. 초기 상태와 첫 연결의 비교 기준도 토큰 관리가 정한다.
- A-19: 토스 연결 사건은 T-02의 BrokerConnectionChanged를 사용하고 같은 사건에 SelfCheckChanged를 추가하지 않는다. 자체 점검 이벤트는 토스 연결 밖 항목 변경에만 낸다.
- A-06, A-07, A-12, A-13, A-15, A-16, S-11: 결과 저장·상태 반영 후 architecture 3.5의 이벤트를 발행한다. 저장 트랜잭션의 성공 여부·단일 발행 책임은 버스가 검증하지 않는다.
- U-02: EventSubscriber 구현을 등록하고 AccountId를 제거한 DTO로 변환한다. accountSeq의 문자열 표현도 보내지 않는다. 트레이트와 버스의 수정은 필요하지 않다.
- U-05: 종류와 키에 맞춰 쿼리를 무효화하고 재조회한다. SettingsChanged는 설정 전체, 선택 계좌 변경은 계좌 조회 전체, 저장소 교체는 저장 데이터 조회 전체를 대상으로 한다.

## 검사와 의존성

통합 테스트는 38개 이벤트의 exhaustive 기대 match, 종류별 필터와 페이로드 보존, 등록·발행 순서, 새 구독자 추가, 빈 집합, 중복 등록, 실패 누적과 회수, 패닉·오류 뒤 전달, 여러 단계 FIFO와 8192회 재발행, 연결 상태의 모든 전이·회복, 일반 이벤트를 합치지 않음을 검사한다. 속성 검사는 Config::with_cases(4096)으로 임의 발행 열과 구독 집합의 필터 결과를 비교한다.

사용자 승인에 따라 application 개발 의존성에 기존 proptest =1.12.0을 domain과 같은 default-features=false, features=[std]로 추가한다. 새 외부 패키지·버전은 없다. Cargo.lock에는 application의 proptest 간선만 추가한다. 의존성 위치 허용 목록에는 application이 proptest를 통해 도달하는 syn·proc-macro2의 기능 통합 경로만 추가한다. 기존 허용 규칙은 줄이지 않는다. proptest의 라이선스는 MIT OR Apache-2.0이다.

## 미해결과 사용자 확인 대상

- 동기 버스다. 구독자는 유한 시간 안에 반환하고 재발행 열도 끝나야 한다. 무한 콜백·무한 순환 이벤트의 시간 제한, 큐 상한·버림 정책은 추가하지 않는다. 긴 작업은 구독자가 기존 작업 큐에 등록하고 반환해야 한다.
- 프로세스 abort, unwind 중 이중 패닉, 패닉 페이로드의 소멸자 패닉은 격리를 보장하지 않는다. 기본 패닉 훅은 변경하지 않는다. 실패 뒤 구독자 내부 상태의 재사용 가능 여부는 해당 구독자가 책임진다.
- 등록 해제·영속 로그·정확히 한 번 전달은 없다. 실패 진단을 회수하지 않으면 누적된다. 이벤트를 놓쳐도 다음 조회로 회복한다는 architecture 3.5를 따른다.
- 연결 상태 타입과 그 Eq의 의미는 T-02가 확정한다. 버스의 상태 비교는 사건 중복 방지를 대신하지 않는다.
- 프로젝트 설정 hooks=true와 실제 프로젝트·훅 정의 신뢰 적용을 별도로 인증할 도구는 없었다. 정상 lefthook과 직접 검사 결과를 증거로 사용한다.

## 변이와 최종 검증 기록

Cargo.lock 변경이 있으므로 현재 선택기 scope.rs의 diff_scope는 Scope::Everything을 반환한다. application/Cargo.toml과 통합 테스트 변경도 좁은 파일 선택의 조건을 충족하지 않는다. 전체 자동 변이 실행은 지시문에 따라 생략했다. git archive와 현재 application 파일을 별도 mktemp 복사본에 놓고 손 변형 27개를 순차 실행했다. 실험에만 cargo-mutants와 같은 cap-lints를 적용했으며 원본 소스·검사 설정에는 검사 끄기를 추가하지 않았다. 27개 모두 컴파일 후 테스트 실패로 검출되었고 생존·시간 초과·컴파일 불가로 센 변형은 없다. 원복 후 같은 테스트도 통과했다.

검출한 변형: 후속 발행 버림·앞 삽입, 등록 종류 오지정·종류 하나 누락·등록 ID 중복·등록 앞 삽입, 구독 포함 조건 반전·무시, 전달 종류 오지정·구독자 역순·첫 구독자만 전달, 큐 LIFO·이벤트 하나만 처리·후속 이벤트 버림·후속 역순·자식을 형제보다 먼저 처리, 오류를 패닉으로 분류·패닉을 오류로 분류, 실패 등록 ID·이벤트 오지정, 실패 회수 역순·회수 뒤 보존·다음 발행 때 이전 실패 삭제, 연결 비교 반전·자체 점검으로 잘못 발행·연결 두 번 발행, 실패 기록 버림.

구현 전 통합 테스트는 공개 API 누락으로 컴파일 실패했다. 구현 뒤 cargo test -p application은 기존 14개와 A-10의 11개 테스트가 통과했다. application 전 대상 Clippy와 source-check·raw-types·arch-check도 통과했다. 시작 기준의 정상 병합 훅은 workspace 1172개와 커버리지 실행 801개가 모두 통과했다. 최종 판정은 이 파일을 포함한 커밋의 정상 전체 검사 결과를 따른다.
