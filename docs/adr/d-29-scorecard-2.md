## 가상 청산

`VirtualExitSignal`은 원래 추정 과제와 실제 진입 관측, 기록된 목표·손절가, 명시한 만기를 소유한다. 진입 관측은 식별된 같은 종목이어야 하고 과제 생성 이전일 수 없다. 기준 관측이 실제 진입인 경우의 생성자와 별도 진입 관측을 받는 생성자를 제공한다. 목표·손절가는 기록된 가격을 사용한다. AI 질문의 기준가로 실제 진입가를 덮어쓰거나 목표·손절가를 다시 계산하지 않는다.

정규장과 H는 D-27의 달력 계산을 실제 진입 시각부터 재사용한다. 명시한 만기와 달력 계산 결과가 다르면 판정 불가다. 확정 수정주가, 종목·통화·수정 기준, 중복 봉 검증도 D-27을 재사용한다. `virtual_exit_adjustment`는 실제 진입 뒤의 분할·병합 근거로 진입가와 목표·손절가를 같은 수정 기준으로 환산한다. 환산이 정확한 유한 십진수로 표현되지 않거나 넘치면 판정 불가다. 불명확한 기업 행위는 추측하지 않는다.

| 상황 | 결과와 가격 | 근거 |
|---|---|---|
| 목표 장중 도달 | 목표 도달, 목표가 | design 6.6: “목표가나 손절가에 닿으면 그 가격” |
| 손절 장중 도달 | 손절 도달, 손절가 | 같은 문장 |
| 목표 이상으로 시작 | 목표 도달, 시가 | design 6.6: “시가가 그 가격을 넘겨 시작한 날이면 시가” |
| 손절 이하로 시작 | 손절 도달, 시가 | 같은 문장 |
| 만기까지 미도달 | 만기 청산, 종가 | design 6.6: “기간이 끝나면 그날 종가에 청산한 것으로 본다” |
| 아직 진행 중 | 진행 중, 가격 없음 | 미래 봉으로 확정하지 않음 |
| 필수 봉 누락·거래량 0·수정 기준 불일치 | 판정 불가, 가격 없음 | ADR 0035·0051과 보수적 자료 완전성 판단 |

진입일과 양쪽 가격 도달일은 1분봉으로 순서를 확인한다. design 6.6은 “기준일 … 과 목표·손절에 모두 닿은 날은 1분봉으로 판정한다. 1분봉으로도 순서를 알 수 없으면 실패로 본다”고 정한다. 같은 온전한 분봉에서 양쪽에 닿으면 손절 가격을 적용한다. 진입 이전 움직임이 섞인 부분 분봉에서 목표 또는 손절에 닿았으면, 진입 이후 도달인지 확인할 수 없으므로 가격을 확정하지 않는다. 일봉에서 양쪽에 닿았는데 필요한 1분봉이 없으면 판정 불가다. 장중 H의 만기는 그 시각에 닫힌 1분봉의 종가를 사용하며, 부분 분봉 만기에 확정 종가가 없으면 판정 불가다.

청산 가격의 봉인된 payload는 목표·손절·만기마다 서로 다른 타입이다. 외부에서 목표 결과를 만기 결과로 다시 포장하여 종가임을 주장할 수 없다. 금액이 들어 있는 신호·청산·비용의 Debug는 원문을 내보내지 않는다.

## 비용과 비교

D-22의 수수료·매수 세율·매도 세율 사실과 적용 기간을 재사용한다. 요율 누락은 0으로 대체하지 않는다. 시장과 적용 기간을 검사한다. `c_buy = commission + buy_tax`, `c_sell = commission + sell_tax`이며 결합 요율도 0 이상 1 이하만 받는다.

`r_net = (P_exit / P_entry) × (1 - c_sell) / (1 + c_buy) - 1`

수익률 결과는 실제 진입·청산 시각과 예정 만기를 별도 접근자로 보존한다. 종목의 거래 통화를 유지하며 D-09의 봉인된 `PerformanceValue`를 반환한다. 비례 비용에 따른 가상 수익률이며, 실제 주문 수량이나 체결 비용을 가정하지 않는다. R-11 Q3의 100주·72,000원 예제는 매수 7,201,080원, 순매도 7,184,520원으로 고정한다. 실제 체결의 원 단위 절사·최소 수수료는 거래내역의 정본 값으로 처리할 후속 사항이다.

`r_excess = r_net - r_benchmark`, `r_benchmark = Π(1 + r_B,i) - 1`

D-09 `BenchmarkSeries`의 날짜는 평가 스냅샷의 정산일이므로, 이것만 신호의 진입·청산 날짜와 비교하면 구간을 잘못 맞출 수 있다. `SignalBenchmark`는 같은 원본 봉·스냅샷으로 `BenchmarkSeries`를 만들고 각 가격 날짜를 같은 시장 달력의 정규장 종료 시각에 연결한다. 실제 진입과 청산이 정확히 이 종가 시각일 때만 비교한다. 정산일 문자열의 일치로 이를 대체하지 않는다. 달력 누락·충돌·역순, 통화 불일치, 일중 진입·청산은 비교 불가이며 순수익률은 유지한다. 국내 가격지수의 배당 제외 표지는 `series()`에 남는다.

## 신뢰구간과 D-17 집계

D-17의 실제 분류와 D-23의 같은 종목 비중첩 표본 선택을 재사용한다. 조기 청산해도 원래 추정의 만기가 지나기 전에는 포함하지 않는다. 진행 중·판정 불가를 수익률 0으로 바꾸지 않는다. 중복 입력은 한 번만 센다. 원래 모델·기간·프롬프트·추정 ID·판정 기록을 소유한 `ScorecardReturnObservation`으로 결합하므로 같은 종목·시간이라는 이유만으로 다른 추정에 붙이지 않는다. 실제 진입은 원래 추정 구간 안에서 시작해야 하며, 만기가 원래 판정 구간과 다르면 결합하지 않는다. 비교 불가 수익률의 건수를 별도로 반환하며 D-17의 전체 비교 조합 수를 보존한다.

R-12 2.4는 “같은 날 만든 제안끼리” 묶도록 한다. 이 초안에서는 실제 신호 진입일을 생성일로 간주하고 모든 시장을 한국 날짜(UTC+09:00)로 통일한다. 청산일은 묶음 키가 아니다. 날짜와 수익률 값으로 정렬한 뒤 날짜별 합·건수를 보존하고, 원래 날짜 묶음 수만큼 복원 추출한다. 뽑힌 묶음에 속한 모든 신호를 포함한 평균을 계산한다. 날짜별 평균의 단순 평균이 아니다.

초안 상수는 2,000회, 보간 없는 백분위법이다. 정렬된 2,000개 평균의 50번째와 1,950번째를 각각 2.5%·97.5% 분위로 쓴다. 입력은 같은 기간·같은 통화의 초과 수익이다. 난수 시드는 호출 인자이고 domain의 정수 SplitMix64를 쓴다. 하위 16비트 후보에 거절 추출을 적용하여 1~65,536 묶음의 색인을 균등하게 정한다. 부동소수점·새 의존성은 없다. 원시 신호 30건과 독립 날짜 묶음 30개를 모두 요구한다. 날짜 30개면 신호도 최소 30건이므로 날짜 수 검사로 둘을 충족한다. 미달하면 구간 없이 `InsufficientSamples`다. 양 끝점 사이에 0이 있으면 등호를 포함하여 `EdgeNotConfirmed`, 하한이 양수면 `Superior`, 상한이 음수면 `Inferior`다.

부트스트랩은 Decimal 계수를 공통 소수 자릿수의 정수로 옮겨 재표본 합과 건수를 계산하고 마지막에만 나눈다. 자릿수는 0~28이므로 자릿수 차와 10의 거듭제곱은 범위가 증명된다. CostRate 각각이 0~1이므로 결합 요율의 정수 계수는 최대 2×10²⁸로 i128과 Decimal에 들어간다. 유효 결합 요율의 매수 비용 계수도 최대 2×10²⁸다. 이에 쓰는 wrapping 연산은 이 범위에서 실제 순환하지 않는다. 입력 상한 65,536 때문에 날짜별 건수와 비교 불가 건수의 증가도 범위를 넘지 않는다. RNG 상태의 순환만 의도된 모듈러 연산이다. 신호 수익률·표본 합·계수 변환이 범위를 넘으면 닫힌 산술 오류로 끝낸다.

분봉 시작 시각은 분 단위 오프셋을 보장하는 Timestamp의 타입 불변식을 사용한다. 분 안의 초·나노초만 빼므로 지원 연도 경계를 넘지 않는다. 이 연산을 위해 기존 시간 모듈에 새 자유 함수 하나만 더했고 기존 impl·기존 테스트는 변경하지 않았다.

## 검증

규칙별 고정 예제, R-11 비용 예제, 독립 정수·유리수 계산, 4,096회 속성 검사를 둔다. SplitMix64의 알려진 정수 출력과 독립 Fraction 계산의 시드 42 백분위 예제 하한 11.866667·상한 18.000000을 고정한다. 날짜 안의 표본을 묶은 재표본 평균을 독립 가중 유리수와 대조하고, 최솟값·최댓값 경계와 입력 순서 무관성을 검사한다. 이 값은 문서에 없는 합성 검증 예제이며 문서의 투자 성과 예제로 주장하지 않는다.

자동 crate 전체 변이 검사는 이번 작업의 명시적 예외 지시대로 실행하지 않는다. 새 파일의 손 변형을 별도 임시 복사본에서 컴파일하고 테스트 실패로 검출되는지 확인한다. 컴파일 실패는 검출 건수에 세지 않는다. 최종 검사와 손 변형의 실측 결과는 구현 보고에 적는다.

## 미해결과 사용자 확인 대상

- 2,000회·백분위 순위·보간 생략과 최소 날짜 30개는 문서가 구체적으로 정하지 않은 보수적 초안이다. 30건은 실력 증명이 아니다.
- 동일 분봉의 손절 우선 가격, 부분 진입·부분 만기 봉의 판정 불가, 거래량 0을 자료 부족으로 보는 정책을 확인해야 한다.
- 실제 신호 진입일을 제안 생성일로 간주하는 것과 한국 날짜로 시장을 묶는 정책을 확인해야 한다. D-24의 raised_at과 가격 관측 시각이 자정을 사이에 두고 다르면 별도 생성일 계약이 필요하다.
- 일별 BenchmarkSeries로 일중 구간을 대체하지 않는다. 일중 벤치마크 자료와 정확한 체결 시각이 없으면 비교 불가라 실제 사용에서 신뢰구간에 들어갈 표본이 크게 줄 수 있다. 일중 비교 지원은 별도 계약이 필요하다.
- 실제 진입 때문에 원래 추정의 만기가 달라지는 경우는 D-17 결합에서 제외한다. 향후 실제 신호 구간으로 비중첩 집계할지 별도 확인이 필요하다.
- 배당락·특수 기업 행위는 S-23의 확인 전까지 임의 조정하지 않는다.
- 프로젝트 설정의 hooks=true와 Git 훅 설치는 확인했다. 현재 T3 세션의 프로젝트 신뢰·훅 신뢰 적용은 직접 확인하지 못했으며 실제 검사 결과와 구분한다.
