# 차트·추정 코어 묶음 결정 표

문서가 정하지 않았거나 잠금 파일·선행 작업 부재로 선택이 필요했던 항목을 ADR 0173에 따라 정리한다.

| 작업 | 정한 것 | 다른 선택지 |
|---|---|---|
| DS-17 | `lightweight-charts`가 잠금 파일(`pnpm-lock.yaml`)과 TS 의존 허용 목록(`harness/ts-deps/allowlist.json`)에 없어 외부 패키지를 추가하지 않고 HTML5 Canvas 2D로 `CandleChart`를 직접 구현했다. `shared/platform/canvasTheme.ts`가 CSS 토큰(`--color-*`)을 읽어 `CandleChart`에 넘기고 테마·크기 변경 시 다시 그리며, U-05가 없으므로 `CandleChart`는 자료·테마·선택 팔레트를 props로 받는 순수 선언형 컴포넌트로 구현했다. | `lightweight-charts` 패키지 신규 설치, SVG 전용 캔들 차트 |
| J-09 | 관심 종목 상한을 200종목으로 두고 `MasterInstrument`의 `ListingStatus::Active`만 등록을 허용하며, `WatchlistRepository::store(previous, next)`로 낙관적 동시성 갱신과 `DomainEvent::WatchlistChanged` 변경 시 발행을 구현했다. 수집·감시·추정 대상 통합(`TrackedUniverse`)은 보유 > 관심 > 후보 우선순위로 중복을 제거한다. | 무제한 관심 종목, 단순 덮어쓰기 저장 |
| E-01 | S-18 저장소는 `EstimateTaskRepository` 포트(`load_assignments`, `commit_assignments`)로 추상화하고, `CreateEstimateTask`는 `TrackingTarget`(보유·관심·후보)을 필수 입력으로 받아 `domain::EstimateTask::create`·`CostEligibleTask::assess`로 60일 미만 표본과 `c/(T+S) > 5%p`를 건너뛰며, `GetEstimateTaskInput`에는 `task_id` 외의 필드를 두지 않았다. | `EstimateSubmissionRepository`에 과제 발급 메서드 추가, 문자열 심볼을 받아 과제 생성 |
| E-02 | `application::SubmitEstimateTool`은 타입이 정해진 다섯 인자(`EstimateToolArguments`: task_id·p·rationale·counterargument·sources)와 신뢰한 실행 문맥(`EstimateRunContext`: 실행 ID·실제 모델·기간·메타데이터)을 나눠 받는다. 출처는 `tool:<요청 ID>`만 받고 새 포트 `ToolCallHistory::calls_in_run`으로 같은 실행의 성공한 호출 원장에서 찾으며 없으면 `UnknownSource`로 거부한다. 빈 출처 목록은 `evidence = None`(출처 없음)으로 기록한다. 다른 실행에 배정된 과제는 `WrongRun`으로 거부한다. `ConcurrentUpdate`는 같은 입력(같은 시각)으로 최신 원장에서 다시 시도하며 횟수 상한을 두지 않는다(충돌은 다른 커밋이 진행됐다는 뜻). 다섯 필드 밖의 필드 거부는 `mcp-server::parse_submit_estimate_arguments`(`deny_unknown_fields`, `additionalProperties: false` 스키마)가 하며 도구 등록은 m 묶음에 남긴다. 근거·반론은 공백만인 값을 거부하고 4000자 상한. | 원문 JSON을 application에서 파싱, 출처 없는 제출 거부, 재시도 횟수 상한 |
| E-03 | `GetProfile`은 저장된 성향이 없으면 기본 성향을 `ProfileView::Default`로 돌려준다. `GetScorecard`는 새 포트 `ScorecardObservationRepository::scorecard_observations`로 읽어 domain `Scorecards::calculate`만으로 판정·적중률을 낸다(30건 미만은 domain `Scorecard::Pending`). 관측이 없으면 오류 대신 `NoObservations`, 모델·기간 조합 선택이 없으면 `UnknownCombination`. 도구 등록·JSON 응답은 m 묶음 몫. | 관측 없음을 오류로 반환, application에서 적중률 계산 |
| E-04 | AI-07 프롬프트 로더가 master에 없어 최소 앞머리 검증기 `application::PromptFile::parse`(여섯 키 정확히 한 번, 빈 값·빈 본문·제공자별 도구 이름 거부)를 두고, `testkit-ports/tests/prompt_files.rs`가 `prompts/` 아래 모든 파일에 돈다. 프롬프트 해시 계산과 실행 기록 연결은 AI-07에 남긴다. 추정 프롬프트는 `prompts/estimate/v1.md`. | `xtask`에 검증기, 해시 계산 의존성 추가 |
| E-05 | `application::RunEstimateCycle`은 `TrackedUniverse::monitoring_targets()`(보유 > 관심, 후보 제외)를 순서대로 하나씩 돌며, 매 종목 전에 새 포트 `BackgroundBudget::admit`으로 예약 한도 허가를 받고 끝나면 `release`한다. 허가가 멈추면 다음 호출 전에 멈추고 마지막으로 처리한 종목(`resume_after`)과 재개 시각을 돌려준다. 한 종목의 실행 오류는 `Failed`로 남기고 다음 종목으로 간다. 장 운영 상태를 보지 않으므로 장이 닫힌 시간에도 추정·기록·신호 계산(제출 뒤 `EstimateSubmitted` 구독)이 그대로 돈다. 실제 단일 호출 실행기(`SingleEstimateRunner`)와 스케줄러 작업 등록은 AI 런타임·스케줄러 쪽에 남긴다. | 후보까지 순환, 실패 시 순환 중단 |
| E-10 | `application::SkipSignal`이 종목·선택 사유·시각을 새 포트 `SignalSkipRepository::record_skip`에만 쓴다. `SkipReason`은 한 줄(줄바꿈 거부)·앞뒤 공백 제거·200자 상한, 빈 값은 사유 없음. 추정 과제·제출 경로(`GetEstimateTask`, `SubmitEstimateTool`)는 이 포트를 받지 않으므로 사유가 다음 추정 입력에 들어갈 길이 없다(테스트로 같은 저장 객체에서 과제 보기 불변을 확인). S-07 영속 저장은 저장소 쪽에 남긴다. | 신호 저장소에 사유 필드 추가, 사유 길이 무제한 |
| G-13 | `application::ComparePromptReplay`가 얼린 재생 세트(`ReplayCase`: 증거 묶음 ID + 그때의 도구 호출 원장)를 기준·후보 프롬프트로 같은 순서로 재생해 건수 지표(사례 수, 스키마 통과, 출처 포함, 숫자 불일치)를 낸다. 비율 계산은 하지 않고 건수만 돌려준다(계산은 domain 원칙). 숫자 불일치는 근거·반론 글의 숫자 토큰이 인용한 `tool:` 호출 결과 JSON에 그대로 없을 때다. 실제 재생 실행기(`PromptReplayRunner`)와 세트 저장은 AI 런타임·저장소 쪽에 남긴다. | application에서 비율 계산, 숫자 정규화(쉼표·단위) 비교 |
| E-11 | master의 U-14 `NotificationEventSubscriber`(`apps/desktop/src-tauri/src/platform/notifier.rs`)가 이미 `SignalRaised`를 `Notification::NewSignal` macOS 알림으로 보내고 테스트(`tests/notifier.rs`)도 있어 새 코드를 더하지 않았다. | 신호 알림 전용 구독자 추가 |
| O-08 | 승인 IPC는 `src-tauri/src/ipc/order_approval.rs`의 `RequestOrderApprovalArgs { proposalId }`(`deny_unknown_fields`)와 `parse_order_approval_args`로 제안 ID 외 필드를 역직렬화 단계에서 거부한다. O-06·O-18·U-03의 승인 실행기가 master에 없어 명령 등록·권한·바인딩 생성은 하지 않았다(빈 명령을 열어 두지 않음). 화면 버튼은 신호 카드가 `onRequestApproval(proposalId)` 하나만 부른다. | 승인 실행기 없이 명령만 등록 |
| E-06·E-07·O-08 화면 | 신호 카드는 `features/signal`에 두고 홈 본문 위에 붙였다. 자료는 `ScreenSources`에 더한 `signals`(기본값 "자료 없음")에서 읽고, 승인·넘기기는 `requestOrderApproval(proposal)`·`skipSignal(card, reason)` 동작으로 부른다(기본값 "자료 없음", 실제 IPC는 O-06·S-07 연결 때). 주문 버튼은 주문 켜짐·장 열림·제안 있음·수량 0 아님일 때만, 장이 닫히면 "장 열리면 확인" 카드에 버튼 없음. `tool` 출처는 세지 않고 남은 출처가 없으면 "출처 없음", 남은 출처뿐이고 도구 참조가 없으면 외부 출처 경고. 판정 건수 같은 표시용 수는 `ChartDecimal`로 받는다. | 카드 전용 화면, 승인 버튼에서 직접 IPC 호출 |
| U-29·J-09·U-13·J-08 | `features/instruments`에 사이드바 종목 목록(보유·관심, 오늘 등락, "상세 보기"), 관심 종목 추가(종목 코드 6자리만 화면에서 거르고 상한·상장 검증은 코어가 거부 사유로 돌려줌)·빼기, 종목 상세(시세·`CandleChart` 일봉·내 보유·논거 노트 현재 노트와 이력)를 두었다. 상세는 `AppShell` 본문 자리에 `Outlet` 대신 열려 종목 목록과 채팅이 그대로 보이고, 닫기·설정 이동 때 닫힌다(새 화면 메뉴 없음). 캔들 라벨은 화면 문구 규칙상 고정 문구를 쓴다. 자료는 `ScreenSources`의 `instruments`·`instrumentDetail`·`thesis`, 동작은 `addWatchlist`·`removeWatchlist`(기본값 "자료 없음"). | 상세를 별도 경로로, 캔들마다 날짜 라벨 |
| E-09·O-14 | 투자 성향(기간·위험 성향·종목/섹터 비중 상한·제외 종목 유형)과 고급 주문(시장가 허용·몇 시간 단위 기간 허용·카드 만료 시간·하루 주문 횟수 상한) 편집기는 `features/settings-risk`에 두고 설정 화면의 접힌 "투자 성향과 주문 설정 바꾸기" 안에 넣었다(U-23 시험의 기본 3항목 유지). 어느 변경이 위험 설정인지와 네이티브 확인 창은 코어(`UpdateInvestorProfile`·U-24)가 정하고, 화면은 초안 전체를 `saveInvestorProfile`·`saveOrderSettings`로 보내 결과(저장·변경 없음·취소됨·확인 불가·거부 사유)만 보여 준다. 저장된 값이 없으면 기본값(몇 주~몇 달·중립·20%·40%·제외 없음 / 꺼짐·꺼짐·10분·두지 않음)으로 시작한다. 제외 섹터는 섹터 목록 출처가 정해지지 않아 종목 유형(ETF·ETN·우선주·스팩·리츠)만 둔다. 하루 주문 횟수 상한 선택지는 두지 않음·3·5·10번. | 화면에서 위험 변경 판정, 섹터 제외 선택, 편집기를 기본으로 펼침 |
