# D-09: 봉인된 성과와 벤치마크 (초안)

상태: 구현 초안. 리뷰 수정은 로컬 master `c1b3a5992a3047649d31f56bae8539d1c62f1287`을 먼저 받아 진행했으며 병합 중 하네스 판정 한계는 메인 승인 절차로 해소했다. 최종 병합·직접 검사 기준은 `9b7c74285cca8ac83d914e609962695aad58ad8b`다. 제품 정책의 최종 승인은 메인이 한다. 시작 기준은 `0c9557a8625f36d858574ead5082f1e20a18968a`, H-43을 받은 최종 검사 기준은 `792a35b5da51e9a8fff146793a172d1c2e210fc1`이다.

## 입력과 결과 경계

`Performance::calculate`는 D-31의 `ValuationSnapshot` 열, KRW/USD의 D-30 `FlowPeriod`, 흐름 시점의 D-04 환율만 받는다. `AccountChange::between`을 스냅샷 쌍마다 내부 호출한다. 다른 쌍의 계좌 변동을 임의로 붙일 수 없다. `HoldingsDailyProfit`은 사용하지 않는다. 맨 숫자의 평가액과 흐름을 받는 공개 생성자는 없다.

두 기간이 모두 Confirmed이고, 토큰의 시작·끝이 요청한 첫·마지막 결제일과 정확히 같아야 한다. 모든 중간 스냅샷이 같은 토큰을 보존하고, 현금 기준이 SettledLedger이며, 전체 계좌 완전성이 Complete여야 한다. Native 계산도 다른 통화의 불완전성을 무시하지 않는다. 불확정 흐름, 불완전 값, 조회 매수가능금액과 원장 현금의 혼합, 확정 기간 밖 재계산은 전체 기간 계산 불가다. 실패한 구간을 빼고 합치지 않는다. 재계산은 토큰 안에서만 허용한다.

평가 시각으로 정렬한다. 기간은 KST 달력일 차이이며 1~4096일, 스냅샷은 최대 4097개, 흐름 환율은 최대 4096개다. D-08의 봉인된 거래 응답 자체도 최대 4096행이다. 중복일·역전일과 0일 구간은 닫힌 오류다. 흐름은 `(이전 평가 시각, 이번 평가 시각]`에 속하는 것만 사용한다. 가중치 날짜는 처리 시각의 KST 날짜다. 결제일로 흐름 시각을 바꾸지 않는다. 결제일과 처리 시각이 어긋나 D-31 계좌 변동을 확정할 수 없으면 그 오류가 전파된다.

`PerformanceValue`는 표시용 근사 값이다. 공개 생성자·숫자 접근자·Default·금액·수량·정확 비율 변환은 없다. 소수 여섯 자리 비율 문자열과 반올림된 표시 기준의 Up/Flat/Down만 공개한다. Debug는 값을 가린다. 오류는 입력값을 싣지 않는 닫힌 열거형이다. MWR의 해 실패는 MWR의 Result에 남고, 독립적으로 유효한 TWR을 지우지는 않는다. 누적 TWR의 입력/연결 산술 실패는 Performance 전체 오류다. 연율화 결과는 annual_twr의 별도 Result로 보관하며 실패해도 누적 twr를 보존한다. 1년 미만의 annual_twr는 NotAnnualized다. period는 MWR의 누적/연율 기준이며 twr와 초과 수익은 항상 누적 기준이다.

## 정의와 근거

| 지표 | 정의식 | 입력과 근거 문장 |
|---|---|---|
| TWR | `Π(1+rᵢ)−1` | R-11 Q1: “현금흐름이 생길 때마다 구간을 나눠 수익률을 사슬처럼 곱한다.” |
| 구간 수익률 | `AccountChange / (V_start + Σ((T−t)/T)F)` | R-11 Q1: 중간 평가액이 없으면 Modified Dietz 근사. 흐름 시각의 평가가 있으면 그 경계에서 연결한다 |
| MWR | `Σ CFⱼ·q^(T−tⱼ)=0`, 기간 `q^T−1` | R-11 Q1 XIRR의 365일 식과 동치. 시작 평가·입금은 음수, 출금·종료 평가는 양수 |
| 연율 | `q^365−1` | R-11 XIRR의 365일 기준과 “1년 미만 기간은 연율화하지 않는다.” 실제 364일 이하는 누적, 365일부터 연율 |
| 변동성 | `sqrt(Σ(r−평균)²/(n−1))`, 연율 `sqrt(252·s²)` | R-11 Q9의 단순 일수익률, 표본 분모 n−1, 252 고정. ACC-8에 따라 60거래일 수익률 미만은 표본 부족 |
| 베타 | `Cov(r_p,r_b)/Var(r_b)`, `R²=Cov²/(Var_p·Var_b)` | R-11 Q9: 비동기 장 때문에 주간 수익률 52주 이상. 표본 분모 n−1 |
| 초과 수익 | 같은 기준의 `포트폴리오 TWR−벤치마크 수익률` | D-29의 “같은 기간·같은 통화 벤치마크”. 차의 구체 표현은 초안의 보수적 선택 |

Native(KRW/USD)와 ConvertedKrw를 구별한다. 원화 전체는 스냅샷 당시 Mid와 외부 흐름 당시 Mid를 사용하여 환율 효과를 포함한다. 원통화에서는 환전이 흐름이고, 원화 전체에서는 내부 이동이다(ADR 0052). 다른 통화의 흐름과 금액 0은 해당 Native 기간의 구분을 바꾸지 않는다. 흐름 시점 환율이 없거나 유효한 Mid 후보가 여러 개면 임의 선택하지 않는다.

평가액은 흐름 직후 값으로 해석한다. 평가 시각과 흐름이 같으면 끝 경계의 가중치는 0이다. 사이에 흐름이 있으면 TwrMethod가 LinkedModifiedDietz다. 통화별 환전은 보수적으로 근사 표지를 유지한다. 분모가 0 이하, 성장계수가 음수이면 계산 불가다. 분모가 입력 규모의 1e-12 미만이거나 양의 성장계수가 1e-6 미만이면 정밀도 부족이다. 외부 흐름 없이 실제 전액 손실인 경우 TWR −1은 허용하지만 양의 IRR 근은 없을 수 있다. 곱셈이 0으로 언더플로하면 실제 0으로 표시하지 않는다.

윤년에도 연율 기준은 365다. 실제 366일 수익 0.1의 연율은 0.099714다. 달력 경계 테스트는 2024-02-28→2025-02-28의 366일, 02-29→02-28의 365일, 03-01→02-28의 364일을 고정한다.

## MWR 수치 방법과 정확도 계약

근사 산술은 새 전용 파일 `performance_arithmetic.rs`에 두고 checked Decimal만 사용한다. D-11의 제곱근과 D-21의 실패 전파 방식을 따른다. exact_arithmetic에 근사 연산을 추가하지 않는다. 같은 날짜의 현금 합산은 기존 exact_arithmetic의 정확 덧셈으로 한다. 표현할 수 없는 합을 반올림해 다른 현금흐름으로 만들지 않는다. 새 의존성·maths 기능·부동소수점은 없다. 산술·표시 허용 목록은 이 전용 파일 한 곳만 추가했다.

1. 현금을 날짜·금액으로 정렬하고 같은 날짜끼리 정확히 합친다. 0을 제거한 뒤 시간 순 부호 변화가 정확히 한 번이고 첫 부호가 음수인 경우만 푼다. 이 경우 양의 q의 근은 유일하다. 그 밖은 AmbiguousOrMissingRoot다. 여러 근이 가능한 흐름에서 임의의 근을 선택하지 않는다.
2. 시작과 종료의 두 현금뿐이며 출력 기간이 입력 기간과 같으면 `종료/시작−1`의 닫힌 식을 쓴다. 일간 근 범위 제한을 적용하지 않으며, 흐름 없는 경우 단순 수익률과 일치한다. 이 경로의 오차 계약은 Decimal 나눗셈·뺄셈의 반올림을 포함한 `1e-27·max(1,성장계수)` 이하의 절대 오차다. 출력 자체가 큰 경우 일률적인 절대 1e-8 보장을 주장하지 않는다.
3. 수치 풀이에서는 현금을 최대 절댓값으로 정규화한다. 합산 전·후 모두 비영 계수가 최대 계수의 1e-6 이상이어야 한다. 상쇄 때문에 정규화 후 작은 계수가 생기는 경우도 거부한다. 첫·마지막 비영 현금 날짜로 다항식의 활성 기간을 줄이되 출력 기간은 요청한 전체 기간을 유지한다.
4. q의 정수 계수를 소수 24자리로 이분한다. 범위는 `[0.989999999999,1.010000000001]`이다. 명목 일간 ±1%에 정규화 경계 오차 여유 1e-12를 둔다. 이 범위는 상품의 수익률 한계가 아닌 수치 지원 범위다. 범위 밖은 RootOutsideRange, 128회 안에 폭 1e-24 이하가 되지 않으면 NonConvergence, 중간 산술 실패는 오류다.
5. 좁은 구간만으로 성공하지 않는다. 계산된 잔차와 반올림 예산으로 출력 오차를 다시 검사한다. 계수 개수 N, 활성 일수 T, 출력 일수 D(공개 계산에서 최대 365), `M=max(1,q^T)`, `η=1e-26`일 때 잔차 예산을 `B=2MN(2T+N+3)η`로 잡는다. 정규화·정수 거듭제곱·항 합산의 오차를 포함한 보수적 예산이다. `ε=|계산 잔차|+B`, `δ=2ε/1e-6`, 출력 오차 예산 `4D·max(1,q^D)·δ + 2Dη·max(1,q^D)`가 1e-10 이하일 때만 성공한다. 예산 계산의 실패도 InsufficientPrecision이다.

한 번의 부호 변화에서는 음수 항의 지수가 양수 항보다 모두 크다. 음수 항 절댓값 합 N(q)와 양수 합 P(q)의 비율에 대해 `d log(N/P)/d log q ≥ 1`이고, 마지막 양수 상수항 때문에 P의 하한은 정규화 계수 하한의 절반이다. 이것으로 잔차를 근의 상대 오차로 옮긴다. 공개 수치 풀이의 최종 수익률 절대 오차 계약은 **1e-8 이하**다. 위의 1e-10 통과 기준은 추가 여유를 둔 조건이다. 이 계약은 분류·가격·환율 원본의 정확성이나 Modified Dietz 모델 오차를 보증하지 않는다.

독립 검증은 테스트에서만 수행한다. 유리수 q=(1000+k)/1000, k=−10..10, 2~8일의 입금 사례를 정수 거듭제곱과 i128 교차곱으로 만들고, 4,096개 생성 사례에서 수익률 소수 12자리의 오차를 1단위 이하로 대조한다. 현금의 정렬·역순 및 십진 단위 축소도 같은 해를 내는지 검사한다. 부호 변화·경계 근·해 없음·반복 소진·정밀도 부족·넘침·상쇄의 회귀 사례를 별도로 둔다. 이 생성 범위를 전체 Decimal 입력의 경험적 검증으로 확대 해석하지 않는다.

R-11 예제 1의 독립 Python Decimal 70자리 기준은 연율 `0.03217660051320667477343616703463136349825362847786542611858867422131750`, 363일 기간 `0.031997499326470338710444561791420378233562317354873086731773663009449`다. Rust 결과와 차이 1e-20 미만도 검사한다.

## 표본과 벤치마크 정렬

변동성은 포트폴리오 일별 수익률의 표본 분산과 D-11 제곱근을 사용한다. HolidayCarry와 AwaitingSession도 D-31이 직전 확정 종가를 보존한 유효 평가이므로 표본으로 인정한다. 시장별 가격일이 역전되면 거부한다. 16:00 KST(07:00 UTC), 미국 정규 세션 17:00~21:00 UTC의 달력으로 테스트했을 때 미국 가격 표지는 AwaitingSession이고 가격일은 전일이다. 이를 USD·원화 환산 표본에서 거부하던 문제가 실제로 재현되어 수정했다. 호출자는 시장별 실제 세션과 직전 세션을 가진 SnapshotCalendar로 생성한 완전 스냅샷을 넘긴다. 지금 D-31에는 간격의 누락 유무를 봉인하는 타입이 없다. 기존 1일·금요일→월요일 3일 간격만 유지하고 평일 공통 휴장 간격 허용을 넓히지 않는다. D-31 후속으로 시장 달력 전체에 대한 연속 관측 증거와 누락된 열린 세션을 구별하는 봉인이 필요하다.

베타는 끝일 기준으로 7달력일씩 역산한다. 앞의 부분 주는 명목 구간에서 제외한다. 각 경계의 직전 7일 안에서 경계일 이하인 가장 가까운 공통 스냅샷을 사용한다. 빈 주의 경계에는 값을 만들지 않고, 인접한 두 경계 모두 관측이 있는 주간 수익률만 센다. 빈 주를 넘어 2주 수익률을 한 주로 합치지 않는다. 52개 미만이면 InsufficientSamples이며 365·366일 열도 52주 값을 낸다. 결과의 start/end/weeks는 실제 채택한 첫·마지막 관측일과 주 수다. 경계 이전 종가를 사용하면 실제 일수는 7일과 다를 수 있다. 포트폴리오와 벤치마크는 같은 날짜 열을 공유한다.

벤치마크는 KOSPI, KOSDAQ, S&P 500 ETF, 혼합을 구별한다. D-37 지표 캔들 타입이 없으므로 D-11 Candle을 받는다. 동일 instrument·currency·adjustment, 확정 일봉, 날짜 유일성을 검사한다. 미국 ETF의 raw 봉은 거부한다. 실제 지수·ETF 식별자의 인증은 공급 어댑터의 책임으로 남긴다. KOSPI/KOSDAQ는 배당 제외, ETF/혼합의 배당 보정은 Unverified로 공개한다. 수정 봉이라는 사실만으로 총수익지수를 주장하지 않는다.

각 스냅샷의 시장별 price_date와 정확히 맞는 봉을 선택한다. HolidayCarry는 D-31이 지정한 직전 가격일을 사용한다. 한쪽 휴장에도 요청한 전체 스냅샷 날짜 열을 유지하며, 교집합만 골라 기간을 줄이거나 임의 보간하지 않는다. 날짜가 없으면 BenchmarkMismatch다. 원화 미국 다리는 그 스냅샷의 유효 Mid를 사용한다. 초과 수익과 베타는 전체 날짜 열과 PerformanceCurrency가 같아야 한다.

혼합은 R-11의 동적 실제 시장 비중을 사용한다. 메인 결정에 따라 국가 비중의 분자는 KRW 주식 평가액, 분모는 전체 주식 평가액의 원화 환산 합계이며 현금은 제외한다. 근거는 R-11 Q6 “현금은 통화 비중에만 넣는다”다. 주식 합계가 0이면 계산 불가다. 공개 mixed는 Performance만 받아 그 안에 정렬·보관된 스냅샷의 비중을 사용한다. 별도 스냅샷 열을 끼울 수 없다. 공개 BenchmarkWeights::StocksExcludingCash 표지로 현금 제외 기준임을 알린다. 이 비중 정의는 사용자 확인 대상이다. 0·1 비중은 허용하고 양쪽 비영 비중은 1e-6 이상이어야 한다.

예제 9의 짧은 열은 산술 기준을 검사한다. 공개 위험 함수는 그 짧은 열로 값을 내지 않는다. MDD는 D-10 범위여서 구현하지 않는다. Config::with_cases(4096)의 독립 유리수·흐름 없는 동일성·분할 불변성·입력 순서·불확정/불완전 거부·KST 날짜 속성 검사가 있다. 공개 API는 외부 소비자 컴파일 검사로 숫자 탈출 경로가 없음을 확인했다.

## 리뷰 수정의 보수적 선택과 사용자 확인 대상

MWR은 원시 현금의 부호 변화가 한 번인 조건을 유지한다. 출금 후 재입금은 실제 유일해가 있어도 거부할 수 있다. 범위를 넓히려면 누적 현금의 부호 변화에 기반한 충분조건으로 유일성을 증명하고 독립 기준과 대조해야 한다. 중간 평가액이 0인 전액 출금·재입금 구간도 전체 수익률 계산 불가를 유지한다. 향후 재투자 시작을 새로운 구간으로 취급하는 연결 정책을 사용자에게 확인해야 한다. 이번에는 누적 현금 조건이나 0 평가 구간 연결을 구현하지 않는다.

리뷰 통합 회귀는 R-11 예제 1을 실제 평가·원장·확정 토큰으로 구성하고 흐름을 두 번째 구간 이후, 평가 시각과 같은 시각에 둔다. TWR 0.058750·MWR 0.031997을 고정한다. 출금 환전과 내부 수익이 함께 있는 사례의 독립 70자리 IRR 기준은 0.010712925907940526878869459387437983399702160933010579684451152618735이며 표시값은 0.010713이다. 정확도 인증은 1.0000000000000000124에서 성공, 1.0000000000000000126에서 실패하는 1일 현금 [-1,+1] 경계를 고정한다.

전액 출금 뒤 재입금의 중간 평가 0을 통합 테스트로 확인했다. 기존에는 수정 디에츠 분모가 재입금 가중치로 양수가 되어 누적 TWR이 나오는 경로가 있었다. 구간 시작 평가액이 0 이하이면 NonPositiveCapital로 닫아 요청한 보수적 정책을 명시적으로 보장한다. 종료 평가액 0인 실제 전액 손실의 TWR은 유지한다.
