## 제출과 보정의 공개 표면

| 타입·함수 | 계약 |
|---|---|
| SignalTaskKey::from_task(&CostEligibleTask) | 원래 EstimateTask 전체의 결정적 동등성 키. 종목의 시장·심볼·내부 식별, 기준가·시각·기간·변동성과 과제 설정을 보존한다. 같은 사실은 같은 키이고 다른 사실은 다르다. 키 필드는 비공개이며 task()는 불변 참조다 |
| SignalSubmission::create(task, calibration_key, ai_probability, evidence, submitted_at) | 한 제출의 과제 키·AI 확률·근거·모델/기간 키·제출 시각을 함께 봉인한다. 과제 생성 이전 제출은 BeforeTask. 공개 접근자로 다섯 사실을 읽는다 |
| calibrate_signal_submission(&Calibration, SignalSubmission) | 제출 자신의 모델/기간 키와 확률만 D-23에 전달하고, 원래 제출과 결과를 SubmittedCalibration에 함께 보존한다 |
| SubmittedCalibration | 직접 생성·역직렬화·필드 변경 경로가 없다. submission()·calibration()만 읽는다. 별도 보정 결과를 끼워 넣지 못한다 |
| SignalEstimate::create(eligible, submitted_calibration, margin) | 과제 키 동등성을 검사하고 D-22 create 뒤 자기 보정 결과 전용 bound_signal_conditions를 호출한다. 공개 buy_condition·sell_condition과 같은 비교 함수를 공유하므로 분리된 보정 결과와 불가능한 오류 분기가 없다. 과제 불일치는 SubmissionMismatch, 기간 불일치는 D-22 HorizonMismatch |
| SignalDecision::assess(estimate, context) | 별도 calibration·매수 금액 인자가 없다. SignalContext에 SignalTiming(now, calendars)을 전달한다 |

키는 내용의 동등성이며 영속 UUID나 실행 인증서가 아니다. E 작업의 외부 task_id·제출 ID를 대체하지 않는다. 보정 결과가 원래 제출 전체를 소유하므로 다른 제출의 확률·근거를 나중에 조립하는 경로가 없다. 같은 내용의 중복 제출 식별·반복 제한은 E·D-25에 남긴다.

## 매수 한도와 후속 경계

Policy의 기존 buy_limit 계산을 새 pub(crate) 자유 함수 signal_buy_limit로 추출했다. 기존 check_buy도 같은 함수를 사용하며 기존 테스트 본문은 바꾸지 않는다. 새 함수는 금액 없이 종목·섹터·현금 최소 비중의 남은 여유 최솟값을 반환한다. 여유가 0 이하이면 차단이다.

BuySignal에는 Unchanged/Reduce가 없고 limit()이 항상 있다. D-25는 이 한도 이하로 수량을 정한 뒤 실제 금액으로 Policy::check_buy를 다시 호출한다. 한 번에 사는 비중·통화별 매수가능금액·30건 전 작은 비중·같은 종목 H 안의 반복 제한은 D-25다. 매도가능수량·미체결·최신 호가는 D-26/O-01이다. SellSignal에는 원래 보유 수량과 observed_at이 함께 있다.

표본 부족에서도 신호는 가능하다. 여유분은 D-22가 강제하며 수량 축소는 D-25다. EligibleBeforeE91도 실제 보정 완료를 뜻하지 않는다. 확률 표시는 별도 자유 함수에서 최근접·중간값 0에서 멀어지는 반올림으로 백분율 소수 첫째 자리를 만든다. 임계값의 방향별 올림/내림을 확률에 전용하지 않는다. 목표·손절 거리는 기존 근사 표시를 사용하며 금액 가격은 D-26 범위다.

## 시각과 미해결

만기는 D-27 schedule의 계산 결과를 반환하는 작은 pub(crate) 자유 함수로 공유한다. H를 달력일이나 초로 외삽하지 않는다. Hours의 정규장 1/4, 거래일 5·40·126, 캘린더 연속성·시장 검사는 모두 D-27과 같다. 만기 등호부터 신호 없음이다.

매도 보유 관측은 과제 생성 시각 이상, 판정 시각 이하, 판정 시각에서 60초 이내여야 한다. 60초 등호를 허용하며 1ns 초과는 막는다. 60초는 확정된 제품 상한이 없는 상황에서 이번 지시대로 고른 보수적 초안이다. design 5.2의 보유 조회 5분 주기는 신선도 보증이 아니므로 상한 근거로 꾸미지 않는다. E는 판정 전에 보유를 갱신하고 이 상한은 사용자 확인 대상으로 남긴다.

원장 진위·종목 관련성·외부 task_id 및 제출 ID의 발급·중복 제어는 위 책임 표대로 미해결 연결 작업이다. SignalContext와 SignalTiming의 Debug는 내용을 가린다. 새 의존성·검사 끄기는 없다. 프로젝트/훅 신뢰의 런타임 적용 자체는 입증하지 못하며 실제 검사와 Git 훅 결과를 증거로 사용한다.

## 검증

리뷰 회귀 테스트를 먼저 새 API로 작성해 컴파일 실패를 확인했다. 기존 D-24의 자체 테스트만 수정했고 master의 기존 테스트 본문은 보존했다. 독립 기준은 생성 입력의 표본 수에서 보수/보정 가능 상태를 직접 계산하며 구현의 operation()을 정답으로 쓰지 않는다. 전체 검사·손 변형·자동 변이 조건과 결과는 최종 보고에 남긴다.

수정 검증에서는 자기 보정 결과의 비교를 내부 경로로 묶고 60초를 TimeSpan 상수로 두어 도달 불가능한 오류 분기를 제거했다. D-22의 기존 공개 불일치 거부 계약과 master 테스트는 유지한다. 표시의 일반 내부 수치 포매터는 범위 초과도 오류로 반환하며 확률 호출부는 검증된 Probability만 그 포매터로 넘긴다.

최종 손 변형은 27개 모두 컴파일 후 실제 테스트 실패(종료 100)로 검출됐다. 심볼만 비교하는 리뷰 생존 변이, 시장만 비교, 원칙 한도·현금 최소 비중, 제출 결합·시각·만기 등호·관측 시각 payload·출처 원장 검사를 포함한다. 복구 후 전용 테스트 13개가 통과했다. 커버리지 대상 559개도 통과하며 위반은 0건이다. 외부 소비자 컴파일은 성공하고 SubmittedCalibration·SignalSubmission·BuySignal 직접 생성과 일반 보정 결과 전달은 거부됐다. 병합한 master 4c9428d에는 H-43이 없어 조건부 자동 변이는 NOT_RUN이며 다른 기준에서 실행했다고 주장하지 않는다.
