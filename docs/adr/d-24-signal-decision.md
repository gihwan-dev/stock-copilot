## 입력과 연결

비용 적격 과제에서 임계값을 만들고 과제·원래 보정 결과·임계값·선택적 Evidence를 하나의 봉인된 SignalEstimate에 보존한다. 별도 과제와 임계값을 조립하는 공개 경로를 만들지 않는다. 판정 시 받은 보정 결과는 D-22 buy_condition·sell_condition으로 비교하여 생성 시 결과와의 불일치를 거부한다. 일반 Probability는 판정 입력이 아니다. D-23 두 변형을 분기해서 운용 상태와 표시 확률을 읽는다.

## 판정 순서

문서는 제외·출처의 선후 관계까지 정하지 않는다. 아래는 신호가 덜 나오는 쪽의 결정적 초안이다. 앞 행에서 결론이 나면 뒤 행은 실행하지 않는다.

## 출처의 정의

Evidence 자체는 0개를 허용하지 않으므로 Option::None이 근거 0개다. Web은 수집 항목의 Web 출처와 URL, News는 뉴스 출처와 URL, Disclosure는 공시 키와 URL을 모두 대조한다. 수집 항목만 있고 공시 키가 없으면 공시 출처를 증명하지 못한다. Tool은 별도의 호출 참조 원장과 대조하지만 실질 출처 개수에는 넣지 않는다. 하나 이상의 실질 출처와 모든 참조의 원장 일치를 요구한다. 웹만 있는 추정은 출처가 있으므로 신호를 허용하고 E-06에서 외부 출처 경고를 붙인다. D-16의 논거 변경 보류 규칙을 추정 신호에 전용하지 않는다.

원장 입력의 진위, 추정과 근거의 의미적 관련성, 과제·제출 모델의 일치는 E-02·J-02·저장 어댑터가 보장해야 한다. domain 생성자는 외부 사실을 인증하지 않는다.

## 후속 경계와 미해결

- 표본 부족에서도 신호는 가능하다. D-22가 매수 max(설정,15%p), 매도 15%p를 강제한다. 운용 상태를 결과에 남기고 작은 매수 비중은 D-25가 강제한다. EligibleBeforeE91도 실제 보정 완료를 뜻하지 않는다.
- D-25는 봉인된 매수 신호와 원칙 축소 한도를 받아 수량·통화별 매수가능금액·반복 제한을 처리한다. D-26/O-01은 매도가능수량·미체결·최신 호가를 검사한다. D-24의 보유 수량은 주문 가능 수량이 아니다.
- RaisedSignal에는 매수·매도 payload만 있다. SignalDecision의 신호 없음에서는 이를 꺼낼 수 없다. Proposal 생성·주문·승인 경로는 추가하지 않는다. D-18/A-13은 판정 결과로 SignalRaised·SignalCleared를 기록하고 이벤트에는 ID와 종류만 담는다.
- E 작업은 과제의 목표·손절·기간과 확률·임계값 표시를 사용한다. 목표·손절은 근사 거리의 표시이며 금액 가격이 아니다. design/README.md 예문의 목표가·손절가 표시는 D-26의 가격 정책이 연결된 뒤 완성한다.
- 평가 불가가 하나라도 있는 스냅샷과 보유 조회 실패에서 매도를 막는 선택, 미분류 종목의 매도도 막는 선택은 보수적 초안이며 사용자 확인 대상이다. 완전한 보유 응답을 빈 성공으로 꾸미지 않도록 어댑터가 실패를 명시해야 한다.
- 신호의 최신성·유효 기간·계좌 및 저장 원장 식별, 새 추정으로 교체는 application/E 작업의 책임이다. 이 타입은 정적 사실의 판정이다.
- 새 의존성·기존 테스트 변경·검사 끄기는 없다. 프로젝트/훅 신뢰의 런타임 적용은 입증하지 못했으며 실제 검사와 Git 훅 결과로 검증한다.

## 검증

완료 기준에서 먼저 작성한 테스트는 SignalDecision 등 미정의 타입으로 컴파일 실패했다. 구현 뒤 전용 테스트 10개가 통과했다. 독립 기준 대조, 양쪽 조건의 배타성 및 표시 사실, 판정 불가 안전성은 각각 Config::with_cases(4096)이다. 독립 기준은 비용 0의 적격 과제에서 원래 기준 확률과 정수 퍼센트·여유분을 사용하며 D-22의 조건 함수나 판정 구현을 정답으로 쓰지 않는다. 비용 공식 전체의 독립 검증은 D-22 기존 테스트의 범위다.

손 변형 20개는 제외·출처 검사 제거, 원장 회원 검사 제거, 웹·뉴스 종류 및 공시 키·URL 대조 제거, 도구를 출처로 세기, 미지 분류 통과, 불완전 보유 통과, 매수·매도 분기 제거, 양수 수량·동일 종목 검사 제거, 원칙 차단·축소 제거, 양쪽 보정 결과 대조 제거, 도구 원장 검사 제거, 매수·매도 payload 추출 제거다. 모두 컴파일 성공 뒤 nextest의 실제 테스트 실패(종료 100)로 검출됐다. 초기 도구 검사 제거 생존은 정상 웹과 원장에 없는 도구가 섞인 회귀 사례를 추가해 해결했다. 한쪽 확률 대조만 제거하면 다른 쪽 대조가 남아 불일치를 거부하므로 양쪽 대조 제거를 유효 변형으로 검증했다. 자동 변이 검사는 실행하지 않았다.

외부 rustc 소비자는 정상 신호 소비가 성공하며 BuySignal 필드 직접 생성은 비공개 필드 오류, 일반 Probability 판정 입력은 타입 불일치로 거부된다. 이는 일회성 외부 계약 검증이며 영속 compile-fail 회귀는 후속 하네스 범위다. 출처 없는 결과에서 RaisedSignal을 꺼내지 못함은 런타임 테스트로도 고정한다.

테스트 파일을 별도 형제 모듈에 뒀을 때 coverage:unmeasured-file이 발생해 새 signal_decision.rs 안의 cfg(test) 모듈로 합쳤다. master의 기존 파일에는 lib.rs 끝의 선언·재내보내기만 추가했으며 기존 impl과 테스트 본문은 바꾸지 않았다. 새 ADR 등록에 필요한 config·해시는 저장소의 쓰기 모드 스크립트로 다시 생성했다. 최종 전체 검사 결과와 SHA는 구현 보고에 남긴다.
