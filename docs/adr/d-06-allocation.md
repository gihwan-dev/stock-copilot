# D-06 ADR 초안: 평가 비중과 표시 배분

- 상태: 초안
- 기준: af70b46fc6c62a0d1a7b036c9977b3d2f3d47366
- 작업: D-06

## 결정과 근거

| 규칙 | 근거 문장과 적용 |
|---|---|
| 종목·섹터·국가는 보유 평가액 합을 분모로, 통화만 매수가능금액을 포함 | R-11 Q6 “현금은 통화 비중에만 넣는다”. 각 결과의 AllocationBasis에 분모 범위를 보존한다. 현금은 open-issues I-05에 따라 매수가능금액이며 예수금으로 간주하지 않는다. |
| 불완전 입력은 비중 없음 | ADR 0038 “불완전 값에 완전 표시를 붙이지 않는다”. 원화 총평가가 불완전하거나 한 종목이라도 환산 실패면 모든 비중이 Incomplete다. 토스 요약으로 전체 Total이 Complete여도 종목 환산 성공을 별도로 요구한다. 현금 오류는 통화 비중만 막는다. |
| D-05 종목별 선택 평가액을 원화 Mid로 환산 | ADR 0038의 토스 선택값·출처와 ADR 0031의 “원화 합산 기본” Mid. D-05가 사용한 환율만 재사용한다. 새 시세·환율을 받지 않는다. 원본 PortfolioValuation 전체를 읽기 접근자로 보존한다. |
| 계산 비중과 표시 비중 분리 | ADR 0029 “근사 몫을 더하지 않는다”. AllocationWeight는 최대 정밀도 RatioQuotient와 Approximate 정확도다. 정확한 십진 몫이라도 평가 자체의 근사성을 없애지 않는다. AllocationDisplay는 0.01% 단위 정수만 읽을 수 있으며 Ratio·Money 변환과 산술 API가 없다. |
| 표시 0.01%, 총 10,000단위 | R-11 Q6 “표시 단위(예: 0.01%)”를 초안 기본으로 채택. 금액 정수 계수를 공통 소수 28자리로 맞추고 10,000배 분자의 내림 몫과 나머지를 구한다. 계수 최대 96비트 × 10,000 × 10^28은 204비트 미만이고 기존 384비트 안에 들어간다. 제한된 스케일 확대는 이 증명으로 실패 경로 없이 처리한다. 0~10,000의 이진 탐색과 정수 차감으로 몫·나머지를 얻으므로 큰 금액과 소수 28자리에도 중간 Decimal 곱셈이 없다. |
| 잔여 내림차순, 동률은 그룹 키 오름차순 | ADR 0029 “안정적인 동률 순서를 인자로”. 키를 받는 공통 배분 함수에 종목은 Market→Symbol(대소문자 구분), 섹터는 Classified의 SectorId 사전순→Unclassified, 국가는 KR→US, 통화는 KRW→USD 순서를 전달한다. 0인 그룹에는 잔여가 배분되지 않는다. |
| 섹터 ID 정규화는 항등, 대소문자 구분 | ADR 0039의 SectorId는 불투명 식별자이며 Exclusions는 동일 ID 비교다. trim·대소문자 변환·분류 체계 자동 변환을 하지 않는다. D-20 코드와 기존 테스트 변경 없이 같은 SectorId를 대응표와 제외에 함께 사용한다. |
| 미지정은 별도 Unclassified | R-11 Q7 “미분류를 더한다”. 임의 SectorId 문자열을 예약하지 않아 실제 ID와 충돌하지 않는다. 한 종목당 대응 하나이며 중복 대응은 같은 섹터라도 DuplicateAssignment다. ETF 분해·복수 소속 합산은 하지 않는다. |
| 국가·통화는 닫힌 경계 | R-11 Q6 “통화는 거래 통화, 국가는 상장 시장 기준”. D-05의 봉인된 ResolvedOrderInstrument와 Holding의 통화·시장 정합을 사용한다. 통화 키는 Currency를 전부 매핑한 AllocationCurrency다. |
| 빈 목록·합계 0은 비중 없음 | 0으로 나눌 수 없으므로 ZeroTotal. 현금만 양수면 통화만 유효하다. 음수 입력은 거부하며 정확한 합산이 불가능하면 기존 Overflow·PrecisionLoss를 보존한다. |

그룹 합산은 키·금액의 고정 순서로 수행한다. 원본의 순서가 합산 경계 판정이나 잔여 동률을 바꾸지 않는다. 공개 생성 경로는 평가 결과를 받는 Allocation::new뿐이며 그룹 결과·행·표시·계산 비중의 필드는 비공개다. 오류에는 입력값이 없다. 새 의존성과 검사 끄기는 없다.

## 미해결과 후속

- R-11의 0.01%는 확정 표시 사양이 아니라 예시다. 초안 기본값의 사용자·메인 확정이 필요하다.
- R-11의 일반식 “원화 환산 총자산”과 “현금은 통화 비중에만” 사이의 분모 의미를 위처럼 해석했다. 보유 비중은 현금에 의해 희석되지 않는 보수적 값이다. D-12·D-25는 AllocationBasis를 확인해야 하며 총자산 대비 주문 상한에 그대로 대입하면 안 된다. 총자산 대비 정책 비중 API의 확정은 후속 판단이 필요하다.
- 토스 전체 요약과 종목 합이 다를 때 구성비는 종목별 선택 평가액 합으로 계산한다. 이를 토스 전체 요약 대비 비중으로 부르지 않는다. 원본의 출처·대조·시각은 Allocation::valuation에서 읽는다.
- SectorAssignment는 대응만 제공한다. 분류 체계·출처·사용자 확인·시점 저장은 저장소/분류 수집 작업에서 별도로 맡는다. 섹터 ID 대소문자를 같게 보는 외부 제공자는 어댑터에서 일관된 ID를 공급해야 한다.
- 프로젝트 설정의 hooks=true와 상위 프로젝트 신뢰 설정을 확인했다. 현재 T3 세션에 Codex 훅 신뢰가 적용되었는지는 입증하지 못하므로 직접 실행한 검사와 Git 훅 결과를 근거로 삼는다.

## 검증

표시 배분은 Config::with_cases(4096)의 독립 u128 분수 기준과 순열 대조로 검증한다. 합 10,000단위, 참값과의 차 1단위 미만, 키별 배분의 일치 및 최대 정밀도 몫의 근사 표지를 검사한다. 고정 테스트는 3등분 동률, R-11 원화·달러 59.26/40.74%, 한 종목, 0, 음수 거부, MAX, 최소 양수, 서로 다른 스케일, 4,096개 극소 비중, 중복 섹터, 대소문자 제외 일치, 평가·현금·요약 실패 경계를 포함한다. domain 파일별 줄·영역 커버리지 100%를 직접 검사한다.

표시 배분의 이진 탐색은 배타적 상한과 하한의 차가 1이 될 때 끝난다. 종료 비교를 `!= 1`로 쓰고 정수 `midpoint`를 사용한다. 엄격한 부등호와 비트 이동을 사용하던 최초 구현에서 두 변이가 무한 반복으로 시간 초과됐고, 해당 연산 경로를 제거했다. 수정 후 경계·독립 정수 기준 4,096회 테스트를 다시 확인한다. 단일 전체 변이 실행은 최초 커밋을 대상으로 하므로 그 결과와 수정 뒤의 일반 검증은 별도 증거다.
