# D-06 ADR 초안: 총자산 비중과 보유 구성비의 타입 경계

- 상태: 초안, 적대적 리뷰 수정
- 기준: af70b46fc6c62a0d1a7b036c9977b3d2f3d47366
- 근거: R-11 Q6·Q7, ADR 0029·0031·0038·0039, D-06 리뷰 후 메인 지시

## 두 분모와 공개 API

| 목적 | 공개 결과와 값 타입 | 분모·현금 | 허용하는 사용 |
|---|---|---|---|
| 총자산 대비 비중 | AssetAllocation<K>, AssetWeight | D-05 원화 환산 총자산. 각 축에 현금 항목을 포함 | D-12·D-25는 Allocation::assets().instruments()/sectors()의 행에서 AssetWeight::cmp_profile_weight(&ProfileWeight)를 호출한다. 주의 기준도 같은 함수로 비교한다 |
| 보유 구성비 | HoldingsComposition<K>, CompositionWeight | 보유 종목 선택 평가액 합. 모든 축에서 현금을 제외 | Allocation::holdings()로 읽어 표시와 같은 구성비 사이 비교만 한다. ProfileWeight 상한 비교 함수는 없다 |

R-11 Q6의 “w_i = 원화 환산 평가액_i / 원화 환산 총자산”을 정책 비중에 그대로 적용한다. “현금은 통화 비중에만 넣는다”는 종전 표시 해석과 섞지 않고 두 결과를 다른 타입으로 제공한다. 런타임 AllocationBasis는 없앴다. AssetInstrument는 종목/통화별 현금, AssetCountry는 상장 시장/현금이고 섹터 축에도 현금 버킷이 있다. 통화 축은 거래 통화별 보유와 해당 통화 현금을 합친다. 현금은 I-05의 매수가능금액이며 예수금으로 간주하지 않는다.

두 값 타입은 봉인된 근사 비중이다. 유한 십진 몫이어도 평가에서 나온 값이므로 항상 Approximate다. 공개 RatioQuotient·Ratio·Decimal 접근자, From/Deref, 금액·수량 산술, 역직렬화 생성자는 없다. 같은 분모의 값끼리 compare만 제공하고 AssetWeight에만 cmp_profile_weight를 둔다. 이 비교는 ADR 0029의 최대 정밀도 근사 몫 수치를 비교하며 참값의 엄밀한 동등성을 인증하지 않는다. 표시값은 별도 AllocationDisplay이며 산술 타입으로 변환하지 않는다. 각 결과·행·값의 필드는 비공개이고 오류에 입력 금액은 없다.

## 완전성과 경계

- ADR 0038의 종목별 선택 평가와 실제 사용한 Mid 환율만 사용한다. 원본 평가·출처·시각·환율은 Allocation::valuation에서 보존한다. 어떤 종목이라도 평가·환산이 실패하면 두 분모 모두 Incomplete다. 전체 요약이 완전하다는 이유로 빠진 종목을 숨기지 않는다.
- 총자산 비중은 현금도 전부 평가 가능해야 한다. 음수 현금은 NegativeCash(Currency)로 해당 총자산 결과들을 거부한다. 현금이 필요 없는 보유 구성비는 계속 제공한다. 현금 환산 실패는 MissingFx/Conversion, 불완전 자산 합계는 Incomplete다.
- 종목 선택 평가액과 현금을 더한 합이 D-05 총자산과 다르면 TotalMismatch다. 토스 요약과 구성 종목의 차이를 임의로 현금이나 미분류로 채우지 않는다. 보유 구성비는 별도 분모이므로 제공할 수 있다.
- 현금만 양수면 총자산의 네 축은 유효하고 보유 구성비는 ZeroTotal이다. 평가액 0 종목은 0 비중으로 남는다. 현금도 보유도 모두 0이면 두 결과 모두 ZeroTotal이다. 음수 종목 값은 거부하고 Overflow·PrecisionLoss를 보존한다.

## 섹터 대응

AllocationSector의 닫힌 변형은 Classified(SectorId), EtfFund, Cash, Unclassified다. R-11 Q7의 “ETF·펀드(분해 전), 현금, 미분류를 더한다”를 반영한다. SectorAssignment는 종목별 InstrumentClassification(Sector/EtfFund/Unclassified)을 받고, 분류가 없는 종목은 미분류다. 현금은 실제 현금 입력에서만 만든다. ETF·펀드 종목 유형의 정본 입력 책임은 T-09 종목 마스터다. ETF를 실제 구성 종목으로 분해하지 않는다.

SectorAssignments::try_new가 대응 목록을 만들 때 중복 종목을 거부한다. 같은 섹터인 중복과 보유하지 않은 종목의 중복도 이 경계에서 거부한다. Allocation은 이미 검증된 목록만 받아 중복 검사를 반복하지 않는다. SectorId는 D-20과 같은 불투명 ID이며 대소문자를 구분하는 항등 정규화를 유지한다. 분류 체계 사이 자동 변환은 하지 않는다.

scheme/source/as_of/사용자 확인 메타데이터는 이번 순수 비중 API에 임의 기본값으로 만들지 않는다. T-09가 제공자 분류 체계·원본 출처·조회 시각을 공급하고 S-10이 사용자 지정 대응의 버전·출처·확인 상태를 보존하도록 인계한다. 이 분류 메타데이터 저장 계약은 후속에 남는다.

## 표시와 검증

- 표시 단위는 기존 0.01%, 총 10,000단위를 유지한다. 정수 최대 잔여법을 두 결과 각각에 적용한다. 총자산 쪽은 현금까지 포함해 100.00%, 보유 구성비는 현금 없이 100.00%다.
- AllocationDisplay.range의 Zero/BelowUnit/AtLeastUnit은 참값 범위다. 양수이지만 0.01% 미만이면 잔여 배분으로 표시 단위를 받더라도 BelowUnit이다. 표시 계층은 이 표지로 “<0.01%”를 만들 수 있고 units의 합은 여전히 정확히 10,000이다.
- 동률은 키 오름차순이다. 종목은 시장·심볼, 자산 종목의 현금은 종목 뒤 통화순, 섹터는 분류 ID·ETF·현금·미분류 순, 국가는 시장·현금 순, 통화는 KRW·USD 순이다. 입력 순서와 무관하다.
- ADR 0029의 정수 경로를 재사용한다. 96비트 계수 × 10,000 × 10^28은 204비트 미만이라 기존 384비트 안에 들어간다. Decimal 곱·나눗셈을 새 경로에 추가하지 않는다. 이진 탐색은 차가 1일 때 끝나고 정수 midpoint를 사용한다.
- 공개 Allocation::new 속성 테스트는 Config::with_cases(4096), 0 평가액·혼합 스케일·MAX·최소 양수·임의 순열을 포함한다. 네 축과 두 분모의 표시 합·독립 정수 기준 배분·1단위 미만 오차를 확인한다. 내부 나머지도 47/29016 고정 반례와 독립 u128 기준 4,096회로 대조한다.
- 외부 crate 컴파일 실험으로 근사 값의 Ratio·Decimal·Money·Quantity 전환, 구성비의 상한 비교와 두 결과 타입의 혼용이 실패하는지 확인한다. 이번 회차 마지막 검증은 메인 지시에 따라 crate 전체 변이 대신 두 파일의 분기를 제거하는 손 변형 12개 이상을 사용한다.

0.01% 표시 단위는 메인의 사용자 확인 목록에서 관리한다. 새 의존성·검사 끄기는 없다. Codex 세션의 훅 신뢰 적용은 확정하지 못했으므로 직접 검사와 Git 훅의 전체 검사 결과를 증거로 사용한다.
