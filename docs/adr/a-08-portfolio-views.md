# A-08 포트폴리오와 비중 조회

- 상태: 초안

## 결정

저장된 최신 SyncRecord를 계좌별로 읽고 Complete·Partial·Failed·AccessBlocked와 자료 없음(Missing)을 구분한다. 저장소 오류는 원 오류로 반환한다. domain의 Portfolio::evaluate와 Allocation::new만 호출한다. 통화별 현금은 BuyingPower이고 총자산은 domain의 Total<AssetEstimate>라서 불완전 여부와 근사를 유지한다. 보유·요약·현금의 원래 수집 시각을 보존한다.

저장 시각에 유효한 USD/KRW Mid를 저장소에서 조회한다. 조회 결과 자체와 실제 사용한 환율은 구분한다. 쌍·종류·유효 구간이 맞지 않는 환율은 계산에 쓰지 않으며 원 조회 결과는 exchange_rate_lookup에 남긴다. 실제 사용한 종류·시각·출처는 domain 환산 값의 분해 결과에 남는다. 환율 저장소 오류가 나도 통화별 자료를 숨기지 않는다. 재시도·실제 API 호출·쓰기·이벤트 발행은 없다.

현재 저장 포트에는 섹터 대응 조회 메서드가 없으므로 임의 포트나 분류 사실을 만들지 않는다. 빈 SectorAssignments를 domain에 넘겨 보유 종목은 미분류로 계산한다. 기존 domain의 미분류 정책을 그대로 사용한다.

직전 성공 자료와 최신 실패를 함께 보여 주는 정책은 미정이고, 현재 포트에는 성공 기록 선택·이력 조회가 없다. 최신 실패를 숨기거나 과거 성공을 현재 성공으로 재사용하지 않는다. U-09/U-10에서 병행 표시 필요 여부와 선행 저장 포트 계약을 메인에게 인계하며, 그 결정까지 직전 성공 값의 제공은 정의 대기다.

U-09/U-10은 현재 미분류가 저장 분류 미적용의 결과이고 분류 완료를 뜻하지 않음을 소비 계약에 유지한다. 보유 구성비의 미분류와 총자산 섹터 축의 현금은 별개다. 실제 사용 환율의 표시는 domain 환산 값의 목록만 사용하고, exchange_rate_lookup은 조회 증거와 원 오류 확인에 쓴다. 환율 저장소 오류를 중첩 결과에서 읽어 A-19의 기존 분류에 연결하는 책임도 함께 인계한다. 내부 정의 대기 이름을 사용자 화면에 그대로 내보내지 않는다.

장중 시세의 5분 기준(ACC-4)은 있지만 저장 포트폴리오 전체의 신선도 판정 함수는 없다. 지시문에 따라 새 domain 함수와 포트를 정의하지 않는다. 이 때문에 오래됨을 자동 판정하는 기준은 빠져 있다. 사용자 확인 절차나 설정은 추가하지 않는다.

## 검증

시작 의존성 설치와 Git 훅 설치 성공. 프로젝트 설정 hooks=true는 확인했으나 프로젝트 신뢰와 훅 정의 신뢰 및 이번 세션 런타임 적용은 확인 불가다. 기존 테스트·의존성·가짜·검사 끄기 변경 없음. 기존 테스트 변경 승인 건수 0.

## 구현 커밋 검증

전체 속성4,096회에서 workspace1,732개와 커버리지 계측1,062개가 모두 통과했고 커버리지·test-diff·hooks-installed도 위반 없음이다. 기존 테스트 변경 승인0건, 새 검사 끄기0건, 새 의존성과 새 포트0개다. 최초 수동 실행의 기본256회 커버리지 누락5건은 전체 횟수 재실행으로 해소했다.

정상 훅 첫 실행은 새 ADR 보호 등록 생성물과 환경 오류가 함께 나와 예외를 쓰지 않았다. 생성 스크립트로 등록한 뒤 재실행은 session-r1의 R4 한 건만 Xcode 라이선스 미동의로 실패했다. 사용자의 환경 안내2에 따라 나머지 전체 검사 본문과 check-ts의 나머지 세 검사를 직접 통과한 뒤 해당 커밋에만 환경 예외를 사용한다. 테스트·훅·검사 규칙은 수정하지 않는다.

## 1차 리뷰와 비판 반영

Opus의 중요2·사소4 지적을 새 Codex가 독립 검증해 타당1·부분 타당3·기각2로 평가했다. 최신 실패 반환과 분류 없는 비중은 실제 포트 및 승인된 정의 대기 범위와 일치하므로 현재 중요 결함으로 보지 않는다. 전수 match를 사용해 새 StoredView 변형이 Missing으로 흡수되지 않게 했다. 조회 증거 접근자는 exchange_rate_lookup으로 명확히 했고, 실제 저장 후 실패 조회·섹터와 현금 분리·비중의 신선도 표지 전달·토스 보고 요약의 정본 보존을 통합 테스트로 추가했다. 신선도와 직전 성공 병행 표시 정책은 발명하지 않고 실제 수신 화면 작업과 메인에게 인계했다.

구현 담당이 수정본 별도 mktemp 복사본에서 StoredView에 임시 Stale 변형을 추가하자 전수 match가 E0004로 컴파일을 거부했다. 외부 crate의 RecordedView 필드 변경과 구조체 리터럴 생성도 각각 E0616/E0451로 거부됐다. 이 두 실험은 독립 리뷰어의 NOT_RUN을 소급해 통과로 바꾸는 증거가 아니다.
