## 스키마 대응

국내·해외는 동일한 Transaction 스키마를 쓴다. 모든 필드는 required이며 아래의 선택 값만 null을 허용한다. 거래 ID, 주문 ID, 원거래 ID가 전혀 없다. 종목 ISIN은 거래 식별자가 아니다. 같은 내용의 행이 여러 개 올 수 있으므로 모든 필드의 도메인 값 동등성과 개수를 함께 비교한다. 숫자의 1과 1.0은 같다. 원본 JSON의 철자·스케일은 S-03 어댑터가 별도로 보존한다.

| 토스 필드 | 도메인 표현 | 국내·해외 의미와 null |
|---|---|---|
| transactionType | TransactionKind | 아래 11개 및 Unknown |
| marketCountry | Market | KR/US, 현금·환전은 통화에 따라 시장 결정 |
| currency | Currency | KRW/USD, 모든 금액의 통화 |
| symbol | Option<Symbol> | 주식·옵션 심볼. 채권·현금·확인 불가 주식은 null. 옵션 심볼을 주식 API에 전달하지 않는다 |
| assetClass | Option<AssetClass> | STOCK/OPTION/BOND. 현금은 null. Stock·Option·Bond 및 봉인된 Unknown(원문 64바이트 상한) |
| isinCode | Option<IsinCode> | 거래 당시 주식·채권 ISIN. 옵션·현금은 null. 실제 체크디지트 검증은 하지 않는다 |
| quantity | Option<Quantity> | 매매·증권 입출고. 나머지 null. 옵션 계약 수·채권 개수 |

| amount | Option<Money> | 거래 총액, 증권 입출고 null. 수량×단가로 재계산 금지 |
| commission | Money | 항상 제공, 없으면 0 |
| tax | Money | 항상 제공, 없으면 0. 채권 이자 원화 세금 별도 WITHDRAWAL 가능 |
| netAmount | Option<Money> | 정산 금액, 증권 입출고 null. 미결제는 임시 계산값, 예수금 변화와 다를 수 있음 |
| exchangeRate | Option<Ratio> | 1 USD당 KRW 비율. 관측값과 부재를 보존하며 미결제 환율은 이상 조합으로 알림 |

| settled | Settlement | false=Pending, true=Settled. 시각과 독립 |
| transactionTime | Option<Timestamp> | 처리·취소 시각. 스키마가 허용하는 null·미결제 시각을 독립 보존 |
| isCancellation | Cancellation | false=Regular, true=Cancelled |

스펙 금액 문자열 maxLength는 30이며 전송·파싱 어댑터가 검사한다. 도메인은 기존 정확 십진 타입을 쓴다. 금액 음수와 통화 불일치를 거부하고 절삭하지 않는다. Code와 IsinCode는 복제 전 1~64 ASCII 표시 바이트로 제한한다. 이것은 공식 ISIN 문법이 아닌 원문 보존용 내부 상한이다. 새로운 의존성은 없다. FxRate 병렬 작업에 의존하지 않도록 환율은 단위가 고정된 Ratio로 보존하며 환산은 하지 않는다.

| SECURITIES_TRANSFER_OUT | SecuritiesTransferOut |

UnknownTransactionCode는 비공개 필드이며 생성자가 없다. TransactionKind::new만 모르는 코드 분기에서 만든다. 알려진 코드를 Unknown에 넣는 공개 경로가 없다(ADR 0022 방식).

## 완전 응답과 조회 범위

`reconcile`은 행 목록과 창을 직접 받지 않는다. `CompleteTransactionResponse::after_last_page_without_quarantine(account, window, filter, rows, CompletionAttestation::AllPagesAndAllMatchingPendingReceived)`로 봉인한 응답만 받는다. 계좌, 닫힌 결제일 창, 전체/일부 거래 종류, 전체 페이지와 해당 종류의 전체 미결제 수신 확인을 포함한다. 확인 인자가 빠진 생성자 호출은 컴파일되지 않는다. 복원·Default·다른 공개 생성 경로는 없다. 일부 필터는 1~64개 종류를 받아 정렬·중복 제거한다. 응답에 필터 밖 종류가 있으면 오류다.

이 확인은 어댑터의 명시적 증언이며 네트워크 사실을 도메인이 증명하는 것은 아니다. T-06은 hasNext=false인 마지막 페이지까지 받고, 계좌·필터·커서가 일관되는지 확인해야 한다. limit보다 적거나 빈 페이지를 종료로 간주하지 않는다. 커서 오류·중단·파싱 실패·격리 행이 있으면 이 타입을 만들지 않는다. 어댑터가 거짓 확인을 제공하는 것은 타입이 탐지하지 못한다.

`Currency`는 KRW/USD로 유지한다. 미지 통화 행은 T-06에서 원문을 격리·보존하고 사용자에게 알린다. 그 응답에는 완전 확인을 부여하지 않고 사라짐 대조 자체를 호출하지 않는다. 미지 통화를 KRW/USD로 치환하거나 행만 빼고 완전 응답으로 만들면 안 된다. T-06의 녹화 계약 테스트와 A-07의 실패 경로로 넘긴다. 이번 변경은 해당 어댑터를 구현하지 않는다.

결제 행만 조회 창을 적용한다. API의 to=오늘 조회는 예상 결제일이 미래인 미결제를 누락할 수 있으므로 그 조회의 마지막 페이지만으로 위 확인을 제공할 수 없다. T-06은 별도로 상한 없는 미결제 조회 등으로 조회 종류 전체의 최신 미결제 집합을 확보해 합성해야 한다. 미결제는 창과 무관하게 조회한 종류 전체를 교체한다. 부분 필터라면 조회하지 않은 종류의 미결제만 보존한다. 전체 필터에서는 모든 미결제를 통째 교체한다. 예상 결제일이 오래전이거나 미래여도 임시 행을 보존할 수 있다.

커서 페이징은 서버 스냅샷이 아니다. 페이지 사이 결제가 발생하면 같은 거래가 임시·결제 양쪽에 보이거나 결제 행이 중복·누락될 수 있다. 완전 확인은 페이지 수신 완료이지 일관된 시점의 보장이 아니다. 중복 결제 행을 임의로 하나로 줄이지 않고 멀티셋 그대로 보존한다. 미결제와 결제를 합산하는 접근자는 제공하지 않는다. A-07의 하루 1회 전체 기간 검사는 저장 값과 다시 받은 멀티셋이 다른 구간을 찾아 경고하는 대조이며, 주문 체결과의 확정 연결이나 손익 정답 증명은 아니다. 응답 상한을 넘는 전체 이력은 완결된 날짜 구간 단위로 나누어 검사해야 한다.

## 대조와 계산 규칙

| 상황 | 결과 |
|---|---|
| 계좌 불일치·마지막 동기화보다 이른 시각 | 오류, 원본 상태 보존 |
| 활성 결제 n행 / 응답 m행 | min(n,m) 유지, 부족분 추가, 초과분 사라짐 표시 |
| 일부 종류만 조회 | 창과 종류가 모두 해당하는 활성 결제 행에 대해서만 사라짐 판정 |
| 창 밖·필터 밖·이미 사라진 이력 | 그대로 보존 |
| 재등장 | 과거 사라짐을 유지하고 새 관측 추가 |
| 미결제→결제 | 해당 종류 임시 집합 전체 교체, 새 결제 행만 영구 집합에 추가. 추정 연결 없음 |
| 국내 취소 | 원래 종류·원문 보존. 취소 행의 계산 효과는 항상 NoEffect |
| 취소 후보가 창 밖에 활성으로 남음 | 원 행을 자동 제거하지 않고 UnconfirmedCancellation과 후보 수 반환 |
| 대량 사라짐 | 사라짐을 적용하되 MassDisappearance 경고와 개수 반환 |
| 같은 응답·같은 동기화 시각 반복 | 상태 동일. 이후 시각 반복은 마지막 동기화 시각만 갱신 |
| 빈 응답·빈 상태 | 마지막 동기화 시각도 기록. 1000→3000→2000은 마지막 단계 거부 |

대량 사라짐은 조회 범위 안 활성 결제 행을 분모로 하여, 20행 이상이 사라지거나 5행 이상이면서 50% 이상 사라질 때다. I-06의 서버 멀티셋 반영과 R-01의 다르면 경고를 따라 적용+경고를 선택했다. 공식 API 기준이 아닌 내부 잠정 기준이며 사용자 설정을 추가하지 않는다. 5/10과 20/1000은 경고, 4/4·5/11·19/1000은 경고 없음이다. 완전하다고 잘못 증언한 빈 응답의 50행 사라짐은 적용되지만 반드시 경고를 반환한다. 경고 표시 책임은 A-07·U-11에 있다.

`history_rows()`는 모든 관측 이력, `active_settled_rows()`는 사라지지 않은 결제 행, `active_settled_for_calculation()`은 활성 결제 중 계산 효과가 있는 행만 제공한다. 계산용 접근자에는 미결제·사라진 행·취소 행이 들어가지 않는다. 계산 효과의 SettledTransaction은 원가·외부 흐름 분류를 완료했다는 뜻이 아니며 후속 D-28·D-30이 종류·상품·미확인 취소를 확인해야 한다.

R-11의 원거래와 취소 금액을 적용하지 않는다는 의미는 계산에 적용한다. 확정 I-06에 따라 원본 이력은 물리 삭제하지 않는다. 원거래는 완전한 조회 범위에서 빠졌을 때 사라짐 표시로 계산 대상에서 제외하고, 취소 행 자체도 NoEffect로 제외한다. 취소만 창 안에 있고 원거래가 창 밖이면 원거래 효과는 아직 미확정이다. 비교 후보 키는 종류·시장·통화·종목·상품·ISIN·수량·amount이며 처리 시각·결제일·수수료·세금·환율은 제외한다. 동일 거래임을 증명하는 키가 아니므로 자동 상계·삭제하지 않는다. 전체 검사나 사용자가 확인해야 한다.

거래 전용 TransactionPrice는 0 이상 Money다. 주문 Price의 양수 정책은 바꾸지 않는다. 결제 상태와 처리 시각은 독립이며 미국 취소, 시각 없는 결제, 시각 있는 미결제, 미결제 환율·비매매 종류도 보존한다. `anomalies()`는 알려진 의미와 다른 조합을 닫힌 열거형으로 제공한다. 상품별 필수 필드·ISIN 체크디지트는 이 타입의 보존 경계에서 강제하지 않는다. 음수 금액과 한 행 안 금액 통화 불일치는 계속 거부한다.

## 상한, 메모리와 복잡도

- 한 응답과 현재 미결제 집합: 각각 4096행. 필터 목록: 입력 64개. 이상 조합 목록: 코드상 최대 4개. 미확인 취소 목록: 입력 취소 행 수 이하.
- 영구 이력: 1,000,000행. 사라진 행도 보존하되 응답 상한과 분리한다. 매일 100건을 기록해도 약 27.4년, 10건이면 약 274년이다. 초과는 TooMuchHistory이며 삭제·축약하지 않는다.
- 현재 macOS arm64 빌드의 size_of: Transaction 288바이트, StoredTransaction 320바이트, RowChange 328바이트. 100만 이력의 고정 슬롯은 320,000,000바이트(약 305.2MiB)다. 한 행의 동적 문자열 최댓값은 종류 64 + 시장 32 + 종목 32 + 상품 64 + ISIN 64 = 256바이트이므로 내용까지 약 576MB이며 할당기 부가 비용은 별도다. 원본+순수 함수의 결과 복사+최악의 행별 변화 목록을 동시에 유지하면 내용 기준 약 1.73GB까지 늘 수 있다. 실제 알려진 코드와 빈 필드는 이보다 작다. 성능·메모리 실측을 통과 기준으로 고정하지 않는다.
- H=전체 이력, R=응답(4096 이하), W=창·필터 안 활성 이력, C=응답 취소 종류 키 수다. 응답만 BTreeMap으로 정렬·묶는다. 일반 대조는 O(H + R log R + W log R), O(H+R+W) 결과 메모리다. 전체 이력을 정렬하거나 H×R 선형 탐색하지 않는다. 취소가 없으면 후보 검사를 즉시 끝낸다. 취소가 있으면 창 밖 활성 이력을 한 번 순회하면서 최대 C개의 키에 조회하므로 추가 O(H log(C+1))이다. R·C가 제한되어 이력 증가에 대해 거의 선형이다.
- 행 전체 Ord는 모든 17개 필드와 정확 십진 값 동등성을 따른다. 1과 1.0은 같은 키다. 추가 행과 임시 집합을 정렬하므로 동일 초기 상태에서 응답 순서를 바꿔도 결과 상태가 같다.

## 검증과 남은 범위

리뷰의 부분 필터·빈 50행 응답·창 밖 취소·오래된 미결제·1000→3000→2000·0 단가/미국 취소/독립 시각 재현을 단위 테스트로 고정한다. 속성 테스트는 Config::with_cases(256)로 여러 날짜·창·종류·부분 필터·미결제 혼합을 생성하며, 사라진 이력에서 재등장한 뒤 다시 대조한다. 기대 활성·임시 집합은 독립 필터·정렬·개수 계산으로 구하고 순서 무관성·멱등성·이력 비감소를 검증한다. 같은 행 n,m 각각 0~16의 289개 조합과 4096/4097 응답·100만/100만+1 이력 경계를 별도로 확인한다.

완전 확인의 사실 검증, 미지 통화 격리·사용자 알림, 페이지 시점 불일치, 전체 검사와 경고 표시, 증권 입출고·채권 현금 흐름 분류는 후속 어댑터·유스케이스 작업이다. 실제 키·계좌·주문 경로는 사용하지 않는다. 이 변경은 종류별 원가·현금 계산을 구현하지 않는다.
