# H-44 기본 브랜치를 받아들이는 병합의 검사 기준

- 상태: 초안

## 결정

커밋 훅은 평소에 merge-base HEAD refs/heads/master를 기준으로 한다. 이름 있는 현재 브랜치가 refs/heads/master가 아닌 작업 브랜치일 때 다음 두 경우만 로컬 master 끝을 기준으로 선택한다.

1. MERGE_HEAD가 존재하면 소문자 40자리 ID인 내용 줄 하나만 허용한다. 마지막 줄바꿈 없음, LF 하나, CRLF 하나를 받는다. 공백, 빈 줄 추가, 여러 부모, 이름, 축약·대문자 ID는 받지 않는다. 그 ID가 정확히 현재 로컬 master 끝이면 그 끝을 선택한다. 읽기 실패·잘못된 UTF-8는 오류이며 트리 조건으로 넘기지 않는다.
2. MERGE_HEAD 파일이 없으면 master 끝을 SHA로 고정하고 git merge-tree --write-tree HEAD <고정한 끝>을 실행한다. 종료 0이고 유효한 트리 ID 하나가 나왔으며, git write-tree가 성공해서 낸 인덱스 트리 ID와 같을 때만 그 끝을 선택한다. 충돌, 인덱스 불일치, 잘못된 출력에는 적용하지 않는다. 메타데이터가 있지만 유효하지 않은 경우에도 트리 조건으로 넘어가지 않는다.

두 경로 모두 detached HEAD, master 자체, refs/heads/ 밖의 symbolic HEAD에는 적용하지 않는다. MERGE_HEAD의 형식, 현재 브랜치, refs/heads/ 검사는 출력 값만 보면 중복처럼 보이는 경우에도 병합 상태와 작업 브랜치라는 허용 범위를 명시하므로 유지한다. 각각을 직접 관찰하는 테스트를 둔다.

Git 2.38 이상이 자동 병합 트리 기능의 최소 요구다. 로컬과 CI가 같은 기능 실행으로 지원 여부를 확인한다. 미지원이나 명령 실패는 닫힌 Unavailable 변형으로 분기점에 물러나며 stderr에 이유와 최소 버전을 알린다. Git 2.38 미만도 기존 분기점 검사는 유지한다. 구현 환경은 Git 2.45.2였다. CI의 Git 버전을 이번 로컬 실행으로 실측했다고 주장하지 않는다.

## 검사 경로의 분리

BaseUse는 Ancestor와 Commit 두 변형이다. resolve_base는 항상 HEAD 조상을 요구하며 push-base가 이 함수를 쓴다. Commit 변형도 임의 비조상을 받지 않고 commit-base를 다시 계산해 요청한 SHA와 같을 때만 허용한다.

commit-check가 자식 check에 STOCK_COPILOT_BASE_USE=commit을 명시한다. xtask 조립 지점만 이 값을 읽고 닫힌 변형으로 해석한다. 환경 허용 목록은 var 전체가 아니라 이 상수 키를 직접 읽는 호출 하나만 허용한다. 다른 키·동적 키·별칭·같은 줄의 다른 호출은 기존처럼 실패한다. 미설정은 Ancestor, 모르는 값과 읽기 실패는 오류다. test-diff·끄기 보고·변이 범위 계산은 이 타입을 받는다. 일반 check·CI는 기본 Ancestor다. push-check는 기존 레시피를 유지하며, push-base가 먼저 Ancestor로 검증한 SHA만 check-full에 전달한다. require-base CLI는 환경이 Commit이어도 항상 Ancestor다. just require-base의 공통 검증 명령은 지정한 검사 종류를 재검증하며 기본은 Ancestor다. 환경 값은 승인 증거가 아니며 Commit을 고르더라도 위 두 조건을 다시 만족해야 한다.

이 전달을 위해 justfile, 검사 목록, xtask main.rs, main.rs의 환경 읽기 허용 이름도 바꾼다. 원래 master에 있던 테스트 본문과 변이 레시피는 유지한다. 새 의존성·검사 끄기는 없다.

## 실제 작업 절차

작업 브랜치에서 git merge --no-ff --no-edit master 한 번으로 받는다. 자동 pre-merge-commit 시점에는 MERGE_HEAD가 없으므로 트리 조건이 적용된다. 충돌이 나면 해결하고 모든 결과를 스테이징한 뒤 git commit --no-edit로 마친다. 이때는 MERGE_HEAD 조건이 적용된다. 구현 담당에게 --no-commit을 요구하지 않는다. 병합으로 받은 master의 승인된 테스트 변경은 “기존 테스트를 바꿔야 하면 막힘”에 해당하지 않는다. 작업 브랜치가 직접 기존 테스트를 바꾸는 것은 계속 위반이다.

## 일반 커밋의 안전 분석

master가 HEAD의 조상이면 깨끗한 병합 결과는 HEAD 트리다. 따라서 인덱스가 HEAD와 같은 경우에만 트리 조건이 참이다. 선택한 master 끝은 기존 merge-base와 같아 판정이 바뀌지 않는다. 다른 인덱스의 일반 커밋은 분기점 기준을 쓴다.

master가 HEAD의 조상이 아니어도 인덱스가 충돌 없는 병합 결과와 같으면 실제 커밋할 내용은 작업 HEAD와 master를 합친 트리다. master 끝 대비 차이는 작업 브랜치가 더하는 변경 전부다. 기존 테스트 변경도 그 차이에 남는다. 승인된 master 변경만 제외되며 추가로 끼워 넣은 차이가 있으면 트리 조건이 성립하지 않는다. 인덱스와 작업 트리의 일치는 기존 커밋 가드가 먼저 요구한다. 반례가 없어 자동 경로를 특정 훅 이름으로만 좁히지는 않는다.

-s ours나 충돌이 난 -X ours의 결과를 트리 조건으로 승인하지 않는다. MERGE_HEAD가 있는 상태에서는 기존 규칙대로 master 끝과 비교하므로 승인된 master 변경을 되돌린 차이도 잡는다.

## 참조와 잠금의 신뢰 분석

기존 커밋 기준은 로컬 master 참조를 사용하며 인증된 CI 기준을 조회하지 않는다(ADR 0015 H-13). CI의 검증된 기준, 사용자 서명, 잠금 지점 후손 검사는 별도 경로(ADR 0020, harness 7.6)이며 그대로 유지한다.

S11b: 로컬 master를 HEAD의 조상이 아닌 R로 옮기고 MERGE_HEAD도 R로 만들면 새 조건에서 R이 기준이 된다. 이는 변경 전에는 없던 허용 상태다. 이 사실을 “동작이 같다”로 축소하지 않는다. 다만 참조 쓰기는 기존 가드가 막으며 그 권한이 있다면 변경 전에도 금지 변경을 담은 HEAD로 master를 옮겨 merge-base를 HEAD로 만들어 비교를 비울 수 있었다. 새 인증 권한을 제공하는 것은 아니지만 로컬 참조를 승인 증거로 삼을 수 없는 한계는 남는다.

replace·graft 및 Git 경로 환경 변수 무효화는 기존 git_base::git을 계속 사용한다. Git 작업 사본별 경로에서 MERGE_HEAD와 인덱스를 조회한다. 동시 참조·인덱스·작업 트리 변경의 경쟁 상태는 기존처럼 OS 경계의 한계다.

## 미해결과 한계

master가 지운 테스트를 작업 브랜치가 약하게 되살리면 master 끝 기준에서는 새 테스트로 취급한다. 다음 일반 커밋과 푸시의 기준도 삭제된 master 끝이면 다시 잡히지 않는다. “다음 일반 커밋·푸시에서 다시 잡힌다”는 가정은 재현으로 반증했다. 그 테스트가 기준에 다시 들어가기 전에는 이 비교 방식으로 보호하지 못한다. 이번 수정에서 테스트의 존재 여부 정책까지 확장하지 않는다.

프로젝트 신뢰·훅 정의 신뢰는 제공된 세션 도구로 확인하지 못했다. 실제 lefthook, 전체 check와 손 변형 결과를 증거로 남긴다.
