# H-44 기본 브랜치를 받아들이는 병합의 검사 기준

- 상태: 초안

## 결정

커밋 훅의 기본 기준은 계속 로컬 refs/heads/master와 HEAD의 분기점이다. 이름 있는 현재 브랜치가 master가 아니고 Git의 작업 사본별 MERGE_HEAD 파일이 정확한 40자리 커밋 ID 한 줄이며 그 값이 로컬 master 끝과 같을 때만 들어오는 끝을 선택한다. detached HEAD는 예외를 받지 않는다. 문어발·오래된 master 커밋·다른 끝을 병합하면 기존 기준으로 검사한다.

공유 기준 검증은 HEAD 조상 또는 위 조건을 만족하는 정확한 병합 기준이라는 닫힌 변형만 허용한다. 불린 옵션이나 임의의 비조상 커밋 허용은 없다. test-diff는 기준과 현재 파일 전체를 비교하고 실제 테스트 목록도 검사한다. 커밋 가드가 부분 커밋·미추적 파일·인덱스 불일치를 먼저 막으므로 실제 커밋되는 병합 트리를 검사한다. 충돌 해결 중 추가한 기존 테스트 변경도 기준 대비 차이로 남는다.

## 안전 분석

기존 commit-base는 검증된 CI 기준을 조회하지 않고 로컬 master 참조만 사용한다(ADR 0015 H-13). 서명 작업이 마지막으로 성공한 master와 잠금 지점의 후손 조건은 별도 CI 서명 경로(ADR 0020, harness 7.6)에 있다. 현재 잠금 파일은 비어 있다. 이 작업은 이 경로와 신뢰 자료의 출처를 바꾸지 않는다.

master를 임의 커밋 R로 옮겨 비조상 R을 병합하면 이전 분기점 방식은 R의 테스트 변경도 검사했고 새 방식은 R을 기준으로 삼는다. 이 판정 차이는 실제 존재한다. 그러나 로컬 master 참조 쓰기 권한 자체가 기존 방어의 경계 밖이다. 같은 권한으로 금지 변경을 담은 작업 HEAD W로 master를 옮기면 기존 merge-base HEAD master도 W여서 이미 금지 변경을 비교에서 지울 수 있었다. 따라서 승인 위조 능력은 기존과 같다. 로컬 master를 인증된 기준이라고 부르지 않으며, 이 규칙만으로 승인 여부를 증명하지 않는다. 실제 승인 관문은 기존 메인의 기준 확인과 CI 서명 검증이다.

참조 쓰기 권한이 없는 경우 임의 SHA 인자만으로 예외를 얻을 수 없다. 단일 MERGE_HEAD, 정확한 master 끝, 작업 브랜치 조건을 공유 검증에서 다시 확인한다. 다른 커밋·다중 부모·역방향·병합 밖에서는 비조상 기준을 거부한다. replace·graft와 Git 경로 환경 변수 무효화도 기존 git_base::git을 그대로 사용한다. 작업 사본별 Git 경로를 조회하므로 공유 저장소의 다른 병합 상태를 읽지 않는다.

병합 후 master가 그대로면 merge-base HEAD master는 받아들인 끝이다. master가 추가 전진하면 다음 분기점은 해당 히스토리에 따른다. 병합 시점의 끝을 영구 설정으로 저장하지 않는다.

## 바꾼 것과 유지한 것

바꾼 것은 커밋 기준 선택과 공유 조상 검증의 한정된 병합 변형, 추가 회귀 테스트와 관련 안내다. 기존 테스트 본문·테스트 비교 규칙·커밋 가드·훅 설치·just 레시피·CI 서명·잠금·푸시 기준은 유지한다. 추가 의존성·검사 끄기·사용자 설정은 없다.

## 미해결과 한계

로컬 master 참조를 인증하려면 저장소 밖 신뢰 앵커가 필요하다. 원격 추적 참조도 로컬에서 바꿀 수 있고 현재 로컬 master가 원격보다 앞설 수 있으므로 새 원격 의존성은 넣지 않는다. 악의적 동시 참조·작업 트리 변경의 경쟁 상태는 기존과 같이 별도 OS 경계의 책임이다. 프로젝트 신뢰와 훅 정의 신뢰는 제공된 세션 도구로 확인되지 않았으며 실제 Git 훅과 check 결과를 증거로 남긴다.

Git의 자동 병합 pre-merge-commit 훅에서는 MERGE_HEAD가 아직 기록되지 않는 것을 실제 lefthook 실험에서 확인했다. 이 단계에는 새 규칙을 적용하지 않는다. 충돌 해결 뒤 또는 --no-commit으로 준비된 병합의 git commit에는 MERGE_HEAD가 있어 새 규칙을 적용한다. 상태가 없는 자동 병합까지 허용하려고 부모를 추측하거나 훅을 건너뛰는 경로는 만들지 않는다. 자동 병합 자체의 UX 개선은 별도 메인 결정이 필요하다.
