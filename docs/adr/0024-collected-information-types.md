# ADR 0024: D-15 수집 정보의 출처와 비신뢰 텍스트

- 상태: 확정 (2026-11-13)
- 최초 기준: df24cd3b0b81e077f6a2b776225b63d76297671b
- 수정 기준: master b4b239cc9805bb1929ddbb0b401357a710d27bf5를 병합한 d65b9a90b5efb61c1b48dc9790206b2486fce3b8
- 관련: D-15, D-16, N-03, N-05, N-09, M-08, C-05, C-07, SEC-4, SEC-10

## 출처와 비신뢰 텍스트

NewsItem과 Disclosure는 CollectedItem을 포함한다. 외부 공개 생성자는 CollectedItem::from_web뿐이며 출처는 Web으로 고정한다. crate 내부의 from_source는 NewsItem·Disclosure가 출처를 붙이는 경로다. 소스는 내부 레지스트리의 닫힌 집합이며 외부 열거값을 파싱하는 타입이 아니다.

제목과 본문은 비공개 필드의 UntrustedText다. 신뢰 문자열로의 From, Deref, Display, 직렬화 구현을 제공하지 않는다. 명시적인 as_untrusted_str에서만 원문을 읽는다. Debug는 내용 대신 byte_len만 표시하므로 CollectedItem을 Debug로 출력해도 본문이 나오지 않는다. 이 값은 안전한 HTML이나 검증된 지시문을 뜻하지 않는다. 원문을 조용히 자르거나 신뢰 텍스트로 승격하지 않는다.

URL은 8192바이트, UntrustedText는 65536바이트로 복제 전에 제한한다. 오류에는 입력값을 넣지 않는다.

## 공시 번호와 키

R-07 24행의 KIND acptNo와 62행의 DART rcept_no는 14자리다. DartReceiptNo·KindReceiptNo는 정확히 ASCII 숫자 14자리만 받는다. R-07 68~78행은 SEC EDGAR 응답을 실측하지 않았고 accession 번호의 형식을 명세하지 않았다. SecEdgarReceiptNo는 사용자 수정 지시에 제시된 ASCII 숫자 10자리-2자리-6자리만 받는 보수적 내부 정책이다. 공식 API 제약을 확인했다는 뜻은 아니다. 길이는 정확히 20바이트며 다른 표시·축약 형태는 받지 않는다.

ReceiptNo는 Dart(DartReceiptNo), Kind(KindReceiptNo), SecEdgar(SecEdgarReceiptNo) 열거형이다. DisclosureKey는 그 값을 봉인하며 열거형 판별자가 source를, 내부 값이 receipt_no를 이룬다. Disclosure는 ReceiptNo에서 출처를 정하므로 검증한 번호와 다른 출처를 전달하는 인자를 두지 않는다. URL·제목 변경은 키를 바꾸지 않는다.

R-07 66행의 하루치 표본에서는 거래소 경유 공시 23쌍의 9번째 숫자가 달랐다(DART 20261111800749, KIND 20261111000749). 반면 숫자가 같았던 금감원 직접 제출 공시 13건은 서로 다른 공시였다. 따라서 두 출처의 키를 합치거나 숫자 한 자리를 치환하지 않는다. 같은 번호도 출처가 다르면 다른 키다. 공식 대응 규칙은 R-07 252행에서 미확인으로 남아 있다.

정정본은 다른 접수번호를 유지한다. 원 공시를 가리키는 필드가 없다는 R-07 63행에 따라 원본 연결·정정 처리의 책임은 N-03이며, KIND 전환 시 대응은 N-05, 알림 등급 처리는 N-12가 확인한다. 제목에서 꼬리표를 제거해 자동으로 같은 키로 만들지 않는다.

## URL 정규화

R-07 Q6은 스킴·www./m.·추적 인자를 언급하지만 정확한 치환표가 없다. 스킴·DNS 호스트 대소문자와 빈 경로(/)를 통일한다. HTTP/HTTPS, www./m., 기사 경로, 쿼리 순서·중복 키는 구분한다. Google 중계 주소를 제목만으로 원문과 합치지 않는다.

소문자 utm_source·utm_medium·utm_campaign·utm_term·utm_content만 제거한다. 제거 뒤 빈 쿼리와 빈 & 구간을 없앤다. 퍼센트 인코딩의 16진수는 대문자로 통일하되 디코딩하지 않는다. %2F와 /, %3F와 ?는 구분한다. 프래그먼트는 문서 안 위치이므로 키에서 제외한다. 빈 쿼리·빈 & 정리는 이번 사용자 수정 판정의 내부 정책이며 RFC의 일반적인 쿼리 동등성 규칙이라고 주장하지 않는다. 근거는 사용자 수정 판정과 [RFC 3986 6.2.2.1 및 6.1](https://www.rfc-editor.org/rfc/rfc3986#section-6.2.2.1)이다.

ASCII DNS 레이블이 두 개 이상인 절대 HTTP(S) 주소만 받는다. 마지막 레이블이 숫자뿐이거나 0x/0X 뒤에 16진수만 있는 경우(접미사 없음 포함)를 거부한다. xn-- 레이블은 대소문자와 유효성에 관계없이 모두 거부한다. 인증 정보·포트·IPv6·원시 비ASCII·공백·제어 문자·역슬래시·잘못된 퍼센트 인코딩·점 경로도 거부한다. 점 경로 검사는 경로에만 적용하며 쿼리의 /../는 보존한다. 외부 링크 권한과 HTTPS 열기 정책은 이 타입의 책임이 아니다.

url 2.5.8(default-features=false, features=[std])을 dev-dependency로만 추가한 실험에서도 arch-check가 domain => serde, syn, proc-macro2를 거부했다. 사용자 지시에 따라 매니페스트·잠금 파일을 원복했으며 차등 테스트를 위해 구조 규칙을 완화하지 않았다. master에 proptest도 없어 무작위 차등 속성 검사는 포함하지 않는다. 넓은 명시 입력 목록과 기존 생성 조합 검사로 정규화·거부·멱등성을 고정한다.

## 묶음

Cluster는 필수 대표 기사와 추가 기사 목록을 불변으로 보관하고 정규화 URL 중복을 거부한다. 총 항목 수는 대표 포함 256개(추가 255개)로 제한하며 초과 시 TooManyMembers를 반환한다. 이는 외부 소스 규칙이 아닌 내부 자원 상한이다. 제목 유사도·종목 대응·48시간 조건으로 묶음을 정하는 것은 N-09다.

## 미해결

- N-05 전환 때 같은 공시가 두 건이 될 수 있음, N-03·N-05가 확인. 출처별 키를 유지하면서 공식 대응 근거와 정정 연결 자료를 먼저 확보한다.
- SEC EDGAR 번호의 공식 형식과 실제 응답은 N-07에서 확인한다.
- UTM_SOURCE·fbclid·gclid·utm_id 및 인코딩된 추적 키는 보존한다. 제공자별 동등성이 확인되지 않은 값을 제거하지 않는다. www./m.과 HTTP/HTTPS 동등성도 N-09가 녹화 자료로 확인한다.
- 연합뉴스 input 매개변수는 피드마다 다를 수 있다. 현재는 키에 보존하며 N-09가 마켓+·경제 피드의 같은 기사에 대한 input 차이와 중복 제거 정책을 확인한다.
- 제어·양방향·영폭 문자는 UntrustedText에 원문 그대로 보관한다. M-08은 MCP 출력에서 제거한다. C-05·C-07의 화면 경계 DTO·표시 어댑터도 직접 as_untrusted_str을 렌더링하지 않고 이 문자들의 표시 정규화를 담당해야 한다. DS-18의 raw HTML 차단만으로 충분한지 화면 회귀 테스트로 확인하는 것은 미해결이다.
- 언론사 본문 보관 금지·소스별 본문 읽기·Google 제목 한정 정책은 N-17·M-06 및 저장 어댑터가 강제해야 한다.
- IDN·포트·IPv6 지원과 무작위 차등 테스트는 domain 의존 정책 확인 후 다룬다.
- 발행·수집 시각은 D-01 병합 뒤 추가한다. 이번에는 시간 crate와 시간 필드를 두지 않는다.
