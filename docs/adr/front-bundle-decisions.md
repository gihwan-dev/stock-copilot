# front1 묶음 결정 표

경량 절차(ADR 0173)로 `front1` 묶음(U-09, U-10, U-11, U-21, U-27, U-16, U-17, U-25, DS-12)을 구현하며 문서가 정하지 않은 것을 정한 기록이다.

| 작업 | 정한 것 | 다른 선택지 |
|---|---|---|
| U-09 | 코어 화면 명령(현황·자산배분·거래내역·자체 점검·상태)이 아직 IPC에 없어 `shared/ipc/screen-sources.ts`에 화면 자료 타입과 `ScreenSources` 포트를 두고, 기본값 `pendingScreenSources`는 모두 "자료 없음"(`no-data`)을 돌려준다. `App`의 `sources`로 주입하고 테스트는 가짜 원본을 넣는다. 코어 명령이 생기면 native 묶음이 `call.ts` 함수로 바꿔 끼운다 | `src-tauri`에 빈 명령을 추가(native 묶음과 충돌), 생성 바인딩 손편집(생성물 검사 실패) |
| U-09 | 화면 쿼리 키는 `["portfolio","view"]`처럼 기존 키의 하위 키(`screenKeys`)다. 코어 이벤트 무효화는 접두어로 그대로 닿고, 다른 곳이 상위 키에 둔 값과 섞이지 않는다 | 상위 키를 그대로 사용 |
| U-09 | 주 화면은 U-04의 앱 연결 확인(app_version)을 먼저 거치고, 현황 자료가 없을 때 "앱이 준비됐어요." 빈 상태를 보인다 | 연결 확인 제거(U-04 고정 테스트와 어긋남) |
| U-09 | 네 상태: 불러오는 중, 자료 없음(`no-data` 오류 또는 빈 자료), 오류(다시 시도), 정상 | 자료 없음을 오류로 표시 |
| U-10 | 자산배분은 차트 대신 종목별·섹터별 비중 표와 상한 단계(여유·주의·초과) 배지, 쏠림 한 문장으로 보인다. 차트는 화면 테마 훅이 없어 넣지 않았다 | DonutChart(테마를 고정해야 함) |
| U-10 | 상한 단계와 쏠림 판정은 코어가 정해 보낸 값을 그대로 표시한다 | TS에서 비중 비교 |
| U-21 | 자체 점검 문제의 순서 판정은 코어(A-19)가 하고 화면은 받은 문제 하나만 한 문장으로 보인다. 토스 키·허용 IP·키 중복은 "설정 열기" 버튼을 붙이고, 나머지는 문장만 보인다. 자료 없음·오류·불러오는 중에는 띠를 보이지 않는다 | 화면에서 여러 문제를 정렬 |
| U-21 | 허용 IP 문장에는 현재 IP 값과 복사 버튼을 넣지 않았다. IP 확인과 복사는 첫 실행 허용 IP 화면(U-07)이 한다 | 상태 띠에서 공개 IP 조회 |
| 병합 | master의 front2(첫 실행 확인·고급 > 시스템 절)와 이 계열의 U-23 설정 화면을 합치며, `App`에 `settingsClient`가 주어질 때만 첫 실행 확인과 시스템 절을 붙인다. 주어지지 않으면 둘 다 결과가 "통과"라 동작은 같고, U-23·front2 고정 테스트를 고치지 않고 모두 통과한다. 시스템 절은 master 배치대로 설정 화면 본문 아래에 보인다(UX-7의 "나머지는 고급 아래"와 어긋나므로 메인 확인 필요) | 시스템 절을 고급 안으로 옮기고 두 고정 테스트를 수정(기존 테스트 변경이라 하지 않음) |
| U-27 | 상태 화면은 점검 기록 표, AI 실행 환경·한도(재개 시각), 작업별 AI 사용량, 소스별 마지막 성공 시각을 보인다. UX-6 예외 화면이라 "사전 점검", "토큰"을 쓴다. 토큰 수와 초는 코어가 보낸 십진 문자열을 그대로 보인다 | 화면에서 토큰 합산 |
| U-16 | IPC는 네트워크가 아니므로 쿼리·변경의 `networkMode`를 `always`로 둔다(기본값이면 오프라인에서 쿼리가 멈춘다). 오프라인 여부 표시는 코어가 보낸 `connection: "stored"`로 한 줄 띠를 보인다. 채팅 기록 열람 화면은 채팅 묶음(C-03) 담당이라 같은 설정으로 쿼리가 도는 것까지만 시험했다 | 화면에서 `navigator.onLine` 감지 |
