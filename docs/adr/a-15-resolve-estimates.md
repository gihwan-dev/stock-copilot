# A-15 추정 판정과 보정표 갱신

- 상태: 초안
- 기준: 896049a64bbd02c263288964421e44dbcb2bb6e2
- 근거: A-15, ACC-9, design 6.2·6.6, ADR 0051·0065·0080·0119 및 이번 지시문

## 결정

`EstimateResolutionRepository`는 A-12와 같은 완전 제출 원장에서 거래 여부와 무관하게 모든 미판정 제출을 열거한다. 기록은 과제 ID로 식별한다. 각 제출에 시장 자료를 모아 domain 판정을 호출하고, 확정된 판정만 그 판정의 ID·실제 모델·원래 확률로 보정 사실을 만든다. `Calibration::with_fact`는 선택된 표본만이 아닌 기존 모든 사실을 보존하고 기존 생성·중복·겹침 규칙을 다시 적용한다. 서로 겹치는 같은 종목 추정은 모두 판정하지만 보정 집계에는 domain이 선택한 것만 들어간다.

기존 `EstimateRepository`의 개별 판정·보정 쓰기는 원자적 묶음을 보장하지 못한다. 새 포트의 `commit_resolution`은 원본 제출의 존재와 동일성, 미판정, 해당 모델·기간의 현재 표본과 `previous` 일치를 한 트랜잭션에서 검증하고 판정과 새 보정 버전을 함께 추가한다. 이미 판정된 ID는 `AlreadyResolved`, 이전 표본이 바뀌면 `Conflict`, 저장 실패는 아무것도 쓰지 않은 오류다. 반환이 불확정인 실제 저장 결과는 단순 저장 실패로 바꾸지 않는다. 호출자는 충돌을 보고 받고 다음 실행에서 새 표본으로 재시도한다. 이는 서로 다른 판정이 같은 보정표를 갱신할 때의 유실도 막는다. 실제 어댑터의 원자성은 S-18의 책임이며 가짜 실행만으로 영속 트랜잭션을 증명하지 않는다.

시장 자료 포트는 제출과 판정 시각을 받아 자료를 조회한다. 자료 부족의 domain 사유와 시장 조회 `PortError`, 저장소 조회 `SystemPortError`를 구분해 원래 오류를 보존한다. 완전한 자료가 없는 경우 `record_unavailable`은 미판정 확인과 사유 기록을 원자적으로 수행한다. 이미 판정된 추정은 사유로 덮지 않는다. 이후 성공 커밋에서 해당 미판정 사유를 정리한다. 사유 기록 자체가 실패하면 저장 오류를 보고한다. 종목 키 이벤트는 성공 커밋 이후 기록당 한 번 발행하고 구독 실패는 별도로 반환한다. 프로세스 종료를 가로지르는 내구 이벤트 전달은 ADR 0065의 범위가 아니다.

ADR 0051의 기존 공개 함수는 마감 뒤 빠진 필수 분봉을 모호 실패로 처리한다. 이번 A-15 지시의 자료 불완전 시 미판정 유지가 더 구체적이므로 별도 `evaluate_with_complete_data`에서 필수 분봉 누락을 `MissingCandles`로 반환한다. 목표·손절·같은 온전한 분봉의 동시 도달·만기 등의 계산과 다른 검증은 동일 domain 경로를 쓴다. 기존 호출의 누락 처리와 기존 테스트는 보존한다. 자료를 공급하는 쪽은 행사 목록과 캘린더의 출처·완전성 및 수정 기준을 보장해야 한다.

## 제안

A-15의 판정 결과는 성공·실패와 그 근거를 기록한다. 추정 자체의 수익률을 이 판정에 추가하는 규칙은 문서에서 독립적으로 정해지지 않았다. design 6.6의 가상 청산 수익률은 신호에 대한 별도 D-29 계약이므로 거래하지 않은 모든 추정의 수익률로 재해석하지 않는다. 제안: 추정별 수익률의 진입가·청산가·비용·벤치마크 및 자료 누락 규칙을 정의한 뒤 domain에서 계산하고 별도 사실로 연결한다.

## 인계

| 받는 작업 | 내용 |
|---|---|
| S-18 | A-12 제출과 같은 저장 원장에서 누락 없는 미판정 열거, ID별 중복 거부, 판정·보정 버전의 조건부 원자 커밋, 사유 기록 및 재시작 복원. 기존 종목 조회와 같은 저장 사실을 돌려준다 |
| D-51, A-27 | 보정표가 어느 판정까지 반영했는지의 증거와 없음·정상 빈 표·오래됨을 구별한다. 현재 `Calibration`에는 반영 범위 증거가 없다 |
| T-07, T-13, S-23, J-12 | 달력·수정 봉·기업 행사 입력의 종목·기간·수정 기준·완전성 및 필요한 분봉 보존과 앱 재시작 뒤 재시도를 보장한다 |
| D-29, 성적표 연동 작업 | 신호 가상 청산 수익률과 추정별 수익률의 의미를 분리하고 위 제안의 소유 작업·규칙을 정한다 |

## 검증

시작 시 프로젝트 신뢰와 세션 훅 해시 신뢰의 적용은 확인하지 못했다. frozen 설치 및 Git lefthook 설치는 성공했다. 첫 변경분 검사에서 타입 별칭에 대한 raw-types 위반이 발견되어 별칭을 제거했다. 통합 테스트와 후속 검사 결과는 최종 기록에 남긴다.
