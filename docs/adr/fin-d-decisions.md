# fin-d 묶음 결정

경량 절차(ADR 0173)로 `fin-d` 묶음(AI 러너·MCP 서버를 데스크톱 앱 조립 지점에 연결)을 구현하며 문서가 정하지 않아 정한 것이다.

| 작업 | 정한 것 | 다른 선택지 |
|---|---|---|
| fin-d 1 | AI-17이 미룬 "실행마다 새 토큰"을 `ClaudeCodeProvider::run_attached`·`resume_attached`로 연다. 실행별 첨부(`RunMcpAttachment`)는 브리지 설정과 토큰을 담고, 분석 실행에서만 받는다. 수집 실행에 첨부를 주거나 서버 이름이 기대와 다르면 자식을 띄우지 않고 검증 오류로 끝낸다. 설정에 고정된 브리지·토큰 경로(`run`)는 그대로 둔다 | 실행마다 `ClaudeCodeProvider`를 새로 만들기(중단·한도 추적이 실행마다 흩어짐) |
| fin-d 1 | 첨부에 `SpawnedPidNotice`를 달면 자식을 띄운 직후, 첫 stdin 줄을 쓰기 전에 CLI의 PID를 알린다. 실행별 MCP 서버가 상대의 부모 PID를 묶는 데 쓴다(architecture 2.4 보조 확인) | 스트림 이벤트로 PID 전달(앱 계약 `AiEvent` 변경 필요) |
| fin-d 2 | 앱 쪽 연결 계층 `ai_runtime`을 `src-tauri`에 둔다. `McpAttachedAi`가 `application::AiProvider`를 구현하고, 분석 실행(실행·재개·사전 점검)마다 `RunMcpHost`로 실행별 MCP 서버를 열어 소켓·토큰·PID 묶기를 첨부해 넘긴다. 수집 실행은 서버를 열지 않고 그대로 넘긴다(앱 MCP 없음, architecture 2.2). 어댑터 타입 이름은 `main.rs` 밖에 두지 않으므로(arch-check `adapter-construction`) 어댑터는 `AttachableAi` 트레이트 뒤에 둔다 | 어댑터가 MCP 서버를 직접 띄움(ai-claude-code → mcp-server 의존, 구조 규칙 위반) |
| fin-d 2 | 서버를 못 띄우면 CLI를 띄우지 않고 `Unavailable`로 끝낸다. 스트림이 끝나거나(`None`·오류) 버려지면 세션을 놓아 토큰 폐기·소켓 삭제가 일어난다(`McpServerHandle`의 `Drop`) | 실행 종료 기록 시점에 정리 |
| fin-d 2 | 서버는 부모 PID를 `Pending`으로 시작하고 첨부의 PID 알림으로 CLI PID를 묶는다. 묶기 전 연결, 다른 부모, 상대 확인 수단 없음은 모두 거부(mcp-server 기존 동작)를 앱 조립 경로에서 다시 확인한다 | 상대 확인 끄기 |
| fin-d 2 | 소켓 기반 폴더는 앱 데이터 폴더 아래 짧은 `m`(0700)으로 하고, 실행마다 `RunSocketSpec::generate_under`로 무작위 하위 폴더를 만든다. 경로가 104바이트를 넘거나 조상에 심볼릭 링크가 있으면 분석 실행을 띄우지 않는다 | 시스템 임시 폴더 |
| fin-d 3 | 제품 분석 카탈로그는 `mcp_server::build_analysis_catalog`로 문서 도구 20개(design 3.1, `fixtures/mcp/tools_list.json`)를 그대로 등록한다. 자료원 포트 중 제품 구현이 없는 것(포트폴리오·시장·뉴스·웹 조사·기사·논거 대상·호출 이력·추정 실행 문맥·투자 성향)은 `UnconnectedToolData`가 저장소 사용 불가 오류로 닫고, `read_article`의 본문 읽기는 꺼짐으로 본다. 논거 저장소·추정 과제·제출·성적표 관측은 `SqliteRepositories`에 위임을 더해 연결한다 | 자료원이 생길 때까지 해당 도구를 목록에서 빼기(문서 목록과 어긋남) |
| fin-d 3 | 앱 MCP 서버 이름은 `stock`, CLI 허용 도구는 카탈로그 이름에서 `mcp__stock__<도구>`로 만든다(사전 점검의 기대 목록과 같은 원본) | 이름 목록을 따로 고정 |
| fin-d 3 | MCP 호출 원장은 `SqliteRepositories`의 `ToolCallLedger` 위임(채팅 저장소의 추가 전용 표)으로 남긴다 | 원장 미설정(모든 호출이 `ledger_unavailable`) |
| fin-d 4 | 제품 조립(`main.rs`): `claude`는 알려진 위치·로그인 셸 PATH로 찾고(AI-13 탐색만, 로그인 점검 실행은 하지 않음), 못 찾으면 `AiAvailability::Missing`으로 모든 AI 호출이 `Unavailable`이다. 설정은 서버 이름 `stock`, 허용 도구는 카탈로그에서, 내장 플러그인 허용 목록은 R-02 실측값 4개(`cc-plugin-agents-md`·`telemetry`·`privacy`·`plugin-authoring`), 수집 실행 `--json-schema`는 `WEB_COLLECTION_JSON_SCHEMA`, 호스트 환경은 프로세스 환경에서 허용 키만(`HostEnvironment::from_pairs`). CLI 버전 허용 목록은 AI-16 연결 전까지 두지 않는다(기록만) | 앱 시작 때 로그인 점검까지 실행 |
| fin-d 4 | 작업 폴더는 `$TMPDIR`의 실제 경로 아래 `stock-copilot-ai`, 실행별 MCP 소켓 기반 폴더는 `$TMPDIR` 실제 경로 아래 `sc-mcp`로 바꾼다(fin-d 2의 앱 데이터 폴더안 대신). `sandbox-exec` 겹이 앱 데이터 폴더 읽기·쓰기를 막는데 브리지(CLI 자식)가 같은 겹 안에서 소켓에 닿아야 하기 때문이다. 겹은 앱 데이터 폴더를 막는 프로필로 시작 때 자가 점검해 적용될 때만 쓴다(AI-18) | 소켓을 앱 데이터 폴더에 두고 겹을 끔 |
| fin-d 4 | 브리지 위치는 앱을 만든 뒤 Tauri `resource_dir()/mcp-bridge`로 한 번 정한다(`BridgeLocation`). 정해지기 전에는 분석 실행이 서버를 열지 않고 `Unavailable`이다. 실행 파일 옆(`current_exe`)을 쓰려면 소스 검사 허용 목록(보호 파일)에 항목을 더해야 해 쓰지 않았다. 번들에 브리지를 리소스로 넣는 설정은 I-01(번들) 몫이다 | `std::env::current_exe` 옆(허용 목록 변경 필요) |
| fin-d 4 | 상대 확인은 `/bin/ps -ww -o ppid= -o comm= -p <pid>`로 부모 PID와 실행 파일 경로를 읽는다(`PsPeerInspector`). `comm`은 exec 경로(argv0)라 보조 수단이며(architecture 2.4), 실패·없음은 연결 거부다. 새 패키지·`unsafe` 없이 할 수 있는 방법이라 골랐다. 테스트 샌드박스(nextest `sandbox-exec`)에서는 setuid `ps` 실행이 막혀, 테스트는 대역 스크립트로 인자·파싱·실패 경로를 고정한다 | libproc FFI(`unsafe` 필요) |
| fin-d 4 | `AiRunnerQueue`를 채팅 큐 포트로, 그 예약 슬롯을 `scheduler::AiJobQueue`로 잇는다(`ProductAiJobs`: 작업별 슬롯 실행 ID를 들고 있다가 해제 때 `Completed`로 놓음). `PortTypes`에 `AiJobQueue` 연관 타입과 `Ports.ai_jobs`를 더하고 스케줄러가 `DisabledAiJobQueue` 대신 이것을 쓴다(테스트 조립은 `DisabledAiJobQueue`) | 스케줄러 전용 상태로 따로 넘김 |
| fin-d 4 | `EventBus`가 복제되지 않아 `Ports.events`를 `Arc<EventBus>`로 바꾸고, AI 큐·MCP 카탈로그(추정 제출 이벤트)가 앱 상태와 같은 버스를 공유한다 | 버스를 여러 개 만듦(구독자 중복) |
| fin-d 4 합류 | 같은 시각 master에 J-03(브리핑 문맥 포트와 브리핑 3종 등록, `AppStoredJobs`가 `Ports.ai_provider`로 `RunBriefing`)이 들어와 그쪽을 살리고, 이 묶음의 중복 구현(`HoldingsBriefingContext`·`register_briefing_jobs`·`RunBriefingRunner::with_shared_events`)은 뺐다. 브리핑은 조립된 러너(`Ports.ai_provider`)와 예약 슬롯 큐(`Ports.ai_jobs`)를 거친다. master의 수집기 시험은 새 `product_ports` 시그니처(AI 부품 인자)에 맞춰 CLI 없는 조립으로 바꿨다 | 두 구현 병존 |
| fin-d 5 | 메인 승인으로 소스 검사 허용 목록의 `main.rs`에 `test-awareness:env::current_exe`를 더하고, 브리지는 시작 때 실행 파일 옆 `mcp-bridge`로 정한다(`bundled_bridge`). fin-d 4의 `resource_dir()` 주입은 뺐다. 브리지 바이너리가 그 자리에 들어가는 번들 설정은 여전히 I-01 몫이다 | `resource_dir()` 유지 |
| fin-d 6 | MCP 호출 이력(`ToolCallHistory`)은 기존 추가 전용 `tool_call_ledger` 표를 실행 ID로 읽는 조회(`TOOL_CALLS_IN_RUN`)를 store-sqlite에 더해 `SqliteRepositories`로 연결한다. `get_profile`·추정 도구의 투자 성향은 설정 저장소의 `profile()`(`StoredProfile`)로 연결한다 | 미연결 유지 |
| fin-d 7 | 수집 시각은 `information_items`에 열을 더하는 대신 마이그레이션 0021의 별도 표 `information_times(item_id → information_items.id, published_payload, collected_payload)`에 둔다. `ALTER TABLE`은 열기 때 스키마 검증(선언 DDL과 실제 DDL 대조)에 걸려 RepositoryIntegrity로 실패했다. 고정 테스트 2개(마이그레이션 수 20→21, 스키마 객체 수 206→207)와 `schema.snapshot.sql`을 새 표에 맞춰 갱신했다 | `ALTER TABLE ADD COLUMN`(검증기 수정 필요) |
| fin-d 7 | 수집 항목 핸들 규칙: 뉴스는 `n-<information_items.id>`, 공시는 `d-<id>`(앞자리 0 없음, 종류와 접두어가 맞아야 함). 시각이 없는 항목(0021 이전 수집분)은 도구에 내보내지 않는다(ACC-4 수집 시각 필수) | URL 해시 |
| fin-d 7 | 시각 기록은 새 포트 `CollectedTimes`로 하고, `CollectFeed::with_times`로 선택적으로 붙인다(기본은 아무것도 하지 않는 `NoCollectedTimes`라 기존 호출·시험은 그대로). 앱 수집 워커는 `SqliteRepositories`를 붙여 관측마다 게시·수집 시각을 남긴다. 읽기는 `CollectedItemReads`(`collected_since(종류, 시각)`·`collected_item(핸들)`, 최근 1000건 상한) | `NewsRepository::store` 시그니처 변경(fin-e 등 모든 구현 수정) |
