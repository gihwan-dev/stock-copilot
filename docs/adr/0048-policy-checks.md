# ADR 0048: D-12 투자 원칙 검사

- 상태: 확정 (2026-11-14)
- 기준: 최초 기준 09bc27a58efa647b041effcdcbf6528124879cd3, 적대적 리뷰 수정 기준 9dad71aa4a9891cfd891d6347ed59038019b7e7e. 이번 사용자 결정이 이전 초안의 전면 차단 해석을 대체한다.

## 원칙의 닫힌 목록

| 원칙 | 입력 | 위반 조건 | 위반 시 결과 | 근거 문장 |
|---|---|---|---|---|
| 종목 비중 상한 | 총자산 대비 종목 비중, WeightCaps | 현재 비중 > 상한; 매수 후 비중 > 상한 | 현재 초과 보고; 양수 여유까지 축소, 이미 상한 이상이면 차단 | design 6.2 “수량을 깎거나 신호를 막는다”, “종목 20%”; R-11 Q6 “ETF는 한 종목으로 계산” |
| 종목 주의 기준 | 총자산 대비 종목 비중 | 주의 기준 이상 | 경고만 하고 매수는 막지 않음 | design 6.2 “10%부터 주의” |
| 섹터 비중 상한 | 확정된 SectorId 버킷의 총자산 대비 비중 | 현재 비중 > 상한; 후보와 같은 SectorId의 보유 합 + 매수 금액이 상한 초과 | 종목·섹터 여유 중 작은 값까지 축소, 양수 여유가 없으면 차단 | design 6.2 “섹터 40%”; R-11 Q7의 대표 섹터 사용자 지정·“분해 전” 단계; 이번 사용자 결정 |

| 현금 최소 비중 | 선택적 ProfileWeight, 총자산, 통화별 현금의 원화 환산 합 | 현재 현금/총자산 < 기준; 매수 뒤 현금/총자산 < 기준 | 현재 위반 보고; 현금 여유까지 축소, 여유가 0 이하이면 차단. 설정이 없으면 적용 안 함 | design 8장 “현금 최소 비중”; 이번 사용자 결정 |

| 자유 서술 원칙 | PolicyText 목록 | 코드가 임의로 해석하지 않음 | 원문 보관·AI 맥락 전달. 매수 판정에 쓰지 않음 | design 8장 “자유 서술 원칙, 현금 최소 비중, 쏠림 경고 기준”; 이번 사용자 결정 |

기간·위험 성향은 과제·임계값·수량의 입력이다. 반복 매수 제한은 D-25, 주문 잔고·시장·승인은 O-01에 남긴다. tasks G-01의 “게이트와 AI 맥락에 반영”, design 2.2의 “원칙 위반은 코드가 검사한다”는 집합 전체의 일반 문장이다. 자유 서술을 직접 실행 가능한 코드 규칙으로 해석하라는 문장은 없다. 이번 사용자 결정에 따라 현금 최소 비중은 코드 게이트, 쏠림은 경고, 자유 서술은 AI 맥락으로 각각 반영한다.

## 섹터와 사실의 경계

- 다른 보유가 ETF·펀드 또는 미분류 버킷이어도 확정된 후보 SectorId의 합만 검사한다. ETF·펀드/미분류 버킷 자체에는 섹터 상한을 적용하지 않는다.
- ETF·펀드 후보는 종목 상한만 적용한다. 사용자가 대표 섹터를 지정해 Classified가 된 ETF에는 그 섹터 상한도 적용한다. 유형 제외는 항상 적용한다.
- 후보가 미분류이면 CandidateSectorUnassigned로 차단한다. 사용자가 섹터를 지정하면 풀린다. 현재 상태는 미분류 보유가 있어도 결과를 내고 SectorUnassignedHoldings(전용 개수 타입)를 함께 반환한다.
- PolicyCandidate는 종목 식별과 후보 비용만 가진다. 유형·섹터 필드가 없다. 섹터는 함께 받은 SectorAssignments에서 직접 찾는다. 유형은 PolicySecurityFacts에서 종목 식별로 찾는다.
- PolicySecurityFacts의 입력 생성자는 crate 내부 `from_master_lookup_results`다. 공개 역직렬화·원시 값 삽입·가변 접근자가 없다. Default는 빈 사실 목록이므로 알 수 없는 유형을 통과시키지 않는다. T-09는 실제 종목 마스터 조회에서 이 사실을 만드는 domain 경계를 연결해야 한다. 호출 위치 제한은 하네스 작업이다. SectorAssignments의 사용자 확인·종목 마스터 출처는 ADR 0043대로 T-09·S-10 책임이다.

## 계산과 후속 계약

비중 비교는 AssetAllocation과 AssetWeight::cmp_profile_weight만 쓴다. 보유 구성비와 표시 비중은 받지 않는다. 같은 스냅샷에서 총액 일치·완전성·음수 현금 검사를 통과한 뒤 원화 평가액으로 여유를 계산한다. 불일치 요약의 총액이나 불완전 부분합으로 매수 한도를 만들지 않는다.

종목 여유 = 총자산 × 종목 상한 − 해당 종목 평가액. 확정 섹터 여유 = 총자산 × 섹터 상한 − 같은 SectorId 평가액 합. 현금 여유 = 원화 환산 현금 합 − 총자산 × 현금 최소 비중. 현금은 검증된 총자산 − 전체 보유 평가액 합으로 계산한다. 적용되는 여유의 최솟값만 반환한다. 정확 곱·차가 표현되지 않으면 산술 오류로 차단한다. 소수 달러 평가와 현금을 Mid 환율로 환산한 소수를 내림하지 않는다.

D-25의 결과는 Pass / Reduce(PolicyBuyLimit) / Block(PolicyViolation)다. PolicyBuyLimit는 비용 비교만 허용하고 Money·Ratio·Decimal로 공개 변환할 수 없다. Debug도 금액을 가린다. D-25는 이 원화 상한 이하로 수량을 내리고 달러 매수가능금액·환율·비용·반복 제한을 추가로 검사한다. 매도는 이 원칙으로 차단하지 않으며 다른 주문 검사를 면제하지 않는다.

실행 계약이 실제로 없는 원칙은 설명을 가진 PolicyPrinciple::from_missing_contract로 등록한다. unresolved는 목록이고 모두 보존하며, 하나라도 있으면 판정 불가다. 이미 구현한 여덟 원칙을 여기로 보내지 않는다. 기본 프로필의 목록은 비어 있다. 자유 서술과 쏠림은 별도 API를 사용해 이 목록에 들어가지 않는다.

## 검증과 인계

- 기본 프로필 사용자가 평범한 포트폴리오(ETF 포함)에서 매수할 수 있는지 검증한다. ETF 10 + A(Tech) 10 + B(Energy) 10 + 현금 70에서 C와 A의 통과·축소, ETF의 종목 상한 적용, X 미분류 보유를 추가해도 C 매수 가능, 현재 상태 결과·미지정 개수 반환을 고정한다.
- 현재 상한 등호, 독립 정수·유리수 기준 각 4,096회, 현금 최소 비중 독립 기준 4,096회, 여러 축 동시 누락 4,096회를 검증한다.
- 총자산 요약 1,000과 실제 합 100의 불일치, 소수 달러 0.125·달러 현금 0.015·Mid 환율 1375.25의 원화 여유 28.09375와 현금 하한 적용 뒤 8.09375를 고정한다.
- 이번 회차는 자동 변이 실행을 중단하고 손 변형 16개 이상으로 검증한다. 총액 가드 제거와 평가액 내림 등 리뷰 생존 변형을 포함한다.
- D-07이 아직 master에 없으므로 네 상태의 최소 PolicyConcentration 입력을 둔다. D-07의 결과 타입이 병합되면 변환 경계를 연결한다. 쏠림 계산은 여기서 중복 구현하지 않는다.
- 평가액은 스냅샷의 근사 평가다. 실제 체결 금액 보증이 아니며 D-25/O-01이 최신 시세·잔고로 다시 검사한다.
- 새 의존성과 검사 끄기는 없다. 현재 세션의 프로젝트·훅 신뢰 적용 자체는 증명하지 못하므로 직접 검사와 커밋 훅 결과를 증거로 사용한다.
