# H-58: 리뷰 사본 임시 디렉터리 정리

- 상태: 초안

## 배경

독립 리뷰와 비판 뒤 별도 작업 사본에 변형용 `.rv-*` 디렉터리와 `target`이 남는다. 역할의 쓰기 제한 때문에 리뷰어가 정리하지 못하는 경우가 있다.

## 결정

종료 시점에 자동으로 `target`을 지우면 아직 필요한 결과까지 제거할 수 있고 종료 훅이 실제 세션에 적용됐는지도 별도 확인이 필요하다. 공통 Claude 역할 가드에서는 명시적인 `rm` 정리만 허용한다. 등록된 별도 Git 작업 사본의 루트에서 `target` 또는 `.rv-`와 영문·숫자 등으로 이뤄진 맨 폴더 이름을 지정해야 한다. 다른 파일시스템으로의 재귀 진입을 막도록 macOS에서는 `-x`, Linux에서는 `--one-file-system`을 요구한다. 재귀·강제와 이 경계 옵션 외의 `rm` 옵션, 절대 경로, `/`, `.`·`..`, 링크, 메인 저장소, 다른 등록 사본, HEAD 또는 색인의 추적 파일이 들어 있는 폴더는 허용하지 않는다. 등록된 사본의 각 조상과 대상 폴더를 장치·inode로 비교하고, 색인(`git ls-files -z`)과 HEAD(`git ls-tree -z --name-only HEAD`)의 최상위 추적 항목도 대소문자 무시 이름 비교와 `(dev, ino)` 비교로 함께 검사해 macOS 대소문자 비구분 파일시스템에서 `.RV-UPPER` 같은 추적 디렉터리를 `.rv-upper`로 이름을 바꿔 삭제하는 우회까지 차단한다. 대상이 사라졌거나 Git 상태를 확인하지 못하면 거부한다.

macOS에서 링크 이름 끝에 `/`를 붙인 재귀 삭제가 링크 대상의 내용을 지우는 것을 별도 임시 폴더에서 재현했으므로 끝 `/`도 허용하지 않는다. 또 macOS의 `rm -xrf .rv-owned --`가 `.rv-owned`뿐 아니라 `--`라는 폴더도 지우는 것을 별도 임시 폴더에서 재현했으므로 첫 대상 뒤에는 옵션처럼 시작하는 인자를 둘 수 없다. 예를 들어 루트에서 macOS는 `rm -xrf target`, Linux는 `rm -rf --one-file-system target`을 쓴다. 경계 옵션은 같은 장치 번호를 공유하는 별칭 마운트까지 증명하지는 않는다. 소유는 T3가 분리한 작업 사본과 미추적 디렉터리라는 범위로 판단한다. 훅의 사전 판정은 파일 시스템의 경합을 원자적으로 차단하지 않으며 디렉터리 생성자의 OS 수준 증명은 아니다.

## 범위 결정

메인 결정에 따라 Codex 비판자 역할 부분은 H-58 범위에서 제외한다(Codex는 사용하지 않는다). Antigravity 역할 문서화는 별도 브랜치 H-61로 인계하고 이 브랜치에서는 `docs/agents/*`를 건드리지 않는다. 따라서 H-58의 구현·검증 범위는 공통 Claude 역할 가드와 실제 Claude 진입 훅 경로로 완결된다.

## 검증과 인계

공통 역할 가드와 실제 Claude 진입 훅에서 허용·거부를 시험한다. 정적 링크와 `..`, 절대·홈 경로, 다른 등록 사본, 메인 저장소, 스테이징 삭제 중인 HEAD 추적 파일, 대소문자만 다른 추적 디렉터리(`.RV-UPPER`·`TARGET`의 이름 변경 별칭), 리다이렉트와 `rm -P`를 거부한다. 경계 옵션 없는 명령과 `--` 뒤의 가짜 옵션은 거부한다. Linux 판정은 macOS에서 플랫폼 값만 바꾼 단위 시험이며 Linux에서 실제 `rm` 실행은 CI에서 확인해야 한다.
