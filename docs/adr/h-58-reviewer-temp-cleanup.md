# H-58: 리뷰 사본 임시 디렉터리 정리

- 상태: 초안

## 배경

독립 리뷰와 비판 뒤 별도 작업 사본에 변형용 `.rv-*` 디렉터리와 `target`이 남는다. 역할의 쓰기 제한 때문에 리뷰어가 정리하지 못하는 경우가 있다.

## 결정

종료 시점에 자동으로 `target`을 지우면 아직 필요한 결과까지 제거할 수 있고 종료 훅이 실제 세션에 적용됐는지도 별도 확인이 필요하다. 공통 Claude 역할 가드에서는 명시적인 `rm` 정리만 허용한다. 등록된 별도 Git 작업 사본의 루트에서 `target` 또는 `.rv-`와 영문·숫자 등으로 이뤄진 맨 폴더 이름을 지정해야 한다. 다른 파일시스템으로의 재귀 진입을 막도록 macOS에서는 `-x`, Linux에서는 `--one-file-system`을 요구한다. 재귀·강제와 이 경계 옵션 외의 `rm` 옵션, 절대 경로, `/`, `.`·`..`, 링크, 메인 저장소, 다른 등록 사본, HEAD 또는 색인의 추적 파일이 들어 있는 폴더는 허용하지 않는다. 등록된 사본의 각 조상과 대상 폴더를 장치·inode로 비교해 대소문자나 링크 별칭도 검출한다. 대상이 사라졌거나 Git 상태를 확인하지 못하면 거부한다.

macOS에서 링크 이름 끝에 `/`를 붙인 재귀 삭제가 링크 대상의 내용을 지우는 것을 별도 임시 폴더에서 재현했으므로 끝 `/`도 허용하지 않는다. 또 macOS의 `rm -xrf .rv-owned --`가 `.rv-owned`뿐 아니라 `--`라는 폴더도 지우는 것을 별도 임시 폴더에서 재현했으므로 첫 대상 뒤에는 옵션처럼 시작하는 인자를 둘 수 없다. 예를 들어 루트에서 macOS는 `rm -xrf target`, Linux는 `rm -rf --one-file-system target`을 쓴다. 경계 옵션은 같은 장치 번호를 공유하는 별칭 마운트까지 증명하지는 않는다. 소유는 T3가 분리한 작업 사본과 미추적 디렉터리라는 범위로 판단한다. 훅의 사전 판정은 파일 시스템의 경합을 원자적으로 차단하지 않으며 디렉터리 생성자의 OS 수준 증명은 아니다.

## 미완료: Codex 비판자

현재 `harness/codex-hooks/adapter.mjs`의 `actorInput`은 메인 밖의 모든 작업 사본을 구현자로 분류한다. 실제 Codex 어댑터에 대한 임시 fixture에서 추적 파일의 `rm`과 사본 밖 `rm`이 허용되고 `.rv-*` 정리는 거부됐다. 공통 가드의 `review-critic` 역할 사례가 통과해도 실제 T3 Codex 비판자가 그 역할로 식별된다는 증거가 아니다.

구현자와 비판자의 권한을 브랜치명·detached HEAD·에이전트가 임의로 제공하는 문자열로 추측하지 않는다. 비판자의 실제 세션 역할을 신뢰된 T3 컨텍스트에 묶고 추적 파일·사본 밖 경로 거부를 유지하는 경로는 H-58 인계로 남긴다. 이 경로가 없으므로 H-58은 일부 구현이며 완료가 아니다.

## 검증과 인계

공통 역할 가드와 실제 Claude 진입 훅에서 허용·거부를 시험한다. 정적 링크와 `..`, 절대·홈 경로, 다른 등록 사본, 메인 저장소, 스테이징 삭제 중인 HEAD 추적 파일, 리다이렉트와 `rm -P`를 거부한다. 경계 옵션 없는 명령과 `--` 뒤의 가짜 옵션은 거부한다. 임시 복사본의 첫 전체 훅 시험은 pnpm·Prettier 경로와 생성 해시가 준비되지 않아 84개 중 3개가 실패했고, 그 실행에서는 하위 Cargo에 요청된 부하 제한 변수를 명시하지 못했다. 준비를 고치고 두 제한 변수를 설정한 재실행은 86개 모두 통과했다. 이후 대소문자 별칭 반례를 발견해 inode 비교를 보강한 뒤 전체 훅 시험 86개가 다시 통과했다. Linux 판정은 macOS에서 플랫폼 값만 바꾼 단위 시험이며 Linux에서 실제 `rm` 실행은 CI에서 확인해야 한다. H-58: 메인은 Codex 비판자의 신뢰 가능한 역할 식별과 적용 여부를 결정하고 실제 훅으로 검증한다.
