## 계산 정의와 책임

R-11 Q9는 로그가 아닌 단순 일수익률 `P[t]/P[t-1] - 1`을 지정한다. 수익률 n개의 평균을 빼고 제곱합을 n−1로 나눈 표본 분산의 제곱근이 일간 σ다. 연율 값은 요청 시 일간 근사 값의 제곱에 252를 곱한 제곱근으로 계산한다. 일간 계산과 실패 경로를 분리한다. D-21의 T = a·σ√H에는 daily만 쓴다. 로그를 추가하면 R-11 예제와 달라지므로 구현하지 않는다.

계산의 수학적 하한은 종가 3개(수익률 2개)다. 상한은 종가 10,001개(수익률 10,000개)이며 할당 전에 검사한다. 60거래일 정책은 D-21의 과제 생성과 D-09의 표시 책임이다. samples는 종가 수가 아닌 일수익률 관측 수다. 정책을 충족하려면 종가 61개가 필요하다. 59·60개 수익률 경계와 최대 표본을 테스트한다. D-11의 짧은 표본 계산은 R-11 예제 재현과 순수 계산의 재사용을 위한 것이며 표시나 과제 생성 허가가 아니다.

반환 타입 DailyVolatility와 AnnualVolatility는 서로 다른 봉인된 타입이며 정확한 Ratio나 Money가 아니다. 공개 임의 생성자·Default·역직렬화·가변 접근자·서로 간 변환은 없다. Decimal 접근자는 crate 안으로 닫는다. 외부에는 같은 종류끼리의 순서 비교와 volatility_display.rs의 Display 문자열만 제공한다. 퍼센트와 표시 자릿수 정책은 DS-05가 정한다. 문자열 기본 표현은 최대 30바이트이며 원래 계산값을 바꾸지 않는다. 모든 오류는 입력값을 담지 않는다.

## 계산 수단 비교와 선택

| 선택 | 확인 | 결정 |
|---|---|---|
| rust_decimal 1.43.0 maths | sqrt·checked_ln 제공, maths 자체 추가 의존성 없음. sqrt 구현은 1,000회 미만 assert와 일반 Decimal 연산자를 쓴다 | 채택하지 않음 |
| 같은 버전 maths-nopanic | ln 실패를 0으로 바꾼다. sqrt의 assert는 그대로다 | 채택하지 않음 |
| checked 십진 Newton 제곱근 | 256회 상한, 음수·산술 실패·미수렴은 오류, 로그 불필요 | 채택 |

| 0 | Some(0) | None | panic | 0 |
| −1 | None | None | panic | 0 |
| 1 | 1 | 0 | 0 | 0 |
| 2 | 1.4142135623730950488016887242 | 0.6931471805599453094172321216 | 동일 | 동일 |
| 10⁻²⁸ | 10⁻¹⁴ | −64.472382603833279152503760712 | 동일 | 동일 |

두 기능 실행에서 유효 입력 결과는 같았다. 이는 위 입력의 관찰이며 전체 입력의 panic 부재 증명이 아니다. 자체 구현의 제곱근은 0·1·2·최소 양수·MAX에서 수렴하고, 속성 테스트 4,096회에서 같은 입력의 결과가 같다.

의존성·기능·Cargo.lock 변경은 없다. rust_decimal =1.43.0의 default-features=false, features=[]를 유지한다. maths는 잠재적으로 전이 의존성을 추가하지 않지만 이번 제품에는 활성화하지 않았다. 기존 exact_arithmetic.rs와 money.rs는 수정하지 않는다. volatility_arithmetic.rs만 산술 허용 목록에 추가한다. 이 파일의 곱셈·나눗셈은 통계 근사 연산이며 정확 산술 판정과 별개다. 반환 경로는 DailyVolatility·AnnualVolatility·crate 내부 ApproximateRoot로 봉인한다.

## 정밀도와 검증 범위

중간 값을 표시 자릿수로 반올림하지 않고 checked Decimal의 표현 정밀도를 쓴다. Newton의 연속 추정 차이가 `10⁻²⁴ × max(1, 다음 추정)` 이하이면 종료한다. 256회 안에 이 조건을 만족하지 못하면 NonConvergence다. 이 종료 조건 자체를 수학적 전체 오차 보증으로 간주하지 않는다.

검증 계약은 다음과 같다.

- R-11 예제 값과 소수 여섯 자리까지 일치한다(기대값과 절대 차이 < 0.0000005). 일간 값은 독립 Python Decimal 정밀도 80 계산과 절대 차이 < 10⁻¹⁸도 검사한다.
- 제곱근 속성 테스트는 계수 1~10⁹, scale 0~28에 대해 `max(1,s)×10⁻²²` 양쪽 구간 끝을 제곱해 원 입력을 감싸는지 검사한다. 같은 Newton 알고리즘을 기준값으로 쓰지 않는다.
- 통계 속성 테스트는 가격 1~10,000, 종가 3~16개에 대해 평균을 쓰지 않는 `Σ(i<j)(rᵢ−rⱼ)² / (n(n−1))`과 대조한다. 일간·연율 σ의 제곱 오차는 `max(1, 기준 분산)×10⁻²⁰` 이하다. 각각 Config::with_cases(4096)을 명시한다.
- 부동소수점 금지는 테스트에도 적용된다. 참조는 정수·십진수만 쓴다.

| R-11 예제 9 입력 | 기대값 | 계산값(소수 6자리) | 원 기대값과의 차이 |
|---|---|---|---|
| 100, 102, 99, 101, 104, 100, 98, 103 | 일간 0.033867 | 0.033867 | 절대 차이 < 0.0000005 |
| 동일 | 연율 0.537618 | 0.537618 | 절대 차이 < 0.0000005 |

독립 80자리 기준은 일간 0.033866770723493094742386374464523430106995959079927823586817611823161294868396033, 연율 0.53761831825923449180117525446907671146036211084865965398579500630096088033534245다. 출력 근사 오차와 R-11의 여섯 자리 표시 반올림 차이를 구분한다.

Decimal 전체 범위에서 통계 결과의 일률적 절대 오차를 증명하지 않았다. 극단적인 비율·제곱합·연율 분산이 범위를 넘으면 Arithmetic이다. 미세한 제곱 편차는 표현 정밀도에서 0이 될 수 있다. 위 오차 계약의 표본 범위를 전체 입력 공간으로 확대해서 해석하지 않는다.

## 시세·캔들 경계

근거는 R-01 및 OpenAPI 1.2.28의 PriceResponse, Candle, CandlePageResponse, OrderbookResponse, OrderbookEntry와 /api/v1/candles 요청이다. 키·실계좌·서버 호출은 없다.

- Quote는 symbol, currency, last_price, nullable timestamp와 수집 시각을 보존한다. timestamp가 없는 것을 수집 시각으로 메우지 않는다. 가격이 있으면 통화가 같고 서버 기준 시각은 수집 시각보다 최대 2초까지 뒤일 수 있으며 AheadWithinTolerance 표지를 보존한다. 그 밖의 미래 시각은 오류다. ACC-4의 5분 노후화 판단은 소비자가 두 시각으로 한다.
- 스키마의 lastPrice와 호가 price는 decimal 문자열이며 minimum이 없다. 0이 스키마상 배제되지는 않지만 거래 정지·호가 없음의 0 표현은 명시되어 있지 않다. Price의 양수 계약은 유지한다. T-07이 0 현재가를 받으면 Quote의 None으로 변환하고 음수는 오류로 거부한다. 호가 0은 유효 Price로 만들지 않고 호가 어댑터에서 부재로 처리한다. 이 매핑은 보수적 내부 정책이며 실제 서버 의미를 확인했다는 뜻이 아니다. 호가 모델 자체는 D-11에 추가하지 않는다.
- Candle의 OHLCV는 스키마상 모두 필수·비nullable이다. 0·음수 가격을 None으로 바꾼 캔들을 만들지 않는다. 양수 Price 생성에 실패하면 해당 캔들은 오류다. 거래량은 0 이상 Quantity이며 소수 거래량도 허용한다. 최대·최소 범위와 통화 모순을 정규화하지 않고 오류로 반환한다.
- CandleTime은 Daily·Minute를 구분한다. 일봉은 보존한 오프셋의 현지 자정, 분봉은 종료 시각의 분 경계다. 둘 다 나노초 0이어야 한다. date는 기준 시각의 보존 오프셋에서 유도하므로 별도 입력 날짜와 모순되지 않는다. 분봉은 `[timestamp−1분,timestamp)` 구간이다. 미국 거래일과 분봉 종료 현지 달력 날짜의 관계는 장 캘린더를 아는 D-27·어댑터가 정한다.
- 봉은 InstrumentId, OHLCV, 기간·날짜·시각, 수정 여부와 기준, 수집 시각을 보존한다. API 응답에는 종목과 adjusted 필드가 없으므로 T-07은 요청 맥락을 반드시 붙인다. 스키마의 최신순 응답은 T-07에서 과거순으로 정렬하고 페이지 중복을 처리한 뒤 넘긴다. domain은 순서를 묵시적으로 바꾸지 않는다.
- PriceAdjustment::Raw와 Adjusted(AdjustmentBasis)는 타입으로 구별한다. Volatility는 일봉이며 전부 같은 종목·통화·수정 기준이어야 한다. 날짜와 절대 시각은 모두 엄격 증가해야 한다. 원주가, 분봉, 중복과 역순, 수정 기준 혼합을 거부한다. 주말 공백은 허용하지만 실제 휴장 여부는 거래일 달력을 가진 경계가 검증한다.
- AdjustmentBasis는 수정주가 요청 묶음의 기준 시각이다. 같은 기준임을 임의 추정하지 않도록 T-07이 동일 요청 맥락을 넘긴다. API는 개별 수정 계수를 주지 않는다. D-27은 기준가와 수정 캔들에서 동일 계수를 확보한 뒤 판정해야 하며 이 타입만으로 액면분할 환산이 완료되지는 않는다. 배당 반영 여부도 미확인으로 남는다.

문자열은 기존 Symbol·InstrumentId·NumericInput의 상한을 유지한다. 계산 목록의 상한을 별도로 검사한다. 주석·검사 끄기·새 의존성은 추가하지 않는다.

## 실행 환경

프로젝트 파일의 hooks=true는 확인했으나 실제 사용자 프로젝트 신뢰와 훅 정의 신뢰의 적용 증거는 없다. 이 세션은 T3 full-access이며 훅이 강제된다고 보고하지 않는다. 실제 홈 설정·인증을 읽거나 변경하지 않았다. frozen install, lefthook install과 기준 전체 검사가 통과했고 최종 커밋의 Git 훅 검사 결과를 별도로 보고한다.

추가로 수정주가 일봉의 현지 날짜가 증가해도 오프셋이 달라 절대 시각이 역전되는 입력을 거부하는 회귀 테스트를 넣었다. 두 속성 테스트는 각각 Config::with_cases(4096)을 유지한다. 수정 뒤 커버리지 검사는 예외 없이 통과했다.

## 적대적 리뷰 수정: 타입 경계와 소비 계약

수정 회차 끝에 master 819bbaee8571aa67a35336e20d10aa19116223d7을 병합했다.

- DailyVolatility·AnnualVolatility를 혼용하거나 자동 변환할 수 없다. D-21의 추정 과제와 D-14의 가격 범위는 DailyVolatility만 받는다. annualized()는 Result<AnnualVolatility, VolatilityError>를 요청할 때 새로 계산한다. 연율 분산이 넘쳐도 이미 계산된 일간 σ는 보존된다.
- 각 숫자 접근자는 pub(crate)다. 외부 crate에서 연율을 일간 인자로 넣는 재현은 E0308, 일간·연율의 Decimal을 Quantity로 꺼내는 재현은 E0624로 컴파일되지 않는다. Display와 같은 종류끼리의 cmp, 메타 접근자는 외부 컴파일 양성 대조군으로 확인한다.
- Volatility는 InstrumentId, 마지막 확정 기준일 as_of(), AdjustmentBasis, 수익률 표본 수를 보존한다. 공개 생성 경로는 검증된 캔들 계산뿐이다.
- 가격 범위 판정은 제곱 비교로 제곱근 없이 한다. D-14가 exact_arithmetic.rs의 넓은 정수 비교를 구현하며, D-14 병합 뒤 그 함수의 변동성 인자를 DailyVolatility로 연결한다. 이번 회차는 D-14 소유 파일을 수정하지 않는다.
- D-21의 a·σ√H는 volatility_arithmetic.rs 안의 전용 함수로 구현한다. 인자는 성향 계수의 전용 타입·DailyVolatility·거래일 수 전용 타입, 반환은 봉인된 근사 거리 타입이다. 근사 거리는 Money·Quantity·정확 Ratio로 변환하지 않는다. 아직 D-21 타입이 없으므로 미사용 빈 함수는 추가하지 않는다. sqrt(H)에 쓸 pub(crate) square_root(Ratio) -> Result<ApproximateRoot, VolatilityError>를 재사용하며 외부 API에는 공개하지 않는다.

## 시계 차이와 확정 여부

시계 차이 허용 폭의 문서 근거 없음. design·open-issues·R-01·OpenAPI에서 값을 찾지 못해 2초를 보수적 초안으로 정한다. 원 시각과 수집 시각은 바꾸지 않으며 ClockAlignment::AheadWithinTolerance를 보존한다. 정확히 2초는 허용, 2초+1ns는 오류다. 이 표지는 시계 차이의 원인을 인증하지 않는다.

CandleObservation은 수집 시각과 CandleStatus::{Finalized, InProgress}를 묶는다. 스키마에는 확정 여부 필드가 없다. T-07이 분봉 종료 시각·수집 시각 및 일봉 거래일의 MarketCalendar 종료 정보를 대조해 상태를 넣는다. 일봉 timestamp는 현지 자정이므로 이것만으로 당일 봉 확정을 추정하지 않는다. 진행 중인 분봉의 종료 시각은 최대 60초 뒤일 수 있다. 그 60초는 정상 구간으로 보고 추가 2초에만 시계 차이 표지를 남기며, 62초+1ns는 거부한다. 확정 분봉에는 정상 60초를 허용하지 않는다. 변동성 계산은 위치와 무관하게 InProgress 봉 하나라도 있으면 Unfinalized다. 어댑터가 거짓 확정 표지를 붙이는 사실까지 domain이 인증할 수는 없다.

## 정밀도 계약 보강

제곱근의 계약은 `|s−sqrt(x)| <= 2 ulp`다. ulp는 해당 값에서 96비트 계수로 표현 가능한 최대 scale의 단위이며 scale의 상한은 28이다. 현실적인 일간 σ(0.5~5%)에서는 ulp=10^-28이다. 큰 제곱근에는 소수 28자리가 물리적으로 들어가지 않는다. 예를 들어 10^14 크기에는 약 소수 14자리까지 가능하므로 모든 값에 절대 2×10^-28을 주장하지 않는다. 이 값별 ulp 해석은 사용자에게 확인 질문을 남기고 권고안으로 적용했다.

고정 seed 0x00d1_1006의 4,096건과 0·최소 양수·MAX에서 `max(0,s−2ulp)^2 <= x <= (s+2ulp)^2`를 10진 넓은 정수의 계수·scale 교차 곱으로 검증한다. Decimal 곱의 반올림이나 같은 뉴턴법을 기준으로 쓰지 않는다. 제곱근은 비음수이므로 0 부근의 하한은 0으로 제한한다. 결과는 floor나 최근접이라는 계약이 아니다.

현실 가격 생성기는 원화 1원·달러 1센트 단위, 시작 계수 1,000~1,000,000, 균형 잡힌 양·음 충격과 ±0.1% 추세의 기하 랜덤워크다. 종가 61~121개, 생성된 일 σ가 실제로 0.5~5%인지도 검사한다. 고정 seed 0x00d1_1007, Config::with_cases(1024)를 쓴다. 독립 수익률은 정수 가격 차이/직전 정수 가격을 넓은 정수 나눗셈으로 소수 40자리까지 얻는다(각 절삭 오차 <10^-40). 이후 분산은 `nΣx²−(Σx)²`를 넓은 정수로 정확히 계산한다. 구현의 Decimal 수익률·평균·편차 계산을 복제하지 않는다.

σ의 상대 오차는 제곱 분산의 상대 오차가 주는 상한으로 검증한다. 비음수 s와 v에 대해 `|s−sqrt(v)|/sqrt(v) <= |s²−v|/v`이므로 이 상한이 10^-15 이하인지 정수 교차 곱으로 검사한다. 1,024건에서 관찰한 최대 상한은 표시 절삭 여유를 포함해 1.2014×10^-24 미만이다. 이는 σ 상대 오차의 보수적 상한이며 전 Decimal 범위의 측정 최대값이라는 뜻이 아니다.

현실적인 σ 영역에서는 Decimal의 한 번에 구하는 분산 공식도 10^-15를 만족할 수 있으므로, 그것을 현실 생성기만으로 반드시 죽인다고 주장하지 않는다. 별도의 높은 추세·작은 잡음 소거 스트레스 입력을 두어 같은 수식의 Decimal 변형이 실패함을 검증한다. 일간 대신 연율 반환(컴파일 실패), 진행 중 봉 허용, 시계 차이 허용 폭 제거, 한 번에 구하는 분산 공식의 손 변형 네 가지를 각각 검출했다.

## 남은 정밀도·어댑터 책임

- 아주 작은 변동은 Decimal 수익률의 소수 28자리 절대 정밀도에 영향을 받는다. 리뷰 실측에서 가격 10^12의 ±1 변동은 상대 오차 2.5×10^-5, 10^15의 ±1 변동은 σ=0이었다. 현실적인 틱/가격 >=10^-8 영역의 리뷰 실측은 <=10^-13이다. 이 숫자는 리뷰어의 실측이며 이번 속성 생성기 결과와 구분한다. D-21은 σ=0 또는 정책 하한 미만이면 과제를 만들지 않는다. 하한의 구체 값은 D-21이 정한다.
- 수정주가 방어는 표지 일치까지다. 공개 AdjustmentBasis 생성자로 어댑터가 미수정 응답에 거짓 표지를 붙이면 domain은 알 수 없다. 요청 adjusted 여부는 있지만 응답에 적용 여부·수정 계수는 없다. T-07은 요청 맥락을 보존하고 가격제한폭을 넘는 하루 수익률을 이상 신호로 차단한다(시장별 제한과 미국 비제한 종목 정책은 문서/실측을 확인). D-21은 이상 신호가 남은 표본으로 과제를 만들지 않는다. 액면분할 반영 여부와 배당 조정은 실측이다.
- 날짜 공백을 임의의 하루 수익률로 해석하지 않도록 T-07이 거래일 캘린더와 대조한다. 누락된 거래일이나 거래 정지에 걸친 관측은 표본 적격성을 충족하지 않으며 D-21은 적격 시계열만 받는다. domain의 단순 날짜 증가 검사는 거래일 연속성을 증명하지 않는다.
- 정지일의 0 가격 OHLCV는 Price로 만들지 않는다. T-07이 해당 자료를 별도 거래 없음 상태로 구분해 보존하고 적격성에 반영한다. 영(0) 봉 하나를 묵시적으로 제거해 다일 수익률을 일수익률로 바꾸지 않는다. 국내 정지일의 실제 응답은 실측한다.
- MarketIndicatorCandle 일봉의 09:00 시작 시각은 이 종목용 현지 자정 CandleTime에 억지로 넣지 않는다. D-09 벤치마크의 별도 지표 봉 시간 계약으로 다룬다.
- Quote의 전일 종가·호가·지연 표지는 PriceResponse에 없다. 오늘 손익의 전일 종가와 D-26 호가는 각 작업이 출처를 정한다. Quote는 API의 Symbol, Candle과 σ는 저장 시계열의 InstrumentId를 유지한다. Symbol만으로 시장이나 안정적인 식별자를 추론해 통일하지 않는다. ADR 0032의 ResolvedOrderInstrument 역시 Symbol+조회 확정 Market이며 InstrumentId 매핑이 아니다. T-09의 종목 마스터가 두 식별자를 연결하고 주문에는 확정 시장 타입을 쓴다.
