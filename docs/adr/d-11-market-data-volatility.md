## 계산 정의와 책임

R-11 Q9는 로그가 아닌 단순 일수익률 `P[t]/P[t-1] - 1`을 지정한다. 수익률 n개의 평균을 빼고 제곱합을 n−1로 나눈 표본 분산의 제곱근이 일간 σ다. 연율 값은 분산에 252를 곱한 제곱근이다. D-21의 T = a·σ√H에는 daily만 쓴다. 로그를 추가하면 R-11 예제와 달라지므로 구현하지 않는다.

계산의 수학적 하한은 종가 3개(수익률 2개)다. 상한은 종가 10,001개(수익률 10,000개)이며 할당 전에 검사한다. 60거래일 정책은 D-21의 과제 생성과 D-09의 표시 책임이다. samples는 종가 수가 아닌 일수익률 관측 수다. 정책을 충족하려면 종가 61개가 필요하다. 59·60개 수익률 경계와 최대 표본을 테스트한다. D-11의 짧은 표본 계산은 R-11 예제 재현과 순수 계산의 재사용을 위한 것이며 표시나 과제 생성 허가가 아니다.

반환 타입 Volatility와 ApproximateVolatility는 정확한 Ratio나 Money가 아니다. 공개 임의 생성자·Default·역직렬화·가변 접근자가 없으며 읽기 접근자로 표본 수와 일간·연율 값을 모두 보존한다. 모든 오류는 입력값을 담지 않는다.

## 계산 수단 비교와 선택

| 선택 | 확인 | 결정 |
|---|---|---|
| rust_decimal 1.43.0 maths | sqrt·checked_ln 제공, maths 자체 추가 의존성 없음. sqrt 구현은 1,000회 미만 assert와 일반 Decimal 연산자를 쓴다 | 채택하지 않음 |
| 같은 버전 maths-nopanic | ln 실패를 0으로 바꾼다. sqrt의 assert는 그대로다 | 채택하지 않음 |
| checked 십진 Newton 제곱근 | 256회 상한, 음수·산술 실패·미수렴은 오류, 로그 불필요 | 채택 |

로컬 registry의 maths.rs를 읽고 저장소 밖 임시 Cargo 프로젝트에서 다음을 실행했다. 0·음수 ln의 panic은 임시 측정 프로그램에서만 catch_unwind로 관찰했다. 제품과 테스트에는 panic 회복 경로를 넣지 않는다.

| 입력 | maths sqrt | checked_ln | maths ln | maths-nopanic ln |
|---|---|---|---|---|
| 0 | Some(0) | None | panic | 0 |
| −1 | None | None | panic | 0 |
| 1 | 1 | 0 | 0 | 0 |
| 2 | 1.4142135623730950488016887242 | 0.6931471805599453094172321216 | 동일 | 동일 |
| 10⁻²⁸ | 10⁻¹⁴ | −64.472382603833279152503760712 | 동일 | 동일 |
| Decimal::MAX | 281474976710656.00000000000000 | 66.542129333754749704054283641 | 동일 | 동일 |

두 기능 실행에서 유효 입력 결과는 같았다. 이는 위 입력의 관찰이며 전체 입력의 panic 부재 증명이 아니다. 자체 구현의 제곱근은 0·1·2·최소 양수·MAX에서 수렴하고, 속성 테스트 4,096회에서 같은 입력의 결과가 같다.

의존성·기능·Cargo.lock 변경은 없다. rust_decimal =1.43.0의 default-features=false, features=[]를 유지한다. maths는 잠재적으로 전이 의존성을 추가하지 않지만 이번 제품에는 활성화하지 않았다. 기존 exact_arithmetic.rs와 money.rs는 수정하지 않는다. volatility_arithmetic.rs만 산술 허용 목록에 추가한다. 이 파일의 곱셈·나눗셈은 통계 근사 연산이며 정확 산술 판정과 별개다. 반환 경로는 ApproximateVolatility로 봉인한다.

## 정밀도와 검증 범위

중간 값을 표시 자릿수로 반올림하지 않고 checked Decimal의 표현 정밀도를 쓴다. Newton의 연속 추정 차이가 `10⁻²⁴ × max(1, 다음 추정)` 이하이면 종료한다. 256회 안에 이 조건을 만족하지 못하면 NonConvergence다. 이 종료 조건 자체를 수학적 전체 오차 보증으로 간주하지 않는다.

검증 계약은 다음과 같다.

- R-11 예제 값과 소수 여섯 자리까지 일치한다(기대값과 절대 차이 < 0.0000005). 일간 값은 독립 Python Decimal 정밀도 80 계산과 절대 차이 < 10⁻¹⁸도 검사한다.
- 제곱근 속성 테스트는 계수 1~10⁹, scale 0~28에 대해 `max(1,s)×10⁻²²` 양쪽 구간 끝을 제곱해 원 입력을 감싸는지 검사한다. 같은 Newton 알고리즘을 기준값으로 쓰지 않는다.
- 통계 속성 테스트는 가격 1~10,000, 종가 3~16개에 대해 평균을 쓰지 않는 `Σ(i<j)(rᵢ−rⱼ)² / (n(n−1))`과 대조한다. 일간·연율 σ의 제곱 오차는 `max(1, 기준 분산)×10⁻²⁰` 이하다. 각각 Config::with_cases(4096)을 명시한다.
- 부동소수점 금지는 테스트에도 적용된다. 참조는 정수·십진수만 쓴다.

| R-11 예제 9 입력 | 기대값 | 계산값(소수 6자리) | 원 기대값과의 차이 |
|---|---|---|---|
| 100, 102, 99, 101, 104, 100, 98, 103 | 일간 0.033867 | 0.033867 | 절대 차이 < 0.0000005 |
| 동일 | 연율 0.537618 | 0.537618 | 절대 차이 < 0.0000005 |

독립 80자리 기준은 일간 0.033866770723493094742386374464523430106995959079927823586817611823161294868396033, 연율 0.53761831825923449180117525446907671146036211084865965398579500630096088033534245다. 출력 근사 오차와 R-11의 여섯 자리 표시 반올림 차이를 구분한다.

Decimal 전체 범위에서 통계 결과의 일률적 절대 오차를 증명하지 않았다. 극단적인 비율·제곱합·연율 분산이 범위를 넘으면 Arithmetic이다. 미세한 제곱 편차는 표현 정밀도에서 0이 될 수 있다. 위 오차 계약의 표본 범위를 전체 입력 공간으로 확대해서 해석하지 않는다.

## 시세·캔들 경계

근거는 R-01 및 OpenAPI 1.2.28의 PriceResponse, Candle, CandlePageResponse, OrderbookResponse, OrderbookEntry와 /api/v1/candles 요청이다. 키·실계좌·서버 호출은 없다.

- Quote는 symbol, currency, last_price, nullable timestamp와 수집 시각을 보존한다. timestamp가 없는 것을 수집 시각으로 메우지 않는다. 가격이 있으면 통화가 같고 서버 기준 시각은 수집 시각보다 뒤일 수 없다. ACC-4의 5분 노후화 판단은 소비자가 두 시각으로 한다.
- 스키마의 lastPrice와 호가 price는 decimal 문자열이며 minimum이 없다. 0이 스키마상 배제되지는 않지만 거래 정지·호가 없음의 0 표현은 명시되어 있지 않다. Price의 양수 계약은 유지한다. T-07이 0 현재가를 받으면 Quote의 None으로 변환하고 음수는 오류로 거부한다. 호가 0은 유효 Price로 만들지 않고 호가 어댑터에서 부재로 처리한다. 이 매핑은 보수적 내부 정책이며 실제 서버 의미를 확인했다는 뜻이 아니다. 호가 모델 자체는 D-11에 추가하지 않는다.
- Candle의 OHLCV는 스키마상 모두 필수·비nullable이다. 0·음수 가격을 None으로 바꾼 캔들을 만들지 않는다. 양수 Price 생성에 실패하면 해당 캔들은 오류다. 거래량은 0 이상 Quantity이며 소수 거래량도 허용한다. 최대·최소 범위와 통화 모순을 정규화하지 않고 오류로 반환한다.
- CandleTime은 Daily·Minute를 구분한다. 일봉은 보존한 오프셋의 현지 자정, 분봉은 종료 시각의 분 경계다. 둘 다 나노초 0이어야 한다. date는 기준 시각의 보존 오프셋에서 유도하므로 별도 입력 날짜와 모순되지 않는다. 분봉은 `[timestamp−1분,timestamp)` 구간이다. 미국 거래일과 분봉 종료 현지 달력 날짜의 관계는 장 캘린더를 아는 D-27·어댑터가 정한다.
- 봉은 InstrumentId, OHLCV, 기간·날짜·시각, 수정 여부와 기준, 수집 시각을 보존한다. API 응답에는 종목과 adjusted 필드가 없으므로 T-07은 요청 맥락을 반드시 붙인다. 스키마의 최신순 응답은 T-07에서 과거순으로 정렬하고 페이지 중복을 처리한 뒤 넘긴다. domain은 순서를 묵시적으로 바꾸지 않는다.
- PriceAdjustment::Raw와 Adjusted(AdjustmentBasis)는 타입으로 구별한다. Volatility는 일봉이며 전부 같은 종목·통화·수정 기준이어야 한다. 날짜와 절대 시각은 모두 엄격 증가해야 한다. 원주가, 분봉, 중복과 역순, 수정 기준 혼합을 거부한다. 주말 공백은 허용하지만 실제 휴장 여부는 거래일 달력을 가진 경계가 검증한다.
- AdjustmentBasis는 수정주가 요청 묶음의 기준 시각이다. 같은 기준임을 임의 추정하지 않도록 T-07이 동일 요청 맥락을 넘긴다. API는 개별 수정 계수를 주지 않는다. D-27은 기준가와 수정 캔들에서 동일 계수를 확보한 뒤 판정해야 하며 이 타입만으로 액면분할 환산이 완료되지는 않는다. 배당 반영 여부도 미확인으로 남는다.

문자열은 기존 Symbol·InstrumentId·NumericInput의 상한을 유지한다. 계산 목록의 상한을 별도로 검사한다. 주석·검사 끄기·새 의존성은 추가하지 않는다.

## 실행 환경

프로젝트 파일의 hooks=true는 확인했으나 실제 사용자 프로젝트 신뢰와 훅 정의 신뢰의 적용 증거는 없다. 이 세션은 T3 full-access이며 훅이 강제된다고 보고하지 않는다. 실제 홈 설정·인증을 읽거나 변경하지 않았다. frozen install, lefthook install과 기준 전체 검사가 통과했고 최종 커밋의 Git 훅 검사 결과를 별도로 보고한다.

추가로 수정주가 일봉의 현지 날짜가 증가해도 오프셋이 달라 절대 시각이 역전되는 입력을 거부하는 회귀 테스트를 넣었다. 두 속성 테스트는 각각 Config::with_cases(4096)을 유지한다. 수정 뒤 커버리지 검사는 예외 없이 통과했다.
