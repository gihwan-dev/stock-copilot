# D-35: 호가, 종목별 가격대 호가 단위와 가격 제한

- 상태: 초안

## 출처와 초안 상수

로컬 OpenAPI 1.2.28의 OrderbookResponse·OrderbookEntry·PriceLimitResponse·ConditionRequest.orderPrice와 OrderCreateRequest.price를 읽었다. 미국은 ConditionRequest.orderPrice가 1달러 미만 0.0001달러, 이상 0.01달러 단위를 명시하며 기존 UsOrderPrice도 같은 가격 자릿수를 검사한다. 단순 자릿수 설명만으로 단위를 추정했던 이전 결정을 이 명시 문장으로 대체한다.

국내는 메인이 승인한 2023-01-25 시행 KRX 표를 **초안 상수**로 둔다. 출처는 [한국거래소 유가증권시장 업무규정 시행세칙 제32조 제2항의 호가가격단위](https://law.krx.co.kr/las/LawBon.jsp?lawid=000111)다. 스펙의 50,000~200,000원 100원 예시와도 일치한다. 전체 원문 직접 조회는 timeout·403이었고 검색에 노출된 공식 조문과 메인의 명시적 초안 승인을 근거로 했다. 현재 모든 시장·상품·특례의 현행 규정을 독립 인증했다는 뜻은 아니다.

| 표 | 가격대와 단위 |
|---|---|
| 국내 일반 주권 초안 | 2,000원 미만 1원 / 2,000~5,000원 미만 5원 / 5,000~20,000원 미만 10원 / 20,000~50,000원 미만 50원 / 50,000~200,000원 미만 100원 / 200,000~500,000원 미만 500원 / 500,000원 이상 1,000원 |
| 국내 ETF·ETN·ELW 표 초안 | 2,000원 미만 1원 / 2,000원 이상 5원 |
| 미국 스펙 표 | 1달러 미만 0.0001달러 / 1달러 이상 0.01달러 |

TickTable은 MasterInstrument에서만 생성한다. QuoteInstrument와 표 종류를 비공개 필드로 결합한다. KOSPI·KOSDAQ의 Stock·ForeignStock·DepositaryReceipt는 일반 표, Etf·ForeignEtf·Etn은 상품 표를 쓴다. KR_ETC, 국내 InfrastructureFund·Reit와 표 적용이 불확실한 유형은 Unavailable이다. 미국은 알려진 유형에 스펙 표를 쓰되 StockWarrants는 보수적으로 제외한다. 미지 시장·미지 유형은 항상 Unavailable이다.

현재 D-33에는 별도의 ELW 유형이 없다. STOCK_WARRANTS는 신주인수권증서/증권과 구별할 근거가 없으므로 ELW로 치환하지 않는다. ELW의 표 자체는 위 상품 초안과 같지만, 정확한 마스터 유형을 확보하기 전에는 ELW 추정 입력도 Unavailable이다. 사용자 확인 대상은 국내 초안 상수의 시행일·적용 유형·특례와 ELW 식별 계약이다. 새 사용자 설정이나 별도 승인 화면은 만들지 않는다.

## 가격의 함수와 종목 결합

호가 한 개에 단위 한 개를 붙이던 모델을 제거했다. TickTable::tick_size는 요청 종목과 가격을 받고 종목이 다르면 DifferentInstrument, 가격 통화가 다르면 CurrencyMismatch다. 공개 tick_alignment와 round_to_tick도 같은 종목 대조를 통과해야 한다. TickSize::from_response는 pub(crate)로 닫아 외부 crate가 임의 단위를 만들 수 없다. 표의 필드·종류도 외부에서 조립할 수 없다.

공개 반올림은 Down/Up을 받아 Price 또는 닫힌 오류를 반환한다. 내림이 0이면 BelowFirstTick이다. 내부 고정 단위 함수는 정확한 Money 후보를 계산하며, 그 후보를 공개 경계에서 양수 Price로 검증한다. 부동소수점과 중간 근사 반올림을 쓰지 않는다. 원래의 정수 계수 나머지 계산과 Amount의 정확 합·차 검증을 유지한다.

경계는 아래 구간에 포함하지 않고 경계부터 다음 구간 단위를 적용한다. 모든 표 경계는 양쪽 단위의 공통 배수이므로 입력 가격대의 정확한 내림·올림이 경계를 넘으면 경계 자체에 도달하며 결과 가격대에서도 유효하다. 예를 들어 49,990원은 아래 49,950원·위 50,000원, 0.99995달러는 아래 0.9999달러·위 1.00달러다. 각 표의 독립 정수 기준 4,096회 속성 테스트로 결과 가격대의 배수·방향·한 입력 단위 미만 차이를 확인한다. 지정가의 최종 방향 선택은 D-26 책임이다.

표현할 수 없는 내림 중간값 때문에 표현 가능한 올림까지 PrecisionLoss가 되는 극단 입력은 기존 내부 산술의 닫힌 실패로 유지한다. 현실 가격대의 위 표 계산에서는 이를 관찰하지 않았지만 임의 정밀도 십진수 전체에 대해 올림 가능성을 보장하지 않는다. 넘침·표현 손실을 가짜 가격으로 대체하지 않는다.

## 호가 순서와 봉인

스키마 설명은 매도 낮은 가격순·매수 높은 가격순이지만 국내·미국 예시는 매도 내림차순이다. 양쪽 모두 엄격 오름차순 또는 엄격 내림차순을 받아 매도 오름차순·매수 내림차순으로 정규화한다. 원래 순서는 Empty/Single/Ascending/Descending으로 보존한다. 중복·비단조는 닫힌 오류로 거부한다. 실제 서버의 순서는 O-15 실측 대상이다.

OrderbookInput은 봉인된 OrderbookLevel이 아니라 경계 입력 OrderbookLevelInput만 받는다. 단계 출력은 호가 생성 안에서 요청 QuoteInstrument에 결합한다. 출력 필드는 비공개이고 공개 생성자·Default·역직렬화·입력으로의 변환은 없다. 단계의 tick_alignment는 봉인된 종목을 사용하므로 다른 종목의 표와 섞으면 DifferentInstrument다. 원시 응답을 올바른 요청에 대응시키는 진위 확인은 어댑터 책임이며, 공개 숫자 접근자를 이용해 새 경계 입력을 발명한 호출자의 진술을 인증하지는 않는다.

통화 일치·양수 Price·0 이상 Quantity를 검증한다. 잔량 0·소수와 한쪽 또는 양쪽 빈 목록은 보존한다. 최우선 접근자는 NoQuote/Available이며, 빈 쪽과 잔량 0의 주문 가능 여부는 D-26이 판정한다. 각 단계가 표에 맞는지는 생성 때 거부하지 않고 닫힌 접근자로만 묻는다. 실측 전에 전체 응답을 잃지 않기 위한 선택이다.

정규화한 뒤 최우선 매수 < 최우선 매도를 강제한다. 매도 [101,102]와 [102,101] 각각에 대해 매수 100.5는 수용, 101.5·101·102는 CrossedOrLocked다. 단일가·동시호가의 실제 동가·교차 형태는 아직 미확인이라 거부를 유지한다. 표시용 소비자(A-14, O-04)는 현재 오류를 호가 없음과 구분할 수 없다. 필요해지면 닫힌 변형으로 보존하는 후속 계약이 필요하다.

## 시각과 가격 제한

호가는 nullable 서버 timestamp와 Clock 수집 시각을 각각 보존한다. 서버 시각 없음은 OrderbookTimeAlignment::Unknown이며 Aligned로 채우지 않는다. 서버 시각이 있으면 D-11 Quote의 assess_time을 재사용해 최대 2초 미래를 Known(AheadWithinTolerance)로 보존하고 그 밖의 미래는 거부한다. 오래된 호가를 거르는 신선도는 D-26 책임이고, Unknown인 호가를 신선하다고 판정해서는 안 된다.

PriceLimits는 종목·응답 통화·필수 서버 시각·수집 시각을 봉인한다. check는 요청 종목을 필수로 받아 DifferentInstrument를 먼저 검사하고, 같은 종목의 다른 통화 가격은 CurrencyMismatch다. 국내는 양수 하한·상한과 하한 ≤ 상한을 요구하며 양 끝을 포함해 Within/BelowLower/AboveUpper를 반환한다. 미국은 양쪽 미제공일 때만 Unlimited다. 국내 종목에 USD 응답 통화와 USD 상·하한이 함께 와도 CurrencyMismatch다.

국내 상·하한이 둘 다 없는 응답은 계속 거부한다. 정리매매에서 그러한 응답이 실제로 생기는지는 추정일 뿐이며 실측 대상이다. 한쪽만 제공·역전·미국 제한값 제공도 거부한다. 모든 오류는 입력값을 담지 않는다.

## O-15·A-20·D-26 인계

실측 담당은 tasks.md의 O-15 소액 실주문 검증(사용자)다. 실제 키·계좌·주문 실측은 사용자가 하며 이 작업에서는 호출하지 않는다. T-10은 랭킹·수급이므로 담당으로 지정하지 않는다. A-20은 아직 정의 대기인 호가·가격 제한 읽기 포트에 이 타입을 연결하고, D-26은 종목·시각·단위·가격 제한을 함께 대조한 뒤 지정가를 만든다.

작업표에 넣을 제안 문구(이 작업에서 tasks.md는 편집하지 않음): **시장·종목 유형·가격대별 초안 호가가격단위를 주문 오류 응답의 data.tickSize와 대조하고, 실제 호가 순서·시각 미제공·동시호가 교차·국내 상하한 미제공 사례를 기록한다.**

새 의존성·검사 끄기·실제 토스 호출은 없다. 프로젝트 훅 신뢰 적용 자체를 추정하지 않으며 직접 실행한 검사와 Git 훅 결과로 보고한다.

## 수정 회차 검증

새 API·정규화·종목 결합 테스트를 먼저 적용해 기존 인터페이스에서 컴파일 실패를 확인했다. 이후 Rust 린트와 대상 테스트를 통과시켰고, 커버리지 검사에서 지적한 도달 불가능한 표 조회 실패를 유한 구간과 마지막 구간으로 분리해 제거했다. 도달 가능한 최대 국내 가격 올림의 Overflow를 추가했다. 새 검사 끄기·허용 목록 변경·기존 master 테스트 변경은 없다.

외부 독립 crate의 정상 호출은 전후 모두 컴파일된다. TickSize::from_response 직접 호출은 E0624, OrderbookLevel 및 TickTable 필드 조립은 E0451, 봉인된 OrderbookLevel을 다른 호가 입력으로 넘기기는 E0308, PriceLimits::check의 종목 인자 생략과 임의 단위 기반 공개 반올림 호출은 E0061이다. 같은 통화의 다른 내부 종목 ID를 가진 PriceLimits·TickTable·호가 단계의 결합은 단위 테스트에서 DifferentInstrument로 거부한다. 외부 실험은 합성 마스터·가격만 사용하며 키·계좌·서버 호출은 없다.
