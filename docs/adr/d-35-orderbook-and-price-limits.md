# D-35: 호가와 가격 제한 사실

- 상태: 초안
- 기준: 6a33bc1b1ec4ef9dd055b60f10c0f93aba350a20
- 소비자: D-26 지정가 계산, A-20 읽기 포트, O-01 주문 게이트

## 근거와 계약

로컬 docs/toss-openapi-1.2.28.json의 GET /api/v1/orderbook, OrderbookResponse, OrderbookEntry와 GET /api/v1/price-limits, PriceLimitResponse를 확인했다. 외부 호출과 실계좌 자료는 사용하지 않았다. design 6.3, architecture 3.3, ADR 0029·0035·0055·0059를 따른다.

OrderbookLevel은 양수 Price와 0 이상 Quantity를 비공개 필드에 담는다. 두 값의 생성자가 음수 잔량과 0·음수 가격을 거부한다. 잔량 0과 소수 잔량은 스키마에 하한·정수 제약이 없어 보존한다. 잔량이 0인 단계를 체결 가능한 유동성으로 간주하지 않는 것은 D-26 책임이다. 가격 0을 호가 없음으로 매핑하는 경계 정책은 ADR 0035를 따르며 이 생성자에 0 가격을 넣을 수 없다.

Orderbook은 마스터에서 얻은 QuoteInstrument와 양쪽 단계, nullable 서버 timestamp, Clock 수집 시각을 봉인한다. 응답 통화·모든 단계·제공된 호가 단위의 통화가 식별 통화와 같아야 한다. asks는 엄격 오름차순, bids는 엄격 내림차순이며 중복·역순은 오류다. 자동 정렬하지 않는다. 스키마 설명은 낮은 매도·높은 매수 가격순을 명시하지만 국내·미국 매도 예시는 내림차순이다. 설명을 우선하는 보수적 정책이며 이 모순은 실측 대상이다.

양쪽이 있으면 최우선 매수 < 최우선 매도를 강제하고 동가·교차는 CrossedOrLocked다. 배열에는 minItems가 없어 한쪽 또는 양쪽 빈 목록을 허용한다. best_ask·best_bid는 Available 또는 NoQuote다. 모든 오류는 입력값을 담지 않는다. 변경 가능한 필드·Default·역직렬화는 제공하지 않는다. 공개 생성자는 값의 구조와 일관성을 검증하며 실제 응답의 진위를 인증하지 않는다. 응답과 요청 종목의 대응은 어댑터 책임이다.

서버 시각은 Quote와 동일 assess_time을 재사용해 수집 시각보다 최대 2초 앞선 경우만 AheadWithinTolerance로 보존한다. null을 수집 시각으로 채우지 않는다. 오래된 호가를 거르는 신선도 판단과 시각 미제공 시 주문 차단은 D-26 책임이며 D-35는 시각과 정렬 표지만 노출한다.

## 호가 단위와 정확 산술

호가 단위는 응답값으로만 받는다. OrderbookResponse와 PriceLimitResponse에는 호가 단위 필드가 없다. R-01 Q7과 주문 스키마는 국내 정수 원·호가 단위 준수, 미국 가격 자릿수 제한과 오류 응답 data.tickSize·nearestPrices를 설명하지만 시장·가격대별 호가 단위 표를 제공하지 않는다. 자릿수 제한을 유효 호가 단위 표로 간주하지 않는다. 추측한 표나 기본 단위를 만들지 않는다.

TickSize는 검증된 양수 Price로부터 from_response로만 만들며 통화를 보존한다. 이 이름이 외부 응답 출처의 진위를 인증하지 않는다. 현재 정상 조회 어댑터는 TickSizeAvailability::Unavailable을 전달해야 한다. Reported는 실제 단위 응답을 확보한 후에만 쓸 입력이다. 단위 미확보를 가격 제한 없음과 혼동하지 않는다. 오류 응답의 단위를 정상 조회의 확정 사실로 자동 승격하지 않는다.

tick_alignment는 OnTick/OffTick, round_to_tick는 Down/Up을 받아 같은 통화의 Money 또는 닫힌 오류를 반환한다. 매수·매도별 방향 선택은 D-26에서 한다. 내림 결과 0은 Money로 표현하며 Price로 변환할 때 거부된다. 반올림한 지정가가 유효 주문 가격이라는 증거는 아니다. D-26이 시장 정밀도·가격대 변경에 따른 단위·가격 제한을 다시 확인해야 한다.

십진수의 양수 정수 계수와 scale을 사용해 정확한 나머지를 구한다. 피제수의 scale이 작으면 매 단계 나머지에 10을 곱해 최대 28번 확장한다. 나머지는 96비트 단위 계수보다 작아 10배도 i128 안에 있다. 제수의 scale이 작으면 제수 계수를 확대한다. 확대가 i128을 넘으면 원래 96비트 피제수 계수보다 크므로 피제수 자체가 나머지다. 결과는 try_from_i128_with_scale로 검증한다. 내림은 기존 Amount의 정확 뺄셈, 올림은 내림값과 단위의 정확 덧셈을 사용한다. 표현 손실·넘침은 MoneyError를 담은 닫힌 오류이며 중간 반올림하지 않는다. 새 Decimal 산술 허용 목록과 의존성은 필요 없다.

## 시장별 가격 제한

PriceLimits는 동일한 QuoteInstrument·응답 통화·필수 서버 시각·수집 시각을 보존한다. 국내는 양수 하한·상한을 모두 요구하고 하한 ≤ 상한을 검증한다. 미국은 양쪽 미제공일 때만 Unlimited다. 국내 누락·미국 값 제공·한쪽만 제공은 오류로 닫는다. 미래 시각은 호가와 같은 규칙이다. check는 같은 통화만 받아 Within(양 끝 포함), BelowLower, AboveUpper, Unlimited를 구분한다. 이 사실과 다른 종목의 가격을 결합하지 않도록 소비자는 instrument도 대조해야 한다.

## 미해결과 인계

- T-10 실측: 정상 호가·가격 제한 응답의 단위 부재와 단위 확보 경로. 현재 tasks T-10은 랭킹·수급이며 이 요청의 실측 항목을 후속 담당자가 연결해야 한다. T-07도 실제 호가 응답 매핑을 확인한다. 단위를 확보하기 전 D-26 지정가 생성은 닫힌 실패여야 한다.
- T-10 실측: 설명과 반대인 매도 예시의 실제 순서, 잔량 0·빈 쪽·가격 0의 의미. 원시 응답의 정렬 오류를 감추지 않는다.
- 단일가·동시호가에서 실제 동가·교차가 나오는지 스키마와 design은 설명하지 않는다. R-01은 OPG 주문 지원만 설명하며 호가 형태의 증거는 아니다. 그러한 응답도 현재 생성자는 거부한다. 세션별 허용을 만들려면 별도 근거와 소비 계약이 필요하다.
- A-20은 아직 정의 대기인 읽기 포트에 이 타입들을 연결한다. 이 작업은 포트·어댑터·지정가 산정식을 구현하지 않는다.
- 프로젝트 hooks=true 및 Git 훅 설치를 확인했다. 이번 세션의 프로젝트 신뢰·훅 정의 신뢰 적용 증거는 없어 직접 실행한 검사 결과로 보고한다. 홈 설정을 읽거나 수정하지 않는다.
