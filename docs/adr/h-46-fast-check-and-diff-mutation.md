# H-46: 변경분 검사와 변경분 변이

- 상태: 구현 초안, 메인 결정 반영

## 결정

전체 just check의 이름과 보장은 유지한다. 이름 있는 비-master 작업 브랜치 커밋만 fast를 선택한다. master·detached HEAD·알 수 없는 상태의 커밋, push와 CI는 전체다. fresh-build·commit-guard 순서는 유지한다. fast도 commit-guard·test-diff·source-check·disable-report·hooks-installed를 실행한다.

fast의 영향 범위는 순수 경로 판정과 워크스페이스 역의존 폐쇄다. 변경 crate와 그것에 의존하는 crate의 clippy·nextest를 실행한다. 정적 검사는 전체, 프런트 검사 묶음은 프런트 변경 때만 실행한다. 하네스·xtask·설정·잠금 파일 및 미지 경로는 전체 검사로 승격한다. 커버리지는 전체 검사에 둔다. 선택 실행까지 확대하면 측정·예외 관리가 복잡해지므로 이번 fast에서는 생략한다.

속성 횟수는 기존 testkit의 테스트 도우미 한곳으로 모은다. 외부 의존성은 추가하지 않는다. 기본 256, 전체 레시피가 내보내는 STOCK_COPILOT_PROPTEST_CASES=4096에서는4096이다. 변수에 다른 값이 있어도4096으로 처리한다. 제품 테스트 본문은 횟수 표현만 기계 치환하고 단언은 유지한다.

참조 그래프와 추가 전용 증명 선택기를 제거한다. 변경분 변이는 변경된 대상 src 파일만, 그중 diff 영역과 겹치는 변이만 실행한다. 설치된 cargo-mutants 27.1.0의 --help와 공식 문서 https://mutants.rs/in-diff.html 에서 --in-diff가 diff 파일을 받고 변경 영역과 겹치는 변이에 적용됨을 확인했다. untracked Rust 파일은 /dev/null 대비 diff로 더한다. 삭제된 src 파일은 현재 변이 대상이 없으므로 지원 변경과 함께 밤 대상임을 알린다. 변경분은20분을 넘으면 소유 프로세스 그룹을 종료하고 실패한다.

밤 전체 변이는 기존4조각을 유지한다. 미검출과 시간 초과는 실패하며, always 단계로 결과를 Actions 작업 요약과 로그에 남긴다. 실패 알림은 기존 issue 알림이다. 워크플로 수동 실행은 하지 않는다.

## 감수하는 것

작업 브랜치 커밋이 전체 검사에서 깨질 수 있으며 메인이 master에 --no-ff 병합 커밋을 만들 때 잡힌다. 테스트 약화로 다른 파일의 변이가 살아남는 경우는 변경분에서 잡지 못하고 현재 밤 전체는 미완주 상태이므로 검출을 보장하지 못하며 H-47에서 보완한다. branch 이름·로컬 참조의 인증은 기존 OS·에이전트 경계에 의존한다. 같은 HEAD에서 브랜치를 바꾸거나 master를 이동시키는 권한이 있으면 로컬 이름만으로 의도를 인증할 수 없다. Git 환경 주입·잘못된 symbolic HEAD는 정규화와 보수적 전체 선택으로 막는다. 동시 참조 변경 경쟁은 기존 한계다.

## 검증 기록

실측과 수정/삭제 테스트 목록은 H-46 결과 보고에 기록한다. 성공하지 않은 전체 검사나 CI 실행은 통과로 기록하지 않는다.


고정 표본 수를 직접 단언하는 structured_categories_each_reach_4096_nonzero_nonunit_successes는 기존 단언을 보존하기 위해 property_cases_at_least(4096)을 부른다. 일반 속성의 기본256은 유지하되 이 범주별 표본 완전성 검사는 로컬에서도4096을 유지한다. 횟수 표현만 바꾸며 단언은 바꾸지 않는다. 과거 변경 실측에서256으로 실행하면 원본 단언이 실패함을 확인한 뒤 보완했다.


fast의 test-diff는 소스 비교를 저장소 전체에 유지하고, nextest 목록 확인만 선택한 crate들로 제한한다. 변경이 없는 xtask와 macOS 앱의 테스트 바이너리를 다시 컴파일하던 비용을 없앤다. Rust 테스트 모듈 등록을 지우는 반례가 선택된 crate의 목록 검사에서도 실패함을 고정한다. 전체 check의 test-diff는 작업 공간 전체 목록 검사를 유지한다.


변이 작업6개가 각각 nextest의 전체 코어 수를 쓰는 중첩 병렬화를 피하도록 작업별 nextest 스레드를 코어 수/작업 수(최소1, 최대4)로 제한한다. 테스트 집합·단언·20분 제한은 유지한다. cargo-mutants 공식 cargo-args 문서에서 --cargo-test-arg가 nextest에도 전달됨을 확인했다.


변이 자식 빌드에서는 개발/테스트 프로필의 디버그 심볼만0으로 둔다. 테스트 집합은 유지하고 debug assertions와 overflow checks를 명시적으로 켠다. 변이 자식에서만 opt-level=1을 사용한다. 변이마다 큰 테스트 바이너리의 심볼 정보를 다시 만드는 비용을 줄이는 선택이며, 실패 위치는 변이 보고의 소스 경로·줄과 nextest 테스트 이름으로 남는다. 전체 검사 빌드 프로필은 그대로다.


실측에서256회로 줄인 뒤에도 도메인 전체의 누적 테스트 CPU 비용이 변이 수에 비례해 남았다. 공식 성능 문서 https://mutants.rs/performance.html 의 프로필 선택 지침에 따라 변이 자식의 최적화 수준1을 적용했다. 심볼 제거·스레드 제한만 적용한 중간 실험과 이 최종 구성을 구분해 기록한다. 검사·단언을 끄지 않으며 전체 check 프로필은 그대로다.

변이 작업마다 Cargo 빌드 작업 수는1로 고정한다. 변이 작업 자체의 병렬도는 유지하되 각 작업이 여러 Rust 컴파일러를 다시 띄워 메모리와 CPU를 과점하지 않게 한다.


IPC 바인딩 생성 검사는 Rust 앱을 실제 빌드하므로 빠른 정적 검사 묶음에서 분리한다. 프런트가 바뀌거나 역의존 폐쇄에 src-tauri가 들어올 때만 실행한다. Rust 앱이 의존하지 않는 domain 변경으로 macOS 앱까지 빌드하지 않는다. 앱이 domain에 의존하게 되면 메타데이터 폐쇄가 자동으로 이 검사를 포함한다. Rust 앱 검사에 필요한 dist는 vite build로 준비하며, TS 타입·린트·JS 테스트 묶음은 프런트 변경 때만 실행한다. 이 경계는 순수 함수의 반례로 고정한다.


nextest는 테스트를 별도 프로세스 그룹에 띄운다. 20분 예산의 마지막10초는 소유 그룹에 SIGINT를 보내 cargo-mutants와 nextest가 자식 그룹에 종료를 전달하도록 둔다. 예산을 넘으면 소유 부모 그룹만 SIGKILL한다. 공식 nextest 신호 처리 계약과 cargo-mutants의 Ctrl-C 전파를 확인했으며 실제 nextest의 별도 테스트 PID가 종료되고 무관한 PID가 살아남는 회귀로 검증한다. ps는 macOS 테스트 샌드박스에서 실행할 수 없어 사용하지 않는다. 이름으로 종료하지 않는다. 시간 초과 배수는 자원 제한 뒤 기준 실행의5배이며 시간 초과는 계속 실패다.


fast의 브랜치 판정은 대소문자만 다른 master 표기와 비ASCII ref를 전체 검사로 보낸다. macOS 파일시스템의 Unicode 이름 접기 때문에 maſter 같은 표기가 master 파일과 같은 참조를 가리킬 수 있으며, 새 정규화 의존성을 추가하는 대신 불확실한 이름에 전체 검사를 택한다. H-44의 비교 기준 판정은 기존 의미를 유지하고 fast 선택만 이 조건을 더한다.

워크스페이스 설정·하네스·훅·CI 같은 공용 지원 입력만 바뀐 경우에는 특정 crate로 좁힐 근거가 없으므로 모든 변이 대상 crate를 밤 전체 실행 대상으로 출력한다. crate 안의 테스트·지원 파일은 그 crate만 알린다.


H-46 리뷰 결정: master는 메인만 움직인다. 전진은 --no-ff 병합 커밋 또는 master의 직접 커밋으로만 하며, 이때 master 커밋 훅이 전체 검사를 실행한다. --ff-only, branch -f, update-ref는 커밋 훅 밖이다. 이를 사용한 전진은 CI의 master 전체 검사가 사후에 알리는 한계가 있다. 구현 담당은 push와 master ref 이동을 하지 않는다.

밤 전체 변이는 완주 기록이 없다. 2026-11-13은 실패, 11-14는 네 조각이120분 부근에서 취소됐고 취소 전 한 조각에서 미검출18건이 확인됐다. 따라서 현재는 보완 장치로 작동한다고 볼 수 없다. 완주와 결과·취소 처리 보완은 H-47로 넘긴다. 변이 실행은 기본256회를 쓰며 상속된 전체 검사4096 환경을 제거한다.4096 강제는 전체 테스트 검사에만 적용한다.
