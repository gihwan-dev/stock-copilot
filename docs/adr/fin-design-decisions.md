# fin-design 묶음 결정 기록

디자인 점검 묶음(사용자 지시: AI 슬롭 제거, 창 높이·배경 문제가 구조적으로 생길 수 없게)에서 문서가 정하지 않은 것을 정한 기록이다.

| 작업 | 정한 것 | 다른 선택지 |
|---|---|---|
| FD-1 | 창 전체 높이·배경은 새 DS 원시 요소 `AppFrame` 하나만 맡는다. `App`이 모든 화면을 `AppFrame`으로 감싸고, 경로 화면은 `AppShell`(스크롤 영역 소유) 또는 `StepScreen`(스크롤 + 하단 고정 버튼) 안에서만 그린다. 설정·상태 경로와 오류 대체 화면도 `AppShell` 안으로 옮겼다. `AppShell`·`StepScreen`·`Page`는 `bg-bg`와 `h-screen`을 더 쓰지 않는다 | `theme.css` base 층에 html/body/#root 배경·높이 지정(고정 theme·DS02/DS19 CSS 게이트가 `vh`와 theme 변경을 막고, 화면마다 높이를 따로 정하는 구조는 그대로 남음) |
| FD-1 | ESLint 넘침 정책 #22(창 단위 길이)의 허용 파일을 `AppShell`·`StepScreen`에서 `AppFrame` 하나로 줄였다. `AppShell`·`StepScreen`에 `h-screen`/`min-h-screen`을 쓰면 실패하는 위반 예제를 `harness/eslint-violations/ds19-overflow.json`에 더했다. 기능 화면은 원래 `className`을 쓸 수 없으므로 배경·높이·바깥 여백을 직접 정할 길이 없다 | 기능 화면용 새 규칙(이미 클래스 자체가 막혀 있어 중복) |
| FD-2 | 창 채움 검사는 `shared/ds/testing/overflow-geometry.ts`를 늘리지 않고 `harness/screen-audit/window-fill.mjs`에 둔다. 앱 소스 규칙(DOM 값 접근·원시 타입 금지)과 250줄 상한 때문에 브라우저 측정 코드는 하네스 쪽이 맞다 | `overflow-geometry.ts` 확장(줄 수 상한 초과, 보호 파일 허용 목록 추가 필요) |
| FD-2 | 검사 항목: `[data-app-frame]`이 있고 배경이 칠해져 있으며 창과 같은 크기, 문서 자체의 가로·세로 스크롤 없음, 세로 스크롤 영역 안 가로 잘림 없음, `[data-pinned-actions]`(StepScreen 하단 버튼)이 창 안에서 보이고 가려지지 않음, 대화상자가 창 안. 점 찍어 보기(elementFromPoint)로 배경을 재는 방식은 모달 배경막이 pointer-events를 끄면 오탐해서 버렸다 | 화면 픽셀 비교(테마별 기준 색 추정이 불안정) |
| FD-2 | 장면은 `harness/screen-audit/scenarios.mjs`에 기존 노드 시험의 가짜 자료를 옮겨 28개(온보딩 4, 현황 6, 업데이트 시트, 종목 상세 3, 브리핑 3, 거래내역 3, 설정 3, 상태 3 등)로 둔다. 시험 `apps/desktop/tests/screen-window-fill.test.mjs`가 라우터의 모든 `path`에 장면이 있는지 확인하고, 모든 장면을 1440×900·1024×700·960×640(최소 창) × 라이트·다크로 검사한다. `node --test apps/desktop/tests/*.test.mjs`에 들어 있어 `check-lite`가 돈다 | 별도 just 레시피(justfile 고정 기대값 시험이 막음) |
| FD-2 | 브라우저는 저장소에 있는 `@playwright/test`의 Chromium을 먼저 쓰고, 그 판이 설치돼 있지 않으면 같은 Playwright로 시스템 Chrome(`channel: "chrome"`)을 쓴다. 새 패키지 없음 | 브라우저 내려받기 |
| FD-2 | 스크린샷은 `node harness/screen-audit/run.mjs <이름>`이 `target/screen-audit/<이름>/`(git 무시)에 1440×900·1024×700 라이트·다크로 남긴다 | `design/audit/`(git 무시 경로가 아님) |
| FD-3~5 | 현황 순서를 총평가(큰 숫자)·오늘 손익 → 통화별 → 보유 → 자산배분 → 신호 → 브리핑 → 성적표로 바꿨다. 첫 화면에서 "내 돈이 얼마인가"를 먼저 보이고, 신호·브리핑은 그 아래에 둔다 | 신호를 맨 위(신호가 없을 때 빈 카드가 첫 줄을 차지함) |
| FD-3 | 신호 카드는 수량·금액과 "실제 적중률을 반영한 확률 vs 기준 확률"만 위에 두고, 현재가·수수료·주문 후 비중·AI 원 확률·구간 적중률·판정 건수는 "앱이 계산한 값" 접기 안으로 옮겼다. 근거·반론·출처와 주문·넘기기는 그대로 보인다(AI 원칙: 근거는 늘 보임) | 9개 숫자를 같은 무게로 나열(초점 없음) |
| FD-4 | DS `Money`·`PriceChange`에 `emphasis`("inherit"·"display"·"large")를 더해 이미 있던 `text-num-display`·`text-num-lg` 토큰을 쓴다. 이름을 `size`로 하면 공개 props 규칙이 토큰 타입을 요구해 `emphasis`로 했다 | 기능 화면에서 숫자 크기를 직접 정함(클래스 금지라 불가) |
| FD-4 | 차트 색 모드는 플랫폼 훅 `useColorScheme`(data-theme 우선, 없으면 prefers-color-scheme)로 정한다. 기능 화면이 `theme="light"`를 고정해 다크 모드에서 흰 상자가 나오던 것을 고쳤다 | 차트마다 테마 prop 제거(DS 공개 props 변경 폭이 큼) |
| FD-5 | 상태 화면의 토큰 수처럼 `ChartDecimal`을 표에 보일 때 자릿수 구분이 되도록 DS `ChartNumber`를 공개 목록에 올렸다(이야기·부하 이야기·카탈로그 항목 추가) | `DataText`에 자릿수 구분(종목 코드 "005930"까지 바뀜) |
| FD-5 | master에서 들어온 시험 깨짐(첫 실행 종단 시험들이 새 `get_portfolio` IPC를 모킹하지 않음, 허용 목록 고정 시험·위반 예제에 `risk-schema.ts`·`status-schema.ts` 누락, DS 부트스트랩 시험의 축소 lib에 `text` 없음)을 check-lite 녹색을 위해 최소로 맞췄다 | 그대로 둠(check-lite 실패) |
| FD-7 | master의 G-03 `ipc/self_check.rs`·`tests.rs`가 arch-check `adapter-construction`에 걸렸다. 원인은 조립 검사가 지역 변수·매크로 안 이름 `sources`를 어댑터 크레이트 `sources`로 읽는 것과 시험이 `broker_toss::TossTimestamp`를 직접 쓴 것. 변수 이름을 바꾸고 시험 시각은 `domain::Timestamp::from_parts`로 만들었다 | xtask 검사 완화(보호 파일, 오탐 범위가 넓어짐) |
| DS-12 | 건너뜀. 컴포넌트 기준 화면은 정책(`harness/visual/policy.mjs`)상 linux/arm64 Docker 이미지에서만 만들 수 있고 호스트(darwin) 기준 화면은 거부된다. 이 기기의 Docker 데몬이 꺼져 있어 기준 화면을 만들 수 없다. 점검 하네스의 호스트 Chromium 스크린샷은 기계마다 달라 기준 화면으로 쓰지 않는다 | 호스트 스크린샷으로 기준 화면(정책 위반) |

## AI 슬롭 기준 (이 프로젝트용)

출처: kill-ai-slop(yetone, Apache-2.0)의 분류·탐지, impeccable(pbakaus, Apache-2.0)의 craft-floor·critique-rubric·distill·clarify·layout(Mode=Operate), hallmark(Nutlope, MIT)의 Floor. 문서는 저장소에 복사하지 않고 아래 규칙만 요약한다. 이 묶음 규칙·보안 제약과 부딪히면 묶음 규칙이 앞선다.

1. 한 화면 한 목적. 첫 화면은 그 화면이 답할 질문(현황: "지금 얼마인가")의 답을 큰 숫자로 먼저 보인다.
2. 같은 정보는 한 번만. 제목 → 카드 제목 → 표 캡션처럼 같은 말을 겹치지 않고, 편집 화면이 있으면 읽기 전용 요약을 따로 두지 않는다.
3. 카드는 묶을 이유가 있을 때만. 카드 안 카드, 표를 감싼 카드, 한 문장짜리 카드를 만들지 않는다. 여백과 정렬로 묶는다.
4. 배지는 예외에만. 모든 행에 붙는 "정상" 같은 기본 상태 배지를 두지 않는다.
5. 빈·오류 상태의 가운데 정렬 아이콘 블록은 화면의 주 블록 하나에만 쓴다. 보조 구역은 왼쪽 정렬 한 줄로 알린다.
6. 숫자는 한 형식: 자릿수 구분, 오른쪽 정렬, 단위 붙임. 같은 종류 숫자의 크기는 같다. 고정폭 글꼴은 코드·식별자(종목 코드, 버전)에만 쓴다.
7. 장식 금지: 그라데이션 글자, 의미 없는 그림자·이모지·아이콘, 한쪽 굵은 테두리 강조, 눈썹 제목(kicker), 01/02 번호.
8. 버튼 문구는 동작 이름(주문, 넘기기, 재시작, 다시 시도). 기본 버튼은 화면에 하나.
9. 문구는 짧은 존댓말 평서문. 고정 고지(U-17)는 법적 문구라 줄이지 않는다.
10. 레이아웃: 창 높이·배경은 `AppFrame`만, 화면은 `AppShell`·`StepScreen` 안에서만 그린다(FD-1·FD-2 검사).
