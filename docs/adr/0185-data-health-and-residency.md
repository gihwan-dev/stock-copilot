# ADR 0185: 데이터 수집 정상화, 업데이트 뒤 재시작, 상주와 로그인 시 시작

- 상태: 확정 (2026-11-26). v0.4.4 실사용 진단 기록(ADR 0181)에서 거래내역 호출이 초당 3회씩 끝없이 이어지고 다른 예약 작업이 멈춘 것을 보고 정한다.

## 관찰 (2026-11-26 10:16~13:11 진단 기록)

## 결정

1. 전체 검사의 구간 상한을 `u32::MAX`일로 한다(`FULL_INSPECTION_RANGE_DAYS`). 계획은 구간 하나가 되고, 어댑터가 전 기간을 한 번 받아 같은 대조 규칙을 그대로 적용한다. ADR 0117의 시작일 정책(개설일 미상이면 0001-01-01)과 완료 판정은 바꾸지 않는다. 어댑터에 `from`·`to` 질의를 붙이는 쪽이 더 싸지만 기존 어댑터 시험이 요청 줄 `?limit=100`을 고정하므로 이번에는 하지 않는다(후속).
2. 스케줄러의 모든 작업 실행 기록(`JobRecordSink`)을 진단 기록에 `job id=<code> result=<executed|skipped-missed-window|deferred|failed> ...` 한 줄로 남기고, 전체 검사 결과를 `sync job=transactions-full-inspection`으로 남긴다. 값은 `DiagnosticText`를 거친다.
3. 단일 실행 가드를 앱 상태(`InstanceSlot`)에 두고 `RunEvent::Exit`에서 먼저 놓는다. Tauri는 `Exit` 콜백 뒤에 재시작하므로 새 프로세스가 1차 인스턴스가 된다.
4. 메뉴 막대 아이콘이 없으면 Dock 아이콘(`ActivationPolicy::Regular`)을 쓴다(`residency_presence`). 창을 닫으면 지금처럼 숨기고 작업은 계속 돈다. Dock 아이콘을 누르면 `Reopen`으로 창이 다시 열린다. 트레이가 들어오면 같은 함수가 메뉴 막대 전용으로 바꾼다.
5. 로그인 시 시작은 외부 crate 없이 `~/Library/LaunchAgents/dev.stockcopilot.desktop.login.plist`(`/usr/bin/open -g -a <번들> --args --login-start`)로 한다. 설치된 `.app` 번들에서만 켠다. 첫 실행 표식(`autostart-configured`)이 없으면 기본 켬(P-4)으로 맞추고, 그 뒤에는 파일 유무가 사용자의 선택이다. `--login-start`로 켜지면 창을 띄우지 않는다. 설정의 "로그인 시 자동 시작"은 스위치가 되고 `set_auto_start` 명령으로 바꾼다.
6. 업종 분류는 `SectorClasses`가 토스 업종 목록과 대분류 구성 종목을 시장별 하루 한 번 받아 `sector_assignment_from_compositions`로 보유 종목을 분류하고, `GetAllocationView::with_assignments`로 자산 배분 조회에 넘긴다. 목록을 못 받으면 저장하지 않고, ETF·펀드는 종목 정보만으로 분류한다.
7. 뉴스 수집 계획은 5분 동안 다시 쓴다(`ReusedPlan`). 장 상태 전환은 최대 5분 늦게 반영된다.
8. 상태 화면에 "데이터 수집" 표를 둔다. `get_data_status`가 작업별 마지막 성공(저장된 실행 기록과 이번 실행 중 성공 중 늦은 것), 다음 예정, 최근 결과를 준다. 내부 작업 이름 대신 "보유 종목과 잔고", "거래내역", "일별 평가 기록" 같은 이름을 쓴다.

## 하지 않은 것과 후속

- 메뉴 막대 아이콘: `tray-icon`(과 전이 의존성)을 `deny.toml` 허용 목록에 넣어야 한다. 보호 파일이므로 사용자 승인이 필요하다.
- 기간 수익률·변동성·최대 낙폭: 도메인 계산(`Performance::calculate`, `performance_volatility`)은 있으나 확정된 입출금 기간(`FlowPeriod`)과 일별 평가 묶음을 읽어 넘기는 연결이 없다. 빠진 날 재계산(I-09: 일봉과 거래내역으로 과거 보유를 되짚어 평가)도 없다. 둘 다 금액 계산이므로 리뷰 등급 3의 별도 작업으로 한다. 이번 변경으로 일별 평가는 앱이 상주·로그인 시작하는 동안 매일 쌓인다. 변동성은 거래일 60개, 베타는 52주가 필요하다.
- 거래내역 어댑터의 `from`·`to` 질의: 결정 1의 비용을 더 줄인다. 기존 시험 변경이 필요하다.

## 다른 선택지

- 전체 검사 시작일을 최근 날짜로 줄이기: ADR 0117이 과거 누락을 숨긴다고 버렸다.
- `tauri-plugin-autostart`: 잠금 파일에 없고, 표준 라이브러리 파일 쓰기로 같은 일을 한다.
- 업데이트 뒤 자동 재시작: 사용자가 쓰는 중에 창이 닫힐 수 있다. "재시작" 버튼이 실제로 다시 켜지게 고치는 것으로 충분하다.
