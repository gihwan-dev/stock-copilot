# ADR 초안: D-17 성적표의 표본과 표시 경계

- 상태: 초안, 미해결 사항은 아래에 기록
- 기준: 0c9557a8625f36d858574ead5082f1e20a18968a
- 근거: design 6.6·AI-5, open-issues 1.4, R-12 2.3·2.4·3.4, ADR 0027·0029·0041·0051

## 지표와 집계 대상

| 지표 | 정의 | 집계 대상 | 근거 문장 |
|---|---|---|---|
| 구간별 적중률 | D-23의 구간 적중 수 / 구간 건수 | D-23이 선택한 비겹침 판정 사실 | design 6.6: “판정 건수는 같은 종목에서 기간이 겹치지 않는 추정만 센다” |
| Brier 점수 | BS = Σ(pᵢ−yᵢ)² / N, 성공 y=1, 손절·만료·모호 실패 y=0 | 위와 같은 집합 | design 6.6: “Brier 점수와 신뢰도 도표”; 두 지표의 별도 표본 규정은 없음 |
| 신뢰도 도표 | 각 구간의 평균 예측 확률, 실제 적중률, 건수 | 위와 같은 집합, D-23의 네 구간 | R-12 2.3: “50~60%, 60~70%, 70% 이상”; ADR 0041의 [0,50), [50,60), [60,70), [70,100] 초안 재사용 |
| 판정 보류 | N < 30이면 Pending, 30부터 Ready | 조합별 비겹침 판정 수 | R-12 2.4: “확정된 제안이 30건 미만이면 숫자만 보여 주고 ‘판정 보류’를 표시한다” |
| 비교 수 | 지금까지 비교한 고유 (제공자, 모델 이름, 모델 버전, 프롬프트 해시) 수 | 실행 기록에서 전달한 누적 비교 목록 | R-12 2.4: “여러 모델과 프롬프트 버전을 비교한 뒤 가장 좋은 것을 고르면 선택 편향이 생긴다”, “지금까지 비교한 조합 수” |

비교 수는 p₀만 내는 예측이나 상수 예측과의 Brier 비교가 아니다. 성적표 집계 키는 D-23의 모델·기간 그대로다. 프롬프트를 성적표 키에 추가하지 않는다. 비교 목록은 표본과 별도 메타데이터이며, 판정 전 시도와 버린 모델도 누적 목록에 포함하는 것은 실행 기록 소비자의 책임이다. AI-5의 같은 입력을 함께 돌린 짝지은 모델 비교는 D-17의 단일 조합 기술통계가 구현하지 않는다. 여기서 우위 판정은 내리지 않는다.

## 타입과 산술

Scorecard::calculate는 Calibration과 ScorecardComparisons만 받는다. 맨 성공·실패나 확률 배열을 받지 않는다. Calibration의 유일한 공개 사실 생성 경로는 D-27 판정 변환이다. Calibration의 비공개 키를 읽는 자유 함수 하나만 calibration.rs에 추가했다. 기존 impl과 테스트는 바꾸지 않는다.

Pending payload에는 키·현재 건수·비교 수만 있다. Ready payload와 타입이 달라 재포장할 수 없으며 공통 점수·도표 접근자가 없다. 빈 구간은 NoData이고 값 0을 만들지 않는다. 소비자는 UI messages.ts에서 Pending과 NoData를 각각 판정 보류와 자료 없음으로 번역한다. D-29·E-08은 표시 문자열과 닫힌 분기를 소비하고 새 수익률·신뢰구간 계산은 별도 타입으로 추가한다.

확률의 정규형은 스케일 2 정수 계수 q=1..99다. Brier는 정수 Σ(q−100y)² / (10000N)을 그대로 유지하고 표시에서 한 번 반올림한다. 평균 예측 확률도 Σq/(100n)이다. 구간 적중률은 CalibrationBinStats::hit_rate의 RatioQuotient를 그대로 사용한다. 최대 65,536건의 정수 비율이므로 스케일 28 근사가 표시 4자리의 비동률 경계를 뒤집지 않는다. 정확한 표시 동률은 유한 십진수이며 Exact로 유지된다.

표시는 소수 네 자리, 최근접·동률은 0에서 먼 쪽이다. R-12는 Brier의 계산 수치와 표시 자릿수를 지정하지 않으므로 이 정책은 보수적 초안이다. 모든 표시 반올림은 scorecard_arithmetic.rs에 있고 공개 결과는 ScorecardDisplay뿐이다. Decimal·Ratio·Money·Quantity 접근이나 변환, 일반 산술 API는 없다. Debug는 표시 숫자를 가린다. 계산 오류는 입력 없는 Calculation 하나다.

정수 wrapping 연산의 상한: Brier 분자는 65,536×9,801 < 2³⁰, 분모는 655,360,000, 표시 배율은 10,000이다. 평균 분자도 65,536×99 이하이다. 재사용 적중률의 계수는 10²⁸ 이하, 표시 배율 적용 후 10³² 이하로 u128에 들어간다. 이 경로에서 실제 wrap은 없다. 가변 분모 나눗셈은 checked_div로 거부한다. 새 의존성과 허용 목록 변경은 없다.

## 예제 대조

R-12에는 Brier나 신뢰도 도표의 입력별 정답 예제가 없다. 0.016은 외부 예측 대회의 개선량이며 이 앱의 검산 정답이 아니다. 아래는 정의식에서 직접 계산한 추가 계약 예제다.

| 예제 | 기대 결과 |
|---|---|
| p=60% 30건, 18 Hit·12 Miss | (18×0.16+12×0.36)/30 = 0.2400; 평균 예측 0.6000, 적중률 0.6000, 건수 30 |
| p=50% 30 Miss | Brier 0.2500, 평균 0.5000, 적중률 0.0000 |
| p=99% 전부 Hit 또는 p=1% 전부 Miss | Brier 0.0001, 허용 AI 입력의 최선 |
| p=1% 전부 Hit 또는 p=99% 전부 Miss | Brier 0.9801, 허용 AI 입력의 최악 |
| 이론적 완벽 p=y / 완전 반대 p=1−y | Brier 0 / 1; AI 입력에서 0·100%는 금지이므로 내부 표시 경계로만 검사 |
| 29 / 30건 | Pending / Ready |
| 같은 모델·프롬프트 반복, 새 프롬프트, 새 모델 | 중복 제외 3조합 |

R-12 3.4의 194건·197건과 Wilson 구간은 통계적 우위 검정·D-29의 후속 범위이며 30건을 실력 증명으로 바꾸지 않는다.

## 미해결과 한계

- Brier·도표의 표본을 별도로 구분한 문장이 없어 비겹침 집합을 채택했다. 전체 판정 집합과 다를 수 있으며 사용자 확인 대상이다.
- 네 자리 표시와 구간 초안은 확정 제품 결정이 아니다.
- 비교 목록의 완전성과 프롬프트 해시의 출처는 실행 기록 연결에서 검증해야 한다. 여기서는 받은 목록의 고유 쌍만 센다.
- 모델 별칭의 숨은 변경과 D-27 자료 누락의 선택 편향은 기존 제한이다.
- 프로젝트 hooks=true와 Git 훅 설치를 확인했지만 세션의 프로젝트 신뢰·훅 신뢰 강제 적용 증거는 확보하지 못했다. 직접 전체 검사와 Git 훅 결과로 검증한다.

## 구현 검증

- 테스트를 먼저 추가해 Scorecard API 부재의 컴파일 실패를 확인했다. 독립 유리수 대조·순서 불변·범위, 29/30 경계·허용 AI 확률의 최선/최악, 이론적 완벽/최악 예측을 각각 Config::with_cases(4096)로 검증한다.
- 성적표 테스트는 scorecard.rs 안에 둔다. 테스트 전용 src 파일은 커버리지 미측정으로 분류되어 같은 새 모듈로 옮겼다. 오류 전파는 조립 함수에서 실패 입력을 주입해 부분 지표가 반환되지 않음을 검사한다. 기존 테스트와 검사 정책을 변경하지 않았다.
- Clippy·source-check·raw-types 통과. 커버리지용 557개 테스트 전부 통과, 줄·영역 커버리지 위반 0건. 최종 전체 검사는 커밋 훅 결과로 보고한다.
- 외부 rustc 소비자의 정상 match는 컴파일 성공. Pending의 점수 접근, 표시 값의 Decimal 접근, Metrics 직접 생성, Display 직접 생성, CalibrationFact 직접 생성은 각각 컴파일 거부. 영속 compile-fail 하네스는 기존 ADR의 후속 범위다.
- 변이 검사 직전 로컬 master는 4c9428d790553d1d253c27e962b949bc8b229814이며 H-43·ADR 0054가 없어 자동 변이는 실행하지 않았다. 새 scorecard 파일 두 개에 손 변형 16개를 각각 주입했다: 표본 문턱 제거, Hit·Miss 분기 변경, 제곱 제거, Brier 누적 제거·분모 변경, 반올림 제거, 구간 평균 누적 제거·분모 변경, 관측 분기 제거, 적중률 값 제거, 마지막 구간 제거, 프롬프트·모델 버전 구분 제거, 비교 중복 제거 무력화, Debug 가림 제거. 모두 컴파일 뒤 실제 테스트 실패로 검출됐으며 생존·컴파일 불가·시간 초과 0개다. 원본을 복구했다.
