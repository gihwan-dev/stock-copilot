## 전체 입력과 조합

공개 계산 진입점은 Scorecards::calculate(전체 ScorecardObservation 목록, 기준 시각) 하나다. 호출자는 건수나 비교 목록 또는 이미 선별한 Calibration을 넘기지 않는다. ScorecardObservation은 추정 ID, 모델·기간 키, 프롬프트 ID, AI 확률과 D-27 EstimateOutcome 전체를 보존한다. 성공·실패·진행 중의 기간은 D-27 근거와 대조하며 다른 기간으로 다시 이름 붙이면 거부한다. 판정 불가는 D-27 근거가 없으므로 원래 실행 기록의 키를 받는다.

전체 결과는 모든 모델·기간 조합 목록과 전체 비교 수를 함께 갖는다. select는 전체 결과에서 하나를 읽는 접근자다. 단일 조합을 직접 계산하는 공개 API는 없다. 조합 하나를 읽어도 전체 비교 수가 보존된다. 빈 입력은 EmptyInput이므로 공개 전체 결과의 비교 수는 항상 1 이상이다.

비교 수는 입력에 실제 나타난 고유 (제공자, 모델 이름, 모델 버전, 프롬프트 ID) 수다. 만기 전·진행 중·판정 불가도 비교 수에 포함한다. 기간은 비교 수의 별도 차원이 아니며 통계 조합만 나눈다. 제공자만·이름만·버전만·프롬프트만 다른 경우를 각각 회귀로 고정한다. 같은 조합·추정 ID의 동일 입력은 한 번으로 치고, 판정·확률·프롬프트 등의 내용이 다르면 전체를 ConflictingObservation으로 거부한다. 입력 순서는 결과에 영향을 주지 않는다.

ScorecardPromptId는 ADR 0022의 불투명 ID 관례에 따라 ASCII 표시 문자 1~64바이트다. 임의 문장이나 빈 값은 받지 않으며 오류에는 입력을 싣지 않는다. **E 작업은 실행 기록의 프롬프트 해시로 이 ID를 만든다.** 이 타입은 해시 출처와 알고리즘 자체를 인증하지 않는다. 전체 입력은 65,536행까지 받으며 초과하면 자르지 않고 거부한다.

## 만기와 제외 건수

| 분류 | 규칙 |
|---|---|
| 전체 건수 | 중복을 제거한 해당 조합의 추정 수 |
| 만기 전 | D-27 근거의 원래 만기가 기준 시각보다 늦음. 일찍 성공·실패했어도 포함하지 않음 |
| 진행 중 | 만기가 기준 시각 이하이고 판정은 아직 Ongoing인 스냅샷 |
| 판정 불가 | D-27의 Unavailable. 근거와 만기가 없으므로 보수적으로 항상 이 사유로 제외 |
| 겹침 제외 | 만기가 지난 성공·실패 사실 중 D-23 선택 규칙이 제외한 수 |
| 판정 수 | 만기가 지난 사실 중 D-23이 선택한 비겹침 표본 수 |

기준 시각과 만기가 같으면 만기가 지난 집합에 들어간다. D-27 판정 근거 시각이 기준 시각보다 뒤인 입력은 FutureOutcome으로 거부한다. 알려진 만기는 만기 전 분류를 먼저 적용하므로 진행 중과 중복해 세지 않는다. 따라서 전체 건수 = 판정 수 + 만기 전 + 진행 중 + 판정 불가 + 겹침 제외다. D-27 근거가 없는 판정 불가에 만기를 꾸며 넣지 않는다. 그 원래 예정 만기를 별도로 복원하는 것은 후속 실행 기록 연결 대상이다.

성적표 진입점에서 D-27의 calibration_fact 변환을 직접 부르고, 만기가 지난 사실만으로 Calibration을 만든다. 성공은 Hit, 손절·만료·모호 실패는 Miss이고 진행 중·판정 불가는 사실을 만들지 않는다. D-23의 중복·구간·선택 규칙은 바꾸지 않는다. 이 구조는 만료 실패가 아직 확정되지 않은 동안 일찍 끝난 성공만 통계에 들어오는 편향을 차단한다.

## 지표와 표시

| 지표 | 정의와 집계 대상 | 근거 문장 |
|---|---|---|
| 구간 적중률 | 만기가 지난 비겹침 사실의 D-23 구간 건수·적중률 재사용 | design 6.6 “기간이 겹치지 않는 추정만 센다” |
| Brier | Σ(pᵢ−yᵢ)²/N, 같은 집합, Hit=1·Miss=0 | design 6.6 “Brier 점수와 신뢰도 도표” |
| 신뢰도 도표 | 같은 집합의 구간별 평균 예측 확률·실제 적중률·건수 | R-12 2.3과 ADR 0041의 네 구간 |
| 비교 수 | 전체 입력의 고유 모델·프롬프트 수 | R-12 2.4 “지금까지 비교한 조합 수” |

R-12와 design은 Brier·도표의 별도 집합을 구분하지 않으므로 D-23과 같은 비겹침 집합을 쓴다. 이번 수정 지시로 원래 만기가 지난 집합을 먼저 고정한다. 모델·기간을 합치는 경로는 없다. 조합마다 선택 판정 수 30건부터 Ready, 0~29건은 Pending이다.

**보류 수치:** design 6.6·R-12 2.4의 “숫자만 보여 주고 판정 보류”는 구간 수치와 Brier 모두에 적용한다. 문서가 Brier만 제외하지 않으므로 1~29건에도 Brier를 보여 주되 우위를 판정하지 않는 보수적 해석이다. Pending의 구간 수치·건수와 Brier는 각각 ScorecardDeferredNumber·Count·Brier의 JudgmentPending 분기를 거쳐야 읽는다. 표시 payload는 Ready의 ScorecardDisplay와 다른 봉인 타입이며 Ready 수치로 바꾸는 API가 없다. 0건 Brier와 빈 구간은 NoData다. 숫자 0으로 채우지 않는다. 사용자 화면은 E-08의 messages.ts에서 판정 보류·자료 없음 문구와 함께 그린다.

**소비자 경계:** 화면과 E 작업은 성적표 타입만 쓴다. D-23의 적중률 접근자와 selected_facts는 보정 전용이다. D-23의 기존 공개 API와 테스트는 유지한다. 하네스에 화면·E 작업에서 Calibration::for_combination().bin().hit_rate() 및 selected_facts()를 직접 호출하지 못하게 하는 호출 위치 제한을 인계한다. 현재는 문서 계약이며 정적 강제는 후속 작업이다.

## 산술과 수치 예제

확률의 정수 퍼센트는 probability 모듈의 전용 타입 접근자로 읽는다. scorecard 산술은 Decimal 계수의 스케일을 추측하지 않는다. Brier는 정확한 Σ(q−100y)²/(10000N), 평균 예측은 Σq/(100n)이다. 가변 정수의 합·차·곱·나눗셈과 거듭제곱은 checked 연산이며 실패는 Calculation이다. wrapping_div·wrapping_rem은 2·10000의 고정된 0 아닌 표시 제수에만 쓴다. 오류에는 원래 값이 없다.

구간 적중률은 D-23의 RatioQuotient를 재사용한다. 최대 65,536건에서 스케일 28 근사 오차가 표시 네 자리의 비동률 경계를 넘지 않으며, 정확한 표시 동률은 유한 십진수다. 모든 표시 반올림은 scorecard_arithmetic.rs에서 최근접·동률은 0에서 먼 쪽으로 수행한다. 공개 결과는 표시 문자열과 닫힌 분기이며 Money·Quantity·Ratio·Decimal 변환은 없다. Ready·Pending 표시의 Debug는 수치를 가린다.

R-12에는 Brier·도표의 입력별 정답과 표시 자릿수가 없다. 0.016은 외부 대회의 개선량이다. 아래 예제는 정의식에서 직접 도출한 검산 계약이며 네 자리 표시는 초안이다.

| 예제 | 결과 |
|---|---|
| 60% 30건, 18 Hit·12 Miss | Brier 0.2400, 평균 예측 0.6000, 적중률 0.6000 |
| 50% 30 Miss | Brier 0.2500 |
| 99% 전부 Hit / 1% 전부 Miss | 허용 AI 확률의 최선 0.0001 |
| 1% 전부 Hit / 99% 전부 Miss | 허용 AI 확률의 최악 0.9801 |
| 이론적 완벽 / 완전 반대 | 0.0000 / 1.0000; AI 입력의 끝점은 여전히 금지 |
| 29 / 30건 | JudgmentPending 수치 / Ready 수치 |

## 미해결과 인계

- **E-08 제안:** 항상 p₀·항상 50%를 내는 예측의 Brier를 나란히 보이기. R-12·design의 필수 요구가 아니므로 이번 구현에는 넣지 않는다.
- E 작업은 모든 추정의 최신 판정 스냅샷과 프롬프트 해시를 공급해야 한다. 타입은 넘기지 않은 DB 행이나 숨은 비교 시도를 탐지할 수 없다. 같은 조합·ID의 여러 판정 버전을 넣어 좋은 결과를 선택하지 말고 최신 스냅샷 하나를 만든다.
- 판정 불가의 원래 만기는 현재 D-27 결과에 없다. 판정 불가 건수에는 보존하지만 만기별 분해는 할 수 없다.
- D-23 접근자의 화면·E 직접 호출 제한은 하네스 후속이다.
- 네 자리 표시·네 구간과 비겹침 통계 집합은 사용자 확인 대상이다. 30건은 표시 최소 기준이며 실력 증명은 아니다. D-29의 수익률·신뢰구간과 AI-5의 짝지은 우위 비교는 후속이다.
- 프로젝트 hooks=true·Git 훅 설치와 직접 검사 결과를 구분하며, 현재 세션 신뢰의 강제 적용을 추정하지 않는다. 새 의존성·검사 끄기·실제 계좌 접근은 없다.

## 리뷰 수정 검증

수정 전 master 병합 커밋의 전체 검사에서 848개 테스트와 커버리지용 564개 테스트가 모두 통과했다. 새 진입점 테스트를 먼저 추가해 API 부재의 컴파일 실패를 확인한 뒤 구현했다. 수정 후 표적 테스트 18개, Clippy·source-check·raw-types와 커버리지용 571개 테스트가 통과했고 줄·영역 커버리지 위반은 0건이다. 최종 전체 검사는 커밋 훅 결과로 보고한다.

- `all_outcomes_exclusions_duplicates_overlap_and_maturity_are_counted`: D-27의 실제 판정 결과로 전체·진행 중·판정 불가·만기 전·겹침 제외·판정 수와 중복 제거를 대조한다.
- `early_success_does_not_change_scores_before_maturity_for_4096_cases`: 일찍 성공한 추정의 확률과 입력 순서를 바꿔도 만기 전에는 기존 점수·도표가 같고 만기와 같은 시각부터 표본에 들어간다.
- `comparison_identity_includes_provider_name_version_prompt_and_all_groups`: 제공자만·이름만·버전만·프롬프트만 다른 경우, 기간만 다른 경우와 전체 조합 보존을 검사한다.
- `pending_numbers_require_judgment_pending_branch_for_29_and_empty`: 29건의 수치와 건수는 보류 분기를 강제하며, 0건 Brier는 자료 없음이다. 기존 독립 유리수·순서·범위·29/30·완벽/최악 속성은 각 4,096회를 유지한다.

외부 rustc 소비자의 전체 성적표·명시적 보류 분기 소비는 성공했다. 단일 조합 직접 계산, 보류 Brier의 Ready 표시 타입 사용, 보류 숫자의 Ready 표시 타입 사용, 전체 결과 위조, 별도 비교 목록 입력, 수치 Decimal 접근은 각각 컴파일 거부됐다. 영속 compile-fail 하네스는 후속이다.

병합한 기준에는 H-43·ADR 0054가 없어 자동 변이는 실행하지 않았다. 성적표 파일의 손 변형 24개를 검증했다. 제공자·모델 이름 제거를 포함한 비교 ID 4개, 중복 제거, 표본 문턱, 만기 검사·등호, 미래 판정, 세 제외 사유, 빈 입력·충돌, Hit·Miss·제곱·두 분모·반올림·관측 분기·마지막 구간·두 Debug 가림을 대상으로 했다. 초기 Hit 변형은 미사용 함수 경고로 컴파일되지 않아 검출로 세지 않았고, 같은 의도의 컴파일 가능한 변형으로 다시 주입해 검출했다. 최종 24개는 모두 컴파일 뒤 실제 테스트 실패로 검출됐으며 생존·시간 초과 0개다. 원본 복구 후 표적 18개를 다시 통과했다. 기존 master 테스트·검사 기준은 바꾸지 않았다.

최종 커밋 검사 첫 시도에서는 기존 Git 훅 회귀 4개가 실패했다. 두 실패에는 하위 commit-guard의 signal 9 종료가 명시됐고 다른 둘은 훅 단언 실패였다. 코드·테스트·검사를 바꾸지 않은 별도 재실행에서 네 테스트가 모두 통과했다. 최초 실패 원인은 확정하지 않았으며 전체 검사를 동일한 정책으로 다시 수행한다.
