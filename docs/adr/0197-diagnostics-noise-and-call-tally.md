# ADR 0197: 진단 기록에서 정상 동작을 빼고, 성공한 토스 호출은 30분 단위로 묶는다

- 상태: 확정 (2026-11-27). v0.5.13 진단 기록이 하루에 1 MiB를 넘겨 회전했다. ADR 0181·0193의 후속이다.

## 관찰

v0.5.13 시작 뒤 1,588줄 가운데 대부분이 정상 동작이었다.
- 성공한 토스 호출 줄: 환율 576, 장 운영 캘린더 547, 일봉 105, 매수가능금액 64 등이다.
- 과거 일봉 조회마다 `toss-response ... mismatch=Validation detail="history-skipped unreadable=0 ... daily-time=..."`가 찍혔다. 버린 행이 없는 경우와 장중 미완결 봉 하나를 뺀 경우(`open-session=1`)도 포함됐다.

## 결정

1. 과거 일봉 경로는 실제로 버린 행(읽을 수 없음, 미래 시각, 봉 생성 실패)이 있을 때만 `history-skipped unreadable=N future=N candle=N`을 남긴다.
   - 자정이 아닌 일봉 시각은 정규화로 정상 처리되므로 설명을 남기지 않는다.
   - 장중 미완결 봉 제외는 정상 동작이므로 세지 않는다.
2. 상태 2xx이면서 오류 코드가 없는 토스 호출은 줄로 쓰지 않고 경로별로 센다.
   - 30분이 지난 뒤 들어오는 첫 사건에서 `toss-calls ok minutes=N GET /api/v1/...=N ...` 한 줄로 내보낸다(`CallTally`).
   - 상태가 2xx가 아니거나 오류 코드가 있거나 전송이 실패한 호출, 그리고 다른 모든 사건(동기화, 작업, 응답 거절, 토큰)은 지금처럼 바로 쓴다.
   - 성공 호출의 응답 시간(`ms`)은 집계에 남기지 않는다. 느림은 시간 초과로 실패 줄에 남는다.
   - 앱이 종료될 때 남은 집계는 버려진다. 다음 실행의 첫 30분 집계부터 다시 남는다.
