# 토스 묶음 구현 결정 기록 (ADR 0173 경량 절차)

| 작업 | 정한 것 | 다른 선택지 |
|---|---|---|
| T-19 | `broker-toss` 안에 외부 패키지 추가 없이 순수 Rust FIPS 180-4 SHA-256을 두고 `docs/toss-openapi-1.2.28.json`의 원시 해시(`broker_toss_schema::SPEC_SHA256`)와 정규화 JSON 해시를 테스트로 고정 검증한다 | `broker-toss/Cargo.toml`에 `sha2` 의존성 추가 및 `Cargo.lock` 갱신 |
| T-19 | 공개 스펙 조회 전용 `PublicDocsRoute`와 `TossHttpClient::get_public_doc`(비인증 GET, `Last-Modified` 헤더 수집)을 두고, `TossSpecSource`는 `ReadEndpoint`와 분리된 닫힌 `SpecFetchError`를 반환한다 | `ReadRoute`·`ReadEndpoint` 확장(`store-sqlite` 태그 및 OpenAPI 경로 검사 계약까지 연쇄 변경) |
| T-19 | `CheckTossSpec::check`는 드리프트 감지 시 `SpecDriftStatus::DriftDetected { reasons, review: SchemaReviewState::PendingTypeDiffReview }`를 고급 상태 저장소(`TossSpecStatusRepository`)에 기록하고 상태가 바뀔 때만 `DomainEvent::SelfCheckChanged`를 발행하며 주 화면 배너(`SelfCheckAction`)를 만들지 않는다 | `SelfCheckInput`에 스펙 상태를 합쳐 주 화면 경고 경로와 섞음 |
| T-17 | 새 외부 웹소켓 패키지(`tokio-tungstenite` 등)를 추가하지 않고 `reqwest 0.13.5`의 HTTP/1.1 `Response::upgrade()`와 순수 Rust RFC 6455 프레임 코덱(`ws_frame.rs`)으로 구현해 `https_only(true)`·`no_proxy()`·`LoopbackResolver`·`arch-check` `http-socket` 제약을 그대로 유지한다 | `tokio-tungstenite`·`tungstenite`를 새로 추가하고 `deny.toml`·`Cargo.lock`·`arch-check` 예외를 확장 |
| T-17 | 웹소켓 전용 `TossWsEndpoint`(`https://openapi-ws.tossinvest.com`, `local(port)`)와 `TossWsConnector`(전체 타임아웃 없는 `configured_ws_client`)를 `endpoint.rs`·`http.rs`의 동일 닫힌 가드(`arch_check/source/endpoint.rs`) 아래 둔다 | `TossEndpoint`에 URL 치환 메서드를 추가하거나 전체 30초 타임아웃 `TossHttpClient`를 공유 |
| T-17 | `TossWsClient::reconcile_orders_with_token`은 전달받은 토큰으로 `TossHttpClient::get`을 직접 호출하고, `Arc<TossWsClient>`에 `TokenRenewal`을 구현해 `TokenManager`의 만료·재발급 경로(발급→닫기→재연결→재선언→주문 재조회)에서 교착 없이 동작하게 한다 | `TokenRenewal` 내부에서 `TokenManager::get`을 재귀 호출하거나 별도 브리지 래퍼 타입 추가 |
| A-26 | `domain`에 소유형 날짜별 입력 `ValuationDayInputs`(행 집합·이력·`DayCashLedger` 둘·관측)와 `ValuationGapPlan::excluding`을 두고, `application::BackfillValuationDays`가 계획 → 성공일 조회(`ValuationDaySuccessSource`) → 제외 → 날짜별 입력 수집(`ValuationDayInputSource`) → 재계산 → 날짜별 기록 순으로 돈다 | 입력 공급 포트가 빌린 `ValuationRecomputeInput`을 직접 돌려주게 함(수명 때문에 비동기 포트에 맞지 않음) |
| A-26 | 입력 포트의 `ValuationInputError::Missing(SnapshotError)`는 그 날짜만 실패로 기록하고, `Port(PortError)`·저장소 오류는 그 자리에서 실행을 멈춘다(앞서 기록한 날은 남고 다음 실행에서 이어 감). 성공일만 제외하므로 실패일은 다음 실행에서 다시 시도한다 | 일시 장애도 그 날짜의 실패로 기록 |
| T-14 | 비식별화 도구는 `toss-smoke deidentify <녹화> <폴더>` 하위 명령(`toss_smoke::deidentify`)으로 둔다. 계좌번호 키 값은 `synthetic-account-<n>`, `*Seq`는 1부터의 일련번호, 숫자·숫자 문자열은 0·부호·소수 자릿수를 지키는 합성값으로 바꾸고 종목 코드·식별자·통화 키는 남긴다. 결과에 계좌번호 형태가 남으면 파일을 만들지 않는다. 새 실행 파일은 source-check 허용 목록 변경이 필요해 쓰지 않았고 `usage_text`는 기존 고정 테스트 때문에 바꾸지 않았다 | 별도 `toss-deidentify` 실행 파일, `xtask` 명령 |
| T-14 | 저장소 픽스처 전수 검사(`toss-smoke/tests/deidentify_tests.rs`)는 하이픈으로 묶인 세 묶음 이상·9자리 이상 숫자(ISO 날짜 제외)와 계좌 키의 비합성 값을 계좌번호 형태로 보고, `/api/` 픽스처의 `origin`은 `synthetic`·`deidentified`만 허용한다. 기존 `t05-accounts.json`의 `00000000731`은 마스킹 테스트가 쓰는 합성 자리표시 값이라 0 여섯 개로 시작하는 계좌 값은 합성으로 인정한다. 하이픈 없는 긴 숫자는 시가총액 등 금액과 겹쳐 계좌 키에서만 본다 | 기존 픽스처 값을 바꿔 기존 마스킹 테스트를 약하게 만듦 |
| G-05 | 단계 0은 `ResearchEvidenceSource` 포트가 ID·수집 시각을 단 `EvidenceItem`을 내고 `EvidenceBundle`이 빈 묶음·중복 ID·256개 초과를 거부한다. 단계 1 검색어는 `research_search_plan`이 "종목명 주제어"(코드 주제 목록 `ResearchTopic`)로만 만들고 `WebSearchGuard`(SEC-9)를 통과한 것만 넘긴다. 단계 2 결과는 `CollectedItem::from_web`(출처 `web`)으로 저장한 뒤 `web-<n>` ID와 수집 시각으로 묶음에 더한다. 웹 수집 실패·승인 검색어 없음은 로컬 증거만으로 계속한다 | 웹 수집 실패 시 연구 중단 |
| G-10 | 단계 3은 `ResearchAnalyst::draft(stance, model, ledger)`를 긍정·부정 각각 한 번씩 같은 증거 묶음으로 부르고 상대 초안은 인자에 없다. 모델은 `ResearchModels`로 입장별로 따로 정한다. 단계 4는 `ClaimVerifier::verify(claim, cited)`가 주장 하나와 그 주장이 인용한 원장 항목만 받는다(초안 전체 없음). 원장에 없는 인용이 하나라도 있으면 AI를 부르지 않고 `Unsupported`/`MissingEvidence`로 둔다. 분석 실패(중단 포함)는 그 단계를 멈춘다 | 검증기에 초안 전체 전달, 없는 인용만 빼고 검증 |
| G-11 | 단계 5는 `ResearchConcluder`가 검증된 주장과 원장만 받아 노트 패치(`ThesisPatch`)와 추정 제출 목록을 낸다. 단계 6(`FinishResearch`)은 추정 3개 초과 거부, 원칙 검사 포트(`ResearchPrincipleCheck`)의 위반 목록, 웹 근거뿐인 지지 주장 경고, 주장 집계, 노트 적용 후 상태·확인 대기 수를 모으고 추정은 기존 `SubmitEstimate`로 넘긴다(임계값 비교는 기존 신호 경로). `RunDeepResearch`는 단계마다 `ResearchCheckpointStore`에 저장하고 저장된 단계부터 이어 가며, 분석의 `Interrupted`는 오류가 아니라 `Paused(단계)`로 돌려준다 | 단계 안 주장별 저장, 원칙 위반 시 추정 제출 중단 |
| G-06 | "주로 야간"은 KST 22:00~06:00만 실행하는 창(`deep_research_window`)으로 정하고 낮에는 22:00까지 기다린다. 예약 한도 비율(AI-2)은 기존 `BackgroundBudget::admit/release`(AI-06의 70% 한도)로만 판단한다. `RunDeepResearchCycle`은 보유·관심 종목을 차례로 돌며 야간 밖·한도 도달·채팅 끼어듦(`Paused`)에서 그 종목을 다음 시작점으로 돌려준다(체크포인트로 이어 감). 시작점이 목록에 없으면 처음부터 돈다 | 낮에도 한도가 남으면 실행, 유망 후보까지 순환 |
| G-07 | 후보는 `DiscoveryLists` 포트의 랭킹·섹터 구성·수급 상위 목록에서만 뽑고(`DiscoverCandidates`), 같은 종목은 출처를 합친다. 시가총액은 섹터 구성의 값만 쓰며 원화 10조 이상 대형·1조 이상 중형·그 밖과 미상은 소형으로 두고 기본 할당은 대·중·소 2·3·3(`DiscoveryQuota::DEFAULT`), 남는 칸은 다른 구간으로 넘기지 않는다. 구간 안에서는 출처 수가 많은 순, 최종 순서는 시드 기반 결정적 섞기. 보유·관심 등 이미 아는 종목은 뺀다. 목록 하나가 실패하면 나머지로 계속하고 셋 다 실패하면 오류 | 시가총액 전용 포트 추가, 빈 칸 재분배 |
| G-08 | "토요일 오전"은 KST 토요일 06:00~12:00(`weekly_review_slot`)으로 정한다. 쏠림·원칙 위반은 기존 `Policy::check_current`로 판정해 카드에 그대로 담고(판정 불가는 `Unavailable(사유)`), 성적표 갱신(`ScorecardRefresh`)과 AI 요약(`WeeklyReviewNarrator`) 실패는 카드에 실패로 남기고 계속한다. 같은 토요일에 이미 카드가 있으면(`WeeklyReviewCards::last_week`) 다시 만들지 않는다. 화면 표시는 다른 묶음 | 성적표 실패 시 카드 저장 중단, 오전 범위 08:00~12:00 |
| G-12 | 짝지은 비교는 종목·KST 날짜 해시로 정하는 결정적 표본(`paired_sample`, 기본 5건 중 1건)에서만 돌리고, 예산은 `BackgroundBudget`(AI-2) 한 번 허가로 두 갈래(기준·도전, `ComparisonArm`)를 같은 대상으로 차례로 부른다. 갈래 실행기(`ComparisonArmRunner::record_only`)는 신호를 만들지 않는 기록 전용 실행 ID만 돌려주고, 쌍은 `PairedComparisonLog`에만 남긴다. 어느 갈래든 채팅으로 끊기면 기록하지 않는다. 성적표 비교 수는 기존처럼 관측의 (모델, 프롬프트) 조합 수로 반영된다 | 한쪽 실패 시 기록 생략, 별도 비교 수 저장소 |
| T-09 | 종목 마스터(`/stocks/all`, T-21)와 섹터 조회는 이미 master에 있고 `/stocks/all`은 제한기의 `StockAll` 그룹(초당 1회, 보수 간격 약 1.67초)에 묶여 있어 코드 변경 없이, 가짜 서버로 연속 전체 종목 조회 간격이 1초를 넘고 섹터 그룹은 그 대기에 막히지 않음을 통합 테스트(`t09_instrument_pacing`)로 고정한다 | 전체 종목 조회 전용 제한기 추가 |
