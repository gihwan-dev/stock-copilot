## 1. 매매 제안을 확률 신호로 바꾸기

사용자 의견: AI는 확률만 계산하고, 코드가 임계값과 비교해 매수·매도 버튼을 띄운다. 투자 성향에 따라 기간을 정한다.

### 1.1 AI가 추정하는 것

"오를 확률"은 얼마나 올라야 오른 것인지가 없어서 맞았는지 채점할 수 없다. 그래서 채점할 수 있는 사건 하나로 정한다.

> 기간 H 안에 **목표 수익률 +T%에 먼저 닿을 확률 p**. 그 전에 손절선 −S%에 닿거나 기간이 끝나면 실패.

- T, S, H는 AI가 정하지 않는다. 코드가 투자 성향과 그 종목의 변동성으로 정한다: T = a·σ√H, S = b·σ√H (σ는 일 변동성, H는 거래일 수, a와 b는 투자 성향별 상수).
- AI는 p와 근거, 출처만 낸다. p는 1~99의 정수 퍼센트다.
- 결과는 코드가 수정주가 일봉으로 판정한다. 기준일, 목표와 손절에 모두 닿은 날, 몇 시간 단위 기간은 1분봉으로 판정한다 (design 6.6). 사람이나 AI의 해석이 끼지 않는다.

### 1.2 임계값

2026-11-11 리뷰([reviews/DESIGN-v0.2.md](reviews/DESIGN-v0.2.md))에서 기준 확률 `S/(T+S)`가 기간 제한이 없을 때의 값이라는 지적이 확정되어 식을 바꿨다. 메인 에이전트가 사용자 결정의 취지(AI는 확률만, 코드가 임계값)를 유지하는 범위에서 승인했다.

한 번 거래의 기대 수익은 `E = p·T − q·S + r·m − c`다. q는 손절 확률, r은 기간 만료 확률(p + q + r = 1), m은 만기로 끝났을 때의 평균 수익률, c는 왕복 수수료와 세금이다. 가정: AI의 정보는 확률을 손절에서 목표로 옮기고 만기 몫(r, m)은 바꾸지 않는다. 정보가 없을 때 비용을 빼기 전 기대 수익은 0이므로, p가 기준 확률보다 Δ만큼 높으면 `E = Δ·(T+S) − c`다.

| 값 | 식 | 뜻 |
|---|---|---|
| 기준 확률 p₀ | 방향 없는 무작위 움직임에서 두 경계(+T, −S)와 기간 제한(H)이 있을 때 +T에 먼저 닿을 확률. 급수 해는 [reviews/DESIGN-v0.2.md](reviews/DESIGN-v0.2.md) 2절 | 아무 정보가 없을 때의 확률. AI가 넘어야 할 출발선. `S/(T+S)`는 기간 제한이 없을 때의 값이라 쓰지 않는다 |
| 손익분기 확률 | `p₀ + c/(T+S)` | 기대 수익이 0이 되는 확률 |
| 매수 임계값 | `p₀ + c/(T+S) + 여유분` | 이 이상이면 매수 버튼 |
| 매도 임계값 (보유 종목) | `p₀ − 여유분`. 5% 아래로 내려가지 않는다 | 보유 종목이 이 이하이면 매도 버튼. 매도 비용은 지금 팔든 나중에 팔든 같으므로 넣지 않는다 |
| 그 사이 | - | 버튼 없음 (보유 유지) |

- T와 S가 변동성에 비례하므로 p₀는 (a, b)로 거의 정해진다. 위험 성향별 (a, b)는 p₀가 20~40% 안에 들도록 고른다.
- `c/(T+S)`가 5%p를 넘거나 변동성 표본이 60거래일 미만이면 그 종목에는 추정 과제를 만들지 않는다. 신호가 없고, 화면에 따로 드러내지 않는다. 몇 시간 단위 기간은 T와 S가 작아 이 규칙으로 대부분 걸러진다.

예 (국내 주식, c = 0.25%, 여유분 10%p, a = 1, b = 0.5, 일 변동성 2%). (a, b)와 H는 계산을 보이기 위한 예시 값이고 확정값이 아니다. 몇 시간 단위는 하루 변동성이 시간의 제곱근에 비례한다고 가정했다. 계산 스크립트로 급수 식을 직접 계산한 값이다.

| 기간 (H) | T | S | 기준 확률 p₀ | c/(T+S) | 손익분기 | 매수 임계값 | 매도 임계값 |
|---|---|---|---|---|---|---|---|
| 몇 시간 (0.25거래일) | 1.00% | 0.50% | 27.3% | 16.7%p | 과제 없음 | - | - |
| 며칠 (5거래일) | 4.47% | 2.24% | 27.5% | 3.7%p | 31.3% | 41.3% | 17.5% |
| 몇 주~몇 달 (40거래일) | 12.65% | 6.32% | 28.1% | 1.3%p | 29.4% | 39.4% | 18.1% |
| 반년 이상 (120거래일) | 21.91% | 10.95% | 28.6% | 0.8%p | 29.3% | 39.3% | 18.6% |

같은 (a, b)에서 일 변동성이 1%면 p₀는 27.2~28.0%로 거의 같고, 며칠 기간은 `c/(T+S)`가 7.5%p라 과제를 만들지 않는다. 몇 시간 단위 기간은 기본값에서 꺼 둔다.

### 1.3 투자 성향

설정에서 고른다. 값은 초안이다.

| 항목 | 선택지 | 바뀌는 것 |
|---|---|---|
| 기간 | 며칠 / 몇 주~몇 달 / 반년 이상 (몇 시간은 선택 사항) | H, 그리고 그 기간의 변동성으로 T와 S를 정함 |
| 위험 성향 | 보수 / 중립 / 공격 | T와 S의 변동성 배수 (a, b), 여유분, 한 번에 사는 비중 |
| 제외 | 종목 유형, 섹터 | 신호 대상에서 뺌 |
| 비중 상한 | 종목, 섹터 | 기존 투자 원칙과 같음 |

### 1.4 확률을 믿을 수 있게 만드는 장치

LLM이 말하는 확률은 실제 빈도와 잘 맞지 않는다(R-12). 그래서 다음을 둔다.

- 모든 추정을 기록한다. 거래하지 않은 것도 기록하고 결과를 판정한다.
- AI에게 기준 확률을 먼저 보여 주고, 근거가 있을 때만 거기서 올리거나 내리게 한다.
- 판정이 끝난 추정이 쌓이면 "AI가 60%라고 한 것 중 실제로 몇 %가 맞았는지"를 계산해 성적표에 보여 준다. 모델별, 기간별로 따로 낸다.
- 판정된 추정이 30건이 되기 전에는 여유분을 크게(15%p), 한 번에 사는 비중을 작게 둔다. 30건은 표시를 시작하는 최소 기준이고, 실력을 증명하는 수는 아니다(R-12 계산으로는 약 200건). 판정 건수는 같은 종목에서 기간이 겹치지 않는 추정만 센다. 모델이 바뀌면 그 모델의 건수가 30건이 될 때까지 보수적 운용으로 돌아간다.
- 30건 이후에는 코드가 실제 적중률로 확률을 보정한 뒤 임계값과 비교한다. 보정 방법은 E-91의 ADR에서 정하되, 표본이 적을 때 기준 확률 쪽으로 당기는 방식이어야 한다. 확률 구간별 적중률은 성적표 표시용이다.

## 2. 약관 문제

### 2.1 Anthropic 소비자 약관의 증권 조항

약관 3조의 금지 목록 원문(R-13):

> To rely upon the Services, the Materials, or the Actions to buy or sell securities or to provide or receive advice about securities ...

- 이 조항은 Claude가 주문을 내는지가 아니라 **사용자가 Claude의 출력을 믿고 매매하는지**를 말한다. 그래서 "AI가 직접 하지 않는다"로는 벗어나지 못한다.
- 확률 도구로 바꿔도 그 확률로 매수·매도 버튼이 뜨므로 문언상으로는 같은 범위다. 1장의 방식은 약관 때문이 아니라 채점할 수 있고 판단을 코드가 한다는 이유로 채택한다.
- 조항 끝의 "Anthropic은 증권사나 투자자문업자가 아니므로"를 근거로 책임 부인 문구로 읽는 해석도 있다. 실제 제재 사례는 찾지 못했다.

선택지:

| 안 | 내용 | 비용 | 약관 위험 |
|---|---|---|---|
| 가 | 전부 Claude 구독으로 | 추가 없음 | 문언상 위험. 계정 제한 가능성을 감수 |
| 나 | 확률 추정 작업만 Codex(ChatGPT 구독)로, 나머지는 Claude 구독 | 추가 없음 (ChatGPT 구독이 있으면) | OpenAI 약관에는 증권 금지 조항이 없고 사람 검토 없는 금융 거래 자동화만 금지한다. 사람 승인 구조와 맞음 |
| 다 | 확률 추정 작업만 Claude API 키로 | 사용량만큼 과금 | 상업 약관에는 이 조항이 없음 |

상태: `확정`. 사용자가 **가**로 정했다. 공개하지 않는 개인용 앱이고 위험은 본인 계정에 한정된다는 판단이다. 어댑터 구조는 유지해서 필요하면 설정에서 작업별 제공자를 바꿀 수 있게 한다.

### 2.2 구독 한도를 쓰는 예약 작업

상태: `확정`. 사용자가 위험을 감수하기로 했다. 한도 초과를 대기 상태로 다루는 설계는 그대로 둔다.

## 3. 뉴스 수집과 웹 검색

문제 세 가지가 얽혀 있다.

- 네이버 검색 API를 쓸 수 없다(신규 신청 중단, 저장 금지).
- Claude Code와 Codex에는 웹 검색 도구가 내장되어 있다. 이것으로 종목별 뉴스를 찾을 수 있다.
- 그런데 보유 내역을 아는 AI가 웹 검색을 하면 검색어로 수량과 금액이 새어 나갈 수 있다(R-12에 실제 사례).

해소: **실행을 둘로 나눈다.**

| 실행 | 볼 수 있는 것 | 쓸 수 있는 도구 |
|---|---|---|
| 수집 실행 | 종목명과 코드만. 수량, 금액, 계좌는 모름 | 내장 웹 검색, 웹 읽기 |
| 분석 실행 | 보유 내역 전체, 수집 실행이 모은 자료 | 앱 MCP 도구만. 웹 도구 없음 |

- 수집 실행은 새어 나갈 비밀을 갖고 있지 않다. 그래서 웹 읽기 도구를 다시 허용해도 된다.
- 분석 실행에는 웹으로 직접 나가는 도구가 없다. `read_article`은 본문 읽기가 켜진 언론사 RSS 소스 도메인의 주소만 받고 수집 실행이 웹에서 가져온 주소는 거부한다. 남는 것은 낮은 대역 통로다: 분석 실행이 웹 조사에서 고르는 종목과 주제가 검색어에 드러난다. 고를 수 있는 값은 코드의 목록(앱이 아는 종목, 코드가 정한 주제)뿐이다 (2026-11-11 리뷰 반영).
- 종목명이 검색 제공자에게 전달되는 것은 남는다. "이 종목에 관심이 있다"는 정도의 정보다.
- 채팅에서 사용자가 웹 검색을 시키면 수집 실행을 따로 띄워 결과만 받아 온다. 사용자가 채팅에 직접 쓴 문장은 AI가 고쳐 쓰지 않고 원문 그대로 수집 실행에 넘긴다.
- 공시(KIND, DART)와 언론사 RSS 수집은 지금처럼 코드가 한다.
- 언론사가 기사에 "AI 활용 금지"를 표시한 경우를 위해 소스별로 본문 읽기를 끌 수 있게 한다.

상태: `확정`.

| I-03 | AI CLI 격리. 설계의 명령으로는 사용자 훅과 플러그인이 섞인다 | 사용자의 기존 로그인을 그대로 쓴다(P-2). 격리는 환경 변수 비우기, `--restricted --disable-slash-commands`와 R-02의 권한 옵션, 빈 작업 폴더, 실행 전 점검으로 한다. R-02 실측에서 이 조합으로 훅, 플러그인, 설정, CLAUDE.md가 차단되고 구독 인증이 유지됐다. 앱 전용 설정 폴더는 별도 로그인이 필요해서 쓰지 않는다 | 확정 |
| I-04 | CLI가 대화 기록과 큰 도구 결과를 자기 폴더에 평문으로 남긴다 | 도구 결과를 3만 자로 제한하고 나눠서 준다. 예약 작업과 채팅 모두 기록을 남기지 않는 옵션으로 돌린다. 채팅은 대화 동안 프로세스 하나를 유지하고, 앱을 다시 켜면 앱이 보관한 대화를 다시 넣는다(2026-11-11 리뷰 반영. `--resume`에 기대지 않는다). CLI가 앱 작업 폴더 이름으로 만든 폴더가 남으면 앱이 지운다 | 확정 |
| I-05 | 예수금을 알 수 없다 | 화면에는 매수가능금액으로 표시한다. 거래내역으로 현금을 재구성하는 것은 대조용으로 나중에 한다 | 확정 |
| I-06 | 거래내역에 고유 ID가 없다 | 최근 14일을 매번 다시 받아 같은 행의 개수까지 맞춘다. 사라진 행은 지우지 않고 표시만 한다 | 확정 |
| I-07 | 결과를 모르는 주문 | 10분 안에는 같은 키로 재요청. 이후에는 종목, 방향, 가격, 수량, 시각으로 대조 | 확정 |
| I-08 | 토스 스펙이 버전 번호 없이 바뀐다 | 스펙 파일의 해시로 변경을 감지한다 | 확정 |
| I-09 | 기간 수익률 계산에 일별 평가 기록이 필요한데 앱이 꺼진 날은 기록이 없다 | 메뉴 막대에 상주해 창을 닫아도 돌게 한다. 빠진 날은 일봉과 거래내역으로 다시 계산한다 | 확정 |
| I-10 | 감사 로그를 "지울 수 없게" 만들 수는 없다 | "변조를 탐지할 수 있는 로그"로 요구사항을 낮춘다. 토스 주문 내역과 대조한다 | 확정 |
| I-11 | 셸 명령으로 보호 파일을 고치는 것을 훅으로 못 막는다 | 샌드박스의 쓰기 금지 목록과 CI의 서명 검사를 함께 쓴다 | 확정 |
| I-12 | 격리해서 띄운 리뷰어도 원본에 쓸 수 있다 | 시작과 종료 때 원본 상태를 비교하는 훅 | 확정 |
| I-13 | 커버리지 100% 기준과 방어용 분기의 충돌 | 타입으로 분기 자체를 없앤다. 남는 것은 보호된 예외 목록에 적는다 | 확정 |
| I-14 | `testkit`이 `order-execution`에 의존하면 주문 차단 구조와 충돌한다 | `testkit`은 `order-execution`에 의존하지 않는다. 가짜 본인 확인은 `application`의 `UserPresence` 포트 가짜로 `testkit`에 두고, 가짜 증권사는 `trade-fakes`에 둔다. `order-execution` 안의 테스트 전용 모듈은 `src-tauri` 경로 고정 테스트가 쓸 수 없어서(`cfg(test)`는 그 crate 안에서만 보인다) 이 방식으로 바꿨다 (architecture 3.2) | 확정 |
| I-15 | TS 금액 타입을 문자열 브랜드로 만들면 산술이 그대로 통과한다 | 내부를 볼 수 없는 객체 타입으로 만든다 | 확정 |
| I-16 | TypeScript 7을 린트 도구가 아직 지원하지 않는다 | 타입 검사는 7, 린트는 6으로 함께 설치한다 | 확정 |
| I-17 | 이 PC의 Rust가 1.88인데 Tauri 2.12는 1.90 이상이 필요하다 | 저장소에 도구 버전을 고정한다 | 확정 |
| I-18 | 미국 지수와 금리 출처 | 장중은 토스의 미국 ETF 시세, 일별 값은 미 재무부와 FRED | 확정 |
| I-19 | 리서치 결과가 설계 문서에 반영되지 않았다 | 작업 R-90. Opus 서브에이전트와 리뷰 절차로 진행 | 확정 |
